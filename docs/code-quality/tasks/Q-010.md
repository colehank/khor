已确认根因：原代码只比较scrollHeight，漏了clientHeight。keyboard resize引发scroll先于ResizeObserver时，将浏览器布局滚动误判为用户上翻。实际原始基线top3421→0，viewport663→357。原始证据baseline-probe.log、baseline-debug.log。

首版clientHeight检查解决原复现，但composer增高的晚到scroll仍落后100px。第二版补一帧layout纠正，独立审查的真实wheel+同帧resize发现会撤销用户滚动；WebKit还在682ms后恢复旧位置。对应红证据composer-debug/results.json、scroll-input-race-red2/results.json、scroll-script-webkit/results.json。

第三版在统一owner中先接纳真实输入后已发生的位移，输入归因有界且惯性滚动续期；无输入的外部composer焦点恢复不改变阅读意图。layout同时比较内容与viewport高度，真实上翻保留新锚点，显式到底部恢复尾随。普通非composer纯scroll仍按原逻辑接受。

Chrome与WebKit开发验证覆盖ACP/Khor尾部、历史、同帧输入+resize；结果路径chat-third-fix。测试作者在运行中补了逐帧断言，所以本次仅计开发验证，最终固定源码/脚本指纹需重跑。独立审查记录Q-010-011-review.md，第二版阻断尚待第三版复审关闭。
