## 现场与根因

原实现 A→B 后外部回到 A，mine 只替换 was，仍保留旧 by，save-road 将新读取 A 推进为旧 head B。mine 同时捕获点击时的旧文本，且迟到 fetch 可在 discard/unmount 后通过 asked 写入。

- typing-during-read 同样被旧 head 推进。
- cancel-during-read 在真实组件卸载和 discard 后仍发出第 3 次写入（原有 2 次），违背取消。

## 实现

- save-road.readForOverwrite 读到新磁盘基准后，只有在 pin(text) 被消费时才校验 road epoch/hush 并创建新 by。即使 read 已完成、消费前发生 discard/reopen，旧结果也不能提供 pin；没有可编辑 digest 的读取同样拒绝。
- FileView 按挂载/文件/动作代次撤销旧覆盖读；pin 使用 leaving 中同步更新的最新文本，不使用点击时捕获文本。基准 file、edit 和下一次写入保持同一新编辑线。
- 普通 write/forward/asked 的 CAS 行为不变。独立旧 buffer 仍会冲突，确认后磁盘再次改变仍拒绝，内容 ABA 在相同摘要时按既有 CAS 接受。
- 不清全文件 lineage，不把 asked 当作强写开关。
