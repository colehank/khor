## Khor本地confirmed与待证实根因

### 对修复边界的建议（待root决策；未实施）

确认两层责任：Tauri锁定实现的listen ack并非JS注册ready；Khor的owner撤销既忽略异步cleanup失败，又没有回调gone保护。仅return/await cleanup可收住unhandled，却不能修复未发native unlisten与callback遗留；仅加gone guard可避免旧owner回调，却不能释放资源；仅补registry缺id guard会把throw退化成已证实的静默callback遗留。

建议由root独占公共API，选择一个明确的版本兼容适配边界，再逐项验证：

1. 订阅handle自身拥有确切handlerId与native eventId，撤销即禁止业务回调；不依赖event registry“此时已执行”才能移除JS callback，native unlisten独立可达；listen拒绝也释放已分配handler。这可做成窄的本机Tauri adapter（仍走实际plugin:event命令与callback引擎），但目前SDK没有公开unregisterCallback export，需明确是否允许这一锁定内部入口，不能偷偷伪称全公共API。
2. 或在固定上游依赖修其register-ready/cleanup契约并验证两端；不要无依据升级/固定延迟/删StrictMode。Rust eval当前sync安排队列不是JS完成回执，若修ready需真正完成信号而非多等一帧。
3. 第一方统一的mount owner只在import结束仍活跃时发起listen；已入场才撤销则完成确切双侧清理，幂等并观察cleanup拒绝。需覆盖hear、onPageWord、onQuitRequested/onFullscreen等同形适配以及SDK drag listener边界，不能只全局吞TypeError。

### 最小状态与资源归属

adapter handle分别持有：owner是否仍活跃、唯一handlerId（可空）、native EventId（未知/已知）、入场Promise（未发/等待/接受/拒绝）、一次cleanup任务（未开始/等待id/写线/ack/失败）。owner状态不能由RPC答复反向变活；同event并行的句柄只清理自身两个id。被调用业务函数单独置null，关闭立即释放对组件/附件闭包的持有，不能只把gone设true仍长期抓着原回调。

| 时序/结果 | 必须行为与实际完成判据 |
| --- | --- |
| owner先于dynamic import完成关闭 | 不再分配callback、不再发listen。import失败有明确subscribe诊断，不触达已关闭组件。 |
| handler已分配，listen尚等待时关闭 | 同步inactive、清空业务函数、通过已知handlerId删除core Map callback一次；等待原入场结果仅为获取EventId并撤销native，不能再次调用用户函数/onReady。 |
| listen拒绝 | 回收本句柄handler；有阶段为listen的诊断。没有EventId时不能发猜测id。若原生返回明确拒绝可确认为未入场；若桥接中断/丢ack导致“可能接受但无id”，必须标资源状态不确定，不能谎报Rust已释放。文档销毁是最终框架回收边界；不要无限隐藏重试。 |
| ack先于注册eval，但owner仍开 | handler保持活跃；eventId已归此handle。即使native先派发事件，也只接受本owner的callback；不能把ack标为JS注册完成。 |
| ack先于eval，owner已关/随后关 | **与event组是否存在无关**：已知handler同步清Map，独立native unlisten(eventId)到达真实Rust并等ack；迟到eval只会插入引用已删除handler的数值metadata，不能复活closure。 |
| 在途event | wrapper在触达业务函数前检查owner；关闭后入队/迟到callback都no-op。若业务回调已在同步执行，不能撤销已发生动作；其异步后续也须在本owner处检查，不能声称取消JavaScript已执行部分。 |
| 重复cleanup | 同步inactive幂等；复用一次cleanup结果，不重复unregister/并发发native unlisten，不通过第二次清理改别的owner。只有实际unlisten ack且handler删除完成可记released。 |
| cleanup/unlisten拒绝 | JS callback仍先释放，旧owner不会回调；native失败必须报告为unlisten阶段和该句柄，**不**把catch后当released。可以保留小型失败句柄供显式/受限重试，但不持业务函数，不能自动无限循环或给用户触发多次相同错误。 |
| caller不await（React cleanup） | 同步dispose负责立即撤owner；adapter内部对每条import/listen/unlisten链附owned错误处理；公开释放结果应为明确结果/已观察Promise，不能void原始拒绝。不能拿React返回void的类型误认为SDK真实返回void。 |

失败诊断最小为operation阶段（load/subscribe/unsubscribe/compatibility）、event、目标kind/label、句柄序号、是否已知native id/是否回收handler、原错误；不含event payload/用户消息。订阅失败与退订失败分开，关闭后不再调用组件setState展示它，但仍有统一console/error sink可审计；不吞、不编造成功。

`released`只表Rust listener与JS callback两种资源实际完成。当前Tauri registry自身保留数值entry（原SDK也不delete），adapter不会私自碰它；迟到的数值metadata无业务closure，但大量订阅带来的metadata积累是上游边界，若本任务扩大到它则需独立契约，不能把callback释放冒充“表对象完全归零”。真实native回归应计两种资源/实际事件不会复投，而非仅看零unhandled。
