## 2026-10-25 恢复诊断与设计

所有者：agent_redaction。实际工作副本 `/Volumes/disk0/Khor/worktrees/current/khor-quality-agent-protocol`，HEAD 63f31737；原有未提交 a2a_http.rs 红用例保留并加强，生产尚未修改。

官方 A2A 1.0.1 [§3.4.1 / §3.4.3](https://a2a-protocol.org/v1.0.1/specification/#341-context-identifier-semantics) 明确 Context 可由 Task 或 Message 返回，并用于后续仅 contextId 的会话。当前成功 Message 经 role/parts/size/secret/标识一致性验证后已进入 Ledger.inputs.response，但 context 查询只看 tasks。

拟沿用 ledger v1：同 caller、同 alias、同固定 card_url 的 Task receipt 或已确认 Some(Message) 回执提供 context 所有权；pending input.message.context_id、未知 context 或不匹配端点不能提供授权。不会伪造 Task，不把可刷新 interface/token 当作会话的新身份；service.json 的 alias→card_url 固定边界保留。新增回复 context/task 的 opaque 标识验证。

保留语义已逐处核实：Input 无时间/TTL字段；inputs 只有插入、写 response 与读取，没有 remove/retain/数量淘汰；disconnect 只移除 endpoint.json，保留 service.json、ledger 和凭据。MAX_FILE=32MiB 满时拒绝新写，不淘汰老回执。因此成功 Message 回执在当前模型中是长期授权证据，不会因幂等缓存过期丢失；未来若清理 inputs 必须先保留/迁移 context 授权。

补充回归：原有 JSONRPC/REST 主流程中的 Message续聊/重复不重发/独立进程重启/错caller/错alias/错endpoint；进一步加入同 ledger 的 pending-only、错alias元数据、Task endpoint错配、未知context拒绝，Message无context不伪造context，非法回复context拒绝；断开/同服务重连后成功 Message context仍可用且alias不能绑定另一card。配对connector保留同ledger远端caller与home的双向隔离。

完整红命令拟为 `cargo test --locked -j 2 -p khor-node --test a2a_http jsonrpc_native_agent_interop -- --exact --test-threads=1`，必须等 root 唯一 Cargo 槽，未在此卡将未执行用例写成通过。
