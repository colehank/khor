## 实现与行为变化

- onset 参数在创建临时目录/SSH mux 之前验证；多个 host、含 shell 元字符的 host、purge 缺少 uninstall、卸载混用安装/print 选项均失败。全部参数顺序一致。卸载 dry-run 在此阶段打印计划并结束，不探测机器，不查询 root，不停止或删除。安装 dry-run 原有准备构建/远端探测行为不在本任务范围。
- 卸载将一次 store 选择、停止、binary 删除和可选 purge 放在同一个远端脚本；只有 `root/.khor` 可以被 purge，side-room 自身及其余文件保留。该 binary 原来就是共享 HOME 的公共文件，本任务未改变其普通卸载语义。
- 新 destructive resolver 与安装用 khor_root 分离。已安装 binary 的 `root` 仍是指纹/改名前目录选择权威；查询时清除继承 KHOR_HOME，避免 login 的另一实例 override 改写卸载目标。查询失败、非可执行 binary、未知/空/不可读/异常 owner、布局外路径、穿越、多行、store/room/owner 等符号链接均停止。
- 没有 binary 时，只允许以明确 owner hostname 回退。fingerprint-only 或 owner 不符不猜测；需要恢复可用 binary 才能解析改名身份。无可靠归属时保留数据并返回错误。
- 停服务拒绝符号链接 PID 文件、非数字及0/1（含零填充）PID；错误不再被卸载吞掉。识别到服务但无权 signal、TERM 失败、5秒仍存活均失败，保留 binary/store。正常停止后删除失败会返回非零，不继续 purge；不承诺跨文件原子回滚。
- 远端脚本拼接先完成本地文件，再调用 SSH，避免 POSIX pipeline 把本地读取失败伪装成成功。临时 staging 使用 mktemp 私有目录；mux 关闭失败不阻止本地清理。
