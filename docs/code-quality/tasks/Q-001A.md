### GUI-A01 · P1 · 自动保存把内容摘要当无环版本链，重复内容后制造冲突

- 基线源码：`apps/gui/src/lib/save-road.ts:146–155,213–215`；GUI 接收新摘要而保留编辑线 `by`：`apps/gui/src/views/FileView.tsx:720–724`。
- 触发：同一编辑线依次保存 A→B→C→A，再写 D；每一步均等待写入成功。摘要是内容身份，同样的内容会得到同一个摘要，因此 A→B→C→A 是合法操作。
- 机制：`moved[by,was]=digest` 构成环；`forward()` 固定迭代最多 1000 次，3 节点环最终把当前摘要 A 错指为 B。后端正确拒绝，GUI 错判为外部 `clash` 并停止自动保存。用户草稿仍在，但继续写入受阻。
- 可复现证据：真实模块用 esbuild 在内存转译，mock compare-and-write 使用 A/B/C 作为确定性摘要等价类。前三次 OK，D 的 `was=B` 而 disk=A，得到 `clash`。这是模块运行复现，尚非真 App 验收。
- 建议：以编辑线的单调写入代次及已确认头表示推进关系；至少对重复摘要/回环建立显式处理，不能只把循环上限加大。保留不同编辑线互相冲突保护。
- 验证缺口：应覆盖 A→B→A、A→B→C→A、长链、排队写入、卸载重挂和两个编辑线；已告知 Q-001C 核对现有检查。

### GUI-A02 · P1 · “不保存”期间仍在飞行的失败会重新启动重试并写回已放弃文本

- 基线源码：`apps/gui/src/lib/save-road.ts:235–281,300–326`。
- 触发：开始写入，响应尚未结束时调用 `discard()`；原请求随后失败且磁盘仍为旧内容，下一次重试成功。
- 机制：`forget()` 仅清理调用当时的 `failed/retry/next`；原请求 catch 再填入 `failed`，finally 安排 2000 ms 重试。重试直接调用 `start()`，不经过 `write()` 中的 `hushed` 检查。
- 后果：允许已经在飞行的写入结束是现有声明；但失败后再次提交已被用户放弃的编辑，违反该函数自己的“nothing is retried after it”契约，并可能在用户关闭标签后改变磁盘文件。
- 可复现证据：真实模块内存运行，第一次写入受控拒绝，`discard()` 后仍有 2000 ms timer；手动执行该 timer 后第二次 save 将 disk 从 original 改为 discarded edit。
- 建议：为每条 road 增加取消代次/重试所有权；discard/forget 后旧请求不得创建新 retry。保留“已提交写入可能结束”的明确边界。
- 验证缺口：discard/forget/discardAll 在飞行请求成功、失败、冲突、重试等待各阶段；补足 UI “不保存”真正调用到 discard 的回归。

复现脚本：`/Volumes/disk0/khor-code-quality-evidence/gui-audit/save-road-probe.cjs`；输出：同目录 `save-road-probe.log`。命令：`node /Volumes/disk0/khor-code-quality-evidence/gui-audit/save-road-probe.cjs`。`save-road.ts` SHA-256：`74d527b8c6eff6fa747eb1f0cc4f5cb5af589389f285b6855c8baea7c091d025`。probe 未接触真实文件 API、网络、用户数据，无构建。
