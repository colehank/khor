结论：**静态复核通过，未发现漏授或过授。** 原生重建和实际启动仍须 native 验收；本记录不将源码核对算作 App 通过。

- 当前 Cargo.lock 的真实插件是 `tauri-plugin-notification 2.4.0`。其 `src/lib.rs:225–237` 注册 is_permission_granted 并注入 init-iife；脚本初始化 Notification.permission 时在非 Windows 分支调用 `plugin:notification|is_permission_granted`。脚本中 request_permission 与 notify 仅在相应显式 API 被调用时执行，并非该初始化的额外必需权限。
- 插件 `permissions/autogenerated/commands/is_permission_granted.toml` 精确将 `allow-is-permission-granted` 映射到 commands.allow=["is_permission_granted"]。`src/commands.rs:10–19` 仅读 permission_state，并映射 bool/None；不会弹授权框、发送通知或修改权限。本候选唯一 `notification:allow-is-permission-granted` 正好覆盖该入口，没有引入 notification:default/request/notify 等额外权限。
- 项目 build.rs 仅 tauri_build::build，tauri.conf.json 没有 capabilities 显式筛选。实际 tauri-build 2.6.3 `src/acl.rs:424–435` 默认读取 `./capabilities/**/*`；tauri-utils 2.9.3 `get_capabilities` 在 config 未列 capabilities 时包含文件能力。新文件因此会自动进入新构建；不需要给现有 positional/命令接口额外改动。
- webviews 精确为 main/menu/settings，无 windows 项、无通配符、无 remote。主入口是 WebviewUrl::default，settings 是 App(index.html?face=settings...)，桌面 menu_overlay/desktop.rs 的 menu 是 App(index.html?face=menu)。外部浏览内容由独立标签 WebviewBuilder/WebviewWindowBuilder External URL 创建，不因与 main 同 window 就得到该能力。iOS 自建 inert menu WKWebView 没有 Tauri IPC，不扩大本授权实际范围。
- tauri-utils Capability 默认 local=true、remote=None；resolved.rs:218–228 仅产生 Local 执行上下文，没有 Remote 授权。Tauri 2.11.5 webview::on_message 在 invoke_handler/plugin handler 前校验 invoke key/origin/ACL；来自 remote 的调用即使复用了 main 这样的 label，也不能因本文件得到许可。未发现能力绕过。
