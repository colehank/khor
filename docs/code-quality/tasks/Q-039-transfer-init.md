## Current failure path, facts vs pending runtime

`receive` holds LOCAL mutex and exclusive OS `gate`, checks reservations, acquires a real owner slot file, and creates the final64hex id directory before manifest/body/initial checkpoint. Normal initialize errors clean only after successful mkdir (the existing sentinel fix). A process kill bypasses that cleanup. Next `reservations()` tries to read every64hex stage manifest, so one partial final stage can block unrelated receives/reserved_bytes; cancel also requires the complete matching manifest.

Important error precision: mkdir-before-manifest kill is expected by **source tracing** to return **Error::Io(NotFound)** through read_manifest → private_file/check_file → symlink_metadata, not the assumed typed InvalidStage. No runtime claim yet; prepared test prints actual error. Existing final damaged/missing-meta stages must not be deleted automatically or called recovered by this slice.

## Minimal proposed contract (await root confirmation)

Recommend no new public API. Keep `receive/reserved_bytes/cancel`; after `gate()` obtains both LOCAL and real OS gate, call a private `reconcile_initialization(&Gate)` before reservations/owners. The same gate stays held through any new create/initialize/publish and until receive has bound its owner. A gate holder can prove no cooperating initializer is alive; no PID/age guess, no new live-owner table.

Use **one exact reserved singleton namespace `root/.initializing`**, never a broad prefix GC or per-PID directories. Since the gate serializes initialization, there can be at most one. It is unpublished and can contain **only bounded control files**: `manifest` ≤64KiB (partial contents allowed), `body` exactly0 bytes, `offsets` ≤one72-byte initial record (partial contents allowed). It can never receive network chunks: Sink is created only after final publication. No user body is valid in this namespace. A complete synchronized init may be aborted/retried after crash; it has no Stored receipt.

Initialization sequence under gate:

1. Reconcile only this exact namespace with a strict complete validation pass before deleting anything. Missing is ordinary. Reject/preserve any unknown name, directory, symlink/reparse, hardlink, nonprivate/owner mismatch or over-budget control file; return a diagnostic, do not partially clean the safe-looking siblings. Bound entry listing at4 (only3 are legal), no recursive traversal. For accepted files, unlink exact names then remove now-empty namespace; an interruption of cleanup leaves another accepted subset for next pass.
2. Existing published stages are scanned/counted normally; quota and owner admission occur before initialization. `create_dir(.initializing)` succeeds or returns error with no deletion authority over a failed-mkdir target. Reconciliation and creation are separate: initialization error cleanup may clean only the successfully created namespace via the same validated helper, retaining original error + Cleanup error if cleanup itself fails.
3. Create_new/write/sync manifest, create_new/sync empty body, create_new/write/sync initial checkpoint. Close their handles before directory publish (important for Windows). Validate the completed controls/binding once. No arbitrary temp names / uncontrolled writes inside init.
4. **Atomic no-replace publish** `.initializing → final id`; any existing final destination (even empty) is preserved and causes explicit conflict. Do not use std::fs::rename's possible empty-directory replacement as an overwrite policy. All paths are same trusted canonical root / same volume. Need a small platform no-replace helper or a root-approved narrower cooperating-root assumption; no fallback to check-then-overwrite if the selected primitive is unsupported.
5. Existing owner write/sync+LOCAL insertion and Sink construction stay in current order. No fallible operation after LOCAL insertion. If killed after publication, final stage is fully initialized and charged to quota, and OS owner/gate release permits ordinary resume. No cleanup of published stages/active Sink/unknown entry.

Private helper signatures can make ownership reviewable: `reconcile_initialization(&self, held:&Gate)->Result<()>`, `initialize_unpublished(&self, held:&Gate, manifest,id)->Result<()>`, `publish_no_replace(source,destination)->io::Result<()>`. No new transfer result/Applied variant. The helper token enforces internal gate use; raw file API remains subject to private-root/cooperating-writer contract.

## Safety details and platform boundaries

- Root is an exclusively managed dedicated private directory, as existing TransferStore contract already requires. The cleanup namespace is reserved only for engine controls, not a user content directory. Gate identity assumes cooperating code does not replace/unlink `gate`; arbitrary hostile same-user filesystem mutation is not claimed solved.
- Unix: keep0700/0600 checks; init dir/files must have root's uid (authority is the caller-owned trusted root) and regular init files must have `nlink==1`. Reject links before opening/deleting; directories are checked with symlink_metadata. Do not chmod existing objects or delete a sentinel to pass.
- Windows: stable MetadataExt link-count remains nightly-only. If enforcing hardlink refusal in this slice, use a narrow Kernel32 GetFileInformationByHandleEx(FileStandardInfo=1) query for NumberOfLinks, and reject all FILE_ATTRIBUTE_REPARSE_POINT entries. FILE_STANDARD_INFO layout is two i64, u32 link count, u8 DeletePending, u8 Directory with native alignment (24 bytes), not BOOL-sized final fields. Failure to prove uniqueness fails closed. No Windows runtime result yet. Existing core `check_private` does not validate Windows ACLs; caller-owned private root remains a precondition, not a new asserted ACL implementation.
- Atomic publish candidate primitives: Apple renamex_np + RENAME_EXCL; Linux renameat2 + RENAME_NOREPLACE; Windows MoveFileExW without REPLACE_EXISTING/COPY_ALLOWED (same-volume directory). Exact supported-platform helper/API availability still needs root choice and primary-source checks before implementation. Unsupported no-replace must not silently become destructive rename. Keep no dependency/lock changes.
- Sync meaning: the current core guarantees file sync/checkpoint process restart, not directory power-loss transaction durability. The three control files must finish sync before publication. Any directory sync policy/Windows equivalent needs separate exact contract; do not advertise stronger crash/power-loss semantics from the new name alone.
- Quotas: gate-held reservation check precedes init. The init namespace has at most one empty body plus≤64KiB+72B control data; no unpublished declared-body reservation can receive data. Published stages still count declared bytes and stage count exactly once; max2 owners unchanged. Failure/killed initializer releases its OS owner slot and gate; no LOCAL insertion until complete.

Primary sources checked (not runtime proof): [Rust stable MetadataExt](https://doc.rust-lang.org/stable/std/os/windows/fs/trait.MetadataExt.html) confirms number_of_links is nightly-only; [Microsoft FILE_STANDARD_INFO](https://learn.microsoft.com/windows/win32/api/winbase/ns-winbase-file_standard_info) defines NumberOfLinks and BOOLEAN fields; [Microsoft API class table](https://github.com/MicrosoftDocs/sdk-api/blob/docs/sdk-api-src/content/winbase/nf-winbase-getfileinformationbyhandleex.md) maps class1; [Microsoft MoveFileExW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw) documents same-volume directory moves and replace flag. Apple owned source [vnode_if.h](https://github.com/apple/darwin-xnu/blob/main/bsd/sys/vnode_if.h) identifies matching EXCL flag; direct userspace header/man primary check is still pending before implementing. No third-party source is used as authority.
