# Q015：原生通知插件初始化的权限拒绝

状态：working；发现者 native_acceptance；root 准备独立候选，未修改原生验收中的集成树。

冻结 c3fe828b 的真正 Tauri iOS App 已观察 unhandledrejection：plugin:notification|is_permission_granted 被ACL拒绝。初步定位为 tauri-plugin-notification 2.4.0 自身 src/lib.rs 注入的 init-iife.js，在启动时调用该查询但没有catch；不是App前端额外发送通知。当前 default capability 只有core事件/窗口、scan capability为barcode。实际事件/依赖脚本/capabilities由native验收证据保留，不能只据本卡改权限。

目标：原生启动没有这一未处理拒绝；权限收敛到真实初始化需要的最小只读查询，不因异常直接授予notification:default或发送/请求通知权限。先核对实际冻结依赖/调用和capability匹配窗口/来源；原native验收窗口结束后独立实现并有回归、独立审查。远端不可信网页权限保持拒绝。

验收：同一隔离真实App启动事件不再出现该拒绝，确认查询返回正常且没有扩大到发送或请求系统权限；记录具体capability差异和平台边界。物理设备与模拟器分开，不据此宣称全部通知行为通过。

候选位于 agent-protocol 工作树：新增独立 notification-state capability，仅 main/menu/settings 本地 webview 的 `notification:allow-is-permission-granted`。root 已逐字核对 registry 2.4.0 init-iife.js 的初始化调用及 autogenerated command permission，未添加 send/request/default 权限。候选待非作者审查；当前没有以 JSON 存在代替真实 App 验收，下一原生重建时再检 startup rejection 与 query 返回。
