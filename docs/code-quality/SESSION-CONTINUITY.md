## 2. 产品目标

Khor 中已创建或已导入的会话能够长期保留、可靠打开；历史长度和运行宿主不应让界面失去响应。用户能够看到已有内容、理解当前连接与执行状态，并使用实际支持的操作。

| 顺序 | 交付 | 目标 |
| --- | --- | --- |
| S1 | 长历史有界加载 | 首屏优先近期内容，向前分页；读取、传输、缓存和渲染都有上限；切换和关闭仍可操作 |
| S2 | 全部 ACP 的统一观看 | 以能力选择历史读取、持续跟随、交互和恢复；外部只读查看不接管原执行 |
| S3 | 会话连续性与恢复 | 会话身份和历史独立于一次运行；宿主存活则重连，结束后按能力恢复或重新打开 |

三个交付依次验收。S2 复用 S1 的有界链路，不先把 Codex 接入当前全量加载路径。

### 会话与动作的边界

- 会话长期保存身份、标题、工作目录、原生会话引用及必要配置；运行实例、界面连接、执行任务分别记录状态。
- 关闭视图、结束执行、删除历史是不同动作。暂时离线不能推断执行失败；存有历史不能推断进程仍活着。
- GUI 重开或崩溃后，仍存活的持久宿主应可重连；宿主死亡不抹掉会话及已保存记录。
- 机器重启后恢复记录和适配器支持的原生对话。普通 Shell 的进程内存、任意运行命令不作无损恢复承诺；重新打开是新运行实例，显示分界，不自动重放旧命令。
- 恢复前核对原执行者和同一会话写入归属。远端失联不是允许再启动一个 writer 的依据；结果不明的工具操作不得盲目重做。

## 3. 所有 ACP 智能体的支持契约

| 来源/能力 | Khor 行为 |
| --- | --- |
| Khor 托管的任意 ACP 会话 | 持久记录实际收到的对话事件，统一分页与跟随。只保证已接收记录，不伪造代理未提供的历史；复用/统一现有存储，避免并存多个可写真相来源 |
| 外部会话有安全的历史/观察接口 | 适配器读取并转成统一事件；可持续更新时跟随，否则标明为历史快照 |
| 外部会话只有可读取的原生记录 | 由对应适配器读取和跟随，进入相同的历史服务与展示链路 |
| 外部会话无可用内容来源 | 明确说明内容读取不受支持及实际可用动作；保留身份/状态，不画空白、不伪造内容、不自动恢复或接管 |

- 前端按 `可读历史 / 可跟随 / 可交互 / 可恢复` 等内部能力决定行为；它们不是声称 ACP 已有同名字段。具体接口待授权后设计。
- 当前 Khor 使用 ACP v1。`session/load` 是可选的恢复与历史回放能力，不是通用、无副作用的旁观订阅；不能用调用 load/resume 来冒充纯读取。
- 不能承诺任意第三方 ACP 代理都能旁观其他客户端的运行实例。逐适配器核对实际能力，记录缺口；协议升级不因发现新文档自动纳入。
- 只读会话允许阅读、搜索和复制；不开放发送、停止、修改执行配置或代答权限。它展示结构化对话记录，不等于镜像外部终端画面。
- MCP 提供工具能力，不承担终端画面接入或会话持久化保证。

## 5. 授权后的实现顺序

### S1：有界历史链路

1. 用隔离的长记录夹具固定失败，记录首屏时间、交互延迟、单批字节、读取量、峰值内存及渲染节点数。定位主要耗时后再修。
2. 设计近期首屏、向前分页和向后跟随的游标；首次展示不能依赖完整历史解析。必要索引后台建立，索引和缓存可失效重建。
3. 每批限制记录数与字节量；单条超大消息/工具结果另设按需展开路径。数据预算不能通过截断原始记录实现。
4. 可见区域渲染、缓存淘汰、Markdown/大工具结果延迟处理；早期历史可再次加载，不随翻阅无限占内存。
5. 取消传递到读解析/传输工作；前端请求代次隔离，防止切换后的迟到数据串入其他会话。无可见消费者时不持续做无用解析。
6. 保证跨页工具调用与结果关联、消息顺序、压缩/文件替换、半行写入、重复边界和阅读锚点。虚拟化后复制/搜索不能仅依赖已挂载 DOM。

### S2：能力驱动的统一只读入口

1. 盘点当前已注册和内置适配器的实际能力；明确协议声明与实测结果。
2. 移除前端仅按 Claude/Codex 名称决定观看入口的规则；共享历史服务、渲染与错误语义。
3. Khor 托管的 ACP 更新走明确的持久记录 owner；外部来源通过适配器提供内容，不复制执行逻辑。
4. 只读路径默认不调用会改变会话归属的操作，控制入口后端也校验权限/能力，不只隐藏输入框。

### S3：重启与恢复

1. 复用现有 `_host` / `_ghost` 等基座，先明确登记、运行、连接、任务的所有者，不先重写整套 daemon。
2. 打开顺序：已有历史可展示 → 核对 home 与执行归属 → 存活则重连 → 已结束则按能力提供原生恢复或新 Shell 实例。
3. 将持久化完成、状态发布、退出清理、重连期间的竞态写成契约；旧运行结果不能覆盖新运行状态。
4. 正常关闭、GUI 崩溃、宿主死亡、机器重启、远端断网分别验证，不能用一种重启测试代表全部。

## 6. 验收与交付标准

| 场景 | 必须满足 |
| --- | --- |
| 超长 Claude/Codex 历史 | 首屏不等待整份解析；读取/返回/缓存/渲染符合预定预算；侧栏、切换、关闭仍可响应 |
| 翻旧消息同时有新增 | 不漏、不重、不串会话；工具结果正确关联；阅读锚点稳定 |
| 单条超大输出、半行/损坏记录、文件替换 | 局部错误和可恢复状态明确；不能无界分配内存或无限重试 |
| 快速切换、关闭/重新打开 | 旧请求可取消或及时停止，迟到响应无效；资源回收有实测证据 |
| 各 ACP 能力组合 | 托管会话已有记录可读；外部历史/跟随/不支持路径均有清楚结果；只读不创建第二 writer、不发控制请求 |
| GUI 正常退出/异常退出 | 隔离持久宿主仍工作且可重连；临时会话按自身寿命契约结束 |
| 宿主死亡/机器重启/远端离线 | 历史和身份保留；恢复原 ID 或标明新 Shell 运行实例；不盲目重做副作用 |
| 最终 Lab | 主机长历史交互及窄屏滚动真实验收；标明真机、模拟器或浏览器的实际覆盖 |

性能数值尚未承诺。授权后先在固定设备和固定夹具上建立基线，预先登记响应时间、批次与内存预算，再以同一标准验收，不能事后放宽追绿。
故障先红后绿，正常行为与边界用有意义的测试；不重跑整个上轮矩阵来替代定向验证。新问题登记，不自动扩展专项。
