## 1. 用户要求及授权顺序

用户要求先把涉及多页的工作区布局讨论清楚，**而后制作独立 Lab，由用户验收，将验收后的 Lab 作为参考一并交给下一轮**。这不是立即修改产品 main 或 ship 的授权。

- 没有选中工作区时，右侧不显示内容；选中后左侧显示该工作区的文件树。
- 用户已确认：左侧返回列表时取消当前选择，右侧清空；保留各工作区标签、位置和未保存草稿，重新进入恢复。用户补充：已选工作区但无内容标签时显示该工作区“最近打开”，替代此前正文留空建议。
- 右侧最上方就是与 session 一致的标签页栏，不再有固定工作区标题。
- 标签栏右侧仅保留 session、更多、VS Code 三个图标，取消工作区图标；顶部常驻刷新希望取消。
- 左侧文件树标题第一行工作区名字，第二行 branch（如有）；无 branch 不留无意义空行。
- commit log 入口保留在文件树第一行。点击后在右侧完整标签页显示提交列表，点击提交后在该标签内显示完整详情，不再弹窗。
- 用户已回答提交范围为 **“当前分支完整历史”**，按需加载；不默认扩到整个仓库所有分支，也不能只展示最近 200 条。
- 修复跳转文件下拉两根滚动条、diff 文件标题横条透明；用户要求确认当前运行的是最新 GUI。

## 2. 用户同意进入 Lab 的行为与标签语义

1. **用户已确认。** 工作区选择成为左右两侧共同的状态来源。左侧返回工作区列表时清空当前选择，右侧回到空白；各工作区已有标签、位置和未保存草稿保留，重新进入恢复。
2. **按用户补充更新。** 选中工作区时恢复其已有标签；尚无标签或关闭最后一个内容标签时，保留标签栏右侧的三个操作，显示当前工作区的“最近打开”，点击恢复相应内容标签。不跨工作区混排；未选工作区仍为空白。
3. **已按用户“好的 lab吧”进入实验。** 稳定的标签 ID 与当前内容目标分开：列表目标为当前工作区/分支历史，点进后目标为不可变 commit hash，标签名称随内容改为提交摘要/短 hash；保持同一标签内的返回记录和列表位置。树里的“提交记录”入口打开或回到列表，文件标签并列保留，不因每次点击提交自动堆新标签。尚未将并排比较或新标签打开操作纳入本次必做范围。
4. 详情包括提交信息与完整变动文件/diff；“跳转到文件”仅一个滚动区域，文件粘性标题有稳定遮挡正文的材质。
5. 复用现有 `Tabs` 和设计系统，不复制 session 标签栏样式另造控件。左侧工作区名字/branch 承担身份，右侧标签仅表达正在看的内容。

用户已授权将上述方案制作成 Lab；这是实验方案确认，不等于最终视觉验收或产品发布确认。已制作隔离实例，用户可继续调整，接入正式产品仍属下一轮。
