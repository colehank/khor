## 实际执行顺序

1. H raw消费与production browser固定后，冻结Root源码/生成物/资源；一次构建匹配CLI和私有GUI，不等SDK整包，不发布。
2. 同一当前CLI仅额外产出一次Node libtest，跑L01原exact；当前私有GUI跑L02原两场景。两条原失败分别保留；新失败先读诊断，不重全矩阵。
3. 在私有工作区/测试文件完成桌面W/C/G/Q/B组合：导航、实时更新、路径拖选、长diff/菜单、公式和真实WK。每个结果标明实际入口/主题/材质/宽度，未测的组合保留待测。
4. 收到新的真人可用性后才开启限时Mac IME/保存失败/最后一键→正常Quit验收；不因历史答复自动假定用户现在有空。手机验收单独约定，覆盖同页视口、候选手势和自定义键行，桌面模拟不能替代。
5. SDK/EventStore有界启动闭包与完整S恢复完成后，再测同身份的存活重挂、host丢失和重启；不重复已证明且未受影响的UI/工具用例。新的独立问题只入NEXT-ROUND。
6. 逐项填写精确证据再作最终完成审计。R2-001/016若仍没有原现场或当前复现，明确列未证修复，不凭其它项绿自动关闭；只有用户明确接受延期才调整范围。

每包仍须有非作者Clean Code审查：领域名称、唯一状态owner、IO与纯规则边界、取消/失败清理、迟到结果身份、删除被替代分支，以及只解释必要原因的注释。不得以零注释、格式化数量或新增测试数量当完成目标。
