## 3. 授权后的实现边界

1. **统一打开意图。** GUI 正文、Markdown、终端自动链接与 OSC8 使用同一个内部/系统打开策略；提取器只提供目标。普通点击与 Cmd 点击每次只执行一个打开动作，不能再由局部 fallback 改变用户意图。文本拖选和 TUI 鼠标操作继续保留。
2. **先复现路径折行。** 在同一真实入口放入普通长路径与长网址，宽屏、缩窄、再拉宽，点击每一行；观察识别结果、链接坐标与原始换行标记。先固定失败，再修目标提取或坐标映射；不靠无条件删除换行拼接独立消息。
3. **明确导航状态。** 会话工作区 `{device, cwd}`、浏览位置和未提交草稿分开。左上角按钮显式恢复会话工作区；手动浏览不能修改会话 cwd，shell cwd 更新也不能抢走正在浏览的其它目录。不新增置顶推荐。
4. **修复共用输入边界。** 在操作开始时确定输入框/候选区域归属，保留原生选择与 IME；父子组件不再各自无条件 blur/卸载。真正外部点击在原动作完成后退出，候选内部转移和切换应用不等同于取消草稿。
5. **搜索退出使用同一交互规则。** 收拢 searching、editing 与 query 的退出动作，避免隐藏过滤与焦点不同步。
6. **验真实菜单组合。** 沿用设计系统的菜单材质，检查工作区实际入口在玻璃父层、窗口透明度、宽窄屏下的结果；网页推荐关闭策略不影响工作区补全。

仅共享有明确重复的打开策略、导航动作和输入交互规则；路径与网页保留各自解析/补全。遵守 [ENGINEERING](ENGINEERING.md) 的 Clean Code 约定，不造全能组件、不以增加注释或大范围格式修改代替职责清晰。
