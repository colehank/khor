3. **完成 R3-02。** 先统一可信运行事实及恢复资格，再接药丸状态、动作和固定工具位置；验证没有重复启动、重发命令或接管外部只读会话。按真实声明的 ACP/Pi 恢复能力处理。普通 Shell 结束后是新 run；Shell 内 Codex 一键续接仍需可信关联，不能凭 category 或历史猜测。若需新增关联协议或扩大能力，记录决策点并先与用户对齐，不暗中扩项。
4. **完成 R3-03。** 先核现有文件／提交状态与内容标签所有者，最小共享导航组件和布局槽位，再依次适配独立工作区、会话原导航。两入口逐一验证，保留当前甲板与其他动作。提交实体身份、预览槽和阅读位置沿正式模型处理，不带入 Lab 的假数据或类型强转。
5. **完成 R3-04。** 在真实共用 TabStrip 实现标题样式和预览标记调整，核文件／提交两入口的固定与编辑行为。只改视觉和既定预览契约，不顺带重写标签系统。
6. **组合验收与交接。** 在同一确切版本上按影响范围跑一次组合检查，检查四项联动及 Clean Code，自审最终差异。提供可验收 Lab／隔离实例和清单，分别报告自动、浏览器、Mac／手机真人证据及未验项。完成后回报，合并 main 和 ship 等用户另行明确授权。

每项按“定位与复现 → 最小实现 → 定向验证 → 自审 → 提交／更新账本”闭环，再开始下一项。不用未完成的大范围重构作为功能修复前提，不用反复全量构建代替定向证据。

## 执行纪律与 Clean Code

- 只由 Root 一个智能体执行，不新建、唤醒或派发子智能体。旧 PLAN 的多智能体分工不适用于第三轮；自审如实标为作者自审，不能冒充独立审查。
- 图查询优先，按实际覆盖不足回退定向读源码；界面修改先对照设计系统及最新用户决定。
- 真实状态单一来源、所有者清楚；业务决策不散落在多个 UI 条件中。共享两处相同的导航规则，容器只负责自身槽位和内边距。
- 命名说明意图、函数职责集中、避免布尔组合矛盾和重复分支；必要时以明确状态类型表达关系。只在当前任务触及的边界整理，不搞全仓格式迁移或提前设计泛化框架。
- 用命名和结构表达“做什么”，删除重复解释代码的注释；只保留无法从代码看出的原因、约束及外部协议限制。不以“零注释”机械衡量 Clean Code。
- Bug 先复现再修复；验证公共行为和失败后结果，不写复刻实现的测试。样式微调直接量取布局与观察，不新增低价值测试。通过后仅在改动或新失败影响原结论时重跑。
- 验收同时检查一致性：字与图标尺寸、列线、玻璃形状／选中尺寸、上下间距、动作反馈和状态语义；不同入口共享规则而非复制 CSS 偏移。
