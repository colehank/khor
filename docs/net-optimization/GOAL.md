# 网络优化的交付目标

2026-11-13，用户“定好目标，开始”恢复执行。本页明确产品目标和执行顺序，原[PLAN](PLAN.md) N0–N5及其完整验收范围保留；[STATE](STATE.md)记录实际进度。

在两端在线且至少一条允许的完整路径可达时，让khor个人设备网具备成熟远程连接产品级体验：建联快、稳定选路、故障与换网自动恢复、目录和终端持续跟手、文件与同步公平推进、后台成本可控。

## 必须交付的行为

1. 打开设备后尽快获得有效目录、终端或文件内容；“已连接”状态不能替代真实业务成功。
2. IPv4/IPv6直连、公共Relay、peer relay及SSH按完整路径实测参与速度优先竞争，收益接近时稳定保持。
3. 仅一个可达middle时，只要第二腿可达、信任与策略允许，就自动验证并尝试救通；覆盖第二腿走Relay及信息未知/过时，不要求重开App。
4. 覆盖独立及同时IPv4/IPv6/NAT变化、Wi-Fi↔蜂窝、锁屏/休眠、peer relay移动和失效。恢复可操作与回到更快路径分别计时。
5. 传文件、同步、预览与终端共存，取消和背压释放真实资源；身份、原期限、0-RTT准入及写请求语义保持。
6. 基于经核验的最新稳定iroh/Noq；优先原生能力。每项custom有原因、覆盖和保留/退出依据，减少相互叠加的恢复状态和等待。
7. 优化Rust热路径的排队、复制/分配、锁、阻塞工作、任务和唤醒；最终性能结论来自接近发行配置的产物及真实业务。
8. 验证寻址、中继线路/容量/故障域及用户自家Relay约束；采购和生产部署仍按独立指令处理。

- 首个有效响应、成功率、连续卡顿、恢复时间、p95/p99、吞吐、公平推进及CPU/内存/字节/唤醒/能耗按分场景记录；门槛、样本与失败处理在候选测量前固定。
- 已完成且适用的测试、源和日志继续使用；失败及用户取消均保留。调试构建可作行为回归和定位，不冒充最终发行性能。

- 同一个最终源码版本交付：feat/net实现、状态/职责设计、持续验收矩阵、对照报告与来源明确的候选包。

- main合并、正式发布、生产Relay采购部署和已安装App替换未由本次恢复自动授权。
