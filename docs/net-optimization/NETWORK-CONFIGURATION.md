# 网络配置

本轮工作树为 `feat/network-configuration`，基于 `3f3d036dc`。香港中继退役已纳入本分支。

- 自动使用 Khor 公共中继和寻址，可以独立关闭 iroh 公共中继、查询与发布。公共目录默认只接收本机的中继地址。
- 自定义支持任意组合。完全自管只使用批准的目录与服务器。对端提示、已有记录和未知的 Peer Relay 第二跳都要经过同一套权限。
- 本机配置可从 JSON 或 HTTPS 链接导入。配置内不携带共享密钥，旧密钥按原地址保留。公开的托管配置通过签名和递增版本更新，客户端保留上次验证成功的版本。
- 受支持的预设使用同一份配置模型。All-in-one 用现成 iroh Relay 和 Pkarr，分别验证转发、寻址、IPv6 和地址探测。
- 验证旧设置迁移、完全自管的出站限制、应用前后状态、冷启动、换网与公共服务故障。基础设施实际部署和真机测试以各自的验收证据为准。

## 行为

- 自动配置提供 Khor 共享 Relay、Khor Pkarr 及 iroh 的公共备用服务。共享服务按尽力而为提供。各个来源可单独关闭。
- 完全自管接受配置内的 Relay 和 Pkarr/DNS，保留直接传输和开启时的 mDNS。关闭对端中继、Peer Relay 和 SSH 载运、公共 DNS 兜底。系统 DNS 负责服务主机名。关闭对端中继时，iroh 在打开连接的位置检查配置的 Relay URL，涵盖同步记录、配对票据和寻址返回的候选。
- 已保存的配置和当前驻留进程分开显示。退出并重启 App 或 `khor serve` 生效，适合一次编辑多项后再换网络。临时端点使用其启动时读取的配置。
- 旧文件维持原连接语义，设置页显示其可编辑的选项。首次设置独立策略后写入 v1，损坏文件退回无公共服务的安全模式，可在本机导入修复。
- 自建服务和签名配置见 [单机自建部署](self-hosted/README.md)。固定来源经用户显式导入，可离线启动并手动检查新签名版本。自动模式仍以 App 自带目录冷启动。启用 Khor 自己统一管理的默认签名来源需要运营公钥和发布地址。
