## Overview

khor should read as a Mac app a person already knows how to use. Nothing in it is novel
for the sake of it: the sidebar is a sidebar, a setting is a row in a rounded group, a
choice opens the system's menu, a yes/no is a switch. What khor adds is content — machines,
sessions, workspaces, tabs, quotas — never new kinds of chrome.

**Key characteristics**
- **One skeleton, filled, never reshaped.** Six regions (L0, L1, L2, R0, R1, window). A page
  chooses what goes in them; it does not add a row, remove a row, or change a height.
- **One brand voltage.** khor olive appears where macOS puts the accent colour and nowhere
  else. State colours (busy, blocked, done, errored, failed) are ink only, never fills.
- **System everything.** System font at macOS sizes, native menus for choices and context
  menus, sidebar material on macOS, the window's own buttons untouched.
- **Card on ground for depth.** The board and settings groups are `{colors.card}` on
  `{colors.canvas}`. One shadow tier, for things that float (menus, the search hits).
- **Calm density.** 13 px body, 32/48 px rows on a pointer; the 44 px floor comes back only
  where the pointer is a finger.

## Colors

### Brand
- **khor olive** (`{colors.brand}` — #8fb31e light / #b4d257 dark): the hue. Used as a
  wash (`{colors.brand-wash}`) behind the open rail item, and as ink (`{colors.brand-ink}`)
  for that item's glyph.
- **olive strong** (`{colors.brand-strong}` — #5d7b00 / #99bb36): the solid form — the
  selected list row while the window is key, a switch that is on, focus rings, the one
  primary button in a dialog. Text on it is `{colors.on-brand}`.
- **Why not the system accent.** khor's identity is the olive; a user who set their Mac to
  purple still sees olive in khor, the way Music stays red. That is the one departure from
  "system everything", and it is deliberate.

### Grounds
- **canvas** — the window. **side** — the left block where macOS vibrancy is unavailable.
- **card** — the board and every settings group; one step lifted from canvas.

### Ink
- **ink** for titles and body, **secondary** for subtitles and values, **tertiary** for
  meta (times, counts, group headers). Never a fourth grey.

### State
- The five state colours keep today's values (`check-palette` owns their contrast). Ink
  only: a dot, a word, a halo — never a row background.

## Layout — the shell skeleton

```
┌──────────── L  left block ────────────┬──────────────── R ────────────────┐
│ L0  ● ● ●  [ 搜索              ⌘K ] + │ R0  tabs  ·  or  ‹ ›  页面标题     │  ← both 48
├──────┬────────────────────────────────┤ ┌────────────────────────────────┐ │
│ L1   │ L2 list                         │ │ R1 board                        │ │
│ rail │ (list-row, group-header)        │ │ (page content)                  │ │
│ 64   │ width owned by L                ║ │                                 │ │
│      │                                 ║ │                                 │ │
└──────┴────────────────────────────────╨─┴────────────────────────────────┘─┘
                                          ║ = the one width handle
```

| Region | Size from | Holds | Drags the window |
|---|---|---|---|
| **L** left block | `rail-w` + list width, **stored once, on L** | L0, L1, L2 | — |
| **L0** side-head | `pane-head` | traffic lights (macOS) · search-field · add | its blank |
| **L1** rail | `rail-w` | five landings, 更多, this machine | its blank |
| **L2** list | follows L | list rows, group headers | no *(D3)* |
| **R0** toolbar | `pane-head`, **on every page** | tab strip — or back/forward + page title *(D2)* | its blank |
| **R1** board | margins `spacing.in`, radius `rounded.xl` | the page | no |

- **Drag is declared once, by the shell**, on L0, L1 and R0. Controls inside them are
  excluded by tauri's own rule. Components never mark drag regions themselves.
- **Width has one owner.** The seam at L's right edge is the only handle; L0 follows it and
  the search field shrinks down to its magnifier before anything overflows.
- **Nothing is added between R0 and R1.** No subtitle row, no status sentence. A session's
  day-strip (4 px) is the one exception and it has no text.
- **Platforms.** macOS: traffic lights in L0, sidebar material on L. Windows: minimise /
  maximise / close at R0's right end; L0 starts with the search. Linux: system decorations
  above; L0 starts with the search. Web face: as Linux, without the decorations.

## Page archetypes — every landing is exactly one

Today the right side is composed six different ways (sessions: `Tabs` or `Region`;
machines: `Region`; 额度 and 浏览: their own; 更多: `Region`; an open workspace: raw three
columns). That is why a fix to one page never reaches the others. From here on there are
**three archetypes**, one component each, and a landing declares which one it is.

| Archetype | Mental model | L2 list | R0 toolbar | R1 board | Landings |
|---|---|---|---|---|---|
| **A 详情** single detail | pick one thing, see it | every thing; one selected | ‹ › (selection history) · title · page actions at the right | the selected thing, or the overview when nothing is selected | 机器, 额度, 更多 |
| **B 标签** working set | open several, switch among them | every thing; the front tab's row selected | tab strip · ＋ | the front tab, or the overview when no tab is open | 会话 |
| **C 文档** one thing with its own navigation | the row *is* a live document | every document; one selected | ‹ › ⟳ · address/title · page actions | the document | 浏览 |

A **workspace** is B inside R1: when a workspace is open, the board splits into panes —
**navigator** (file tree), **editor** (B: file tabs), **inspector** (its sessions). Each pane
has its own 48 head aligned with R0; panes are separated by hairlines, never by grounds.

**Rules every archetype keeps**
- **Identity lives in exactly one place**: the R0 title (A, C) or the tab (B). Never a
  second heading inside the board.
- **Overview** — each landing has one, shown when nothing is selected (A) or no tab is open
  (B): sessions → 「等你的事」+ machines; machines → the map; 额度 → all accounts' rings;
  更多 → 通用. It uses the same archetype's R0 with the landing's name as title.
- **Selection and tabs (B)**: pressing a row opens or focuses its tab; closing a tab never
  removes the row; removing a row closes its tab. The list's selection always equals the front tab.
- **History (A, C)**: ‹ › walk the selections made in this landing, like System Settings.
  Absent when there is nowhere to go.
- **Page actions** (新会话, 机器的三个按钮, 注册账户) go to R0's trailing end as toolbar
  buttons; row actions go to the row's context menu. Never both, never a button row in the board.
- **Narrow**: every archetype becomes list screen ⇄ detail screen with a back button in R0;
  B adds the tab count button at R0's end.

## Region states — one look per state, everywhere

| State | Looks like | Never |
|---|---|---|
| **loading, never seen** | skeleton rows / cards in `fill`, no spinner for < 1 s | a blank board |
| **loading, seen before** | the last content, unchanged; a 2 px `brand` bar at R0's bottom while it refreshes | clearing to empty |
| **stale / offline** | last content + one `caption` line in R0's trailing end: 「3 分钟前的读数」 | a banner inside the board |
| **empty** | empty-state component (one sentence, ≤ 1 button) centred in R1 | illustrations, two buttons |
| **error** | the machine's own sentence in the empty-state slot, with 重试 | a red box, a stack trace |

## Overlays — which one for what

| Need | Use | Not |
|---|---|---|
| choose one of a few | native pop-up menu | a custom dropdown |
| act on a row | native context menu (置顶, 删除 first) | an inline button row |
| confirm something destructive | dialog (380, 「不再提醒」 where it applies) | an alert() |
| create / import with a form | sheet dropping from R0 (macOS sheet) | a centred modal with a scrim |
| search results | hang under the search field, no scrim | a centred palette |
| transient report (已置顶, 已复制) | status bar at the foot, 2 s | a toast over content |

## Components

### Shell
- **side-head (L0)** — lights, then the search field (fills, shrinks to a magnifier), then
  add. Typing filters this list; ⌘K or ⇥ widens it to everything, hits hang under it.
- **rail (L1)** — 48 px items, glyph in `secondary`; the open one gets `brand-wash` + `brand-ink`.
- **list-row** — 48 px: avatar (with corner mark) · title (`body`) / subtitle (`callout`,
  secondary) · meta (`caption`, tertiary) at the right. Selected: `brand-strong` fill,
  `on-brand` text; grey when the window is not key.
- **group-header** — `group` style, tertiary, folds; a hairline between the pinned group and the rest.
- **toolbar (R0)** — the tab strip, or on a page without tabs: back/forward (only where there
  is a history) and the page title in `title-sm`.
- **tab** — face · name · close cell. The close cell always keeps its width; the name
  truncates before it. The active tab is `card` and joins the board.
- **board (R1)** — `card`, radius 12, 8 from every edge.

### Settings (the 更多 page)
The rail's 「…」 opens this page directly. L2 lists the sections (通用, 外观, 网络, 安全,
身份, 诊断) as list rows with a glyph; R1 shows the chosen section as settings groups.

- **settings-group** — group label above the card; rows inside separated by inset hairlines.
- **switch row** — title (+ callout note) · switch. For anything that is on or off.
- **pop-up row** — title · `当前值 ⌃⌄`. Opens the **system menu** (a native `<select>` on
  the desktop faces). For one choice out of a few.
- **nav row** — title · `值 ›`. Opens a sub-page in the same board, with back in R0.
- **action row** — title · push button (`管理…`, `生成邀请…`). For a one-shot act.

### Controls
- **switch** 32×18, on = `brand-strong`. **pop-up button** 28 high with the ⌃⌄ chip.
- **push button** 28 high, `fill-strong`; **primary** (`brand-strong`) at most one per dialog;
  **destructive** only in a confirm dialog.
- **search field** 28 high, `fill`, magnifier leading, ⌘K caption trailing.

### Feedback
- **empty-state** — one sentence in `secondary`, at most one push button.
- **dialog** — 380 wide, title-md, one sentence, optional 「不再提醒」, buttons right-aligned.
- **context menu** — native; first two items 置顶, 删除.

## Behavior — what a person must never wait for or lose

Each line is a gate; a line without a gate is not a rule.

| Rule | Gate (red first) |
|---|---|
| A page shows its last content or its skeleton within **300 ms**; this machine's data arrives within **1 s** *(D5)* | fake disk whose `statfs` takes 10 s → machine page has cards within 1 s |
| Coming back shows the last content on the first frame, then refreshes in place | enter, leave, enter: no empty frame the second time |
| A slow source delays only its own cell; blocking work never runs on the async pool | unit: a slow source present, other requests' latency unchanged |
| Every page's L0, L1 and R0 blanks drag the window | walk each page, press every blank point, judge with tauri's own algorithm |
| Dragging the seam moves L, its ground and L0 together | drag to three widths; the four widths agree |
| Nothing between R0 and R1 but the day-strip | kept from 第十四轮 |
| Each round ends with the lead in the real app — drag, widen, switch pages, time them | checklist in handoff; web-face screenshots do not count |

## Do's and Don'ts

### Do
- Fill the skeleton; reference tokens by name, never a raw value.
- Use a switch for on/off, a pop-up for one-of-few, a nav row for anything with its own page.
- Keep olive for selection, on-switches, focus and the one primary action.
- Let the system draw what it owns: menus, window buttons, scrollbars, the context menu.

### Don't
- Don't add a row between R0 and R1, or a subtitle under a tab.
- Don't draw a custom popover where a native menu exists.
- Don't mark drag regions inside a component.
- Don't give a region a second width source.
- Don't use a state colour as a background, or olive as decoration.
- Don't run a blocking call (disk, network, subprocess) inside a request handler.

## Responsive

| Face | Change |
|---|---|
| Wide, pointer fine | as above; controls at `control-*`, rows at `row-1`/`row-2` |
| Pointer coarse (touch) | every hit area grows to `touch` 44; visuals may stay |
| Narrow (< 760) | one column; L0 on top; rail becomes the bottom bar; the board fills the screen without margin or radius |
| Windows / Linux / web | no material; `side` colour on L; window buttons per platform |

## Iteration guide

1. A spec cites this file by section and token; it does not invent layout.
2. A page that needs something not listed here adds it to **Components** first, with why.
3. Every new rule arrives with its gate, and the gate is seen red before it is made green.
4. Change a value here and in `tokens.css` in the same commit; `check-boot` compares them.

## Known gaps

- Windows' drawn buttons and the no-tab window row are unmeasured on this Mac.
- The web face cannot drag and cannot show material; its gates cover layout, not feel.
- Animation timings are not specified yet beyond 「respect reduce-motion」.

## Decisions for the owner

- **D1** Body text 14 → 13 to match macOS (reading surfaces stay 16).
- **D2** Pages without tabs get back/forward + a page title in R0, like System Settings.
- **D3** The list's blank does not drag the window (Finder and System Settings don't); the rail's does.
- **D4** The left block uses macOS sidebar vibrancy (tauri window effect); other platforms keep `side`.
- **D5** 300 ms to last content, 1 s to this machine's data.
- **D6** Selected list row becomes a solid olive fill with light text (today: a light wash).
- **D7** Three page archetypes (A 详情, B 标签, C 文档); 浏览 is C — its list rows are the
  tabs, so it has no tab strip, and R0 is the address bar.
- **D8** An open workspace is B inside the board (navigator · editor · inspector), not its
  own shell.
- **D9** Page actions move to R0's trailing end (toolbar buttons); the board holds no button rows.
- **D10** Forms that create things (新会话, 导入, 注册账户) become sheets dropping from R0.
