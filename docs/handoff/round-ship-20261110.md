## 下一轮已明确的需求

1. 点击会话消息里的文件或网址时，打开独立内容标签页，保留此前打开的内容；标签内普通网页导航仍在当前标签中。
2. 关闭浏览器标签立即停止该页音视频并释放页面资源，覆盖 YouTube 等媒体页面。
3. 新建会话目录不存在时，在目录行下提示“此目录不存在，创建会话时将新建”。仅在点创建时由所选机器创建；离线和权限错误不可误报为不存在。
4. 修复 mobile 工作区返回时与背后页面、标题和按钮重叠的问题，覆盖点击返回和手势返回。
5. 任意历史用户消息修改并重新生成仍延期，需要真实智能体分支或回退能力。
6. 统一桌面 App 与 CLI 的安装和启动入口（用户于 2026-11-11 确认纳入下一轮）：macOS、Windows、Linux 桌面 App 随附同版本 CLI，提供启用 `khor` 命令的入口；独立 CLI 保留服务器与 Web 使用方式。`khor gui` 定位并打开正式 App，未安装时明确引导安装，不再要求用户安装或调用独立的 `khor-gui` 命令。App 包内部的 GUI 可执行文件可以保留该名称。
7. Mobile 机器详情页右上角偶尔只剩“…”溢出菜单。保持正常导航栏，不因恢复页面、布局测量或标题宽度而退化成仅有“…”；窄屏也保留导航能力。截图：`/Users/zgh/khor-drop/IMG_5606.png`。
8. Mobile 在终端打字等情况下离开 App 一段时间，回来后终端有时没有重新适配视口，出现内容尺寸不合适与大段空白。恢复前台时按实际视口、键盘及安全区重新适配终端，保留会话、滚动位置和输入；覆盖键盘打开/关闭、后台停留与再次进入会话的组合。截图：`/Users/zgh/khor-drop/IMG_5609.png`。尺寸适配为待诊断现象，不预先认定根因。
9. 附件选择改为逐个文件的预览卡片，点卡片可预览，附件发送/插入完成后回到原输入目标（终端或 GUI 输入框）并恢复键盘；失败时保留选择并显示错误。逐项取消的交互尚未由用户确定，当前建议卡片右上角小“×”，仅移除本次选择、不删除源文件，先在 Lab 展示确认。验收图片、多文件、长文件名、预览返回及真实手机键盘恢复。
10. 工作区打开非 Git 目录时，隐藏 Git 历史（git log）图标及入口；切换工作区或目录后同步更新，不能残留上一个仓库状态。按实际仓库归属判断，包含仓库子目录与 Git worktree，不以当前目录是否直接含 `.git` 文件夹作为唯一判断。覆盖 Git/非 Git 工作区切换和 Lab 对应数据场景。
11. 会话已读状态全网同步：同一会话在任一机器/界面读到的内容，在同一 Khor 网络内其余设备上也视为已读，对应未读红点与汇总计数同步清除。按会话的阅读进度合并，不能用整条会话无条件清零来吞掉并发新增内容；离线设备恢复连接后补齐状态，旧状态不能把已读内容变回未读。验收桌面/手机双端阅读、机器页与会话列表等不同入口、离线重连，以及阅读同时新增消息的情形。本项保留真正新内容的未读提示，用户要求取消的是已在其他设备读过后仍残留的红点。
12. 导航栏“…”菜单内的“更多”入口改名为“设置”，避免“更多”中再次出现“更多”；沿用现有统一设置界面与入口位置。同步相关页面标题、可访问名称及多语言文案，不改动浏览器、我的 Khor 等独立入口的归属。
13. Shell 内启动 Codex 时，就地识别为该智能体会话，不生成重复会话行。用户报告当前两条 `labsys` 实为同一会话；只读列表确认存在 `shell/5d21c43e9e9be39e`（空闲）与 `shell/01910999df0e3bc7`（忙碌）两条记录，底层宿主/PTY/进程关联及重复记录来源仍待诊断，不能仅按同名合并。维持同一会话身份、终端、历史、标签页、用户自定义名称、置顶与阅读进度，在原条目更新智能体类型、头像和运行状态；Codex 退出后恢复 Shell 展示。排查发现/导入与现有宿主的归并逻辑，兼顾其他终端智能体，不重新引入已退役的 Hook。保留真实 TUI 输入输出链路，不把终端内启动智能体误当作自动新建 ACP GUI。验收 Shell → Codex → Shell、重连/App 重启、多个界面观察及同名独立会话的区分；既有重复记录的迁移不得关闭真实宿主或丢失历史。
14. Khor 会话的 harness 统一管理命令任务与子智能体，参考 Claude Code 等成熟实现，并核对现有 Pi SDK 可复用能力。命令执行作为父 Khor 会话内的任务管理；ACP/A2A 委派保留明确的父子关联、机器/智能体来源、独立上下文、进度、结果与取消能力，自动创建的执行任务和子会话不再平铺污染主会话列表。UI 中，在 session list 再次点击已选中的 Khor 会话，可以查看其子智能体列表、进入详情并返回父会话；先通过真实组件 Lab 验收具体呈现。
15. 机器详情的信息入口整理：连接旁“i”打开的记录按事件时间倒序，最新记录在顶部，实时新增记录也保持此顺序。机器页内的更新说明、版本状态、检查更新、安装进度与失败重试等统一收进版本旁“i”，移除该页其他分散或重复的更新区域。每台机器详情只展示并管理当前所选机器自身的更新，不混入其他机器的更新计划、队列或批量操作；所选机器可以是本机或远端，不能把“只更新自己”误解为仅支持当前操作设备。验收本机/远端切换后的状态隔离、操作目标、记录初次加载及实时追加顺序，并在 Lab 展示。

第 14 项的生命周期已由用户明确：**关闭已结束的子会话，保留父 Khor 会话**。终态结果可靠回传并持久化后，由 harness 自动关闭自己创建的子会话并回收其执行资源；完成、失败、取消须明确区分，等待输入、等待授权、暂时空闲或断线不等于结束。关闭不等于删除：保留结果、历史及父子关系以供回看；继续既有上下文需按对应协议的恢复能力处理。命令与子智能体分别展示、管理，不能把普通命令伪装成智能体。仅清理本次父会话拥有的执行资源，复用的独立会话和外部 A2A 服务不能被整体关闭。验收多机器/多智能体并行、普通命令与长任务、终态回传与清理、用户取消、授权/输入等待、重连/App 重启恢复及旧孤儿记录迁移。参考：[Claude Code 子智能体](https://code.claude.com/docs/en/sub-agents)、[工具与后台命令生命周期](https://code.claude.com/docs/en/tools-reference)。不假定上游所有退出策略可直接照搬到跨机器 ACP/A2A。
