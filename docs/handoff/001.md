## 怎么和用户干活

- **讨论优先**：用户的问题先答，答完才继续干；正在写代码被提问就停下来。
  批准词通常是「好」「继续」。方向岔路列给用户，但要带自己的推荐和理由。
- **一批 = 一件真连可验收的事**，先提案再动手。验收 = 真连 + 对照组 +
  全程 timeout（NET.md 验收一节）；每批跑全量测试 + 双/三进程 CLI smoke。
- **代码里不要中文**（用户纠正过两次）：注释、断言消息、测试数据全英文。
  产品文案一律走语料库：`crates/catalog/zh.toml` 加键，代码引
  `khor_catalog::msg/cli/state`；测试断言也引 catalog——能精确比对用
  assert_eq，带参消息用哨兵切前缀（`msg::x('\u{0}',…)` 再 split）。
  例外：中文测试输入本身是被测对象时保留（频道名清洗那组）。
  换测试数据要查断言是否依赖字节长度（wire.rs「同一段字节」曾因此假红）。
- 后台进程用工具自带的后台执行，别 `nohup &`（会生孤儿）；smoke 脚本自带
  trap 清场，收工按端口和 CPU 查孤儿。
- **零依赖指的是用户侧**：不期待用户装任何东西（tmux、rsync 都不行），
  但编译进来的 Rust crate 不受限——而且**尽量用成熟库，不自写**
  （用户 2026-08-16 裁决；portable-pty 是先例，fast_rsync 是下一个候选）。
- **批次交给 Opus 车道执行（2026-08-16 起，用户定的方式）**：领队写
  任务书拍一条 Opus 车道，任务书**写判据不写做法**——已定裁决（标明
  不可重开）、可证伪的验收、边界（做了算越界）、机器与 git 纪律、
  最终报告必须 SendMessage 投递（正文只到车道自己的终端，栽过一次）。
  车道报告**先核后转**：hash 与测试数领队本机复跑，关键宣称抽查；
  车道的墓碑/挂账随批入 handoff。用户开着 vite dev 旁观 HMR，
  车道不许动 1430/1431。
  细栏定形批实测补进来的三条（事故经过与机制记在那一批的条目里；
  机制一句话：**车道的长循环没有回合边界，队列里的消息排不空，
  改 scope 追不上已开跑的车道**）：任务书要求**车道每落一个可提交的
  单元就停一次报状态**（制造回合边界）；**车道提交前把账本从头过一遍**
  （不依赖时序，最可靠）；领队侧**会改 scope 的裁决先落账本再发消息**，
  消息只当加急铃，并在车道下一个自然停顿点复述一次。

- **「改不了名」落盘竞态：已修（`715988f`），且这条账原来指的两个方向
  都是错的**。原挂账写「register_self 无变化时不 flush，或落盘加锁」——
  2026-08-16 列表秩序批查实：flush 早就在版本没变时不写块，每次
  `Node::open` 必写的是 `load()` 末尾的 `save_ledger()`；**真因在更下
  一层**：`write_atomic` 的临时文件名对同一目标路径是**固定的**
  （`path.with_extension("tmp")`），两个写者都建它、先到的 rename 走了、
  后到的发现文件没了。store.rs 模块头那条「名字里带作者，文件系统层面
  永不冲突」块文件一直守着，**临时文件从来没有**——修法就是把这条规则
  补到 tmp 上（pid + 进程内计数器）。实测经 bridge 打 `pin_session`
  40 次失败 17 次 → 0 次；守门测试 8 线程 × 12 次并发开同一 home，
  拆回共享 tmp 名 96 次红 90 次（旁边那条 `two_writers…` 盖不住它：
  它的两个写者是轮流 flush 的）。**此前每一个「偶发的 CLI exit 1」
  多半都是它**；撞过它的动词有记录的是 `sessions`（重启 serve 后首跑）。
  这条留在账上只为一句判词：**「偶发、重跑就好」的故障是有名字有真因的，

## 本仓特有的坑（都吃过一次）

- loro `insert_container` 返回的才是 attached 句柄，往 pre-attach 的写
  会静默丢（devices.rs 注释有）。
- 一把钥匙一个端点。serve 常驻时一次性动词走递话口（`ipc.rs`）；
  serve 在跑但递不过去**不许**回退直拨。
- serve 里任何会等 DIAL_TIMEOUT 的事**不能内联在 select 循环**——那 10 秒
  serve 是聋的（`7cbb5a7` 修的 bug）。同步泵走 `sync_gate`。
- 从没报过地址的设备不拨（一次性配对的手机只能主动够别人）。
- 收到的 Act 永不二次转发；msgpack 帧纪律在 proto.rs 模块头。
- seen 水位取发送方时钟的最大 `at`，不取本机钟、不取 list 尾。

### 浏览器烟测这一侧（2026-08-16 工具条批各撞一次，都是假红）

- **`locator.focus()` 对一个已经聚焦的元素什么都不发。** 轨道那颗图标刚被
  点开过面板，就已经带着焦点；再 `focus()` 一次不会有 focus 事件，于是
  「键盘聚焦也出浮签」那条断言测的是一个没发生过的事件，读起来却像功能坏了。
  **先把焦点挪走并断言它真的走了**，再聚焦回来。
- **Radix 的浮签有一块 grace area，`mouse.move` 一跳跨不出去。** 内容可悬停
  的浮签会在触发器与内容之间留一块过渡区，只有落在区外的 `pointermove`
  才关它；Playwright 默认 `steps: 1`，那一跳没有中间事件。用 `steps: 12`。
- **动效要量元素，不能读类名。** 少一个 `@import "tw-animate-css"`，
  `animate-in` 那些类照样躺在 markup 里，只是背后什么都没有——量
  `getComputedStyle(el).animationName / animationDuration` 才看得见，
  顺手把时长缓动和 `--dur-*` / `--ease-*` 对一遍，就同时证了「接了令牌」。
- **烟测的 bridge 端口会和用户自己开着的 app 撞。** 撞上时旧 bridge 还在，
  新 bridge 起不来，而浏览器会照常连上**别人的 home** 并一路报绿。
  现在烟测等自己那个 bridge 打出端口行、它先退出就当场报错；
  端口可用 `BRIDGE_PORT` / `VITE_PORT` 覆盖（vite 是借用的，同一份源码，
  借它没问题；**backend 不能借**）。
  **2026-08-16 `3e90a47` 起默认挪到 1442/1443**（此前默认正是用户那对
  1430/1431，实测两个都被占着）。**「可用 env 覆盖」挡不住这件事**——
  覆盖要有人记得写，而默认是没人想的时候用的那个；把默认让开，
  两边同时开着才互相看不见。

## GUI 每批都要守的三条（脚手架批立的，此后各批验过）

- CLI 与 GUI 等价：tauri 命令是薄壳，直接调 khor-node 的同一批函数，
  不在前端复刻任何判断。
- 验证不许手写替身（替身会和 Rust 漂移）：排版验证走 dev 桥 =
  同一批命令函数披 HTTP 皮，真后端真数据；tauri 窗口这台机器开不了，
  装机与手感归用户。
- 词从 catalog 的 TS 脸来（gen_ts 接进前端构建），类型从 Rust 生成
  （ts-rs），前端不许拼词、不许手抄类型。
