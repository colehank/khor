## 怎么和用户干活

- **讨论优先**：用户的问题先答，答完才继续干；正在写代码被提问就停下来。
  批准词通常是「好」「继续」。方向岔路列给用户，但要带自己的推荐和理由。
- **一批 = 一件真连可验收的事**，先提案再动手。验收 = 真连 + 对照组 +
  全程 timeout（NET.md 验收一节）；每批跑全量测试 + 双/三进程 CLI smoke。
- **代码里不要中文**（用户纠正过两次）：注释、断言消息、测试数据全英文。
  产品文案一律走语料库：`crates/catalog/zh.toml` 加键，代码引
  `khor_catalog::msg/cli/state`；测试断言也引 catalog——能精确比对用
  assert_eq，带参消息用哨兵切前缀（`msg::x('\u{0}',…)` 再 split）。
  例外：中文测试输入本身是被测对象时保留（频道名清洗那组）。
  换测试数据要查断言是否依赖字节长度（wire.rs「同一段字节」曾因此假红）。
- 后台进程用工具自带的后台执行，别 `nohup &`（会生孤儿）；smoke 脚本自带
  trap 清场，收工按端口和 CPU 查孤儿。
- **零依赖指的是用户侧**：不期待用户装任何东西（tmux、rsync 都不行），
  但编译进来的 Rust crate 不受限——而且**尽量用成熟库，不自写**
  （用户 2026-08-16 裁决；portable-pty 是先例，fast_rsync 是下一个候选）。
  **「不受限」有一条硬边界：AGPL 一类的传染式许可不进依赖树**（领队
  2026-08-17 裁，起因是 GPU 那批实测的 `silicon-monitor`）。khor 是**分发
  给用户的产品**，AGPL 的传染会一路走到整个产品，那是一个产品层面的许可
  裁决，不是某一批里「选哪个库」的技术选择——**没有哪条技术优点抵得过它**，
  所以它是选型时第一个查、而不是权衡完再查的东西。查法：`cargo info <crate>`
  的 `license:` 一行。（**「优先成熟库」不覆盖这条**：一个库越成熟越好用，
  就越容易让人在读到许可之前已经想好了怎么用它。）
- **车道一律显式 `model: "opus"`（用户 2026-08-17 重申，成本硬约束）**：
  Agent 调用不带 model 参数会**继承领队的 Fable**——烧不动。历史核过：
  至今九条车道全部显式 opus，无一继承；这条写在这儿是给 compaction
  之后的领队看的。
- **批次交给 Opus 车道执行（2026-08-16 起，用户定的方式）**：领队写
  任务书拍一条 Opus 车道，任务书**写判据不写做法**——已定裁决（标明
  不可重开）、可证伪的验收、边界（做了算越界）、机器与 git 纪律、
  最终报告必须 SendMessage 投递（正文只到车道自己的终端，栽过一次）。
  车道报告**先核后转**：hash 与测试数领队本机复跑，关键宣称抽查；
  车道的墓碑/挂账随批入 handoff。用户开着 vite dev 旁观 HMR，
  车道不许动 1430/1431。
  **任务书不是判据的出处，它转述判据，而转述会错**（2026-08-17 设备与
  配对批实撞：任务书与账本都写「钩子补完成/中断两档」，而 claude 的
  hook 映射里根本没有中断——catalog 词一直是对的，错的是两层转述）。
  车道写文案/断言引用判据时**核出处**（代码与判据注释），转述与出处
  不一致以出处为准、报领队；领队写任务书引账本时，引原文别改写。
  **2026-08-17 用户睡前授权：领队持续规划与派活，批次批准权下放**
  （原话「你来持续规划与派活吧，我睡觉了」）。边界：已定路线与已批
  方案内的批照常拍；**要新产品裁决的不许代拍**——借网形态、手机技术
  路线、账户额度这类，探路可以、定形留给用户醒来。用量数据源按领队
  已提方案走（读盘聚合 transcript 的 token 数；账户额度挂账）。
  醒来交一份夜报：每批的账、事故、待裁清单。
  「数字从输出抄」有个盲区（2026-08-16 存续债批自查）：**自己刚写的
  东西最容易凭印象填数——核别人给的数会去查，核自己的数会去回忆。**
  自己写的测试、自己起的进程、自己定的常量，报之前同样跑一遍数一遍。
  细栏定形批实测补进来的三条（事故经过与机制记在那一批的条目里；
  机制一句话：**车道的长循环没有回合边界，队列里的消息排不空，
  改 scope 追不上已开跑的车道**）：任务书要求**车道每落一个可提交的
  单元就停一次报状态**（制造回合边界）；**车道提交前把账本从头过一遍**
  （不依赖时序，最可靠）；领队侧**会改 scope 的裁决先落账本再发消息**，
  消息只当加急铃，并在车道下一个自然停顿点复述一次。

## 本仓特有的坑（都吃过一次）

- loro `insert_container` 返回的才是 attached 句柄，往 pre-attach 的写
  会静默丢（devices.rs 注释有）。
- 一把钥匙一个端点。serve 常驻时一次性动词走递话口（`ipc.rs`）；
  serve 在跑但递不过去**不许**回退直拨。
- serve 的 select 循环与 async 处理器里**不能内联任何会久等的事**——判据是
  **「会阻塞多久」，不是「是不是在拨号」**（2026-08-17 放宽：vitals 采样
  1.9 秒内联在请求处理器里，把它自己那条 QUIC 拖死，两条毫不相干的
  avatar 真连测试在 20 秒超时上红——症状离原因很远。原文只点 DIAL_TIMEOUT，
  于是「我这儿又没有拨号」读起来像豁免）。首例是拨号那 10 秒让 serve
  变聋（`7cbb5a7`）。同步泵走 `sync_gate`；重活去自己的线程/任务。
- 从没报过地址的设备不拨（一次性配对的手机只能主动够别人）。
- 收到的 Act 永不二次转发；msgpack 帧纪律在 proto.rs 模块头。
- seen 水位取发送方时钟的最大 `at`，不取本机钟、不取 list 尾。
- **临时 worktree 不许和主仓共用一个 target dir**（2026-08-16 存续债批实撞）。
  给 HEAD 建 worktree 做「这条测试在旧代码上是红的」对照时，
  `CARGO_TARGET_DIR` 指了主仓那个 `/Volumes/disk0/khor-target`，
  **两棵树的测试二进制就此互相顶替**：
  - 撞到的那次是**主仓复用了 worktree 的旧二进制** → 跑出一个 FAILED，
    而测试清单还是旧的，读起来完全像「我的新实现没生效」。**这是假红。**
  - **反过来同样成立、而且更贵**：worktree 复用主仓的新二进制，
    对照组会一片绿，于是「旧代码上它也不红」——**一条根本没验过的
    拆红被当成验过了**。
  防法二选一：**对照实验用自己的 target dir**（别设
  `CARGO_TARGET_DIR`，让 worktree 用它自己的 `target/`），
  或者共用之后**核一眼跑了多少条、名字对不对得上**
  （`touch` 源文件能强制重编，但那是补救不是防法）。
  这个仓尤其容易踩：主仓的 `target/` 本身就是个指向外挂盘的符号链接，
  「换棵树就是换个 target」这个直觉在这儿不成立。

- **机队 ssh 直连今天连不上，而症状读起来像对面那台挂了**（2026-08-17
  GPU vitals 小批实撞）。aliyun 与 turing **两台都是**
  `Connection timed out during banner exchange`——而 `nc -z` 两个 22 端口
  都**通**、`ping` aliyun 6.7ms 正常。**TCP 通、banner 不来**：这一跳被中间
  的什么东西拦了，不是那台机器的事。**走本机那个 socks 代理就都通**：

  ```
  ssh -o ProxyCommand='nc -X 5 -x 127.0.0.1:7897 %h %p' <host>
  ```

  危险在两个证据各自都会把人带偏：`nc` 说端口开着，于是「机器活着」；
  ssh 超时，于是「sshd 死了」。**两句都对，合起来的结论是错的。**
  下次探机队撞上这个，别去查那台机器，先换这条路试一遍。
  （这台机器设了 `http_proxy`/`all_proxy`，而 **ssh 不读那些变量**——
  所以「设了代理」和「ssh 走代理」是两件事，要显式给 `ProxyCommand`。）

- **`jobs -p` 在这个环境的非交互 bash 里返回空**（2026-08-16 接入债批实撞）。
  为了给一条 flaky 测试加负载，起了 `for i in 1 2 3 4; do (while :; do :; done) & done`
  再 `kill $(jobs -p)`——**那个 kill 是空操作**，四个 busy-wait 当场变成
  `ppid=1` 的孤儿，各烧 95% 一个核。下一条命令查到并 `kill -9` 掉了
  （`ps -eo pid,ppid,pcpu | awk '$2==1 && $3>50'` 复核为空），但这正是
  CLAUDE.md 里那起 205 CPU 小时事故的同一个形状。
  **要造后台进程就每个当场记 `$!`，别信 `jobs -p`**；更好的是
  **别自己造负载**（账本原话：借机器上已有的）。
- **测试自己也会留孤儿，而断言绕得过清理**（同批）。「宿主死孩子活」那条真验
  故意让一个忽略 SIGHUP 的孩子活着，它自己拆红时 panic 在 `kill 孩子` 之前，
  于是那个 `sh` 挂到了 init 底下。**用 `Drop` 守卫，别用收尾语句**——
  panic 跳得过语句，跳不过 Drop。
- **`pkill -f` 的模式匹配的是全网所有同名进程，不是「我起的那个」**
  （2026-08-17 头像样式批实撞）：收自己 1445 上的探针 bridge 用了
  `pkill -f "target/debug/bridge"`，把 1431 上**用户预览用的**桥一起杀了
  （中断约五分钟）。这是「作用域比你以为的大」那一族的第四面
  （前三面：`cargo fmt`、批量脚本、`git add -A`）。判词（车道自己的）：
  **起进程时选对了工具（run_in_background），收进程时要沿用它**
  （TaskStop 或起时记下的那个 pid）——按名字模糊杀，杀的是一类不是一个。
- **pathspec 提交吞了同文件的在制品——领队自己犯的（2026-08-17，
  `b1f7997`）**：往 handoff 加上面那条坑时，车道应用裁决的三处 handoff
  编辑正在工作区里；`git status` 三个脏文件**看见了**，仍在编辑同一份
  文件后径直 `commit -- <路径>`，跳过逐行认——那笔 28 行新增里 20 行
  是车道的。内容无损、归属错位；按规不重写历史，两侧各自报了对方。
  tokens 仓 CLAUDE.md 那张表第一行写的就是这格（pathspec 重读工作区），
  写过判词的人照样犯。两面防法：**领队侧**——同文件有别人在制品时，
  等它落、或走「hash-object 写索引」那第三种；**车道侧**（它自己的话）
  ——**改完账本就地提交，不攒着等收官**：工作区是共享的，东西在里面
  每多待一秒就多一秒被顺走的可能。

### 拆红这一侧（2026-08-16 存续债批与接入债批各撞几次）

- **断言的基准不能和被测对象共用同一条代码路径**（接入债批实撞，
  **这是「假绿」家族的一支新面**）。装钩子那条「不许重排用户的键」的守门，
  第一版拿 `serde_json::Value` 的键序当「装之前」的基准——**而那个 Value 走的
  正是被测的同一套排序**，于是两边一起排、永远相等：把
  `preserve_order` 从 Cargo.toml 里拿掉，它照样全绿。
  改成从**磁盘上的文本**读键序、fixture 也改成字面量且键序**故意不按字母排**，
  才红得出来。**问一句就能抓到它：我这个「预期值」是从哪儿来的？**
- **断言不能量在它要守的那个常量上。** id 宽度那条守门第一版写的是
  `assert_eq!(leaf.len(), link::LEAF_HEX)`——**把 `LEAF_HEX` 改回 8 照样
  全绿**，两边一起动。改成对字面量 `16` 断言才红。这就是账本里「断言量在
  一个常量上」那一条，**是在写它的同一趟里犯的**：写守门的时候人在想
  「别写死数字」，而守门要守的恰恰就是那个数字。
- **烟测里的「探针前提」也会写成不可能成立的。** 「搜索够得着来源机器名」
  那条要先找一个「id 和 title 都不含那个机器名」的行，第一版拿**整行文本**
  当判据——而行里印着「来自 X」、永远含那个名字，于是那个 `find` 永远返回
  空，报出来是「probe dead」，读起来像功能坏了。**判据要贴着被测的那个
  字段取，不是贴着屏幕上那一块。**
- **固定 sleep 的测试，测的是「机器闲不闲」**（接入债批实撞）。tmux 那条
  「一个 shell 在跑东西是忙碌」用了 `send-keys` 后 sleep 900ms；一次和编译
  撞上的全量跑里它红了一次，随后连绿十一遍——`sleep 300` 那 900 毫秒里没起来，
  pane 读出空闲。**换成等被测那一侧自己的输出**（这里是同一句
  `tmux list-panes`），等的东西和断言看到的东西才是同一个来源。
  顺带一条：**等的条件里别写死本机的 shell 名**（原来等 `zsh`）——
  在 bash 机器上那会静默等满超时再往下跑，那是比红更糟的绿。
- **数字要在能算准的条件下量。** `cost.rs` 那条「每次列表扫几遍进程表」用的是
  一个**全进程共享**的计数器，并行跑时另一条测试的快照会算进来：并行量到
  21/12，串行才是 12/12——**21 会读成「列表扫了两遍」**，正是账本当年靠猜
  记错过的那个结论。跑法写进了那份文件头（`--test-threads=1`）。

- **对照组本身可能不是只读的**（2026-08-17 GPU vitals 小批实撞）。macOS 的
  GPU 利用率是个窗口量，**读一次就把窗口清空，而窗口在内核里、全机器共享**
  ——于是拿 `ioreg` 当对照组跑一遍，khor 紧接着那次读数就是 0。症状是 khor
  连三次读出 `0.0` 而对照组印着 48：**读起来完全像被测代码解错了字段**，
  而真凶是那个用来「核对」的动作。同一件事的第二面：三条读它的测试并行跑
  会互相抢窗口、全体读零，两条对照测试双双红在「**对照组自己读出 `[0.0]`**」
  上——同样读起来像被测代码坏了。
  **问一句就能抓到它：我这个对照组，读一遍会不会改变被测的东西？**
  它和上面那条是同一条判据的两个方向：那边是共享计数器被别的测试**加了**，
  这边是共享窗口被别的读者**取走了**。

### `cn()` 盖不掉自定义尺寸类（2026-08-17 头像样式批实撞并量了）

`cn()` 走 tailwind-merge，而 tailwind-merge **不把 `ctl-md` 读成一个高度**，
于是 `h-ctl-md` 和调用方传的 `h-auto` **两个类都留在 markup 里**，谁赢由
样式表里谁后出决定。实测那颗选项按钮：`className` 里两个都在，
**computed height 30px 而 scrollHeight 40**——窄档一换行，上一行的字就被
下一行的脸压住。

**这一族是 `--spacing-*` 生出来的每一个尺寸工具类**：`ctl-sm/md/lg`、
`rail`、`list`、`avatar`、`icon-rail`、`icon-mark`。想用 `className` 盖掉
其中任何一个都盖不掉，而**只有内容溢出时才看得见**——盖不掉但没东西溢出的
地方（`RailItem` 就同形传了 `h-auto`，里面没有可见文字）**至今没有症状，
也没有被改**。

这一批的修法是局部的：`ui/button` 加一档 `size="auto"`，判据写在那一档上。
**根治不做，挂账（领队 2026-08-17 裁决）**：要动 twMerge 配置，那会改变全
app 的类合并行为。**触发 = 下一个动 `components/ui/` 的批顺手根治**（配置 +
一条同族守门测试：拿一个 `ctl-*` 类和一个覆盖它的工具类比，断言只剩一个），
**或第二个症状出现**。

### 浏览器烟测这一侧（2026-08-16 工具条批各撞一次，都是假红）

- **`locator.focus()` 对一个已经聚焦的元素什么都不发。** 轨道那颗图标刚被
  点开过面板，就已经带着焦点；再 `focus()` 一次不会有 focus 事件，于是
  「键盘聚焦也出浮签」那条断言测的是一个没发生过的事件，读起来却像功能坏了。
  **先把焦点挪走并断言它真的走了**，再聚焦回来。
- **Radix 的浮签有一块 grace area，`mouse.move` 一跳跨不出去。** 内容可悬停
  的浮签会在触发器与内容之间留一块过渡区，只有落在区外的 `pointermove`
  才关它；Playwright 默认 `steps: 1`，那一跳没有中间事件。用 `steps: 12`。
- **动效要量元素，不能读类名。** 少一个 `@import "tw-animate-css"`，
  `animate-in` 那些类照样躺在 markup 里，只是背后什么都没有——量
  `getComputedStyle(el).animationName / animationDuration` 才看得见，
  顺手把时长缓动和 `--dur-*` / `--ease-*` 对一遍，就同时证了「接了令牌」。
- **烟测的 bridge 端口会和用户自己开着的 app 撞。** 撞上时旧 bridge 还在，
  新 bridge 起不来，而浏览器会照常连上**别人的 home** 并一路报绿。
  现在烟测等自己那个 bridge 打出端口行、它先退出就当场报错；
  端口可用 `BRIDGE_PORT` / `VITE_PORT` 覆盖（vite 是借用的，同一份源码，
  借它没问题；**backend 不能借**）。
  **2026-08-16 `3e90a47` 起默认挪到 1442/1443**（此前默认正是用户那对
  1430/1431，实测两个都被占着）。**「可用 env 覆盖」挡不住这件事**——
  覆盖要有人记得写，而默认是没人想的时候用的那个；把默认让开，
  两边同时开着才互相看不见。
