## 用户反馈与根因

- Meet → Stay 的菱形先消失再出现：选择器命中了玻璃面内部的模糊边，而非顶层清晰轮廓。
  结果主轮廓被当成装饰，在玻璃体积的圆形擦除遮罩中消失，静态小图标交接时才重新出现。
- 四台机器没有来自四颗外珠：旧逻辑保留收缩图标的原珠，另画四个半径从零增长的设备圆。
- KhorNet 线条生长未考虑标题：过渡外围路径到 90% 才加标题缺口，之前先画完整线。
- 反向合拢有残线：设备已经移动，静态关系线和徽标还在收退；箭头标记也不随描边 dash 收缩。
- “随时继续工作”下方出现英文段落：中文消息截图只切换了 App 控件语言，示例消息本身仍为英文。

## 修复

`story-material.ts` 明确选择顶层清晰菱形。轮廓不参与玻璃面遮罩，材质、厚度与整体缩放连续变化。

过渡中的四个设备实体取自原图四颗外珠，连同各自阴影、高光和边缘一起移动。
半径从原珠的实际屏幕大小插值到设备大小，位置从原珠中心插值到目标机器；主体始终不透明，
没有从零出现的新圆。珠面逐渐转成设备底面，内部显示设备字形。完整标记的外环、菱形、内环
和中心持续收拢到 KhorNet 标题位置，小标记的四个微型连接点随后就位。

外围线从第一个生长片段起使用 KhorNet 标题与标记缺口。只给这条边复制自身的缺口，
避免其他尚未出现的原生网络标题在中途切断外围线。标题到位后不再补切一刀。

关系线和徽标在图进度 .84–1 范围内收退／展开；设备位置在 .82 已到位。
因此反向播放先收完关系，再移动机器。过渡中关闭独立箭头端标记，避免无描边时残留碎片。
从第一幕漫游返回形变时，按“曾经展开”状态重置网络并重新测量 P2P 标题，不依赖是否仍在播放。

设备底面支持实际关系图的渐变 paint server；先解析其颜色参与珠面变化，终点使用原 paint server。
不再把 `url(#...)` 误传给 CSS `color-mix`，避免收尾设备保持错误的荧光绿。

`scenarioForLocale` 为第一段真实会话提供完整中英文消息与工具标题；首屏和局部消息截图共用此数据。
四张完整首图与四张消息片段重新从实际 App 截图，保留 40% 窗口底色。
中文消息现在是“日期和列名已更新，8 项测试全部通过”及中文修复说明，文件名和项目名保持原名。
