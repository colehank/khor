## 真机隔离回路

本地新加 `render-probe.ts`，仅 `import.meta.env.DEV` 有效；未带参数的页面保持完整展示，生产构建忽略参数。入口均为原本地地址加查询参数。

| 参数 | 变化 | 用户Safari结果 |
|---|---|---|
| 无 | 完整GUI、动态Fog与背景合成 | 放大整页报错 |
| `render-probe=poster` | 保留完整首图，不启动交互GUI；Fog与外侧玻璃保留 | **正常放大** |
| `render-probe=no-glass` | 父子文档backdrop及GUI背景surface模糊关闭 | 仍整页报错 |
| `render-probe=no-stream` | GUI背景实时视频停用，其他效果保留 | 仍整页报错 |
| `render-probe=no-fog` | 不启动外层WebGL；GUI背景流亦无来源 | 仍整页报错 |
| GUI独立地址 `/experience/app/index.html?scene=content&hero=1` | 不嵌入首页 | 不能放大，无报错；**不是缩放通过证明** |
| `render-probe=no-backdrop` | 完整移除GUI内附加背景合成层，保留真实GUI、外侧Fog与GUI自有玻璃 | 仍整页报错 |

Chrome已核对各参数确实只停用相应链路，GUI仍可按模式加载；TypeScript通过。每次只按真实反馈推进，不将Chrome结果当作Safari修复验收。

## 当前边界与后续

可优先调查交互GUI的嵌入／合成路径，尚未定位到唯一根因。手机背景surface为对齐整个hero而反向扩大，模糊实测约92.99px；单独关闭模糊或视频均不足以消除用户的故障，不能宣布这两个单项为根因。

`no-backdrop` 也已被用户确认仍整页报错。下一步需要用户选择手机首图／桌面交互的呈现取舍，或继续调查完整手机交互GUI的嵌入／缩放兼容性；不要再将单项视觉开关的猜测称为修复。若继续部件隔离，保持一次一个变量。手机仅显示完整首图已是可复核的稳定对照；把它用于默认手机展示会改变手机交互范围，需和用户确认该取舍，不偷偷删除GUI功能。桌面可操作演示、Fog原参数、原SVG、40%窗口材质等既定内容保留。

当前开发期排查入口仍保留。修复完成后清理临时诊断入口或将其明确留在开发工具范围，并用Safari原始缩放动作验证普通URL。没有通过禁用网页缩放规避故障，没有改原生App或发布。
