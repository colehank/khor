## 1 整个 app 不随滚轮动

> 「整个app的拖动逻辑没有统一. 我在工作区的文件树拖动, 整个app都会下移,
> 正确的应该是整个app是不允许随滑轮变化的」

现状（2026-09-20 查，**builder 就地更正**）：`tokens.css` 的 `@layer base` 里
`html` / `body` / `#root` **已经有 `height: 100%`**——高度从来不是病根，app 本来就
正好填满窗口。缺的是另外两条：没有 `overflow`，也没有 `overscroll-behavior`，
所以一个滚到头的窗格会把接下来的滚动交给整页，而 WebKit 的视口接住它就是橡皮筋，
整个 app 连同左上角三个窗口按钮一起下移。

落法：
- **外壳钉死**：`html`、`body`、`#root` 高度占满、`overflow: hidden`、
  `overscroll-behavior: none`。滚动只发生在窗格里。
- **每个会滚的窗格**自己 `overscroll-behavior: contain`，滚到头不往外传。
  做成一个类 / 一个组件，别在十几处各写一遍。落法（**builder 的判断**）：
  一条挂在 tailwind overflow 工具类上的选择器（`app.css`），不是一个要人记得去加的类
  ——全仓 48 个滚动容器，加类就是 48 个调用点，明天新加一个又漏一个；
  而「这是个滚动容器」这件事在每个调用点已经写下来了，就是那个工具类本身。
  代价明说：类名要是变了，每个窗格会**悄悄**退回链式滚动，而这种坏法在有人
  拨一下触控板之前没有任何症状——所以门量的是真窗格上 `getComputedStyle`
  读回来的值，不是这条规则存在。
- 门：**`npm run wk` 要加一臂**（这是 WebKit 的行为，Chrome 上量不出橡皮筋）。
  **builder 就地更正**：原句要的那两个读数（`scrollTop` 仍是 0、外壳
  `getBoundingClientRect().top` 没变）**在改之前就已经是真的**——khor 的布局里
  document 本来就无处可去，红表印的是 `docTop:0, railTop:0, railWas:0`。
  所以 wk 那一臂的探针页**故意比窗口高**：没有规则的那一臂真的会把导轨推出
  左上角那三个窗口按钮的位置，这才是能红的对照组。面门那边断言的是
  两条声明落没落地（`overflow-y` / `overscroll-behavior-y` 的 computed 值），
  加上那两个读数照印。两道门各量一半，单独一道都不算数。
- 人眼验：在文件树、会话列、机器页、额度页各滚到头再猛滚，窗口按钮不动。

## 5 标签页只有一份，高度等于侧边栏搜索框

> 「所有标签页逻辑保持一致, 并且作出修改: 标签页的高度, 要和侧边栏搜索框的高度一致,
> 保持和谐.现在, 标签页普遍比侧边栏更高一些.」

- 标签页条的高度 = 二级侧边栏顶上那一行（搜索框那行）的高度。**同一个 token**，
  不是两个恰好相等的数。落法：`--pane-head = --touch + --tab-lip`，
  `PaneBar`、树头、标签页条三处都穿它。量到的旧数：标签页条 48，`PaneBar` 44
  ——而 `PaneBar` 写的是 `min-h-ctl-lg`(40)，44 是里面那个搜索框的
  `min-h-touch` 顶出来的，**没人写过这个数**，这正是「两个恰好相等的数」的反面
  （两个谁也不知道从哪来的数）。
- 会话标签页、浏览器标签页、工作区文件标签页：行为一致（关闭、激活、溢出、
  拖动、中键关），长相一致。**builder 就地更正**：这三处**本来就是一份实现**
  （`browse/TabStrip.tsx`，三处各喂自己的 `TabFace[]`），不需要收——
  这一条实际要做的只有高度和第 3 条那个间距。
- 门：面门量每个落地页上「标签页条的高」与「搜索框那行的高」，差值 0。

## 6 侧边栏底色只有一个来源

> 「整体app的视觉一致. 现在, 除了额度页面之外的侧边栏底色都是深灰, 但额度页是黑色.
> 这看起来没有用统一的逻辑进行编写.」

- 所有落地页的二级侧边栏共用一个底色 token。额度页现在走的是另一条路，改回来。
- **做成一个 `<ListPane>`（或同类）壳**：底色、顶上那一行、滚动规则（第 1 条）、
  收起（第 4 条）都在壳里。各落地页只填内容。这是这一轮最要紧的一件——
  第 1、4、5、6、7 条其实是同一个缺口的五个症状。
- 落法（`apps/gui/src/components/ListPane.tsx`）：壳里有**四样**——底色、
  头那一行的高、滚动条、**还有缝**。缝也进壳，是因为额度页缺的正是它：
  它没有缝，所以也没有宽度、没有收起，导轨那条「再按一次」就无处可按。
  四个用户：`data-list`（会话/机器/工作区）、`data-quota-pane`、
  `data-ws-tree`、`data-ws-sessions`。
- 门：面门在深浅两个主题下量每个落地页侧边栏的 `background-color`，全部相等。
  `npm run palette` / `rail` 照跑。

## 7 文件树顶上那一排按钮小一点

> 「工作区的二级侧边栏, 即文件数这里, 搜索框旁边有这些按钮: 新建文件、新建目录、
> 打开session、打开vscode. 可以小一点来支持显示.」

**builder 就地更正（2026-09-20 查）**：树头上只有**两枚**按钮——打开 session、
打开 vscode（`WorkspacePane` 的 `switches`，2026-09-17 第 47 条放的）。
新建文件 / 新建目录不在这一行，它们在树的右键菜单里，以及最后一行下面那块空白
（`FileTree` 的 `data-tree-blank`，第五轮第 36 条）。这一条**照原话的动作做**
（「可以小一点来支持显示」），不照原话的清单做：不往这一行加按钮——这一条要的是
给搜索框腾地方，再加两枚是反着来的。

- 两枚按钮从 `--touch`(44) 缩到 `--ws-switch`(32)，墨迹跟着降一档；搜索框拿回 24px。
- 「后两枚收进一个『…』」**没做，裁掉了**：两枚放不下的窄档不存在，而这两枚是窄档
  进 session 栏和 vscode 的**唯一**入口（第 47 条就是为这个把它们从标签页条挪过来的），
  收进菜单等于把那个入口再藏一层。真出现第三、第四枚按钮时再做。
- **手指大小的下限仍要守**（面门第 3 节量每个可按目标）：宽档可以小，
  窄档（触屏）按 `--touch` 走——`tokens.css` 底下 `(pointer: coarse)` 把
  `--ws-switch` 换回 `--touch`，和 `--tree-row` 同一条路。

## 2 浏览器：标签页进侧边栏，离开不关

> 「浏览器改版为侧边栏. 标签页移动到侧边栏, 参考chrome的最新模式.
> 标签页不应该离开就关闭, 而是缓存着, 如chrome一样, 下次可以快速打开.」

用户给的参照图：Chrome 的竖排标签页——左侧一列标签（favicon + 标题，
当前那枚高亮并带关闭），列底一个「+」，右边整块是页面，地址栏在页面上方。

- 浏览器落地页从「浏览型」（无列表窗格）改成和别的落地页同一个壳：
  二级侧边栏里是**竖排的标签页**，一行一枚：图标 + 标题，当前那枚高亮，
  悬停 / 当前时右侧出关闭。列底「+」新开一枚。地址栏留在右边页面的上方。
- **离开不关**：切到别的落地页再回来，标签页都还在，当前那枚还是当前那枚，
  页面**不重新加载**（滚动位置、表单内容都在）。也就是说 webview / iframe
  在切走时是藏起来，不是卸掉。
- **重启之后也还在**：标签页列表（地址、标题、顺序、当前是哪枚）存盘，
  重开 app 后列表立刻回来；页面内容可以在点到那枚时才加载（Chrome 也是这样）。
  存在哪：和 `recents` 同一类的本机状态，**不同步**。
- 内存：藏着的标签页不设上限会吃光 16G 的机器。落一个上限（比如最近用过的 N 枚
  留着活的，其余只留地址和标题，点到再加载），N 取多少 builder 量了再定并写明。
- CLI 等价：标签页列表是本机状态，CLI 至少要能列、能开、能关
  （`khor tabs` 或并进现有动词，builder 看现有 `khor open` 的形状定）。
- 窄档：一次一屏的规矩照旧（`docs/WORKSPACE.md` 第 40 条那一类），
  标签页列是一屏，页面是一屏。
- 门：面门量「切走再切回，同一个 frame 节点还在、没有重新 load」；
  smoke 量「重启 app 后标签页列表还在」。

  > **builder 就地更正（2026-09-21）：这两条门都不在它们被指去的地方。**
  >
  > 前半条**没有任何一道门做得到**，而且不是没写，是写不出来。页面不是
  > 页面里的一个节点，是一张盖在上面的原生 webview（`open_page` /
  > `hide_page` / `show_page`）；面门跑的是装好料的 fixture，
  > `check-tabs` 跑的是系统 Chrome，两边都没有 tauri——`api.ts` 里这几个
  > 调用在网页脸上本来就写着 no-op。所以「切走再切回没有重新 load」的
  > 实现在 `apps/gui/src-tauri/src/lib.rs` 的复用分支里（同一个出口 +
  > 同一个地址 = 根本不 `navigate`，注释就写着「a reload on every tab
  > switch is exactly the thing keeping a webview per tab exists to
  > avoid」），**只有装机的人能验**。人眼验收的做法：借一台机器的网开一枚
  > 标签，页面里往下滚一段，切到别的落地页再切回来，滚动位置还在。
  >
  > ⚠️ 量的时候要用**带 `-m` 的标签**。不带机器的标签根本不加载页面，
  > 窗口里印的是「这就是本机的网,不用借」——那是借网浏览器本来的规矩，
  > 但拿它去量「有没有重新加载」，量到的是一句话（验收方 2026-09-21 实撞）。
  >
  > 后半条挪了位置：在 `npm run tabs` 里，不在 smoke 里。smoke 从头到尾
  > 没有一枚浏览标签页，而 `check-tabs` 有两个真 home、真 UDP、真 `khor`
  > 在 PATH 上，`khor tabs ls` 在 backend 死着的时候照样读得到文件——那是
  > 这条断言能有「之前/之后」的唯一理由。它在那里是两条：`page.reload()`
  > （窗口没了又回来）和把 bridge 杀掉再起一个（beta 的 node 就是 bridge，
  > 它死等于 app 整个退出）。

## 第二轮：每条侧边栏长一个样（2026-09-21）

用户原话：

> 「浏览器侧边栏也要和其他侧边栏一样有搜索和新建的组件在最上面呀。以及，所有侧边栏内都要
> 支持右键去置顶、删除。会话有独特的转为对话，别的可能有别的特殊的，比如机器的断开等。
> 现在语言不一致，关于置顶与删除的操作统一为置顶与删除。」

### 病根（2026-09-21 查）

- **浏览那一列没有头**，是批二单元一**存心**不画的（`BrowseLanding.tsx` 里那段注释：
  「Chrome 的竖排标签把唯一的动作放在列底」）。用户推翻了它：一样东西（侧边栏）只有一个长相。
- 右键菜单各列各一套，**有的列根本没有**：会话 5 项（转成终端 / 转成对话 / 钉住 / 复制 id /
  关闭）、机器 2 项（置顶 / 移除设备）、工作区 2 项（置顶 / 移出工作区）、浏览标签 0 项。
- 同一个动作四个词：`pin` 在目录里有「钉住」和「置顶」两份；删掉一行叫「关闭」「移除设备」
  「移出工作区」三种说法。

### 落法

1. **每条侧边栏头上都是同一行**：搜索框 + 新建（「+」）。就是 `ListPane` 的 `head` 那一格，
   会话 / 机器 / 工作区已经在用的那个 `PaneBar`。
   - 浏览：搜索标签的标题和网址；「+」新开一枚标签。列底那个「新标签页」按钮撤掉——
     一个动作一个位置。
   - 别的列没有「新建」的，照现有的来（会话的「+」是新会话、机器的「+」是邀请设备、
     工作区的「+」是新建工作区）；**哪一列真没有可新建的东西，头上也不画空按钮**，
     由 builder 查实后写进交付消息。
2. **每条侧边栏的每一行都有右键菜单，头两项永远是「置顶」「删除」，顺序固定**，
   之后才是这一列自己的：
   - 会话：置顶、删除，然后 转为终端 / 转为对话、复制 ID。
   - 机器：置顶、删除，然后 断开（本机那一行没有删除和断开）。
   - 工作区：置顶、删除。
   - 浏览标签：置顶、删除，然后 复制网址、在系统浏览器中打开（如果现有代码已有这条路）。
   - 已置顶的行，「置顶」那一项写「取消置顶」。
   - 「删除」各列的后果不一样（会话是关掉、机器是移出网络、工作区是从列表拿掉、标签是关掉），
     **词统一，后果写在二次确认里**：确认那一句说清删了会怎样（沿用现有的确认规矩和
     `confirm-*` 设置项，不新造一套）。
   - 浏览标签的「置顶」是新行为：置顶的标签排在最上、关不掉之前要先取消置顶，存进 `.khor/tabs.json`，
     `khor tabs` 也要能置顶（CLI 与 GUI 等价）。
3. **「机器的断开」是新动作，先查它指什么**：现有的有 `khor forget`（移出网络，不可逆，
   = 删除）和 `khor pause`（本机暂停，不是某一台）。「断开某一台」若没有现成的节点能力，
   **不在这一轮造**：菜单里不画，交付消息里写明「断开需要一个节点能力，现在没有」，
   我拿去和用户讨论。
4. **文案统一**：「钉住」→「置顶」（目录里那份 `[config] pin` 一并改或撤）；「关闭」「移除设备」
   「移出工作区」在右键菜单里一律 →「删除」；「转成终端 / 转成对话」→「转为终端 / 转为对话」；
   「复制 id」→「复制 ID」。其他页面上已经用「移除设备」的地方（网络页地图卡）改成「删除」，
   让同一个动作在整个 app 里只有一个词。两份 toml 一起改，CLI 上同一个动作的句子跟着改。
   **交付附改前 / 改后表。**

### 门

- 每条侧边栏：头上一行存在，且搜索框那一行的高 = 标签页条的高（第一轮第 5 条的 token）。
- 每条侧边栏的第一行右键：菜单头两项是「置顶」「删除」（词从屏幕上读，比较的是**各列之间相同**，
  不抄目录）。**「一个动作一个词」要有断言**：整个 app 里能读到的「钉住」「移除设备」「移出工作区」为零。
- 浏览标签置顶：置顶后排到最上、重启后还在、`khor tabs ls` 看得见标记。

### builder 就地更正（2026-09-21 查）

- **病根里漏了两条侧边栏、两个词。** 「右键菜单各列各一套」数的是四列，实际是五列：
  **额度那一列也有行菜单**（置顶 / 编辑 / 撤掉，账户行），而且它的删除叫「撤掉」、
  排第三。另外工作区文件树的「删除」一直叫「删掉」（`file-remove`，工作区批④），
  确认框那颗按钮也是它。两处这一轮都并进 `delete`「删除」，额度的顺序改成
  置顶 / 删除 / 编辑。文件树不是「一条侧边栏的行」，它的右键菜单（新建文件 / 新建目录 /
  改名 / 删除…）没按「头两项置顶、删除」重排——文件没有置顶这件事；只统一了词。
- **「`[config] pin` 一并改或撤」——它说的不是置顶。** 那是「单击文件」设置的一个取值：

1. **先压，再溢出。** 放不下时，未选中的标签**一起**从 `--tab-w` 往窄里收，收到一个下限

| 终端 | khor 自己持有的持久终端（`shell/`） |
| 智能体·终端形态 | khor 持有的终端里跑 agent（`tui/`，目前只有 claude） |
| 智能体·对话形态 | ACP 对话（`chat/`）：claude、codex、登记过的任何 ACP agent |

**导入（「+」→ 导入）**，三个来源合成一张候选表：
| 来源 | 怎么认 | 导入后 |
|---|---|---|
| tmux 会话 | 现有 tmux 扫描（含卫星上的 tmux） | 终端（`shell/`），能接进去 |
| 在自己终端里开的 agent | 现有 `Adaptor` 扫描（claude、codex） | 智能体·终端形态，**观察**；能接管 |
| ACP agent 已有的对话 | 登记过的 agent 的 `session/list`（2026-03-09 已稳定，`sessionCapabilities.list`） | 智能体·对话形态，`session/load` 接着聊 |

新建向导里现在那一节「已有的对话」**挪进导入**（一个动作一个位置）。

### 落法

1. **一张「纳入」表**：导入的会话 id 进一份全网复制的文档（哪台机器导入，四台都看得见）。列表 = 新建的 + 纳入表里的 + 对设备的对话。
   扫描照跑（状态、钩子、用量都照旧），只是**没纳入的不画**。
2. **导入面板**：每个候选标机器、目录、标题、最后活动时间；按机器、目录筛；多选导入。已纳入的不再出现在候选里。
   「导入」菜单项上可以标候选数（不是角标、不自动加）。
3. **删除**：导入的行「删除」= 从纳入表拿掉（厂商那边的会话一个字节不动，删除窗里这么说）；它回到候选里。
   新建的行照现有 close 语义。
4. **寿命**：「观察」只经导入出现；新建只有持久与临时。接管（`takeover` / 转为终端 / 转为对话）照旧可用。
5. **升级**：不保留。自动发现、没经过新建的行，升级后从列表消失、进候选；khor 新建的、对设备的对话照旧。
6. **CLI 等价**：`khor import`（列候选，带序号）/ `khor import <序号|id>...`；`khor sessions` 只列列表里的；
   删除对导入行 = 取消纳入。
7. **顺手**：`crates/acp` 头注释里「`session/list` 是没人实现的 RFD」过时了，改成现状（v1 已稳定，`session/delete` 也是），
   并写明各家适配器支持不一，所以磁盘扫描那条路留着。

### 门

- 夹具：一台机器上有一个 tmux 会话、一个在「外面」开的假 claude、一个会 `session/list` 的假 ACP agent。
  起来后列表里**没有**这三样；导入面板里三样都在。
- 各导入一个 → 列表里出现，形态对（shell / 观察的 tui / chat）；另一台机器的列表里也出现。
- 删除导入的行 → 行没了、候选里回来、厂商文件没动。
- 对设备的对话：不导入也在。
- 升级夹具：旧 store 里有自动发现的行 → 新版本起来后不在列表里。
- 先看它红。

## 第九轮：额度是一份抽象，每家一份描述、一条取数链（2026-09-22，khor-58）

用户原话：

> 「额度查询应该是一个统一的抽象，针对各个厂商及对应的系统做 adaptor，这一点，应该已经有开源工具做了。」
> 我给了三条路（调 CodexBar 的 CLI / 照它的抽象用 Rust 自己写 / 外置数据），用户：「用量这选 B」。浏览器 cookie 那种取数：先不做。
> 「可以，用我的 codex 登录试一次」——试了，见下。

### 参照

[CodexBar](https://github.com/steipete/CodexBar)（MIT，Swift）的 provider 形状：**每家一份描述**（名字、网址、默认值、取数流程）；
**一条按优先级排的取数策略链**，每条策略自己说可不可用、`fetch`、失败时要不要退到下一条，留下每次尝试的诊断；
**统一的快照**（主 / 次窗口：已用百分比、窗口长度、重置时间；更新时间；账号身份）；**凭证处理与取数分开**。
我们照这个形状用 Rust 写，不引它的代码；模块头注明参照。

### 两家现在已知的取数路

| 家 | 策略 1（本地，不联网） | 策略 2（登录问接口） |
|---|---|---|
| Claude | `~/.claude/usage-status.json`（状态栏钩子写的，新鲜时用） | 借 Claude Code 存的登录（`~/.claude/.credentials.json` / 钥匙串）问 `api.anthropic.com/api/oauth/usage`（现有） |
| Codex | 会话记录里的 `rate_limits` 快照（`~/.codex/sessions/**/rollout-*.jsonl`，新鲜时用） | 借 `~/.codex/auth.json`（`auth_mode = chatgpt`）问 `https://chatgpt.com/backend-api/wham/usage`，头 `Authorization: Bearer <access_token>` + `ChatGPT-Account-Id: <account_id>` |

**Codex 接口 2026-09-22 用用户自己的登录手动试过一次**（HTTP 200）。回来的形状：
`plan_type`；`rate_limit.{allowed, limit_reached, primary_window, secondary_window}`，窗口是
`{used_percent, limit_window_seconds, reset_after_seconds, reset_at}`；`credits.{has_credits, unlimited, balance}`；
还有 `code_review_rate_limit` / `additional_rate_limits` / `model_usage` / `promo` 等（当时为空）。
对照：本地快照（9-06）读 6%，实时读 9%——快照只能兜底，这正是链的顺序。
**非公开接口**：和 Claude 一样，每个字段都当可选，读不懂就是「读不了」，绝不读成 0、绝不 panic。

### 落法

1. **`Provider` 描述 + `Strategy` 链**（`crates/node/src/quota/`）：每家一个文件；链上每条策略报可用与否、取数、要不要退；
   `khor quota --why`（或 doctor 一项）印出每次尝试的诊断。
2. **一个快照结构**，所有家共用：若干窗口（名字、已用 %、窗口长度、重置时间）、套餐名、credits、是否触顶、取数时刻、**来自哪条策略**。
   界面照现有的额度环画，Codex 一行和 Claude 一行长得一样。
3. **规矩提到抽象层、每家都守**：内存 5 分钟 + 全机共享的盘缓存 + 失败后 10 分钟冷却；**不自动刷新 token**（过期就请人去跑那家的 CLI）；
   说清数字来自谁的登录（现有文案规矩）；测试门（`KHOR_*_USAGE_URL` 一类）每家一个；钥匙串那条「只在账户自己的 home 读」照旧。
4. **第七轮第 3 条建在这上面**：每家的描述里有「本机是否登录了」；登录了就**自动建一条账户登记，只建一次**，删了不回来；
   之后与手动登记的账户一视同仁（置顶、删除、编辑）。补丁里的红句拿回来用。
5. **浏览器 cookie 那种策略不做**（隐私）。Cursor 这类只有 cookie 路的家，这一轮不接。

### 门

- 假 home 里放假 Codex 登录 + 假 `wham/usage` 服务：额度列出现 Codex 一行，窗口与套餐读对；假服务收到的每个请求带的都是假 token（沿用 fake-home 的计数）。
- 链：本地快照新鲜时，接口被问 0 次；快照过期时问 1 次；接口失败 → 冷却期内再读问 0 次，画「读不了」不画 0。
- 形状：接口回一个缺字段 / 多字段 / 字段类型不对的 JSON → 「读不了」，不 panic。
- 自动登记：两家各自只建一次；删了再读不回来。
- 真凭证：smoke 结尾「真登录被读 0 次」照旧（Codex 的 `auth.json` 也算进去）。
- 先看它红。
