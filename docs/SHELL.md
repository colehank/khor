## 1 整个 app 不随滚轮动

> 「整个app的拖动逻辑没有统一. 我在工作区的文件树拖动, 整个app都会下移,
> 正确的应该是整个app是不允许随滑轮变化的」

现状（2026-09-20 查）：`html` / `body` / `#root` 上没有任何 `overflow` 或
`overscroll-behavior` 的规则，所以一个滚到头的窗格会把滚动（和 WebKit 的橡皮筋）
交给整页，整个 app 连同左上角三个窗口按钮一起下移。

落法：
- **外壳钉死**：`html`、`body`、`#root` 高度占满、`overflow: hidden`、
  `overscroll-behavior: none`。滚动只发生在窗格里。
- **每个会滚的窗格**自己 `overscroll-behavior: contain`，滚到头不往外传。
  做成一个类 / 一个组件，别在十几处各写一遍。
- 门：**`npm run wk` 要加一臂**（这是 WebKit 的行为，Chrome 上量不出橡皮筋），
  量「窗格滚到头再滚，`document.scrollingElement.scrollTop` 仍是 0，
  外壳的 `getBoundingClientRect().top` 没变」。`npm run face` 里也量一遍 scrollTop。
- 人眼验：在文件树、会话列、机器页、额度页各滚到头再猛滚，窗口按钮不动。

## 3 会话列的类别图标、标签页标题

> 「session页面的侧边栏list里, session 类别的icon大一点, 现在有点不可读.
> 此外, 标签页上的标题距离头像稍远一些, 现在有些拥挤.」

- 会话行上那个「类别」图标（chat / term / agent 那一枚）放大到读得出来。
  走 token，别写死像素（px 门会拦）；和工作区文件类型图标那次是同一个教训
  （`docs/handoff/history/2026-09.md` 文件类型图标一节）。
- 标签页上头像与标题的间距加大。**改的是标签页那一份组件**，
  所以会话、浏览器、工作区文件的标签页一起变——见第 5 条。

## 4 再按一次额度，收起额度侧边栏

> 「额度页面, 再次点击额度按钮也应该收起额度侧边栏.」

别的落地页（工作区、会话）再按一次自己的导轨按钮就会收起列表，额度没有。
落法：导轨按钮的「再按一次 = 收起」是**一条规则**，由导轨统一给，
不是每个落地页各自实现。查一下机器页、浏览器是不是也漏了，一并补。
门：面门里对每个落地页按两次，量列表的宽度。

## 5 标签页只有一份，高度等于侧边栏搜索框

> 「所有标签页逻辑保持一致, 并且作出修改: 标签页的高度, 要和侧边栏搜索框的高度一致,
> 保持和谐.现在, 标签页普遍比侧边栏更高一些.」

- 标签页条的高度 = 二级侧边栏顶上那一行（搜索框那行）的高度。**同一个 token**，
  不是两个恰好相等的数。
- 会话标签页、浏览器标签页、工作区文件标签页：行为一致（关闭、激活、溢出、
  拖动、中键关），长相一致。现在若是三份实现，收成一份组件 + 三份数据。
- 门：面门量每个落地页上「标签页条的高」与「搜索框那行的高」，差值 0。

## 6 侧边栏底色只有一个来源

> 「整体app的视觉一致. 现在, 除了额度页面之外的侧边栏底色都是深灰, 但额度页是黑色.
> 这看起来没有用统一的逻辑进行编写.」

- 所有落地页的二级侧边栏共用一个底色 token。额度页现在走的是另一条路，改回来。
- **做成一个 `<ListPane>`（或同类）壳**：底色、顶上那一行、滚动规则（第 1 条）、
  收起（第 4 条）都在壳里。各落地页只填内容。这是这一轮最要紧的一件——
  第 1、4、5、6、7 条其实是同一个缺口的五个症状。
- 门：面门在深浅两个主题下量每个落地页侧边栏的 `background-color`，全部相等。
  `npm run palette` / `rail` 照跑。

## 7 文件树顶上那一排按钮小一点

> 「工作区的二级侧边栏, 即文件数这里, 搜索框旁边有这些按钮: 新建文件、新建目录、
> 打开session、打开vscode. 可以小一点来支持显示.」

- 四枚按钮缩小到一排放得下、搜索框仍有可用宽度。窄到放不下时的退路：
  后两枚收进一个「…」，不是换行。
- **手指大小的下限仍要守**（面门第 3 节量每个可按目标）：宽档可以小，
  窄档（触屏）按 `--touch` 走。

## 2 浏览器：标签页进侧边栏，离开不关

> 「浏览器改版为侧边栏. 标签页移动到侧边栏, 参考chrome的最新模式.
> 标签页不应该离开就关闭, 而是缓存着, 如chrome一样, 下次可以快速打开.」

用户给的参照图：Chrome 的竖排标签页——左侧一列标签（favicon + 标题，
当前那枚高亮并带关闭），列底一个「+」，右边整块是页面，地址栏在页面上方。

- 浏览器落地页从「浏览型」（无列表窗格）改成和别的落地页同一个壳：
  二级侧边栏里是**竖排的标签页**，一行一枚：图标 + 标题，当前那枚高亮，
  悬停 / 当前时右侧出关闭。列底「+」新开一枚。地址栏留在右边页面的上方。
- **离开不关**：切到别的落地页再回来，标签页都还在，当前那枚还是当前那枚，
  页面**不重新加载**（滚动位置、表单内容都在）。也就是说 webview / iframe
  在切走时是藏起来，不是卸掉。
- **重启之后也还在**：标签页列表（地址、标题、顺序、当前是哪枚）存盘，
  重开 app 后列表立刻回来；页面内容可以在点到那枚时才加载（Chrome 也是这样）。
  存在哪：和 `recents` 同一类的本机状态，**不同步**。
- 内存：藏着的标签页不设上限会吃光 16G 的机器。落一个上限（比如最近用过的 N 枚
  留着活的，其余只留地址和标题，点到再加载），N 取多少 builder 量了再定并写明。
- CLI 等价：标签页列表是本机状态，CLI 至少要能列、能开、能关
  （`khor tabs` 或并进现有动词，builder 看现有 `khor open` 的形状定）。
- 窄档：一次一屏的规矩照旧（`docs/WORKSPACE.md` 第 40 条那一类），
  标签页列是一屏，页面是一屏。
- 门：面门量「切走再切回，同一个 frame 节点还在、没有重新 load」；
  smoke 量「重启 app 后标签页列表还在」。
