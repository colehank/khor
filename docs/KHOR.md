# Khor

> 坛城（Kyil-khor），意为连接。

p2p 组成用户自己的设备网络：在任意设备同步信息、发起任务、监控状态。
当前聚焦设备上的智能体任务（Claude Code、Codex 等）的交互。

## 三条地基

- **一张网，无中心。** 每台机器既是客户端也是服务器。配对任意一台即入网，
  设备信息全网自动同步。数据只在设备间流动，中继只转发不存内容：
  默认 iroh n0，可选 Khor 中继（海外 fly.io / 国内 aliyun）或自建。
- **Session 是一等原语。** shell、智能体 TUI、对话、文件传输——
  同一个列表、同一套身份、状态词、事件流（形式参考 WeChat）。
  统一的是呈现与协议，不是实现：对话是 CRDT（离线可写）、终端是活进程、
  传输是有终点的任务，硬统一实现会毁掉第一个。
- **CLI 与 GUI 等价。** 同一个 Rust 后端，app 能做的 CLI 都能做。

## 核心功能

- 监控：机器状态（CPU/GPU/内存/磁盘）、session 状态
  （六词：忙碌/待批/完成/中断/失败/空闲，全网全端一词）
- 发起：在任意设备开 session、传文件、借网访问
- 入网：配对一台 = 同步全网
- 网页脸：任一台机器出一张网页，手机或别人的电脑打开即达整个网
  （`khor web` 发链接；**无中心版的 remote control**——没有枢纽，
  你连的就是你自己那台机器）
- Khor 智能体：调度网内设备与 session，完成指派任务

## 实现

Rust 后端 + Tauri v2 前端，一套代码五端：macOS、Linux、Windows、iOS、Android。
网页脸是同一份前端：vite 产物编进那一个二进制（`crates/web`），
落地的机器上仍然什么都不用装——浏览器每台设备本来就有。
UI 用 shadcn/ui，参考 Apple。没有技术壁垒，体验就是壁垒。
