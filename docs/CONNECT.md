# 连接模型

> 2026-09-29 定方向，分期落地。**本页写去处，[NET.md](NET.md) 写现状**——
> 两处说法不一样时，现在跑着的以 NET.md 为准，要改成的以本页为准。

**只凭钥匙连上自己的所有设备。** 一次连接要答三问：你是谁（身份）、
你在哪（寻址）、怎么到（路径）。SSH 只把第一问交给钥匙，后两问是人记
主机名、配跳板。本模型三问都从钥匙推出来，人不配地址、不配中继。

网页脸（局域网 TCP 口加一把随机钥匙，NET.md「网页脸的暴露面」）给的是
浏览器，不走这套身份，不在本页内。

## 设备会在的网络

| 网络 | 典型 | 能怎样 |
|---|---|---|
| 同一局域网 | 家、实验室同网段 | 直连，最快，免费 |
| 一端公网地址 | 云主机、带公网 IP 的服务器 | 对方直接拨 |
| 两端全局 IPv6 | 国内宽带与移动网越来越普遍 | 无 NAT 只有防火墙，同时发包多能打通 |
| 家用 NAT（映射不随对端变） | 绝大多数家用路由 | 打洞容易 |
| 运营商 NAT、对称 NAT（映射随对端变） | 移动网、部分公司 | 打洞难，常只剩中继 |
| UDP 被封，只剩 TCP 443 / HTTP 代理 | 公司、部分校园网、酒店 | 只剩 443 上的中继，可能经代理 |
| 强制门户 | 酒店、机场未登录 | 全不通，要人登录 |
| 只能 ssh 进 | 集群计算节点、跳板机后 | 卫星：经 sponsor 代跑（NET.md） |
| 已在覆盖网 | Tailscale、学校 VPN | 覆盖网内直连 |
| 跨境 | 国内 ↔ 海外 | 直连丢包重；海外中继国内常不通——**中继放哪决定成败** |
| 间歇在线 | 手机后台、笔记本合盖 | 连不上，靠推送唤醒或在线的机器代收 |

## 路径与代价

| 路径 | 延迟 | 谁出钱 | 谁看得到元数据 | 前提 |
|---|---|---|---|---|
| 局域网、覆盖网 | 最低 | 无 | 无 | 知道在同一网 |
| 公网直连、IPv6、打洞、端口映射 | 低 | 无 | 无 | **先有人牵线**交换地址 |
| 中继转发 | 中 | 中继的主人 | 中继：谁和谁、多少流量 | 两端都够得着同一台 |
| 网内一台代转 | 中 | 那台 | 那台 | 它两边都够得着 |
| 卫星（ssh） | 高 | 无 | sponsor 见明文 | 用户已有 ssh 配置 |

**直连也要牵线**：两端先经中继交换地址才打得了洞（iroh 文档：先经中继
交换网络信息，直连不成才退回中继转发；约九成网络最终直连）。所以中继的
本职是牵线和兜底，不是主路——一个一台中继都用不上的设备，连本能直连的
那九成也会失败。

## 身份：用户根钥匙

现在一台一把设备钥匙，信任的根是设备表，网内任何一台都能往里加设备。
模型在设备钥匙之上加**用户根钥匙**：它不参与连接、不加密数据（那仍是
设备钥匙的事），只**签字**。

| 它签什么 | 得到什么 |
|---|---|
| 「设备 X 是我的」（设备证书） | 新设备出示证书，全网立刻认，不等设备表同步、不两两配对 |
| 「设备 X 作废」 | 偷走的设备伪造不了，也没法再往网里加设备 |
| 「我有这几台」（设备名单） | 知道根公钥即可查到全部设备——「只凭钥匙」要的就是它 |
| 网外的第三方可验 | 中继、计费、团队不在你的网里，也能离线验证「这台属于用户 U」 |

- **名单是信任的唯一出处**。设备表 CRDT 照旧，但只载名字、卫星字段、地址
  提示这些不涉信任的数据；CRDT 里有而名单里没有或已撤销的设备不算数。签名
  记录当不透明字节存进设备表那一行，取用时验签、按序号取最大——CRDT 的
  「后写赢」不参与。2026-09-30 已落地（NET.md「身份与配对」写现状）：证书在
  行上，名单放同一文档旁边的一张图、每签一版一个键，合并不丢任何一版，取用
  时验签取最大 seq。
- **新设备入网三路**：持根设备扫码代签（根钥匙不离开它）；恢复词；服务器和
  无屏机器**不导入根钥匙**——它出票（现有配对票反过来用），持根设备拨过去签了
  送回。配对完成的判据从「双方设备表里都有对方」改为「新设备拿到证书」。
  **谁持根**：第一台装的机器自动生根，不分种类——先装在 turing 上它就持根；
  只签过自己的单机并进一张多台的网时把根让出（删自己的 root.key），两张多台的
  网不能并。老网迁移：在一台上 `khor root init`，表里的机器全签上。
- **根不在场**：非根设备只能**发起**入网或移除，进待批（`.khor/pending`，
  单独一张表；和智能体动作待批并进一个界面是以后的事）——持根设备上线批。
  所以根得常在一台随身的设备上。
- **卫星**（NET.md）也进名单：根签「卫星 S 是我的、sponsor 是 D」，签的是它
  ssh host key 的指纹；它没有自己的位置记录，由 sponsor 代发。单 sponsor 的
  单点这一期不动。
- **撤销要新鲜**：序号只防回滚，防不了「一直没更新」——离线一个月回来先碰到
  被偷的那台，它给的是旧名单。所以名单带发布时间，超期先从任一来源取新名单
  再信人；取不到时按旧名单继续、只信上面已验过的、不收新证书，并在连接诊断里
  说「名单已过期 N 天」；新名单一到立刻按它断。现状（2026-09-30）：30 天算
  过期，持根机每 7 天重签一次；新名单只靠平常的同步泵带来，「从任一来源主动
  取」等 3 期的池目录。无 RTC 机器的时钟待定。
- **存放**：一两台主力设备的钥匙串 + 恢复词。丢了用恢复词找回；被偷要换根、
  全部重签——所以要护住。细节待定。
- **不做版本并行**（2026-08-17 立的常规：产品在开发，完全不考虑兼容老端，
  见 handoff 001）：证书一上，全网一起升，老版本直接被拒；位置记录仍带版本号，
  只为诊断里说得出「那台还是旧版」。
- **为共享预留**，这一期只用「设备属于我」一种，但格式不许堵死：
  1. 证书的签发对象可以是设备、用户、团队，带权限与有效期；
  2. 同步数据里凡指「人」的（谁置顶、谁批准）记根公钥，不记设备 id；
  3. 共享的数据单独成文档——绝不把整张设备表、全部对话同步给合作者。
- **以后的共享**：授权 =「用户 V 可在设备 X 上看 / 开会话 / 读目录 Y，到某日」，
  由你的根签发，你的设备凭 V 的证书链离线验证；跨人默认不信、要审计；团队
  = 团队根签成员的根，实验室服务器归团队根。「入网即全信」只在一个人的
  设备之间成立。

## 寻址：签名的位置记录

- 每台持续发布**自己签名**的位置记录：地址候选、网络画像、登记在哪几台
  中继、递增序号。根钥匙下另挂签名的设备名单。
- **五处同时发，谁新用谁**；有签名，谁转来的都行、伪造不了：

| 来源 | 快慢 | 局限 |
|---|---|---|
| 网内设备表 | 快 | 至少连得上一台自己的设备 |
| 家中继 | 快 | 要知道它登记在哪台 |
| Khor 中继池（兼目录） | 快 | 池里每台都存、按根公钥查；够得着池里任一台即可 |
| 局域网 mDNS | 快 | 只同网段 |
| DHT（Mainline，pkarr 签名记录，约 1 KB、定时重发） | 慢，几秒 | 记录公开——内容加密或只写中继不写 IP；国内可用性待实测 |

- **只凭根钥匙、手里没有任何票**（异地、全新设备）时，五个来源里能靠的只有
  池目录：设备表要先连上一台，家中继要先知道是哪台，mDNS 要同网段，DHT 国内
  未必通。所以池兼作目录不是可选项，是「只凭钥匙」在国内成立的那一条。DHT
  只当池外兜底，不作首选；n0 的 DNS 发现服务去掉，不留单点。

## 路径：测量 → 预测 → 竞速 → 迁移 → 学习

1. **测量**：每台持续给自己画像——IPv4 / IPv6 的 UDP 通否、映射是否随
   对端变（对称 NAT）、公网地址、到各中继的延迟、强制门户（iroh 的
   net_report 已给）；另记**网络指纹**（网关、Wi-Fi、公网网段），认出换了网。
2. **预测**：两端画像 → 各路径成功率。例：公网出口相同先试局域网；两端
   对称 NAT 不等打洞直接中继；两端有 IPv6 先 IPv6；UDP 被封走 443 中继、
   必要时经代理（iroh 的 `proxy_from_env`，2026-09-30 已开；它不读 NO_PROXY，
   整个 shell 设了代理时同网段的中继也绕代理走）。
3. **竞速**：首包走最稳的一条（上次胜出的，或中继）；同时按预测顺序并发
   试直连；更好的通了就迁（iroh 1.x 传输即多路径 QUIC，迁移不断线），
   旧路留作热备。**网内一台代转**（NET.md「经那台代问，只一跳」）只走控制
   消息，不进竞速；数据要经自己的另一台，让那台跑 `khor relay` 进自己的池，
   同一条中继路，不另设一档。
4. **学习**：按「我的网络指纹 + 对方的网络指纹」缓存胜出路径，下次先试；
   换网自然失效。
5. **按流量分级**：控制与同步任何路都行；交互终端要低延迟；大件与借网要
   省钱——借网（NET.md「可达性」）经中继时整段网页流量都过中继，是中继上
   最大的一项——只在中继上时先问或降速，等直连。

## 中继：选两端，不选一端

- **选法**：现在各自挑离自己最近的「家」，别人去它家找它。跨境时海外那台
  住海外、国内这台够不着它。改为**选两端都够得着、且较慢一端延迟最小的
  那台**。
- **双家**：每台同时登记国内一台、海外一台。**iroh 1.2 不支持多家**
  （2026-09-30 查源码：一个 endpoint 只许一条中继传输，`socket.rs` 写明；
  `home_relay_status` 的列表永远至多一项；家取最近 5 分钟延迟最低的一台，
  新的要低于旧的 2/3 才换；不是家的中继连接闲置 60 秒拆掉）。后果：设备表的
  地址提示里带全部中继，但一台机器只在家那台上收包，对端从别的中继找它会被
  静默丢包。双家只能 khor 这层做：同一把钥匙再挂一个只连海外中继的 endpoint。
- **四类中继**：

| 类 | 给谁 | 准入 | 谁出钱 |
|---|---|---|---|
| 免费池 | 所有 khor 用户 | 共享密钥 → 设备证书 | 我们；**限速**：牵线、状态、对话够用，大件慢；国内外各至少一台，否则去 n0 后一侧全走跨境 |
| 付费池 | 订阅用户 | 证书链 + 订阅（签名票），中继本地验，不每次问账户服务 | 订阅；全速，国内外都有 |
| 自家 `khor relay` | 有公网机器的人 | 只放行自己证书链上的设备，不填密钥 | 用户；不限速 |
| 原版 iroh-relay | 中继机不装 khor 的人 | 地址 + 密钥 | 用户 |

- iroh-relay 1.2 的库只给 `AccessControl` trait 和「放行所有人」；everyone /
  allowlist / denylist / http 回调 / shared_token 那五种写在它自己二进制的
  main.rs 里，嵌进来的程序要自己实现——`khor relay` 已经实现了共享密钥和
  按名单放行两种（2026-09-30）。自定义的能拿到握手验过的设备公钥和请求头。
  限速是整台一个值，所以免费池与付费池是两组机器。字节计数也是整台一对，
  按设备只有连接次数与在线时长（库不把包交给 AccessControl）。
- **中继池 = 管理者签名的名单**（地址、地区、启停）。由中继自己发布，设备从
  任一台够得着的中继取新版、验签才换；二进制只留启动用的一份。**不能是
  普通同步**：谁能改你的中继名单，谁就能把你的流量引到他的机器上。管理者
  是我们（Khor 池）或团队管理员；个人的 `khor relay` 自动进他自己的池。
  管理页：在线、延迟、在线设备数、流量（iroh-relay 自带指标）、启停、加一台。
- **收费边界**：直连永远免费，牵线免费，自建免费；只对 Khor 中继的全速转发收费。
  对外不卖「p2p 连接」，卖「任何网络都全速、国内外都通」。免费用户在限速
  中继上时，网络设置里安静地说一句，不弹窗。
- **计量只存总数**：每用户、每中继的流量总数与打洞成功率，不存「谁连谁」的
  对——中继看得到的元数据止于内存里的这一刻。这是收费的隐私承诺，和收费
  边界一起写进对外的话。

## 间歇在线

- 手机后台：iOS 断连接，只能推送唤醒——推送服务（APNs）是少数必须有中心
  的一样，只转加密信号不看内容。
- 合盖的机器：显示上次状态和时长（SESSION.md 离线一节）；写操作经 CRDT
  由在线设备代存，回来即合。

## 做不到无感的六处

1. 第一次信任：扫码、输钥匙或恢复词——这是安全的定义。
2. 两端都对称 NAT，或 UDP 都被封：只能中继，花钱或慢。
3. 完全隔离的机器：只能 ssh 卫星。
4. 手机后台：只能推送。
5. 强制门户：要人登录。
6. 本机防火墙：macOS 应用防火墙对没签名的二进制放 loopback、吞别的
   （NET.md 记的症状：握手通、数据一个字节不来）；Windows 首次弹窗。
   要人点一次允许。

其余全部无感；碰到这六处时，**说出卡在哪一处**，不说「连不上」。

## 度量与验收

- 指标：首包时间（中位、p95）、直连占比、中继流量占比、换网后恢复时间、
  「网络类型 × 网络类型」连通矩阵。先在本机连接诊断里给人看，以后可选匿名上报。
- 机器卡片上的路读数（NET.md「走的是哪条路，看得见」）以后从路径模型取：
  在用哪条、备胎哪条、卡住时卡在六处的哪一处；活性仍是行上另一根轴。
- 验收：同机造网——Linux 网络命名空间 + 防火墙规则、macOS 网络条件模拟——
  每类 NAT、UDP 被封都真连一遍，带对照组（不该通的真的不通，NET.md 验收）。

## 差距

| | iroh 已有 | khor 已有 | 要补 |
|---|---|---|---|
| 身份 | 设备钥匙 | 配对、设备表 | 根钥匙、设备证书、签名撤销、设备名单（含卫星）、待批入网 |
| 寻址 | DNS、mDNS；Mainline 寻址是单独的 crate（`iroh-mainline-address-lookup`），不在 1.2 本体里 | 设备表地址提示、配对票、mDNS（n0 DNS 已去，2026-09-30） | 签名位置记录、池目录、五处发布 |
| 路径 | 探测、多路径迁移、端口映射、代理 | 路读数（NET.md）、代问一跳 | 两端画像预测、胜出缓存、流量分级、开代理 |
| 中继 | 服务端、访问控制、限速、指标 | 写死的一台 | 两端选、双家、`khor relay`、池、准入 |

## 待定

- 根钥匙的存放、恢复与轮换细节。
- 设备名单的新鲜度时限；没有 RTC 的机器怎么算过期。
- 卫星要不要多 sponsor。
- DHT 在国内能否用（实测）。
- 双家怎么在 khor 这层做（iroh 不支持，见「中继」）。
- 中继探测与连接走不走代理要一致（NET.md「中继」两笔账之一）：探测跟连接，
  还是两者都读系统代理。
