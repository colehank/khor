# 行为与门

每一行后面都跟着一道能变红的检查。**没有门的那一行不算规则**，只算愿望。

**什么配门（2026-09-25 起）。** 门只给两类东西：机器量得准、人眼看不出的（token 值、对比度、字号档、像素与色值字面量、图标家族、首帧颜色、拖动区域、慢源时限）；以及出过事的。布局摆放——按钮在不在 R0、sheet 离顶多远、某页有没有某一行——不再写成 `check-face` 断言，放进每轮末「真 app 走一遍」的验收清单，由负责人对着看。

**先红后绿只用于修 bug**：先写一个在旧代码上变红的门，再修到绿。新功能不必先证明旧版会红。

## 真 app 验收清单：布局那几条

门不量的摆放放在这里，每轮末负责人在真的 app 里对着看（网页端截图不算）。新加的写在最上面，看过、稳了的留着当回归清单。

**2026-09-29 机器、工作区两栏能筛**

- 机器页：左上搜索框右边多了一颗筛选按钮（和会话页、额度页那颗一样），＋ 还在最右。点它：三组——「连接方式」（本机、直连 / 中继…，借网的机器写「经 某台」，和行上第二行那个词一字不差）、「系统」（Apple / Linux…，没报系统的机器是「未知」）、有机器暂停时才有的「状态 → 已暂停」。
- 勾一个：列表只剩对得上的机器，按钮变亮，搜索框里长出一枚小标签；同一组再勾一个是「或」（两种都留），另一组再勾一个是「且」（两边都得对上）。勾到一台都不剩：列表写「没有匹配项」。
- 点小标签上的 ×、或回菜单再点一次：取消；全取消后机器全部回来，按钮不亮。退出 app 再开：勾过的还勾着。
- 暂停一台机器，勾「已暂停」，再恢复它：列表空了，但「已暂停」还在菜单里、框里标签还在，点掉就回来。
- 工作区页：同样一颗筛选按钮在搜索框和 ＋ 之间。两组——「机器」（行上写的机器名；机器已从网里删掉的那几行归「未知」）、「类型」（git 仓库 / 文件夹，和行角标一样：角标是分支的算仓库，还没答复的那一行角标是文件夹就算文件夹）。
- 在工作区页勾着东西时，右边没打开工作区时的概览（最近打开 / 最近改动）不跟着少，还是全部。
- 把窗口拉窄到 760 以下：机器、工作区的列表那一屏，第一行是搜索框、筛选、＋，三样都在，能勾能取消。
- 会话页、额度页的筛选和以前一模一样。

**2026-09-29 回到工作区不重来**

- 在工作区页等各行的分支、时间都到了，切到会话页再切回来：列表一出来就是刚才的顺序，置顶的在前，仓库那几行一出来就是分支角标、名字旁边就有分支名，不先画成文件夹再换，也不重排。
- 退出 app 再开，第一次进工作区：顺序和角标也直接是上次的；分支名晚一点补上，行不动。

## 选字与手（2026-09-28）

**界面的字不是文字。** 访达的侧边栏拖不出蓝色，双击行名是打开这一行，不是选中一个词。所以页面默认 `user-select: none`（`app.css`，在 `@layer base` 里，工具类还能盖过它），**能选的地方只用一种写法标：`data-selectable`**，标在读的那块面上：

- 对话那一栏（`ChatView` 的 `data-chat-column`）、所有 Markdown（`data-md`）、文件与 diff 与代码（行号自己带 `select-none`，不跟着选）、机器之间的消息；
- 人会抄走的值：「…」页事实行的值（id、版本、路径，`MoreFact`）、网页端的钥匙、中继地址、诊断每一条的原话和出错那一句、diff 读不出来的那一句。
- 输入框、多行框、`contenteditable` **永远能选**——WebKit 里一个 `none` 的祖先会让输入框打不进字。
- 终端是 xterm 自己画的，它在自己的画布上选，不用标。
- 读的面里的按钮仍是界面（复制按钮上的字不是段落的一部分），正文里的链接除外——那是段落自己的字。

**手指形光标只属于正文里的链接。** macOS 的控件、行、菜单、标签、开关、图表上的点都是箭头；手指只在一段字里的链接上出现。今天留着手的两处：Markdown 的链接（`data-md-link`）和对话里的路径（`PathLink`，`data-link`）。别的地方写 `cursor-pointer` 就是 `check-face` 第 3 节的红。**灰掉的控件上也是箭头**：AppKit 不在不可用的控件上换光标，灰已经说了「不能」；shadcn 带来的 `disabled:cursor-not-allowed`（开关、输入框）2026-09-28 拿掉了，§11b 读 computed 也读源码。

**右键。** WKWebView 在任何地方右键都会弹它自己的菜单（重新载入、检查元素）；Mac app 的侧边栏上没有这种菜单。`lib/shortcuts` 在窗口上（冒泡阶段，让 Radix 的行菜单先拿到事件）把它挡掉，**只放过**输入框里和选中的字上——那里系统的菜单有用（剪切、拷贝、粘贴、查询）。行自己的右键菜单照旧。网页端同一条规矩。

没有「帮助」：还没有东西可放，一个空菜单教人别打开菜单。字全部来自目录的 `[menu]` 一节（和竖栏的五个名字），用这台机器现在说的语言；设置里换语言、或在终端 `khor config set lang` 之后窗口回到前面，菜单重搭。Windows 和 Linux 不搭菜单栏——那里的菜单栏会变成窗口里的一行，骨架里没有这一行；那边只有页面的键盘这一条路。

**名字，和 AppKit 自己加的项（2026-09-28）。** app 是以裸二进制跑的（`target/local/khor-gui`，外面没有 `.app`）。一个没有 Info.plist 的进程，AppKit 拿进程名当 app 菜单的粗体标题——读出来是「khor-gui」，不管 `menu.rs` 给那个子菜单起什么名；它自己往编辑、窗口里加的项（自动填充 · 开始听写… · 表情与符号；全部最小化 · 全部缩放 · 填充 · 居中 · 移动与调整大小 · 全屏幕平铺 · 从组中移除窗口 · 排在前面）说英文，因为进程没声明任何语言。现在二进制里嵌着 `src-tauri/Info.plist`（`src/main.rs`，`__TEXT,__info_plist` 段）：`CFBundleName` = khor，声明 zh-Hans 与 en、开发语言 en。**不写 `CFBundleAllowMixedLocalizations`**：AppKit 只在这两种里挑，第三种语言的桌面上它说英文，和 khor 自己的字一样（「非 zh* 一律英文」）。

- **不写 `CFBundleIdentifier`，不改可执行文件的名字，不调 `setProcessName`。** WebKit、CFNetwork、defaults 给自己的目录起名用 `bundleIdentifier`，没有才用进程名。页面的 localStorage 今天在 `~/Library/WebKit/khor-gui/WebsiteData/`（设了 `KHOR_HOME` 的在 `…/khor-gui/WebsiteDataStore/<uuid>/`），缓存在 `~/Library/Caches/khor-gui/`，cookie 在 `~/Library/HTTPStorages/khor-gui.binarycookies`，偏好在 `~/Library/Preferences/khor-gui.plist`。加一个标识符，下次启动就是一个空的页面 store——在临时二进制上量过，数据落进以标识符命名的新目录；`setProcessName` 改不了粗体标题，却把 WebKit 的目录改成了新名字（也量过）。哪天真要打成 `.app`，先迁这几处。
- **AppKit 的项跟 khor 的语言。** 系统的第一语言挑出来的和 khor 正在说的不同时（中文 Mac 上设成英文的 khor），`menu::speak_at_launch` 在启动时把 khor 的语言放到这个进程 `AppleLanguages` 的最前面——**只放在内存里的参数域**，不写任何偏好文件：app 的偏好域以进程名命名，本机每个 khor-gui（负责人的、原生门的）都会读到。这和 macOS 自己的「按应用设语言」是同一个开关，所以管到的也一样：系统面板（选文件、Touch ID）、webview 的 `navigator.language`——浏览标签页先向网站要 khor 的语言，页面的 `auto` 也落到 Rust 那半边选的那种。两者本来一致时什么都不动。
- **只在启动时。** CoreFoundation 第一次被问就把一个 bundle 的语言定下来，之后不再改（量过：进程里换语言再重搭菜单，AppKit 的项还是原来那种；私有的清缓存函数也不行）。所以运行中换语言，khor 自己的项立刻跟上，**AppKit 的项下次启动跟上**。

## Do

- 填骨架；引用 token 名，永远不写原始值。
- 开关管是/否，分段控件管「几个固定的里选一个、全摆出来」（≤ 4 个且不会长），弹出按钮管「一串会长的里选一个」，导航行管「它自己有一页」（2026-09-28）。要打字的是 `TextField`（`ui/input`），和搜索框同一种底、角和焦点环。
- 橄榄绿只给打开的开关、焦点、竖栏打开的字形、以及那一个主操作。选中行是灰块。
- 系统自己能画的交给系统：菜单、菜单栏、窗口按钮、滚动条、右键菜单。
- 一个控件在指针是手指时把热区涨到 `touch` 44，样子可以不变。
- 读的、抄的地方标 `data-selectable`；新快捷键加进 `lib/shortcuts` 那一张表，Mac 上同时进菜单栏。

## Don't

- 别在 R0 和 R1 之间加一行，也别在标签下面加副标题。
- 有原生菜单的地方别自己画浮层。
- 别在组件内部标拖动区域。
- 别给一个区域第二个宽度来源。
- 别拿状态色当底色，也别拿橄榄绿当装饰。
- 别在选中行上用透明度或 `secondary` 分主次——在灰块上都会跌破 4.5。
- 别在请求处理函数里跑阻塞调用（磁盘、网络、子进程）。
- 别给控件写 `cursor-pointer`：手指只给正文里的链接。也别写 `cursor-not-allowed`：灰掉的控件上还是箭头。
- 别拿淡底（`bg-accent`）当悬停或选中：指针下是 `fill`，选中是 `fill-strong`。
- 别在组件里自己挂一个 `keydown` 做全局快捷键：一张表、一处监听，菜单栏才对得上。
- 别让 ⌘W 关窗口：关掉 khor 的窗口就是让这台机器离网。

## 还没定的

- Windows 自己画的窗口按钮、以及没有标签的那条窗口行，在这台 Mac 上量不到。
- 网页端拖不动窗口、也显示不了材质；它的门覆盖布局，覆盖不了手感。
- 动效除了 `duration` / `easing` 四档和「尊重减弱动态效果」之外，还没有逐个场景定下来。
