# 骨架与三种页型

窗口只有一副骨架。六个区域，每个区域的尺寸、谁能拖动窗口、里面允许放什么，都在这里定死；页面只决定放进去的是什么。

```
┌──────────── L  左块 ──────────────────┬──────────────── R ────────────────┐
│ L0  ● ● ●  [ 搜索              ⌘K ] + │ R0  标签条  ·  或  页面标题         │  ← 两条都是 38，一条中线
├──────┬────────────────────────────────┤ ┌────────────────────────────────┐ │
│ L1   │ L2 列表                         │ │ R1 板                           │ │
│ 竖栏 │ （列表行、分组标题）             │ │ （页面内容）                     │ │
│ 64   │ 宽度归 L 所有                    ║ │                                 │ │
└──────┴────────────────────────────────╨─┴────────────────────────────────┘─┘
                                          ║ = 唯一一道宽度把手
```

| 区域 | 尺寸来自 | 放什么 | 空白处能拖窗口 |
|---|---|---|---|
| **L** 左块 | `rail-w` + 列表宽，**只存一处，存在 L 上** | L0、L1、L2 | — |
| **L0** 第一行 | `pane-head` 38（手指 48） | 三颗窗口按钮（macOS）· 搜索框 · ＋ | 能 |
| **L1** 竖栏 | `rail-w` 64 | 五个落地页、更多、这台机器；打开的那一项变**图标**（墨换成 `rail-on-ink` 深橄榄绿、实心块填到 1.0），不变背景 | 能 |
| **L2** 列表 | 跟随 L | 列表行、分组标题 | **不能**（D3） |
| **R0** 工具栏 | `pane-head` 38（手指 48），**每一页都有** | 标签条——或者页面标题（D2） | 能 |
| **R1** 板 | 四边 `gap-in` 8，圆角 `radius-xl` | 页面 | 不能 |

**第一行是 38，一条中线**（2026-09-29，负责人：「怎么标签页到app上沿有空白空间 可以整体顶到上沿，为显示内容腾出空间」，在给的几种里选了「整行收紧到 38」）。L0 和 R0 一起从 48 收到 38，是 macOS 紧凑工具栏的高度（Safari、访达的「使用紧凑布局」），每一页多出 10 px 给内容。**三颗窗口按钮、搜索框、页面标题、标签、页面按钮都在这一行的中线上**（y 19）：

- 标签是一个 `ctl-md` 28 高的「签」落在中线上，下面一截 `tab-lip` 5 的「脚」把它接进板里；所以它离窗口上沿也是 5（(38 − 28) / 2）——那 5 px 是标签上方能拖窗口的一条。脚也按得到标签（打开它的那颗按钮伸进脚里），不会变成一截拖窗口的空白。
- 两行标题（A 页型的每一页和打开的工作区，2026-09-30 起）照样在 38 里：字号不变（15 / 12），行距各收一档——名字用 `body` 的 18、第二行用 `caption` 的 14，18 + 14 = 32，上下各留 3。名字旁边的那几个字（工作区的分支与改动）站在名字的基线上、用 `caption` 的行距，不把名字那一行撑高。`check-face` §12 在每一站量这两档行距（名字那一行 18、第二行 14）。
- **行高跟着指针走，不跟宽度走**：指针是手指时（`pointer: coarse`，手机、iPad）第一行回到 48，标签的签是 `touch` 44、上下各 2。窄档的 Mac 窗口用的是鼠标，照样 38——三颗窗口按钮是建窗口时由 AppKit 放一次的，第一行要是在 760 宽处换高度，它们就离开中线 5 个点。
- `check-boot` 守「行 = 签 + 上下各一脚」（鼠标、手指两种）和 `traffic.rs` 的 38；`check-face` §12 在每个落地页量中线（±1）、标签离上沿、标签接板；`npm run native` 量真窗口里关闭按钮的中心 y 19。

三条不许破的：

- **拖动区域由外壳声明一次**，写在 L0、L1、R0 上。里面的控件由 tauri 自己的规则排除。**组件永远不自己标拖动区域**。
- **宽度只有一个主人。** L 右缘那道缝是唯一的把手；L0 跟着它走，搜索框在溢出之前先变短——框永远是框，不变成放大镜按钮（2026-09-27）。任何区域不许有第二个宽度来源。
- **R0 和 R1 之间不许塞东西。** 不加副标题行，不加状态句。会话页那条 4 px 的「一天」是唯一的例外，而且它没有文字（它的一行上下各 `gap-xxs`：那一行是它的热区，见 `components/DayStrip`）。**它默认不在**（2026-09-29）：再按一下最前面那枚标签才落下，再按收起；没有记录时根本不画——这一行永远不会是空的。**落下来也不占会话的位置**（同日）：那一行浮在会话最上沿，从下面那块面的颜色淡出，会话不挪、不变矮；除了胶囊，这一行上的点击都是会话的。

**平台差异。** macOS：三颗窗口按钮在 L0，左块用侧边栏材质。Windows：最小化/最大化/关闭在 R0 右端，L0 从搜索框开始。Linux：系统装饰在窗口之上，L0 从搜索框开始。网页端：同 Linux，且没有装饰。非 macOS 一律没有材质，左块用 `side` 实色。

## 三种页型——每个落地页正好是其中一种

今天右边有六种各自拼的做法（会话用 `Tabs` 或 `Region`，机器用 `Region`，额度和浏览各写各的，更多用 `Region`，打开的工作区是裸的三栏）。这就是修好一页别的页不跟着好的原因。从这里开始只有三种页型，每种一个组件，落地页声明自己是哪一种（D7）。

| 页型 | 心里的模型 | L2 列表 | R0 工具栏 | R1 板 | 用在 |
|---|---|---|---|---|---|
| **A 详情** | 选一个，看它 | 全部条目，一个选中 | 标题 · 选中那一项的动词在右端（总览时空着） | 选中那一项；没选中时是总览 | 机器、额度、更多 |
| **B 标签** | 开几个，来回切 | 全部条目，最前面那个标签对应的行选中 | 标签条 · ＋ | 最前面那个标签；没有标签时是总览 | 会话 |
| **C 文档** | 这一行本身就是活的页面 | 全部文档，一个选中 | ‹ › ⟳ · 地址/标题 · 页面按钮 | 那个文档 | 浏览 |

**A 页型 R0 的两行**（2026-09-30，负责人：「所有非标签页的落地页和工作区看齐。例如机器页：最上方是机器名，下方一行是 khor 版本与更新时间」）：第一行是标题，第二行 `callout` 配 `secondary`，**只写页面已经问到的事实**——不为它多问一次，没有诚实的事实就不画第二行，不编。第二行由页面写（`PageSubtitle`），外壳摆；窄档的头只有一行，第二行不画。

| 页 | 第一行 | 第二行 | 事实从哪儿来 |
|---|---|---|---|
| 机器（选了一台） | 机器的显示名 `shown` | `khor 0.1.14 · 12 秒前`（这台机器：`更新于 14:02`） | 设备表里这台机器的读数（`MachineCaption`，以前挂在 R0 右端） |
| 机器（总览，地图） | 机器 | `5 台机器 · 已连接 3 台`；只有这一台时只有前半句 | 地图画的那张设备表；「已连接」只数直连和中继，和网络页同一个数法 |
| 额度（选了一个） | 账户名 | `Max · turing 读取于 3 分钟前`：套餐和这份读数的来历与年龄 | 额度板的那一行（`ReadCaption`，以前挂在 R0 右端） |
| 额度（一个账户都没有） | 额度 | 不画 | 没有读数可说 |
| 通用（更多的总览） | 通用 | `khor 0.1.14` | 这一页问过的 `about` |
| 外观 | 外观 | 不画 | 这一页只有设置本身，没问任何事实 |
| 网络 | 网络 | `在线 · 已连接 3 台`（没配对时 `在线 · 尚未与其他机器配对`） | 状态那一组的两个事实，同一个数法 |
| 安全 | 安全 | `锁定已开启 · 闲置 5 分钟后自动锁定`／`锁定未开启` | 外壳问过的锁（`lock`） |
| 这台机器 | 这台机器 | `turing · khor 0.1.14` | 设备表里的本机与 `about` |
| 诊断 | 诊断 | `更新于 14:02`：这一组检查是什么时候答的 | 这一页那次 `doctor` 的回答 |

**R0 右端只留「过期 / 离线」那一句**（`20-states`）：一页的读数整个过期时它说「3 分钟前的读数」；一样东西自己的年龄在第二行，不在右端。

**设置式的「…」页没有板**（2026-09-28，负责人定的明文例外）：A 页型里，内容是一组组设置（`SettingsGroup`）的详情页——通用、外观、网络、安全、这台机器、诊断——**不画板**，设置组（`card`）直接落在 `canvas` 上，像 macOS 的「系统设置」。理由：设置组本身就是「`card` 落在 `canvas` 上」那一层深度；再垫一块 `card` 的板，同色的组落在同色的板上就看不见了，只剩一条条发丝线漂着。R0（标题 + 页面按钮）照旧，骨架不变——变的只是 R1 的那块面由页面自己的 `canvas` 盖住。**只有这一类**：别的落地页的详情一律有板。（「网络」曾经是一张图、照常在板上；09-28 起它也是设置页，地图只在机器总览，`MoreFrame bleed` 撤了。）

**工作区是 B 装在 R1 里**（D8）：工作区打开后，板内部分成三栏——导航（文件树）· 编辑（B：文件标签）· 检视（它的会话）。每一栏自己有一条头，和 R0 同一个 `pane-head`（38，2026-09-29 跟着收：三栏的头彼此对齐，里面的搜索框、＋、文件标签都是 28，放得下，代码多出 10 px）；栏与栏之间用发丝线分，**不用底色分**。

**打开的工作区的 R0**（2026-09-28，负责人定的样子；2026-09-30 负责人改：「上方标题，下方完整目录；标题旁边是 git branch 加改动简介」，同日又撤了「改动简介」：「还是不写多少个文件已修改这样的 git 注释吧」）：

```
R0 │ work  ⎇ main                                        [VS Code]  [▥ 会话] │
   │ peer:/home/peer/work                                                    │
   ├──────────────────────────┬──────────────────────────────┬──────────────┤
   │ [🔍 搜索文件      ] [＋] │ notes.md  one.rs  ×          │ 会话    [＋] │
```

- **标题两行，都在 R0 的 38 里**（macOS 的标题 + 副标题；行距各收一档，18 + 14，见上「第一行是 38」）。这不是 R0 和 R1 之间的一行。**第一行是目录名，`title-sm`，旁边同一行、`callout` 配 `secondary`，是分支字形和分支名**——它修饰名字，站在名字的基线上（`PageTitleAside`）；放不下时先让它缩（分支名截断），名字最后才让。**不写改动的文件数**（2026-09-30）：「N 个文件已修改」留在列表那一行的角上，页头只说分支。**第二行只剩完整的位置**，`callout` 配 `secondary`，写法和列表那一行的副标题一样：`peer:/home/peer/work`。不是 git 仓库的目录，名字旁边什么都没有，第二行照样是位置。分支只是说，不是控件（节点没有切分支这个动词）。
- **位置太长时从中间截**：留下机器和最后一段（`peer:/home/peer/projects/…/billing-worker`），「…」紧贴最后一段、中间没有空（截多少是量出来的，不交给 `text-overflow`——它按整字丢、留下盒子，省略号和尾巴之间会空出一截），截了才在指上去、或用键盘聚焦时用提示说出整个值；能选、能拷（`data-selectable`，R0 会拖窗口，所以它带一个焦点位让 tauri 把按下交给选字）。
- **字来自页面已经问到的事实**（这个工作区自己的 `git status`），R0 不为它再问一次远端机器——A 页型每一页的第二行都守这一条（上面那张表）。
- **R0 右端是这一页的两颗按钮**（D9）：VS Code，然后最右边是会话栏开关，站在它开合的那一栏正上方。工具栏图标按钮，和机器详情 R0 那几颗一样大（`ctl-md` 方块里 24 画布的字形画成 24，热区跟 `--hit`，各配一个提示；2026-09-30 由 20 放大，负责人嫌小）。**开着是中性的灰块 `fill-strong`，不是 `rail-on-ink` 绿**——选中是灰，品牌绿只有它的三个岗位。VS Code 只在那台机器有编辑器时出现，网页端不出现，第一次按先问（对话框），打开的是一个窗口不是一栏。
- **文件树的头 = 搜索框 + ＋**，和每一条列表的头同一种构造。＋ 落下一个两项的菜单：新建文件、新建目录（和目录右键菜单同两个词，不带省略号），每一项都在树里原地长出命名框；放在哪儿照 VS Code：最后按的一行是目录，就放进这个目录；是文件，就放进这个文件所在的目录（并展开它）；按的是树下空白处、或者什么都没按过、或者按过的那一行已经不在了，放在工作区根目录。⌘N 仍是落地页的「+」（添加工作区…），不借给它。
- **中栏没打开文件时不再说名字、路径、分支**（身份只出现一次）：只有「最近打开」；一个都没有时一句「没有打开的文件」。
- **窄档**：头仍是「‹ work」加这两颗按钮（`NarrowHead`，三屏都有）；名字下面那一行只剩分支，放不下就整条不画，不截成「ma…」。

### 三种都守的规矩

- **身份只出现在一个地方**：R0 的标题（A、C）或者标签（B）。板里不许再有第二个标题。
- **每个落地页有一个总览**，在没选中（A）或没有标签（B）时显示：会话 →「待处理」+ 机器（2026-09-28 由「等你的事」改名，标准词）；机器 → 那张图；额度 → 所有账户的环；**工作区 →「最近打开」的工作区**（每行：机器头像、名字、分支、`机器:路径`、上次改动，按一下打开；这台脸还没打开过任何一个时是「最近改动」，一个工作区都没有时是空状态 +「添加工作区…」，2026-09-28）；更多 → 通用。总览用同一种页型的 R0，标题是落地页自己的名字。总览说的是事实，不是插画（`WorkspaceEmpty` 头上那一段）。
- **选择和标签（B）**：按一行 = 打开或切到它的标签；关标签**不删行**；删行**关它的标签**。列表的选中项永远等于最前面那个标签。
- **没有选择历史（A）**：详情页的 R0 左端直接是标题，不放 ‹ ›（2026-09-26）。列表永远在旁边，选过什么在列表上看得见。C 的 ‹ › 是网页自己的历史，属于地址栏。
- **一个动作只有一个家**（D9，2026-09-30 改写，负责人：「订阅页右上角不要有登记按钮，这个功能属于搜索框旁边的 ＋。类似的冗余不要出现在 app 里：机器页点 ＋ 就是邀请设备和加入网络，更多里的网络页就不要有右上方两个邀请、加入了」）。家由动作的对象决定：
  - **还没有对象的**（新会话、导入、邀请设备、加入网络、登记账户、添加工作区）→ **只在 L0 搜索框旁边的 ＋**。一个动作时 ＋ 直接做；两个以上时 ＋ 落一个菜单，宽档窄档一样（会话：新会话… 导入…；机器：邀请设备… 加入网络…）。⌘N 是菜单里的第一项。
  - **打开的那一样东西的动词** → R0 右端：机器的四颗（开会话、看文件、借网、VS Code）、工作区的两颗、安全页的「立即锁定」（它是去用这把锁，不是新建）。什么都没打开的总览——会话、机器、额度——R0 右端是空的；「…」→ 网络的 R0 右端只剩 ×。
  - **机器页的第四颗 VS Code**（2026-09-30，负责人：「机器页也加一个 VS Code 图标，打开这台机器的 VS Code，不指定目录」）：在三颗之后；打开那台机器的编辑器、不带目录（`code::open` 的 `dir` 为空）。和工作区那颗是同一个标记（`IconCode`，盒子 16、墨与 24 的字形等量）、同一个流程（`components/CodeWindow`）：只在那台机器有编辑器时出现、网页端不出现、那台机器第一次按先问（同意对话框）、再按把已开的窗口拉到前面、窗口关了按钮就灭、离开这台机器就把那边的服务端还回去。一台机器只有一个编辑器窗口（`khor-code:<机器>`）：机器页开过的窗口，在同一台机器的工作区里再按是拉到前面，不另开一个（这是已有的规矩，不是这次新加的）。
  - **一行的动作** → 那一行的右键菜单。
  - 不许两处都有，不许在板里摆一排按钮。空状态那一个按钮（`EmptyState`，「一个工作区都没有」时的「添加工作区…」）是空页面唯一的一句话配的门，不算第二个家。菜单栏的「文件 → 新建… / 导入会话…」是系统的菜单，照 macOS 的习惯每个动作都在那儿，也不算。

- **一种弹窗**（D10，2026-09-30 改写，负责人：「整个 app 所有点击的弹窗，比如新建 session，是要来一个弹窗，而不是现在这样从标题下长出来的奇怪东西——我说的弹窗类似机器页点 ＋ 后的邀请设备弹窗」）：按下去会问你事情的，一律是**居中的对话框**（`Dialog`）——遮罩压暗窗口，`popover` 面 + `float`，标题 `title-md`，右下角唯一的主按钮 `brand-strong`，左边一颗「取消」。带表单的（新会话、导入、加入网络、登记账户、选择目录）是同一种对话框，只是宽一档（32rem，两栏的表单放得下）、按在外面不关（打了一半的字不会被一次误点扔掉）；Esc 和「取消」照关。
