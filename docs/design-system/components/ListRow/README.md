# ListRow

L2 列表里的一行。有副标题就是两行、高 `row-2` 48；没有就是一行、高 `row-1` 32。左右内边距 `gap-in` 8，各部分之间 `gap-row` 12，选中块圆角 `radius-md` 8。

三个槽：**leading**（头像或字形块）· **标题 / 副标题** · **meta**（右端的时间、计数、状态词）。

## 四个角（UX-48，2026-10-07，负责人：每个列表都这样）

头像在最左；**左上**标题；**左下**最新的信息；**右上**状态；**右下**这个状态持续了多久。哪一格没有真话可说就不画——不画「—」，不留占位。时长全 app 一个格式（`words.ts` 的 `span` 梯子：`ago` / `lasted` / `lasting` / `until`，「3 分钟」，不带「前」），tabular 数字。标题旁边不再有灰字（aside）——型号、账户类型、路径都撤了，头像和左下说它们；**留下的只有两处：机器的延迟**（UX-50）**和工作区的分支**（UX-51）。

**机器行（UX-50，2026-10-08，负责人）**：延迟从左下挪到标题行，紧跟机器名，`callout` 配 `secondary`（就是标题行的 aside 那一格），旁边照旧是 UX-26 那颗延迟灯；放不下就整个不画，不裁成半个数。左下**最多三项**：CPU、内存，第三项看机器——有显卡是 GPU，没有显卡是磁盘（同日负责人改定：先是四项，又去掉磁盘，最后定为「GPU 或磁盘」）。每项是一个标签（`secondary`，词和机器页仪表的一样：`vitals-name-*`）加一个值（`ink`、tabular，`row-pct`），项与项之间是 `gap-row` 的空，**不用「·」**。窄了从尾部整项去掉：先第三项，再内存，CPU 永远留着，从不裁一个数（`DevicesList` 的 `Whole`：每次排版先全量一遍、再把放不下的藏起来，藏起来的项带 `hidden`）。磁盘是 `vitals.disk`：khor 的家所在的那个卷——默认就在用户的家目录下（`$HOME` 或 `$HOME/.khor-hosts/<主机名>`），和机器页磁盘环读的是同一个数。宽档默认列宽 340 时两种机器三项都在；实测（鼠标下的字号）有显卡的机器列宽 316 以下先去 GPU、246 以下只剩 CPU，没有显卡的 306 以下先去磁盘、240 以下只剩 CPU。~~UX-48 的 `23 ms · CPU 41% · 内存 81% · GPU 67%`~~。门：`check-face` corners a。

**离线只说够不到**（2026-10-07，负责人）：闲着的连接不是坏了——下一次打开照样拨得通——所以闲着的机器不写离线，写它上次走的那条路和那条路定下来多久了；只有上一次去够它失败了、之后再没听到它（`down_ms`），才写离线、行变灰。~~第一版 UX-48 把闲着和够不到都写离线，只靠变灰区分~~。

**工作区的 git**（UX-51，2026-10-08，负责人在实验台上定）。分支跟在名字后面，像机器名后面跟着的延迟（UX-50）：标题的 aside，`callout` 配 `secondary`，选中行上和别的字一样换成满值 `ink`；窄了**分支先从中间裁**（`MidName` 的 even：头尾各留一半），名字和右上的符号永远完整。右上照 powerlevel10k 的写法：⇣落后 ⇡领先（两个挨着，`⇣2⇡4`），`*` 储藏、`~` 冲突、`+` 已暂存、`!` 改了没暂存、`?` 未跟踪，零的不写，整段是 `data-corner-keep`。每个符号一支 git 墨：`~` 和操作的那个词 `git-conflict`（有东西做到一半）、`+` `git-added`（可以提交了）、`!` `git-modified`、`?` `git-untracked`、⇣⇡ `git-remote`、`*` `git-stash`；两个主题在底上、选中行上都 ≥ 4.5（README「git 的七支墨」）。**没有上游的分支不沉默**：⇡ 数的是没在任何远端上的提交（`HEAD --not --remotes`）；一个远端都没有的仓库不数（不然本地仓库永远挂着整段历史）。操作在 git 目录里读（`gix` 的 `state`），`git am` 没有词。变基、二分时 HEAD 是游离的，分支的位置就写 `@` 加 id。~~UX-48：分支和计数一起是右上的一段 `main ⇡861 *1 !1 ?2`，窄了先裁分支名~~。门：`check-face` corners d（`FACE_ONLY=corners`），宽窄两档、两个主题。

**leading 说「这是哪一类」有两种画法**（2026-10-02，负责人：「角标、浮现这样」）：默认**浮现**——类型标记 18 画在 32 的脸正中，墨按脸换（亮脸暗墨、暗脸亮墨），只有中心明暗混杂的脸压一层够用的罩，没有角标；「…」→ 外观 →「类型标记」选**角标**就回到右下角那枚。会话、机器、工作区、浏览四栏同一个 `FaceMark`，列只交「是谁的脸」（`SideRow.face`：机器的记录 `{ machine }`，额度的环是 `{ art }`）和「是哪一类」（`SideRow.mark`），不交标记的尺寸和墨——墨读的是脸那份记录（2026-10-02 起；之前列交的是画好的脸节点）。细节在 `Avatar`。**文件的行例外**（UX-45）：leading 只画文件类型的图标（脸的 70%），没有机器的脸，那台机器由字说。标题 `body`，选中时换成 `headline`；副标题 `callout` 配 `secondary`；meta `caption` 配 `tertiary`。

**会话行的副标题只有预览**（2026-10-02，负责人：「不要在会话列表显示来自 xxx 机器，头像已经说了」；终端行是命令本身，见上面四个角）：最近说的或屏上最后一行，没有就空着（行照旧 `row-2` 高，`SideList` 的副标题格每行都画、空着不占高）。**不写这一行来自哪台机器**——头像就是那台机器的脸，再写一遍名字是说两次；按机器名搜仍然搜得到。语料库的 `from-device` 撤了（zh.toml / en.toml 墓碑）。

## 选中是一块灰（D6，2026-09-27 改）

- 底 `fill-strong`、圆角 `radius-md`，**普通文字满值 `ink`**（副标题、右端的时间也是）；状态点和状态词保留状态色（2026-10-13，见 `StatusWord`）。窗口在前时标题加到 `headline` 的字重；不在前时回到 `body`。
- **窄档没有选中行**（2026-10-02，负责人在手机上：「窄档回到列表还显示着选中行……窄档没有这个逻辑，用户永远不会同时看到列表和另一个内容」）。选中说的是「打开在旁边的就是这一行」，窄档里列表和它打开的东西永远是前后两屏，回到列表时旁边什么也没有。每个落地页的列表都是 `SideList`，这条只在那一处（`useNarrow`）；工作区里文件树打开的那个文件同理（`FileTree`，`data-open` 照旧是事实）。宽档不变。门：`check-face` §21 a（`FACE_ONLY=phonefix`）。
- 头像（`leading`）不改墨：会话的光晕、额度的环都画在那里，选中时它和状态词一起保留状态色。
- **墓碑**：第十五轮到 2026-09-26 这里是 `brand-strong` 实心 + `on-brand` 白字。负责人嫌「太亮」，额度的环在实心绿上看不清（浅色轨道没有底可以立）。侧边栏是导航，Finder 的选中就是一块中性灰。

## 用

```jsx
<ListRow
  selected
  leading={<Avatar size={32} mark="chat" />}
  title="khor"
  subtitle="把侧边栏的搜索和窗口按钮并到一行"
  meta={<><StatusWord word="busy" /><br/>1 分钟</>}
/>
```

消费方负责：三个槽的内容、`selected`、`onClick`。行**不提供**自己的动作按钮。

## Do / Don't

- **选中行上不许用透明度分主次，也不用 `secondary` / `tertiary`。** 普通文字用满值 `ink`；状态词使用通过灰底对比度检查的状态墨。主次靠字号和字重。
- **行的动作只在右键菜单里**（第一项置顶，最后一项删除，见 `Menu`），不要在行里内嵌一排按钮——那会让行的宽度变成一个可以争的东西。
- **meta 的右缘是一条线。** 状态词是 meta 第一行的最后一个，下面是时间，两者右对齐；机器小头像站在状态词**左边**。未读标记紧跟标题名：0 不画、1 是小红点、>1 是同样大的红点加中性色数字（无底）。点与数紧靠，作为一个整体；红色面积不随数量增加。普通 agent 的未读目前只有 0/1，广播按消息累计。读屏仍读出完整未读数量（2026-10-13）。放在右边时，带小头像的行状态词往左缩了 22，一列字对不齐（2026-09-28 列表审计第 7 条，`check-face` 量右缘）。
- **内容列表的行尾不画 ›**（2026-10-07，UX-44 §4，负责人：「这个app所有的list统一，不要有右侧的">"，WeChat、telegram等app都是没有的」，又「设置页保留」）：会话、机器、工作区、额度、最近、浏览器、附栏里的行、存储的行、机器页的磁盘列表——行按下去打开它说的那样东西，不用一个箭头再说一遍。**设置的行留着 ›**（更多和它的各页、外观的行、键盘面板的「编辑这一行」）：那是「下一屏还有一组选项」。文件树的展开箭头、分组标题的箭头也留着：它们说的是展开没有，不是去别处。~~窄档上能打开一页的行行尾一个 ›（F2.1，`data-side-drill`）~~。门：`check-face` side j。
- **左滑删除**（UX-44 §3，`components/SwipeRow`）：手指下往左拖一行露出它的动作——给了 `swipe` 的行只露那一个红的动作（附栏的最近是「删除」，浏览器是「关闭」，和各自右键菜单同一个词），拖过行宽六成松手当场做；别的行露菜单里的置顶和删除，拖到头也只是露出来（F7.5：结束一个会话不能是手指多走了一点的结果）。鼠标下没有滑动，右键菜单说同一个动作。
- **选中不挪内容。** 只有选中行才画的东西（工作区行尾那个「›」），它的格子每一行都留着、空着；选中只上色，不从行里拿宽度（审计第 14 条）。
- 小头像的机器没有脸时画机器字形（`IconDevices`），不画空的灰圆——18 的空圆挨着字，读起来像图片没加载出来。
- meta 是 `tertiary`，它低于 4.5，**只放扫一眼的东西**。必须读到的（比如「等你」）用 `StatusWord`，它自己带颜色。
- 列表空白处**不拖窗口**（D3）。
- **额度行的标题以类型的标记开头**（2026-09-30）：`{标记} 名字`，标记 `kind-mark-glyph` 14，和字同一行、落在基线上再下沉 0.15em（像 SF Symbol 挨着字，居中在大写字母高度上）。这一行因此没有角标。名字双击改名，和会话行、机器行同一个 `EditableName`。
