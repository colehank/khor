# Shell

> **2026-10-02 起是一张底加灰线**（README 颜色）：下面说的「纸」「框」「左块」都已是同一张底（`canvas` = `side` = `card`），分开元素的是 `hairline` 灰线、玻璃和选中行的灰块。这一段留作来历。

六个区域拼起来的那副骨架：**L0** 第一行 · **L1** 竖栏 · **L2** 列表 · **R0** 工具栏 · **R1** 板 · 窗口本身。页面去填它，不改它。

这个组件在系统里的用处是：**骨架变一次，只在一个地方看得见变化**，而不用在二十个预览里各画一遍。真正的 app 里有它自己的那一份。

**颜色：板是纸，底是框**（2026-09-30）。R0、板四周的 8、窗口脚是框 `canvas`（中间的灰）；板和它上面的一切是纸 `card`（亮色最白、暗色最黑）；左块 `side` 站在纸和框之间（macOS 上是系统的侧边栏材质）；浮层暗色里是最亮的一层。所以第一行左右两半颜色不同：L0 是左块的底，R0 是框——这道缝就是左块这件家具的边。数在 README 颜色「三层底」。

尺寸：两条第一行都是 `pane-head` 38（2026-09-29 由 48 收紧，macOS 紧凑工具栏；指针是手指时回到 48），三颗窗口按钮、搜索框、标题、标签、页面按钮在它的一条中线上；竖栏 `rail-w` 64；列表默认 `list-w` 288，能拖到 `list-w-min` 180；板离四边 `gap-in` 8、圆角 `radius-xl` 12。

**宽度只有一个主人。** L 右缘那道缝是唯一的把手，L0 跟着它走，搜索框在溢出之前先变短（框永远是框，不变成按钮）。拖到三个宽度，量出来的四个宽度必须一致——这是一道门。

**拖动区域由外壳声明一次**，在 L0、L1、R0 上；L2 的空白不拖（D3）。组件内部永远不自己标拖动区域。

**骨架的字不能拖选，骨架上的光标是箭头，骨架上右键不出网页的菜单**（2026-09-28）。能选的只有读的面——对话、Markdown、代码、人会抄的值——用 `data-selectable` 标；手指只在正文的链接上。**键盘和菜单栏也是外壳的**：⌘1–⌘5 是竖栏的顺序，⌘W 关 R0 上最前的那枚标签（没有就不动，从不关窗口），⌘N 是 L0 的「+」，⌘, 是「…」› 通用；页面把自己的标签条和「+」借给这张表（`useTabHost` / `useNewAct`），不自己挂键。全表和规矩在《行为与门》的「选字与手」「键盘」「菜单栏」三节。

## 用

```jsx
<Shell
  head={<SideHead placeholder="搜索会话" />}
  rail={<Rail items={landings} />}
  list={rows}
  toolbar={<Toolbar variant="tabs">{tabs}</Toolbar>}
  board={<Board joined day={day}>{page}</Board>}
/>
```

## Do / Don't

- **R0 和 R1 之间什么都不许加**，只有 4 px 的「一天」是例外。
- macOS 上左块用 `sidebar` 材质（D4），半透明透出桌面；Windows、Linux、网页端用 `side` 实色（2026-09-30 起在纸与框之间：亮 `#f4f4ef`、暗 `#191917`）。这个预览画的是实色那一版。
- Windows 的窗口按钮在 **R0 右端**，L0 从搜索框开始。
- 窄档（< `narrow` 760）变成「列表一屏 ⇄ 详情一屏」，竖栏变底部栏，板铺满、不留边距和圆角。
