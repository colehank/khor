# SideHead

左块的第一行（L0），高 `pane-head` 38（2026-09-29 由 48 收紧；指针是手指时 48）。macOS 上从左到右是：三颗窗口按钮 · 搜索框 · ＋，**都在这一行的中线上**——三颗按钮的中心 y 19，和 28 高的搜索框、＋、R0 的标题与标签同一条线（`traffic.rs` 的 `PANE_HEAD` 由 `check-boot` 对着 `tokens.css`，`npm run native` 在真窗口里量）。搜索框占满中间并且**先于任何东西被压缩**。

**它的空白处拖动窗口**，而且这是外壳声明一次的事——组件自己不标拖动区域，里面的控件由 tauri 自己的规则排除。

**宽度跟着 L 走**，不自己有一份。拖 L 右缘那道缝时，L、它的底、L0 三样一起动；量出来的四个宽度必须一致，这是一道门。

**窄档的详情屏坐在这一行里**（2026-09-28）。窄档没有 R0，这一行就是屏幕的头：列表屏上它放这个列表的搜索框，详情屏上它放「‹ 名字 · 页面按钮」（`NarrowHead`，页面在哪儿写就在哪儿写，外壳决定它坐进来），搜索框不画。这一行本来就让开了三颗窗口按钮、本来就能拖窗口，所以头不自己再做一遍。不许在它下面再叠一条头。

## 用

```jsx
<SideHead placeholder="搜索会话" />
<SideHead placeholder="搜索会话" lights={false} />  {/* 非 macOS */}
```

消费方负责：占位文案、＋ 的动作、平台判断。

## Do / Don't

- Windows 的最小化/最大化/关闭在 **R0 右端**，不在这里；这里直接从搜索框开始。
- **＋ 是这个落地页上所有「还没有对象的」动作的家，也是它们唯一的家**（2026-09-30，负责人：「订阅页右上角不要有登记按钮，这个功能属于搜索框旁边的 ＋」）：一个动作时直接做（额度：登记…；工作区：添加工作区…）；两个以上时落一个菜单，宽档窄档一样（会话：新会话… 导入…；机器：邀请设备… 加入网络…）。这些动作不再在 R0、网络页、新会话对话框里出现第二次（《骨架与三种页型》「一个动作只有一个家」）。⚠️ 墓碑（2026-09-26 起）：这里写的是「＋ 只有一个动作……要选类型就让它落下一个 sheet，别做成下拉」，其余的动作于是挂在 R0 右端，宽档每个动作有两个家。
- 别在这一行加第四件东西。要加的先进《骨架与三种页型》的表。
