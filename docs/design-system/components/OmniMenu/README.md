# OmniMenu：统一候选列表

`OmniMenu` 定义候选行、头像、匹配文字、选中态、空状态及内部滚动。字段负责焦点、组合输入、过滤与提交；列表只在 khor 自己的界面显示。

## 网页阅读与操作（2026-10-22，用户裁定）

原生网页显示期间，不向其上方叠加 khor 的候选、菜单或其它内容。进入地址／机器编辑、打开菜单、标签总览或长按探索时，让网页暂时隐藏；操作结束后，重新计算当前可见 owner，再恢复同一个网页句柄。不能由旧字段的关闭回调直接显示网页，也不能为这些操作销毁、重新导航或裁剪网页。网页自身的交互不受此规则影响。

- 地址编辑明确借用网页内容区，显示一份最近访问；不再在输入框旁重复地址推荐。机器候选仍在统一候选容器中。
- 机器、路径等候选沿用 `MenuViewport` 最大高度与内部滚动，滚动候选不驱动底栏或收起键盘。
- 帮助提示与网页有交叠时不绘制；不能因鼠标悬停让网页闪隐。
- 退后台、切标签和卸载后，过期 owner、迟到的原生 attach 和字段 release 都不能唤回旧页面。
- 桌面会话侧栏的新标签页、文件和网页共用 `ContentToolbar`：左侧双图标 `GlassCapsule` 导航，中间位置框只有一层玻璃，右侧为内容操作与关闭。窄屏保留底部紧凑导航。

## 平台边界

所有前端字段使用 DOM 列表。macOS／Windows／Linux／iOS 的网页句柄仍由已有原生适配器管理，展示规则由 `BrowserPane` 和带 owner 的编辑 lease 协作。Android 当前没有内嵌网页实现，不宣称有原生网页验收。

此前 `menu_overlay.rs`、桌面／iOS 可信菜单宿主及快照协议保留为未启用的基础设施；正式字段不调用 `show_menu`。这些旧模块的协议测试通过不代表当前产品使用网页上层菜单。后续清理须一并处理各平台注册与探针，不能只删除前端快照。

## 验收

- `npm run browser-yield`：挂载生产 BrowserPane、PageField、OmniMenu，验证显式编辑、机器候选、菜单、标签探索、取消、过期 owner、迟到 attach 和工具提示的展示规则。原生 IPC 为边界替身，不代表真实合成层。
- `npm run content-toolbar`：真实 App 前端和独立节点，验证桌面各内容态的双图标导航、单层位置框、文件编辑与原底栏的窄屏行为。
- 真 App：使用独立 KHOR_HOME 与网页数据存储，验证阅读／编辑／菜单切换、输入内容及网页滚动保持、机器候选、切标签与退后台；确认网页没有重载。分别记录实际验收的平台，不用普通浏览器截图代替原生 WebView。

原生协议隔离测试及 `scripts/native-menu-probe` 仍可用于维护未启用模块，其历史验收不作为当前交互的证明。
