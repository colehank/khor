# Tab

> **宽档的现状是 UX-45（2026-10-07，照 Chrome）**，见下面「宽档的标签条」和 `guidelines/10-layout.md`「宽档的标签」。~~UX-39 §7：未选中的平分、选中的从完整名字起长（有邻居时最多半条胶囊），每枚一直显示 ×~~——负责人：「等宽先看看」。标签上没有动作（工作区条的 ↻ / ✓ 在胶囊后面），标签下不画日志线，这两条照旧。下面「再按一下前面那枚」落下「一天」的那一段已经是来历：前面那枚现在开关会话的附栏，「一天」是附栏里「最近」的第一行。

## 宽档的标签条（UX-45，2026-10-07）

负责人在实验室对过草稿（「做吧」）。会话、浏览器、工作区三条宽档的玻璃标签条一套规矩（`TabStrip`，`Tabs` 画的都是它）；手机甲板上那一枚药丸不变。

- **一样宽，前面那枚也一样**（Chrome）：每枚 `tab-w-even` 200，挤了就一起缩，最窄到 `tab-w-floor` 64（6 + 18 的脸 + 6、24 的关闭格、2、再留 8）；再挤就横着滚，前面那枚保持在视野里——从列表、⌘K 或快捷键再选一次前面那枚（它没换），也滚回视野（fix-a，`TabStrip` 的 `seek`：会话的标签每次 `open` / `focus` 加一）。前面那枚只靠亮起的玻璃（`glass-sel`）认出来，不靠宽度。宽度是写死的 `width`，不是 `basis`：每枚是一个尺寸容器（`@container/tab`），只有写死的宽度才给这一行长度。
- **缩的时候按自己的宽度让出东西**（容器查询，阈值是 `container-tab-x` 120、`container-tab-face` 96，容器查询读不了变量，所以写在 `@theme static` 里）：不在前面的那枚窄于 120 时 × 平时不画、指针下才出现，一直到最窄；窄于 96 名字也让开，只剩脸和关闭格的位子。**指针来了脸不动**（ux-q，2026-10-07）：只剩脸时，每一枚（前面那枚也是）把脸放在 × 位子左边那块的正中；不在前面的那枚 × 的位子在鼠标下一直留着（看不见），指针来了 × 出现在那里，脸不挪；手指没有悬停，不留位子。96–120 之间脸本来就在行首、不动。⚠️ 墓碑（UX-45）：只剩脸时脸在整枚的正中，指针来了 × 挤进来、脸跳回行首（量到 91.4 宽时跳 30.7）。**前面那枚在任何宽度都有 ×**（负责人：挤满时按到前面的那枚还得能关）。
- **名字放得下就不截**（`MidName`）：拿版面本身问——整名在它的盒子里溢不溢出——不拿量出来的字宽和一个取整再减 1 的宽度比（负责人的「frontier_diagno…cs.py」就是那样截出来的）。要截时从中间截，先把尾巴从 5 个字缩到 2 个，头不少于 3 个字；再不够就从末尾截（「fron…」），**从不只剩一截尾巴**（「…ue.p」什么也没说）。`even` 那种（传进来的文件）同样守头 3 个字，不够就从末尾截。10 个字以内的名字照旧交给 CSS 截。
- **没有计数**：标签条滚起来也不再出「| N」和它打开的切换器——每一枚都画出来，最窄是脸。
- **最后一枚后面一道灰线、一个 ＋**：在胶囊里、滚动区外面；滚动区和它的标签一样长（`flex-initial`），所以 ＋ 跟着最后一枚，胶囊剩下的地方空在 ＋ 后面。会话条的 ＋ 开一个新标签页（下面），浏览器的 ＋ 开一个空页、地址框拿到光标。
- **悬停的提示先说整个名字**：名字让开了，名字还在提示里。前面那枚的浮层（附栏的提示）第一行是名字，第二行是提示。
- **用指针关时整行不动**（Chrome，`TabStrip` 的 `held`）：指针按的 ×（`detail > 0`）把每一枚钉在当前宽度，后面的往左挪正好一枚，下一枚的 × 落在指针下面，空出来的地方留在最后；指针离开胶囊才松开，松开时用 `useRebalance`（`lib/travel` 的 `TRIP_MS` 240、`--ease-move`）从钉住的宽度长回平分的宽度。⌘W、标签的菜单、键盘按 × 不钉，当场重排。钉住的时候，标签数变了、标签条的尺寸变了都不把前面那枚滚回视野（滚动位置不动），真换了前面那枚才滚。**滚到最右头也一样**（ux-q）：行短了浏览器会把滚动位置往回夹，整行就在指针下往右滑；钉住时最后一枚后面留一块空（`data-tab-hold-room`，正好补上夹掉的那段），滚动位置不动，下一枚的 × 照样落在指针下，松开时这块空一起撤。
- **文件的脸就是文件类型**（负责人：「全都只有文件类型」）：工作区条的文件标签、手机文件页甲板上的药丸、附栏最近里的文件行、标签面板和切换器的行——凡是画文件的脸，都只画文件类型的图标（`FaceMark` 遇到 `file` 直接画它：标签里填满脸的盒子，行里占 70%），下面没有机器的脸，也没有角标；那一行的字已经说了在哪台机器。目录、网页、会话照旧是机器的脸加类型标记。文件树和机器页的磁盘列表本来就画自己的类型图标，不动。
- ⚠️ 墓碑（UX-25 → UX-39 §7 → UX-45）：被挤时停在 `tab-w-min` 104、后面出计数「| N」和切换器；前面那枚从完整名字起长、最多半条胶囊；每枚一直显示 ×；文件标签的脸是机器的脸加文件类型的标记。

## 新标签页（UX-45）

负责人：「+ 应该不给终端，直接新建一个标签页，这个标签页上进行选择」。

- **＋ 开一个标签页，不开对话框**：会话条的 ＋、手机标签面板的 ＋、列表 ＋ 菜单的「新会话…」（⌘N / ⌘T、菜单栏的新建跟着它），一按就在最后多一枚「新标签页」（`gui.new_tab`），在前面，脸是空白圆上一个 ＋（`newTabKind`）。它的 id 是 `new-tab:` 加一个随机串，从来不是哪一行的，所以「行没了关标签」那条规矩碰不到它；**重开 app 不恢复它**。建好了它就原地变成那个会话（`useSessionTabs.become`）；还没建就关掉，什么都不留下。
- **这一页就是新建会话的问题，自上而下一张表**（`views/NewSessionPage.tsx`，原来的 `NewSessionDialog`；`FormGrid`）：目标机器（弹出按钮）· 会话类型（一排格子 `new-tile` 76：选中的那台机器的脸戴上那一类的标记，名字在下面，选中的是 `fill-strong` 的灰块；命令行 · claude · codex · 登记过的智能体 · 留言，「类型」和「智能体」并成一个选择）· 添加…和注册表 · claude 的「对话 / 终端」· 名称和目录 · 最后一行右对齐「取消 · 创建」。不写标题——标签已经说了「新标签页」。**「创建」是品牌色的主按钮**（`primary`，2026-10-07 负责人定）：主按钮本来只在对话框里，这一页就是原来的对话框，是 README「一个品牌电压」里唯一的例外，`check-face` 第十七轮 b 只放过这一颗、tabs b 量它是这一页唯一的品牌色按钮。⚠️ 墓碑（UX-45 → 2026-10-07）：「创建」做成页面的普通按钮。格子一个 Tab 停，方向键走、走到哪选到哪（单选组的键，和分段控件一样）。
- **留言是一种类型**：页面上没有那一行字和「发送」。选留言按「创建」，标签变成那台机器的对话 `chat/<机器名>`（每台机器本来就有一条，不在节点上新建），在那条对话的输入框里写。那条对话收起过、没有新消息，节点就不列它；留言照样打开它，标签先用设备表里那台的名字和脸画，第一条消息让那一行回来。
- **取消回到问的地方**：开的时候记下落地页、它的屏（列表或详情）、「…」里开着的那一页、前面那枚标签；「取消」关掉新标签页，把这几样都放回去。前面原来什么都没有（会话落地页）就回列表。手机和宽档一样。开新标签页时也不会因为标签页上限挤掉原来在前面的那枚。
- **每一条进新建会话的路都开新标签页**，带上那条路知道的：列表 ＋ 和 ⌘N、会话条 ＋、手机标签面板 ＋、空会话页的「新会话…」什么都不带；机器页的「开会话」、「我的 khor」拨盘的「新终端」带机器；工作区那一栏的 ＋ 带机器和目录，「创建」以后回到工作区、那一栏里新的一行被选中（就地，裁定 34）；终端的「发给智能体」「在这里新开会话」带机器（设备 id，页面按名字读）、目录、交过来的那一段（页面上「附上 …」，对话把它当第一条消息；只有「取消」丢掉它，切走再回来还在）。
- ⚠️ 墓碑（UX-45）：新建会话对话框（`NewSessionDialog`，居中、压暗、「取消 · 创建」在脚下），和它里面留言的那一行字与「发送」。

> **2026-10-02 起是一张底加灰线**（README 颜色）：下面说的「纸」「框」「左块」都已是同一张底（`canvas` = `side` = `card`），分开元素的是 `hairline` 灰线、玻璃和选中行的灰块。这一段留作来历。

页型 B 的标签。`tab-w` 160 宽，被挤时到 `tab-w-min` 104 为止；上两角 `radius-md` 8，下面两角是方的——**选中的那枚是 `card`，和板接成一块**（板对应的那个角也跟着变方）。

**选中的标签和它下面的内容是一张纸**（2026-09-30，板是纸底是框）。标签条本身是框（`canvas`），未选中的标签透明地站在框上；选中的那枚是纸，板是纸，**终端也是纸**——以前终端画的是 `canvas`，负责人看到的正是「标签是板的灰，终端是底的黑」，两者不成一体（`check-palette`「终端的底 = 纸」量盒子、交给 xterm 的颜色、板、打开的标签四样一色）。脸的光晕和脸之间那道缝的颜色跟着脚下走：未选中的标签上是框的灰，选中的那枚上是纸（`app.css` `--halo-under`），否则纸色的缝落在灰框上会读成第二圈。

三个槽：16 的脸 · 名字 · `tab-close` 24 的关闭格。会话标签的脸是列表行那一套（光晕说状态、右下角标说类别，2026-09-02），**但按标签的尺寸画**：脸 16，光晕到 24，角标 `kind-mark-tab` 12 / 字形 10。整套墨——光晕和角标都算——必须在标签的盒子里；用行的 32 时光晕到 40，在 28 高的标签里顶出上沿 6（2026-09-28 列表审计第 6 条，`check-face`「列表四处错位」量）。窄档的会话页里它就是底栏上的标签本身（2026-10-02，下面「窄档：标签在脚下」），同一个尺寸。**类型标记跟着「…」→ 外观 →「类型标记」走**（2026-10-02）：默认浮现时标记画在 16 的脸正中，`kind-mark-tab` 12（四边各 2，整像素），墨按脸换、需要时压一层够用的罩（和行里同一份记录：标签的 12 正好是核心推墨时看的那一圈，脸中心直径 75%），没有角标；选角标时是上面那枚 12 / 10。12 而不是角标的 10：10 的时候终端那几笔不到一个像素，几何脸的色块从笔画里透出来。光晕两种画法一样。脸和名字之间是 `tab-gap` 12，不是 `gap-in` 8——负责人嫌 8「有些拥挤」（`check-face` 守着）。标签的高度和 L0 搜索框同高（负责人 2026-09-20「要和侧边栏搜索框的高度一致」），不单独取 34。

**签在中线上，脚接进板里**（2026-09-29，第一行收到 38）：一枚标签是 `ctl-md` 28 高的「签」（脸、名字、关闭格都在里面）落在第一行的中线上——和三颗窗口按钮、搜索框同一条线——下面是 `tab-lip` 5 的一截「脚」，把它接进板里；签上方离窗口上沿也是 5，那一条拖窗口。以前（48 那一行）标签站在行底，离上沿 20，就是负责人问的那块空白。脚也是标签的：打开它的那颗按钮伸进脚里，按在脚上照样是按标签，不是拖窗口。指针是手指时签是 `touch` 44、上下各 2，行 48。**关闭格永远不缩**，名字先截断。未选中的标签平时不显示关闭格，指过去才出现。

## 标签和行的关系

- 按一行 = 打开它的标签，或者切到已经开着的那一枚。
- **关标签不删行**；**删行关它的标签**。
- 列表的选中项**永远等于**最前面那个标签。

## 再按一下前面那枚（2026-09-29）

会话标签：**按已经在前面的那一枚，落下或收起这个会话的「一天」**（`components/DayStrip`），⏎ / Space 同理；按别的标签只是切换。它因此是一个 disclosure 按钮（`aria-expanded`，展开时 `aria-controls` 指着那一行）。双击名字仍是改名：按在名字上的单击等双击的窗口过去（300 ms）才生效，所以改名时带不会闪一下；按在脸上立刻生效。

指着前面那枚有一句提示，挂在标签下面：「点击查看近 24 小时状态」/「点击收起近 24 小时状态」，没有记录时「近 24 小时没有记录」（按了也不落）。这是 `Tooltip`「只给没有字的控件、只写一个名词」的明文例外，负责人点名要的。挂着这句提示的标签不再带系统 `title`（地址），免得一枚标签上叠两个浮层；未选中的标签照旧有 `title`，没有新提示。

标签条自己不知道落下的是什么：这是 `TabFace.again`（提示、是否展开、控制哪一行、按了做什么），只在前面那枚上读；「一天」是唯一的调用方。窄档的标签在会话页的底栏上，前面那枚同样是这个开关；那里提示挂在标签**上面**，「一天」浮在会话的**下沿**、紧挨着按它的那枚标签（`DetailPane`）。~~窄档没有标签条，详情屏头里的脸和名字是它的替身~~（2026-10-02 前）。

## 窄档：标签在脚下（2026-10-02）

负责人看了另一个手机终端：「我可能希望手机版的 session 布局大概是这样。上方完全交给内容，下方是操作与标签页」，并答：会话里不显示落地页的底栏、用「‹」回列表；标签放不下时**横着滚**，和宽档的标签条一样；对话也是同一个样子。窄档打开一个会话时，这一条标签就是会话页底栏的第一行（`components/SessionBar`）：

- ⚠️ 墓碑（ux-q，2026-10-07）：这一段是来历——`TabStrip` 的 `at="bottom"` 和平的（非玻璃）标签条已经删了，手机甲板的那一条是 `SessionBar` 自己画的（用同一个 `TabAvatar`、`MidName`）。
- **同一个 `TabStrip`**，`at="bottom"`：签、脚、宽度、压缩、滚动、计数都不变，只是**接口换了边**——内容在上面，所以选中的那枚从上面的纸**垂下来**：脚在上（`tab-lip`），下两角 `radius-md`，签照旧在这一行的中线上。行就是 `pane-head`（鼠标 38、手指 48），和顶上那条第一行同一个数。底栏和内容之间**没有线**：底的变化就是边，一条线会把选中的标签和它的会话切开。
- 行首是「‹」（钉在滚动区之前，`TabStrip` 的 `head`），行尾是计数（滚起来以后才有；⚠️ UX-45 起宽档没有计数）、过期那一句，和手指下的键盘开关（`tail`）。打开的那样东西的动词还在标签上：再按前面那枚落下「一天」、双击名字改名、× 关掉这一枚；关掉最后一枚就回列表。
- 窄档原来那个一直在的计数按钮撤了：计数现在是宽档的规矩——标签条滚起来、不再把每一枚都摆出来时才出现，按下去是切换器那一屏。⚠️ 墓碑（UX-45）：宽档也没有计数了，每一枚都画出来（上面「宽档的标签条」）。

## 手机甲板的药丸：左右滑换标签（UX-49，2026-10-08）

甲板上那枚药丸里的一条带子（`SessionBar` 的 `DeckBand`，会话页和文件页都是它）静止时只有当前那一枚：脸、名字，名字到药丸边就切掉。手指横着拖，它跟着走，拉进**一枚**邻居，再多就去标签圆钮。

- **成环**：上一枚、下一枚都绕回，两枚时两边都是另一枚；一枚时只给橡皮筋（`GIVE` 28 px，越拉越紧），松手弹回，不震、不换。
- **进来的那枚贴着它进来的那一边**：它占的是当前那枚让出来的那一段，从右边进来右对齐、从左边进来左对齐，名字比那一段长就切掉，所以拖动一开始脸就在、不管名字多长，中间没有空白。从右边进来的那枚在整枚能放下之前是脸贴着出去那枚的尾巴一起走，放下以后钉在右沿。
- **什么时候松手会换**：拖过带子宽的 `COMMIT_SHARE` 0.4，或者一甩——最近 `FLICK_MS` 80 ms 的移动 ≥ `FLICK_SPEED` 0.4 px/ms（400 pt/s，Android 翻页的下限），且离起点 ≥ `FLICK_MIN` 12 px；往回甩不换，哪怕已经过线。手指停住超过 80 ms 再抬起不算甩。
- **线在哪看得见、摸得到**：线内进来的那枚 `DIM` 0.4、出去的那枚满；过线反过来（`opacity` 120 ms 过渡）；每次过线（出去、回来）各一次 `feel("threshold")`——手机上 UIKit 轻的 impact，Mac 和浏览器什么也不做。
- **换过去**：出去的那枚滑出带子，进来的那枚在 `GLIDE_MS` 200 ms 里从它贴着的那边滑到靠左的位置，落地后才 `onFocus`；滑的时候再按一下就当场落地。**没换过去**：原路弹回（200 ms），进来的那枚的那一段收起来，它自己不往左滑。
- **每一种结束都只剩一枚停好**：抬起、`pointercancel`（系统抢走手势、来电）、`lostpointercapture`、触摸已经结束但 Pointer Events 的结束没送达、切后台或窗口失去焦点、标签列表或前面那枚在拖的时候变了（当场停好、拖作废）、`onFocus` 没生效（两帧后还是原来那枚就停回它）。触摸结束只收尾对应的那根手指，不重复换页；切后台直接取消，不在回到前台后补换。重新渲染不打断拖：带子上的位置是手势自己写的行内样式，React 不碰。带子宽度变了（旁边多出一颗圆钮）也不打断，下一次移动按新宽度画。
- 静止时两个邻居是 `display: none`，原生甲板（`lib/native-deck`）读不到它们。浏览器的原生甲板是 `UISwipeGestureRecognizer`，一扫一枚，同样成环；它没有拖动，所以没有橡皮筋、过线和滑动。
- ⚠️ 墓碑（UX-33 → UX-49）：三段、每段至少一个带子宽的轨道一起平移；拖动先平移当前名字的溢出，线内松手停在平移过的地方——负责人看到的「停在一半，旧标签半张脸在药丸外」（门量到 −46.8…−8.8）；邻居那一段左对齐，从左边进来时先过一段空白；过半才换、不成环；`pointercancel` 和抬起一样算，可能换过去。

## 药丸的状态动效（2026-10-13）

重连、上传时当前药丸的外围用 `state-busy` 缓慢呼吸；失败用 `state-failed` 亮起一次，留静态细边。状态色只画边与光晕，不作底。窄档在药丸外周，宽档当前标签的滚动区会裁边，所以向内发光。上传标记保留原图形，箭头在镂空中轻轻向上移动，底边仍显示真实进度。秒数与进度更新不重启动效。

活动结束后光晕在 `time-yield`（2 秒）内淡去，名字立即恢复；取消上传也只是活动结束，不显示成功对钩。切换标签不产生完成提示。减少动态效果时无旋转、呼吸或位移，进行中与失败改用静态边缘。

新增动效 token（两主题同值）：`pill-breathe` 2400ms、`pill-upload` 1400ms、`pill-glow-blur` 12px、`pill-glow-spread` 2px、`pill-arrow-lift` −2px。沿用现有状态墨、`ring-w`、`dur-420`、`ease-out` 和 `time-yield`。

点击行为不变：普通状态与上传中打开贴底附栏并隐藏甲板；重连与失败由 `NoticeIsland` 从原药丸的框向上与两侧长开，下沿不变、盖住圆钮。终端的键盘、键行位置与按钮全部保留。广播和 GUI 对话的输入框由独立的 `above` 槽放在甲板上方；原来的 `under` 槽仍给终端键行，宽窗口两个槽都原位渲染。


## 两层状态（2026-10-13）

头像光环描述会话的工作状态；药丸外周描述操作者与会话之间的交互状态。`TabFace.session` 与 `TabFace.interaction: SessionInteraction` 在类型中分开：`SessionFace` 只读前者，`usePillSignal` 只收后者；重连或上传失败不改会话状态。标题旁的未读点是第三个维度，来自节点的已读记录，不数药丸通知。会话忙碌时可以同时重连或上传。

- 手机来源图标旁增加小号上 chevron，与图标共用点击区域；菜单向上、图标＋文字，无第二颗玻璃钮，编辑时一起让位。

验收：`npm run session-content` 的真实鼠标排序、reload、取消、预览保持、双层选中、整颗悬停、空组侧区、单 ＋ 与分隔线；`npm run content-model` 的句柄、焦点与跨 session；节点 `tabs::tests::reorder_preserves_concurrent_rows_metadata_and_other_sessions` 的局部更新。


## 独立会话内标签（2026-10-18，负责人确认 Lab 后正式接入）

本节覆盖上文旧的「浏览入口不生成空标签」「单例浏览」规则。

- ＋ 每次创建一枚独立的「新会话标签页」，立即进入节点 `content` 集合；首次展开没有标签的 session 时创建一枚。底栏总览与桌面是同一集合，空白标签也计数。
- 新标签、文件、网页使用同一个节点 ID 和观看端句柄。空白起始标签首次选定文件／输入网址时原位填入该枚标签；已打开文件／网页后，返回来源列表再选择其他内容会新增标签，不覆盖已打开的文档。网页内部导航、地址编辑、文件重命名仍原位更新；在不同新标签内选择相同文件仍是两枚独立标签。来自终端等外部入口的同地址打开继续复用已有文档。
- 每枚标签独立保存目录范围、来源、查询、地址草稿、返回历史与滚动位置；输入焦点不持久化。旧单例浏览状态迁入一枚真实起始标签，旧文件／网页的身份不变。关闭最后一枚回到纯 session；再次展开可创建新的起始标签。
- 内外层都使用 `TabStrip`，包括头像、标题、关闭格、悬停整颗、收缩、连续关闭、键盘与拖动。内层只改变选中底色，不复制标签 DOM 或关闭按钮定位。
- 外层沿用 240ms 玻璃移动，内层采用现有 `dur-180`。只在同一集合中真正切换选中项时移动；重复当前项、＋、×、展开／收起不产生玻璃跳转。内外层只解析各自的直接子项，子标签操作不能触发父层玻璃；减少动态效果照旧直接落位。
- 新增请求带操作标识，由节点在锁内去重；一次重试复用已创建记录，连续多次 ＋ 使用不同标识。该标识不替代节点 mint 的 ID，不通过 URL 冒充路径。

验证：`npm run content-model`、`npm run session-content`、节点 `tabs::tests::blank_content_requests_are_distinct_and_retry_without_duplicates`。真机继续核对 iPhone 原生键盘／WebView、触摸滑动与各桌面合成器。

## 药丸连续预选（2026-10-19，负责人确认 Lab）

- 手机根会话、文件／网页内容与来源药丸共用 `DeckBand`。直接横滑连续跟手；原地长按 380 ms 展开药丸上方的头像选择带。横滑先成立时不转成长按。
- 预选只改变药丸或选择带，终端、编辑器与网页保持当前内容；松手停靠后只调用一次最终目标的 focus。首尾双向循环，单个标签只轻微回弹。
- 静止 400 ms 后开始自动翻选。以手指相对起点的水平偏移控制速率：药丸宽度的 24% 外启动，16% 内暂停，68% 达到上限；两方向相同。轻推至推远时，移动时间从 220 ms 平滑缩短到 160 ms，完整停靠从 900 ms 缩短到 480 ms。改变速率保留运动进度，不重启动画，不拉回标签。
- 回中、反向和松手随时响应。长按进入选择后，手指离开药丸、移到上方选择带或向下移动仍持续选择，直到松手；纵向起手仍归原底栏。输入、选字和药丸其他按钮保留自身操作；指针捕获、原生 touchend／touchcancel 只消费一次结束。失焦、后台、宽度变化、当前项／ID 列表变化与卸载撤销预选。
- 两行内容身份、头像状态、通知与网站标记沿用原绘制；上方选择带只一层玻璃，中心选中用现有 fill 与细边。减少动态效果直接完成松手停靠，选择带无入场位移动效。
- 这些时间是产品试验值，不是统一的“人类反应时”。参考 Apple 的连续操控响应原则与 Microsoft 按距离调速的 autoscroll 模式；在 iPhone 上继续验标题识别、误选与反向修正。

验证：`npm run deck-scrub`、默认前端检查；`lab/deck-scrub.html` 使用正式组件验证手势监听与身份布局。原生 iPhone 触控、键盘、WKWebView 与触感必须另验，合成输入不能代替。

2026-10-19 药丸回归修复：选择带按拥有该药丸的整条甲板宽度对齐，不按中间的可滑动区域估算。相邻项静止时不绘制，裁切层不带内边距；内部排版保持带宽，右滑从左边原地揭露，不能随裁切宽度压缩头像与标题。几何回归在 `lab/deck-scrub.html` 的「运行几何验收」中，根会话与文件／网页两种形态都检查。
