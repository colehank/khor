# Icon

一套字形，36 个，全 app 只有这一套。

两种画布，两种描边比例：竖栏的落地页字形是 24 画布、描边 **1.4**；行内标记是 16 画布、描边 **1.5**（对钩和叉是 **1.9**，因为那两个是被当作「答案」读的，不是当作图读的）。描边宽度只有除以画布才有意义，所以永远不要把 24 的字形缩到 16 去用，反过来也一样。

## 家族的两条手艺

这两条是「精致」这件事的全部内容，每个形都得过：

1. **两种密度，不是两种颜色。** 每个形有**一块**实心（`data-body`），按 `icon-body` 0.7 画，其余走线。竖栏里打开的那一项把它填到 1.0——那就是「哪一页开着」的全部信号（见 `Rail`）。
2. **重叠处用等宽遮罩切开，不许把路径断开。** 前景形的轮廓加宽到 `CUT`（24 画布 3.0，16 画布 2.6），两边各留 0.8 / 0.55 的空。这样每一道缝都一样宽，而不是靠手猜两个端点——**靠猜端点正是「粗糙」的来源**。

## 用

```jsx
<Icon name="sessions" />            {/* 24，竖栏 */}
<Icon name="search" />              {/* 16，行内 */}
<Icon name="pin" pinned />          {/* 钉住时转 45°，是两个形不是两个颜色 */}
```

消费方负责：颜色（图标取 `currentColor`，由外面的 `rail-ink` / `secondary` / `brand-ink` / `on-brand` 给）、`aria-label`（字形自己是 `aria-hidden`）。

## `keyboard`（2026-10-02；2026-10-09 换形）

第 32 个，16 画布：窄档会话页甲板上的软键盘开关（`views/TermKeys` 的 `KeyboardSwitch`，iOS 第三步 A）。开关打开（键盘升起）时不换形，按钮落一块 `fill-strong` 灰——选中是灰，不是品牌绿。

**2026-10-09 起是系统画键盘的样子**（icon-a，负责人在 keys 实验室试了几个候选：「键盘用k1和r1，但是，k1键盘上四个点不对称不协调，要么对齐的四个点，要么第二行只有三个点居中对齐」；两条路里主线挑了第二条）：空心的圆角机壳（2.75–13.25 × 4.25–11.75、角 1.6），里面上排四颗键、下排三颗居中、落在上排的缝里（键盘的错位），再下面一条空格键，从下排的第一颗跨到最后一颗。两排和空格都以中线左右对称——实验室的 K1 两排整体偏左 0.5、最后一颗又短了 0.15，就是「不协调」的来源。键是一个单位宽的圆点（比线 0.94 略粗：和线一样粗的点看起来比线细）。

**没有实心块**——和旁边的 `keyRow` 一起，是这套家族里仅有的两个只有线的字形。键就是它的密度；实心机壳上再画键是墨叠墨。原来那块实心机壳上打穿三颗键加空格的画法（`shield` 钥匙孔的做法）撤了。

**落在像素上**：占位是 `fit(1.5, 1.5, 13)`（方块的 0.88，算出来的不是扫出来的），所有坐标是整单位，手指下画成 26 时一个单位正好两个像素，每颗键是一个干净的 2 × 2。16 和 20 上只有中间一列落格，靠对称让几颗点看起来一样。和 `appearance` 一样还没进 `assets/Icons` 和远端的 `bundle.js`，下次同步时带上。

## `keyRow`（2026-10-04；2026-10-09 换形）

甲板上打开、收起终端按键行的那颗圆钮（`KeyRowSwitch`，UX-12）。**2026-10-09 起是一排三颗分开的键帽**（负责人的 R1），替掉原来那条分成三段的长条。点击按钮模式里它和键盘开关并排，两个都没有实心块，靠形状分开：一个是装着键的机壳，一个是一排键帽。

- **键帽之间留家族的那道缝**（`GAP`，0.034 × 13 = 0.44），和 `store` 的箭头离托盘那一道一样。实验室的 R1 三颗键帽间距 0.95、线 1.5，墙贴在一起，读回成一整条。
- **竖着略长、角收紧**（2.58 × 4、角 0.6）：圆角大的键帽在 20 上读成「000」——原来改画长条就是为了躲这个。
- 三颗键帽正好横跨键盘机壳的宽（2.75–13.25），所以两枚共用一个占位，并排时一样宽。

## Do / Don't

- **不要引进第二套图标。** 两套字形的描边比例不同，同屏读起来就像一段话混了两种字体。`scripts/check-icons.mjs` 会因为从外部图标包 import 而让构建变红，并报出是哪个包。
- `quota`、`code`、`eye` 三个不是自己画的——是用户交过来的文件（noun-project 的 token 图、VS Code 的标记、预览用的眼睛），原样收着。**别把它们重画成描边风格**：别人的标记不是我们能改的东西。
- `pin` 的两个状态是**两个形**：平躺是搁在表面上，立起来是钉进去。别拿颜色区分——那样按钮就不再报告自己的状态，得靠看行有没有跳到顶上，而那恰恰在行本来就在顶上时失效。
- `more`（三点）说「还有更多」，`filter`（三条带旋钮）说「怎么看这张表」。别混。
- 新画一个字形时，先问它的实心块是哪一块、它的缝该从哪儿切。两个问题答不上来，那个形还没画完。
- **类型标记画在脸上时是一种密度**（2026-10-02，负责人「浮现」）：会话、机器、工作区那枚标记默认画在机器的脸上，墨是这张脸给的那支（亮脸 `mark-ink-dark`、暗脸 `mark-ink-light`，同日负责人「按脸换墨，不够才压」），需要时脸压一层够用的罩。实心块照竖栏「打开」那一条填到 1.0（`app.css` `[data-mark-at="face"]`）——0.7 的墨会往脸色拉回去，白在白脸上只有 2.3。形不重画、不引进第二套：同一个字形，由 `FaceMark` 定尺寸（脸上 18 / 标签 12，角标里照旧 14 / 10）。缝还是缝：填满以后几块之间靠家族的等宽遮罩分开。全文在 `Avatar`「类型标记的两种画法」。
