khor 是一张点对点的设备网，它应该读起来像随 macOS 一起装进来的 app。窗口是一副固定的骨架——一张底（浅色米白、深色纯黑），列表和内容都落在它上面，元素之间用灰线分——每个页面去**填**这副骨架，而不是改它的形状。字是系统的（SF Pro / 苹方），用 macOS 的字号；控件是系统的形状（开关、带 ⌃⌄ 的弹出按钮、分段控件、普通按钮、搜索框）。唯一有嗓门的颜色是 khor 橄榄绿，只出现在 macOS 放强调色的地方。别的全是墨落在暖中性的底上。深度来自玻璃控件和「面浮在底上」，不来自装饰性的阴影。

照这份做的时候，先记住四条：

- **填骨架，不重塑骨架。** 六个区域：L0 第一行、L1 竖栏、L2 列表、R0 工具栏、R1 板、窗口本身。页面决定往里面放什么，不加一行、不去一行、不改一个高度。
- **一个品牌电压。** `brand-strong` 只出现在三处：打开的开关、焦点环、对话框里唯一的主按钮——外加一个例外：新标签页上的「创建」，它就是原来的新建会话对话框（2026-10-07）（竖栏打开的字形用它的深墨 `rail-on-ink`）。选中的列表行是一块灰，不是品牌色（2026-09-27）。六个状态词只作墨，从不作底。
- **系统的东西交给系统画。** 菜单、菜单栏、窗口按钮、滚动条、右键菜单，都不自己画。也不让网页露馅：界面的字拖不出蓝色，控件上是箭头不是手指，右键不出「重新载入」，快捷键和访达、Safari 一样（《行为与门》的「选字与手」「键盘」）。
- **一张底加灰线（2026-10-02）。** 所有东西——竖栏、列表、终端、对话、文件树、机器卡、额度环、设置组、浏览器——都落在同一张底上（`canvas` = `side` = `card`）；分开它们的是 `hairline` 的灰线、玻璃控件和选中行的灰块。只有一档阴影 `float`，给真正浮起来的东西。**唯一的例外是设置页（2026-10-04，UX-11）**：设置组是成组的卡片（iOS 26 的 inset grouped、Mac 的分组表单），卡片用 `grouped`（浅色白、深色 `#1c1c1a`）落在底上；别的页仍是一张底加灰线。

## 文字怎么写

- **说完就停。** 一行说明是一句话，不带句号也行；不写「请」「您可以」，不写惊叹号。设置行的说明写它**会发生什么**（「超过时先关最久没看的那一枚」），不写它是什么。
- **中文为主，英文只留专有名词。** khor、tmux、Opus 这些保持原样，其余一律中文。中英混排共用一套字体栈 `sans`，永远不要给混排的句子单独设一个只有拉丁字形的字体。
- **动作用动词，状态用名词。** 按钮写「删除」「生成邀请」，动作名称统一不加尾部省略号（2026-10-18，负责人），状态写「忙碌」「等你」「完成」。
- **时间说方向，单位一种写法**（WORDS-1008）。过去「2 秒前」，将来「2 小时 13 分后重置」，持续的状态裸写「4 小时」；M / H / D 只给名字和挤的标签（「5H 窗口」）。延迟「23 ms」，钱的符号在前「$9.21」。机器连不上叫「不通」。全部出 `src/words.ts`，`npm run words` 守。
- **数字全部 tabular。** 计数、体积、百分比、时间，任何一处都是等宽数字，这样上下两行对得齐。
- **不用 emoji。** 需要一个标记就用 `assets/Icons` 里的字形。

## 颜色

**橄榄绿只有三个岗位，第四个岗位是空的。**

1. **身份**——头像的渐变、应用自己的标记，用 `lq1` `lq2` `lq3`。
2. **强调**——`brand-strong` 作实心：打开的开关、焦点环、对话框里那一个主按钮。**唯一的例外是新标签页的「创建」**（2026-10-07，负责人：新建会话从对话框变成新标签页以后，「创建」照旧是品牌色的主按钮）——那一页就是原来的对话框，别的页面上的按钮仍不许用它（`check-face` 第十七轮 b 只放过这一颗）。上面的字一律 `on-brand`。选中的列表行**不在这里**：它是 `fill-strong` 的灰块（2026-09-27，负责人嫌实心绿「太亮」）。
3. **淡底**——`brand-wash` 垫在被定位到的那一行、你自己说的那一段背后，上面的字用 `brand-ink`。它和 `side` 的对比只有 1.11，所以**永远不能靠它自己被看见**，只能被注意到、不能被读。**它不是悬停，也不是选中**：指针下的那一行是中性的 `fill`，选中的那一行是 `fill-strong`，和列表的选中行一样（2026-09-28：会话总览的机器行、⌘K 结果、斜杠命令、框下补全、文件树打开的文件、导入列表勾上的行都穿过它；`check-face` 4K）。
4. ~~可按~~——没有了。`brand` 本色在亮色主题下对纯白只有 2.43，没有比白更亮的底救得了它；「主操作」这个岗位现在归 `brand-strong`，它对白是 4.88。
5. **竖栏的打开态**——`rail-on-ink` 橄榄绿的字形（亮色就是 `brand-strong` `#5d7b06`），**没有底块**，实心块从 `icon-body` 填到 1.0。打开靠**色相**说，不靠加深：`check-rail` 要打开的彩度 ≥ 0.08、未打开的是灰，打开的描边 ≥ 3.0（2026-09-27）。真正被修好的是**彩度**——上一个值只花掉了它那个亮度能给的 64% 的绿。全文在 `Rail`。

**为什么不用系统强调色。** 用户把 Mac 设成紫色，khor 里照样是橄榄绿，就像「音乐」永远是红的。这是「系统的东西交给系统」唯一一处故意的例外。

**一张底加灰线**（2026-10-02 重做定，负责人：「整个背景深色纯黑、浅色米白，元素之间用灰线分」；推翻 2026-09-30 的「板是纸，底是框」三层底）。一条规矩，两个主题都守：

- **一张底**：`canvas`（亮 `#f4f4ef` 米白、暗 `#000000` 纯黑）。`side`（左块）和 `card`（内容、终端、选中的标签）都**就是它**，名字留着只为各处能说出自己站在哪；`check-boot` 和 `check-palette` 都要求三者同值。
- **灰线分元素**：`hairline` 1 px，列表与内容之间、行与行之间、设置组里、标签条下沿。线要在底上看得出：亮 1.27、暗 1.31（`check-palette` 要 ≥ 1.2）。滚动固定标题不画下沿分割线，以正文渐隐和模糊区分。
- **玻璃控件**（右上角的圆钮、胶囊、底部导航、甲板）：`glass` 落在底上比底差 L\* 亮 6.1、暗 10.6；**选中的那一块**亮色变白、浮起（`glass-sel` 白，比玻璃亮），暗色是内容的黑透出来（比玻璃暗）——负责人 10-02 定的方向，`check-palette` 守。
- **选中的行**不在玻璃里：`fill-strong` 的灰块，比底差 L\* 亮 7.7、暗 14.5。
- **`popover` 是浮起来的东西**（对话框、菜单、搜索结果）。亮色是白，比底亮、靠 `float` 的影子浮起；**暗色比底亮一档** `#2e2e2c`（L\* 18.9）——黑影落在黑底上看不见，macOS 暗色的菜单和 sheet 也是窗口里最亮的一层。
- **唯一的局部例外**是「预览背景」（见下面「局部例外」），它只重述底的那几个 token。

`check-palette` 守这些：一张底、浮层离底、灰线看得出、玻璃和选中行离底 ≥ 4 L\*、选中玻璃的方向，并在底、浮层、玻璃、选中的玻璃上量下面每一对。旧的三层底（框离纸 ≥ 6、左块离两边各 ≥ 3）随它量的东西一起撤了。

**脸上的标记按脸换墨，不够才压，两个主题同值**（2026-10-02，负责人「浮现」，同日又定「按脸换墨，不够才压」）：类型标记默认画在机器的脸上；亮脸用暗墨 `mark-ink-dark`（暖近黑）、暗脸用亮墨 `mark-ink-light`（白），**不压罩**；只有中心明暗混杂的脸才压，只压到最差那一点够——亮墨下压黑 `mark-veil-dark`、暗墨下压白 `mark-veil-light`，黑最多 0.42。用哪支墨、压多少是每张脸自己的（`khor_core::avatar` 推出来，跟着脸走，画笔只照画）；标记不透明。脸从不读主题，压在脸上的东西也不读，所以这四个 token 在深色里不重定义——只有没有脸的空白圆用随主题的 `mark-ink-blank`。七种出厂色板 × 三种画法 × 十六台的 336 张真脸里 269 张不压罩，实测最差 3.22（`check-palette`「a mark on a face」，`Avatar`）。~~第一版是一罩一墨：每张脸压黑 0.42、标记一律白~~——负责人：「浮现这，给原始头像上了蒙板？感觉没那么好看了」。

**git 的七支墨只在 git 说话的地方**（2026-10-08 UX-51，负责人：「颜色更丰富」）。文件树的四个字母——`git-modified` 琥珀（改了）、`git-added` 绿（加了 / 已暂存）、`git-deleted` 红（删了）、`git-conflict` 玫红（冲突）——外加工作区行右上角才用的三支：`git-remote` 蓝（⇣⇡，要拉、要推的提交）、`git-untracked` 青（?，git 还不认识的文件）、`git-stash` 紫（*，储藏）。新三支和四个字母同一档亮度（OKLCH 亮 .49–.51、暗 .78），读起来是一家；每支在底上和选中行（`fill-strong`）上两个主题都 ≥ 4.5，最低是亮色选中行上的 `git-added` 4.55、`git-conflict` 4.57。它们不是六个状态词：状态词只在会话上，这七支只在文件和工作区的 git 上；蓝挨着「忙碌」的靛、暗色的青挨着「待批」的青，靠站的地方分，不靠色相分。

**三层墨，没有第四层。** `ink` 给标题和正文，`secondary` 给副标题和当前值，`tertiary` 给时间和计数这类只扫一眼的附注。长文另有 `read-ink`，比 `ink` 软一档。

**六个词只作墨。** `state-busy` `state-blocked` `state-done` `state-errored` `state-failed` `state-idle` 只出现在一个点、一个词、一圈光晕上，**永远不作行的底色**。色相决定是哪个词，亮度只决定一件事：四个要你回头的词比两个安静的词深 8 个 L\*。组内的先后是算出来的，不是设计出来的，别去「修」。

**选中行保留状态颜色**（2026-10-13，负责人）。选中仍是 `fill-strong` 灰块；标题、副标题、时间用满值 `ink`，主次靠字号和字重。状态点与状态词保留六个状态的色相，头像光环同样保留；浅色灰底上「忙碌／空闲」使用对比度足够的选中墨，详见 `StatusWord`。未读标记保持自己的红色。浮层里选中的普通文字（⌘K 结果、框下补全等）仍用 `ink`。~~2026-09-25 起状态词也统一成正文墨，2026-09-27 灰底沿用~~。

### 局部例外：预览背景

调色板只在根上换（`:root[data-theme]`），**文档预览这一处例外**（round UX-4，负责人定）：文件「…」里的「预览背景 · 跟随 / 浅色 / 深色」。渲染出来的文档可以放在它写的时候的那张底上读——深色界面里读一份浅底的文档，或者反过来——而 app 别处不变。

- **只在预览的根上**：`data-ground="light" | "dark"`。宽窗口是 `[data-file-preview]` 那一块；手机的文件页是整页（文件名药丸和底下的圆钮浮在文档上，所以它们也站在这张底上，不然就是 app 的墨落在不是 app 的底上）。比较视图、源码和编辑不受影响。
- **只重述底的那几个 token**：纸（`background` / `card`）、纸上的墨（`foreground` / `card-foreground` / `read-ink` / `muted-foreground`）、发丝线（`border`）、代码块与填充（`muted` / `fill` / `fill-strong`），加上 `color-scheme` 和代码高亮用哪一套颜色。强调色、六个词、玻璃都还是 app 的。
- **值是两套主题各自的原值，在 `tokens.css` 里照抄了一遍**——自定义属性读不到另一个主题的值。所以改任一主题的底，这里要跟着改。
- 按设备存（`khor.preview-ground`），和文件的字号一样。

## 字

字体栈永远是系统的：`sans` 是 `system-ui, -apple-system, "PingFang SC", "Microsoft YaHei", sans-serif`，`mono` 是 `"SF Mono", SFMono-Regular, Menlo, Consolas, monospace`。不打包字体文件，因为这套系统的目标就是看起来像系统自带的。

- 界面默认是 `body` **13**，跟 macOS 对齐。要跳出来的行标题用 `headline`（同字号，只加字重）。
- 副标题和设置说明用 `callout` 12 配 `secondary`；时间、计数、键帽用 `caption` 11 配 `tertiary`。
- 没有标签条的页面，R0 的标题用 `title-sm` 15；对话框标题 `title-md` 17；空状态那一句 `title-lg` 22。
- **只有长读的地方保持 16**：对话和 Markdown 用 `read`，行高 1.5（16 上 24px，主人 2026-09-27 定），配 `read-ink`，行宽不超过 `measure`。字号买到的舒适只在这里值钱。
- 不加字间距。系统字已经调好了。

## 间距、形状、材质

间距是 4 的倍数：`gap-in` 8 是一个东西内部，`gap-row` 12 是一行里各部分之间，`gap-base` 16 是段与段，`gap-group` 20 是设置组之间，`gap-pane` 24 是一个区域对自己边缘的呼吸。

圆角从小到大有名字，照着用，别写数字：`radius-xs` 4 键帽 · `radius-sm` 6 按钮和搜索框 · `radius-md` 8 行的选中块和标签页上两角 · `radius-lg` 10 设置组、对话框、菜单 · `radius-xl` 12 板。除了分隔线，没有直角。

深度只有四档，从下到上：**材质**（macOS 的 `sidebar` 半透明，只给左块）→ **框** `canvas` → **纸** `card`，不描边 → **发丝线** 1px `hairline` → **浮起** `popover` 的面加 `float`，只给菜单、搜索结果、对话框和 sheet（暗色里是那块最亮的面在浮，影子只是陪衬）。`knob` 是唯一的例外，给落在槽里的那一颗：开关的白钮、分段控件选中的那一段（`segment` 的面）。板永远不要再加一层阴影。

### 手机甲板的底部位置（2026-10-23）

横向留白 `nav-gap` 与垂直定位 `nav-bottom` 分开。iPhone / iPad 的浮动控件可使用主屏指示条安全带里较宽松的 20 pt（`dock-home-overlap`）；剩余 `dock-safe-bottom` 取安全区减 20 后的非负值，并在有指示条时保留最多 8 pt 的最低安全带；完整甲板控件底边为它再加内部 8 pt。截图机型安全区 34 pt 时是 22 pt，不写死所有设备为 22。横屏 21 pt 安全区对应 16 pt 底距。全局导航、会话、文件、工作区、网页及历史甲板用同一条完整态基线；折叠胶囊仍按原来的指示条带规则。

Android 保留完整系统导航安全区；没有底部安全区和键盘升起时，控件保留 8 pt。窄桌面窗口的导航仍为 16 pt。内容／弹层使用的 `safe-bottom` 不减小。列表末尾为实际导航高度、底距和 16 pt 呼吸留位，不再从左右边距推算。`dock-position` 与 `content-toolbar` 验证。

应用主界面是一套字形——`assets/Icons` 里那 30 个，加上 2026-09-27 补画的 `appearance`、2026-10-02 补画的 `keyboard`（窄档会话页的键盘开关）、2026-10-06 补画的 `finder`（macOS 机器的系统标记，UX-27）、2026-10-07 补画的 `upload`（文件正在传入会话时标签脸位上的那枚，item 71）、`store`（存储的收件托盘，store-c），和 2026-10-08 补画的 `sshHost`（添加机器的 SSH 主机，join-d），以及 2026-10-09 补画的 `alert`（传输没传到时药丸脸位上的「!」，`upload` 的同一个圆，NOTICE-BRIEF），共 37 个。两种画布：竖栏用 24 画布、描边 1.4；行内标记用 16 画布、描边 1.5（对钩和叉是 1.9，因为那两个是被当作「答案」读的，不是当作图读的）。

两条手艺，每个形都得过，「精致」就是这两条：**每个形有一块实心**（`data-body`，按 `icon-body` 0.7 画，其余走线——两种密度，不是两种颜色）；**重叠处用等宽遮罩切开**（前景形的轮廓加宽到 3.0 / 2.6，两边各留 0.8 / 0.55），不许把路径断开，也不许靠手猜两个端点。2026-09-25 有九个字形照这两条重画过，清单在 `components/Icon/README.md`。

**不要引进第二套图标。** 两套字形的描边比例不同，放在一屏上读起来就像一段话里混了两种字体。`scripts/check-icons.mjs` 会因为从外部图标包 import 而让构建变红。

三个不是自己画的：`IconQuota`、`IconCode`（VS Code 的标记）、`IconEye`——它们是用户交过来的文件，原样收着，不重画成描边风格。别人的标记不是我们能改的东西。

**类型标记两种画法，一处实现**（2026-10-02，负责人：「画在脸上感觉很好看……角标、浮现这样。不做对调了，就是这两种选择」）：会话、机器、工作区、浏览四栏的行，标签页上的脸，窄档详情头——凡是「机器的脸 + 这是哪一类」——都是 `FaceMark` 一个组件，「…」→ 外观 →「类型标记」选**浮现**（默认：标记画在脸正中、墨按脸换、只有需要的脸压一层够用的罩、没有角标、笑脸不画五官）或**角标**（右下角那枚，和以前一样）。字形不重画；画在脸上时实心块填满、墨是这张脸给的那支。全文在 `Avatar`「类型标记的两种画法」。

## 三种页型

右边的内容只有三种搭法，每个落地页声明自己是哪一种：**A 详情**（选一个看它：机器、额度、更多）、**B 标签**（开几个来回切：会话）、**C 文档**（这一行本身就是活页面：浏览）。三种都守同一批规矩：身份只出现一次、页面级按钮只在 R0 右端、每个落地页有一个总览、窄档一律变成「列表 ⇄ 详情」。A 页型打开一台机器、一个额度账户时，R0 左端多一枚占两行的**头像**——机器是列表那一行的头像本身（2026-10-02），账户是厂商的标记本身；32 高，R0 里不垫圆盘、不画 1 像素的圈（2026-10-01）；机器详情的板从一条事实带开始，不再放脸和名字（同日晚，负责人选的方向 A）。细节在《骨架与三种页型》。

**一个动作只有一个家**（2026-09-30，负责人：「订阅页右上角不要有登记按钮，这个功能属于搜索框旁边的 ＋。类似的冗余不要出现在 app 里」）。会让一样新东西出现的动作——新会话、导入、添加机器（2026-10-08 起邀请设备和加入网络合进它，join-d）、登记账户、添加工作区——只在 L0 搜索框旁边的 ＋（一个时直接做，几个时落菜单）；R0 右端只放**打开的那一样东西**的动词（上一段的「页面级按钮」就是这些：机器的四颗、工作区的两颗、「立即锁定」），总览的右端是空的；一行的动作在它的右键菜单。**空状态也不摆**（2026-10-01，负责人：「空状态不加添加工作区和登记」）：一句话，下面一行指路到 ＋。《骨架与三种页型》D9。

**一种弹窗**（2026-09-30，负责人：「整个 app 所有点击的弹窗，比如新建 session，是要来一个弹窗，而不是现在这样从标题下长出来的奇怪东西」）。按下去会问你事情的，一律是居中的对话框，遮罩压暗窗口；带表单的只是宽一档、按在外面不关。从 R0 落下的 sheet 撤了——下文「浮起来的东西」那几处列到的 sheet，今天就是这种对话框。《骨架与三种页型》D10，`Dialog`。**新会话不再是弹窗**（UX-45，2026-10-07，负责人：「+ 应该不给终端，直接新建一个标签页，这个标签页上进行选择」）：＋ 开一枚新标签页，问题就在它的页面上（`Tab`「新标签页」）；页面上的「创建」仍是品牌色的主按钮——它是主按钮离开对话框的唯一一处（2026-10-07，负责人定；⚠️ 墓碑：UX-45 当天把它做成普通按钮）。

## 可选终端配色与桌面窗口材质（2026-10-14）

- 默认仍是「跟随 khor」与实色窗口，统一背景不变。2026-10-19 起，跟随模式的 ANSI 16 色分别采用现有 Catppuccin Latte / Mocha 色表，16–255 保持标准色表。
- 设置 → 终端的配色只作用于 xterm；背景、文字、光标、选区、ANSI 16 色及 16–255 扩展色来自同一个 Palette 数据对象。app 的品牌、状态、头像不读它。预设、DIY 与 JSON 导入共用验证和解析路径；程序输出的真彩色与显式背景色值保留；窗口透明时，程序背景与默认背景遵循同一不透明度，按区域各画一次，文字和选区不随底褪色。
- 配色按观看设备保存，独立设置窗口、当前/保留终端与结束快照同步；修改不会重建 PTY、会话或滚动缓冲。DIY 预览是无主机的真实 xterm，保存前不改正在运行的终端；取消放弃草稿。
- 设置 → 外观的窗口只在原生桌面出现，实色 / 半透明 / 毛玻璃，背景不透明度 0%–100%。文字、头像、状态提示不使用整窗 opacity。主窗口只有一张背景面，终端以自己的配色替换该区域，避免透明底重复合成；设置窗口、菜单、对话框保持厚底。
- 原始底保存在 `canvas-solid`；可选透明时 `background` / `side` / `card` 让出这张背景面，普通实色主题的值不变。macOS 将原生模糊与调色分开、接口不可用时采用系统材质；Windows 采用可用的系统材质；Linux 提供合成器透明背景、不提供 Tauri 尚不支持的毛玻璃选项。网页和手机不显示窗口材质设置。
- 共用滚动固定标题不画分割线、下沿阴影或第二张调色底。标题文字与控件保持完整，正文从标题下方自然淡出并模糊，到标题顶端完全退让，显出既有窗口背景面。实色、半透明、毛玻璃与手机共用布局，切换材质不改变首行、滚动范围或阅读位置。无模糊能力或系统减少透明效果时，由既有窗口背景面实色兜底。紧接标题的差异／表格正文在标题下沿恢复清晰，不给首行叠模糊尾部；普通段落保留自然过渡。
- 门：`npm run appearance`、`npm run boot`、`npm run native`（默认实色主题回归）；原生透明与材质用私有 home 和纯色背景窗口验收。真 app 清单：浅深主题、独立设置窗口、启动/重开、调整尺寸、持续输出和 tmux 历史滚动；用桌面实际背景观察材质与文字清晰度。


### 桌面透明窗口轮廓（2026-10-17）

设置 → 外观 → 窗口的「窗口轮廓」默认开启，`window-outline=on|off`，CLI 用 `khor config set window-outline …`。只给原生主窗口的半透明／毛玻璃模式补一条独立于背景 alpha 的细边，不改变正文、终端配色、原生装饰与缩放热区。设置窗口自身保持厚底；网页和手机不提供该设置。macOS 透明窗口继续抑制沿文字投影的原生阴影，由细边补齐外缘；Windows、Linux 同用兜底轮廓，保留系统装饰与系统阴影行为。平台圆角、最大化方角与全屏隐藏跟随原生状态。原生网页叠层、各桌面环境的系统阴影另做真机验收。

2026-10-18：轮廓与背景不透明度只在非实色模式下显示；切换实色只隐藏选项，不重置保存值。细边使用现有 `--border`；设计语义名 `hairline` 不是 CSS 变量 `--hairline`。验收必须检查实际描边宽度、样式与颜色，根节点的开关属性存在不等于画出了轮廓。

### 弹窗、底部任务弹层与菜单（2026-10-18）

按任务选容器：短确认／PIN 居中；编辑、选择与长列表在手机从底部出现；候选菜单就近展开且独占自己的滚动；文件／网页沿用会话内容底栏。所有弹窗以可见视口为边界，选择类中档打开、可主动展开到大档；初始高度与最大高度独立声明。公共入口为 `TaskOverlay purpose="edit|selection|preview"`，短确认使用 `DialogContent`。详见 [Dialog](components/Dialog/README.md#弹层的职责与边界2026-10-18)，门 `npm run dialogs`。

### 终端可读性与成对配色（2026-10-19）

- 可读性保护默认为标准（4.5），可选关（1）、轻度（3）、加强（7），按观看设备保存，与配色独立。旧配置自动取得标准值；非法值回到标准，明确关闭的值须保留。
- Catppuccin 与 Tokyo 支持随 khor 明暗选择对应上游版本；已有固定预设、DIY 与 JSON 继续是固定颜色，不自动迁移。自定义与导出取当前实际版本，文件只存颜色，不携带保护设置。
- 在线终端、保留标签、结束快照、tmux 历史层和设置预览共用 `terminalAppearance`。颜色及保护变更原位更新，不清缓冲、不改滚动、不重建 PTY、不改程序字节。独立设置窗口通过已有 storage 通知同步。
- 最低对比度在 xterm 呈现层处理。保护开启时，DIM 先保留较淡的层次，再满足完整的所选目标；关闭时恢复 xterm 原始 DIM 行为。光标根据所在格子的有效背景选取可辨认颜色，块状光标的文字另保对比；保持用户原有形状与闪烁策略。颜色查询、原始缓冲、选择文字和 PTY 字节不随保护改变。
- xterm 6／addon-webgl 0.19 的 DOM、WebGL 共享 `protectTerminal`，渲染器回退与恢复自动重接。图形字形沿用 xterm 的排除规则；中等亮度背景未必支持 7，取可达到的最大值。半透明背景还取决于窗后画面，另做实机验收；不能把设置宣称为所有像素的保证。
- 旧 RGB 背景可能继续存在。保护负责可读性，主机颜色应答与进程主题缓存另行调查，本次不改协议、agent 参数或历史字节。
- 门：`npm run terminal-colors`（旧实现缺少统一解析器时先红），`npm test`、`npm run appearance`；真 app 清单为宽窄屏、跨窗口、保留标签、结束快照与 tmux 历史。


### GUI 会话的输入与导航（2026-10-25）

负责人验收：窄屏 GUI 对话顶部为返回、模型与思考强度、独立玻璃新建按钮；会话标题留在切换预选中。输入框右侧是一颗独立的 `GlassCircle` 会话头像，与输入框外沿底边对齐，使用整行可用宽度并保留间隔。输入框放附件、文字和发送／停止；上传位置进附件菜单，模型完整 ID、权限和上下文进模型菜单。宽屏沿用顶部标签，设置使用其尾部槽位。

点击头像展开原药丸，长按使用已验收的倾斜扇形：头像右、标题左，下端向内上收，背景压暗；回到原头像松手取消，弧上回中暂停并保留预选，明确继续反拨才倒退。终端与展开药丸保持左右拨动，候选头像在上、标题在下，循环和三档节拍共用正式模型。玻璃按钮的按压缩放只改外观，手势以稳定外框判断布局，不能把按压动效当成窗口变化。

门：`npm run session-navigation`、`npm run session-navigation-ui`。独立头像右侧定位在未铺满整行时先红，玻璃按压引起松手误取消也已先复现再修复。真机检查包括键盘、中文选字、长草稿、单手回程与触感；浏览器模拟单独记录。
