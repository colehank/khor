khor 是一张点对点的设备网，它应该读起来像随 macOS 一起装进来的 app。窗口是一副固定的骨架——左边一整块（竖栏 + 列表）坐在一种材质上，右边的内容写在一张纸上、纸四周是灰色的框——每个页面去**填**这副骨架，而不是改它的形状。字是系统的（SF Pro / 苹方），用 macOS 的字号；控件是系统的形状（开关、带 ⌃⌄ 的弹出按钮、分段控件、普通按钮、搜索框）。唯一有嗓门的颜色是 khor 橄榄绿，只出现在 macOS 放强调色的地方。别的全是墨落在暖中性的底上。深度来自材质和「面浮在底上」，不来自装饰性的阴影。

照这份做的时候，先记住四条：

- **填骨架，不重塑骨架。** 六个区域：L0 第一行、L1 竖栏、L2 列表、R0 工具栏、R1 板、窗口本身。页面决定往里面放什么，不加一行、不去一行、不改一个高度。
- **一个品牌电压。** `brand-strong` 只出现在三处：打开的开关、焦点环、对话框里唯一的主按钮（竖栏打开的字形用它的深墨 `rail-on-ink`）。选中的列表行是一块灰，不是品牌色（2026-09-27）。六个状态词只作墨，从不作底。
- **系统的东西交给系统画。** 菜单、菜单栏、窗口按钮、滚动条、右键菜单，都不自己画。也不让网页露馅：界面的字拖不出蓝色，控件上是箭头不是手指，右键不出「重新载入」，快捷键和访达、Safari 一样（《行为与门》的「选字与手」「键盘」）。
- **板是纸，底是框（2026-09-30）。** 所有内容——终端、对话、文件树、机器卡、额度环、设置组、浏览器——都落在纸 `card` 上；`canvas` 只是纸四周的框。深度来自纸与框的差；只有一档阴影 `float`，给真正浮起来的东西。

## 文字怎么写

- **说完就停。** 一行说明是一句话，不带句号也行；不写「请」「您可以」，不写惊叹号。设置行的说明写它**会发生什么**（「超过时先关最久没看的那一枚」），不写它是什么。
- **中文为主，英文只留专有名词。** khor、tmux、Opus 这些保持原样，其余一律中文。中英混排共用一套字体栈 `sans`，永远不要给混排的句子单独设一个只有拉丁字形的字体。
- **动作用动词，状态用名词。** 按钮写「删除…」「生成邀请…」（带省略号表示还会再问一次），状态写「忙碌」「等你」「完成」。
- **数字全部 tabular。** 计数、体积、百分比、时间，任何一处都是等宽数字，这样上下两行对得齐。
- **不用 emoji。** 需要一个标记就用 `assets/Icons` 里的字形。

## 颜色

**橄榄绿只有三个岗位，第四个岗位是空的。**

1. **身份**——头像的渐变、应用自己的标记，用 `lq1` `lq2` `lq3`。
2. **强调**——`brand-strong` 作实心：打开的开关、焦点环、对话框里那一个主按钮。上面的字一律 `on-brand`。选中的列表行**不在这里**：它是 `fill-strong` 的灰块（2026-09-27，负责人嫌实心绿「太亮」）。
3. **淡底**——`brand-wash` 垫在被定位到的那一行、你自己说的那一段背后，上面的字用 `brand-ink`。它和 `side` 的对比只有 1.11，所以**永远不能靠它自己被看见**，只能被注意到、不能被读。**它不是悬停，也不是选中**：指针下的那一行是中性的 `fill`，选中的那一行是 `fill-strong`，和列表的选中行一样（2026-09-28：会话总览的机器行、⌘K 结果、斜杠命令、框下补全、文件树打开的文件、导入列表勾上的行都穿过它；`check-face` 4K）。
4. ~~可按~~——没有了。`brand` 本色在亮色主题下对纯白只有 2.43，没有比白更亮的底救得了它；「主操作」这个岗位现在归 `brand-strong`，它对白是 4.88。
5. **竖栏的打开态**——`rail-on-ink` 橄榄绿的字形（亮色就是 `brand-strong` `#5d7b06`），**没有底块**，实心块从 `icon-body` 填到 1.0。打开靠**色相**说，不靠加深：`check-rail` 要打开的彩度 ≥ 0.08、未打开的是灰，打开的描边 ≥ 3.0（2026-09-27）。真正被修好的是**彩度**——上一个值只花掉了它那个亮度能给的 64% 的绿。全文在 `Rail`。

**为什么不用系统强调色。** 用户把 Mac 设成紫色，khor 里照样是橄榄绿，就像「音乐」永远是红的。这是「系统的东西交给系统」唯一一处故意的例外。

**三层底：板是纸，底是框**（2026-09-30 改写。负责人：「用灰色背景，黑色内容怎么样」，又「大改，浅色也类似的去做。这是抽象的更改，要作用到整个 app 上」）。一条规矩，两个主题都守：

- **`card` 是纸**，这个主题里最极端的那一档——亮色纯白 `#ffffff`、暗色最黑 `#0f0f0e`。所有内容落在它上面：终端（`term-bg` 就是它，所以选中的标签和它下面的终端是一张纸）、对话、文件树、机器卡、额度环、设置组、浏览器。板里任何东西都不画 `canvas`。
- **`canvas` 是框**，中间的灰：R0 那一行、板四周的 `gap-in` 8、窗口脚下的状态栏、设置式「…」页上组落着的那一面（那里本来就没有板，组是纸、落在框上）。亮色 `#ebebe5` 比纸深 **7.1 L\***，暗色 `#242422` 比纸亮 **9.84 L\***——都是 macOS 窗框与内容之间那一步（浅色 6.6、深色 9.5）从这张纸量过去。亮色的框不能再灰：它已经在六个词的地板上（忙碌、空闲都是 4.52）。
- **`side` 是左块**，站在纸和框之间：亮色 `#f4f4ef`（比框浅 3.2、比纸深 3.9），暗色 `#191917`（比纸亮 4.4、比框暗 5.4）。离两边各是看得出的一档，左块因此读成一整件家具；它的行是要读的，所以偏向纸那一侧。macOS 上它被侧边栏材质替换（D4）。
- **`popover` 是浮起来的东西**（对话框、sheet、菜单、搜索结果），它既落在纸上也落在框上。亮色与纸同值：在纸上靠 `float` 的影子浮起来，在框上还比框亮 7.1 L\*。**暗色是窗口里最亮的一层** `#2e2e2c`，比框高 4.74、比纸高 14.58 L\*——黑影落在黑纸上看不见，macOS 暗色的菜单和 sheet 也是最亮的一层。

这四档是在 OKLCH 里推的（色相 106.6、彩度 ≤ 0.008 的暖中性，亮色纸是纯白因为 L 1.0 上没有彩度可留），旧值和为什么在《从 tokens.css 迁移》D16。`check-palette` 守这个顺序：纸在一端、框离纸 ≥ 6 L\*、左块离两边各 ≥ 3、浮层离框 ≥ 4（暗色还要离纸 ≥ 4），并在四层上量下面每一对。

**脸上的标记有自己的一罩一墨，两个主题同值**（2026-10-02，负责人「浮现」）：类型标记默认画在机器的脸上，脸压 `mark-veil`（黑 0.42）、标记用 `mark-ink`（白）。脸从不读主题，压在脸上的东西也不读，所以这两个 token 在深色里不重定义。0.42 是界：白脸压罩后白墨 3.04，任何色板的任何脸都过图形的 3:1；七种出厂色板 × 三种画法实测最差 3.24（`check-palette`「a mark on a face」，`Avatar`）。

**三层墨，没有第四层。** `ink` 给标题和正文，`secondary` 给副标题和当前值，`tertiary` 给时间和计数这类只扫一眼的附注。长文另有 `read-ink`，比 `ink` 软一档。

**六个词只作墨。** `state-busy` `state-blocked` `state-done` `state-errored` `state-failed` `state-idle` 只出现在一个点、一个词、一圈光晕上，**永远不作行的底色**。色相决定是哪个词，亮度只决定一件事：四个要你回头的词比两个安静的词深 8 个 L\*。组内的先后是算出来的，不是设计出来的，别去「修」。

**选中的行上没有透明度，也没有第二、三层墨。** 灰块 `fill-strong` 上（亮色，落在左块上），`secondary` 只有 4.51、「忙碌」4.01。所以选中行的标题、副标题、右端时间、状态词全用满值 `ink`，主次靠字号和字重分。**浮层里选中的那一行也一样**（⌘K 结果、框下补全、斜杠命令、导入列表，2026-09-30）：暗色浮层上 `fill-strong` 托着的 `secondary` 只有 4.11。

### 可访问性例外

一处，照实记下来：`tertiary` 低于 4.5——亮色最低在框（`canvas`）上 **2.79**（`side` / `card` / `popover` 上 2.84 / 2.89 / 2.89），暗色最低在浮层 `popover` 上 **3.37**（`side` / `canvas` / `card` 上 3.67 / 3.55 / 3.67）（2026-09-30 在新的四层上重量）。这是照 macOS `tertiaryLabelColor` 的做法保留的原值，不是疏忽。约束是：**任何人必须读到的字不许用它**，它只给时间、计数、快捷键提示和分组标题。要改成合规的话，亮色提到 `rgba(26,26,20,0.615)`、暗色提到 `rgba(238,238,231,0.535)` 正好压线（暗色的最低处从旧浮层换到了新浮层，所以比以前写的 0.49 高），代价是附注会明显变重。

其余每一对都在 `side` / `canvas` / `card` / `popover` 四层上量过（2026-09-30，`check-palette` 逐一守）：

| 对子 | 亮色 | 暗色 |
|---|---|---|
| `ink` | 13.60 / 12.62 / 14.87 / 14.87 | 13.98 / 12.39 / 15.17 / 10.89 |
| `secondary` | 4.88 / **4.73** / 5.06 / 5.06 | 6.14 / 5.72 / 6.36 / **5.26** |
| `destructive` | 5.38 / **4.96** / 5.94 / 5.94 | 6.26 / 5.53 / 6.81 / **4.84** |

## 字

字体栈永远是系统的：`sans` 是 `system-ui, -apple-system, "PingFang SC", "Microsoft YaHei", sans-serif`，`mono` 是 `"SF Mono", SFMono-Regular, Menlo, Consolas, monospace`。不打包字体文件，因为这套系统的目标就是看起来像系统自带的。

- 界面默认是 `body` **13**，跟 macOS 对齐。要跳出来的行标题用 `headline`（同字号，只加字重）。
- 副标题和设置说明用 `callout` 12 配 `secondary`；时间、计数、键帽用 `caption` 11 配 `tertiary`。
- 没有标签条的页面，R0 的标题用 `title-sm` 15；对话框标题 `title-md` 17；空状态那一句 `title-lg` 22。
- **只有长读的地方保持 16**：对话和 Markdown 用 `read`，行高 1.5（16 上 24px，主人 2026-09-27 定），配 `read-ink`，行宽不超过 `measure`。字号买到的舒适只在这里值钱。
- 不加字间距。系统字已经调好了。

## 间距、形状、材质

间距是 4 的倍数：`gap-in` 8 是一个东西内部，`gap-row` 12 是一行里各部分之间，`gap-base` 16 是段与段，`gap-group` 20 是设置组之间，`gap-pane` 24 是一个区域对自己边缘的呼吸。

圆角从小到大有名字，照着用，别写数字：`radius-xs` 4 键帽 · `radius-sm` 6 按钮和搜索框 · `radius-md` 8 行的选中块和标签页上两角 · `radius-lg` 10 设置组、对话框、菜单 · `radius-xl` 12 板。除了分隔线，没有直角。

深度只有四档，从下到上：**材质**（macOS 的 `sidebar` 半透明，只给左块）→ **框** `canvas` → **纸** `card`，不描边 → **发丝线** 1px `hairline` → **浮起** `popover` 的面加 `float`，只给菜单、搜索结果、对话框和 sheet（暗色里是那块最亮的面在浮，影子只是陪衬）。`knob` 是唯一的例外，给落在槽里的那一颗：开关的白钮、分段控件选中的那一段（`segment` 的面）。板永远不要再加一层阴影。

## 图标

一套字形，没有例外——`assets/Icons` 里那 30 个，加上 2026-09-27 补画的 `appearance`，共 31 个。两种画布：竖栏用 24 画布、描边 1.4；行内标记用 16 画布、描边 1.5（对钩和叉是 1.9，因为那两个是被当作「答案」读的，不是当作图读的）。

两条手艺，每个形都得过，「精致」就是这两条：**每个形有一块实心**（`data-body`，按 `icon-body` 0.7 画，其余走线——两种密度，不是两种颜色）；**重叠处用等宽遮罩切开**（前景形的轮廓加宽到 3.0 / 2.6，两边各留 0.8 / 0.55），不许把路径断开，也不许靠手猜两个端点。2026-09-25 有九个字形照这两条重画过，清单在 `components/Icon/README.md`。

**不要引进第二套图标。** 两套字形的描边比例不同，放在一屏上读起来就像一段话里混了两种字体。`scripts/check-icons.mjs` 会因为从外部图标包 import 而让构建变红。

三个不是自己画的：`IconQuota`、`IconCode`（VS Code 的标记）、`IconEye`——它们是用户交过来的文件，原样收着，不重画成描边风格。别人的标记不是我们能改的东西。

**类型标记两种画法，一处实现**（2026-10-02，负责人：「画在脸上感觉很好看……角标、浮现这样。不做对调了，就是这两种选择」）：会话、机器、工作区、浏览四栏的行，标签页上的脸，窄档详情头——凡是「机器的脸 + 这是哪一类」——都是 `FaceMark` 一个组件，「…」→ 外观 →「类型标记」选**浮现**（默认：标记画在脸正中、脸压一层罩、没有角标、笑脸不画五官）或**角标**（右下角那枚，和以前一样）。字形不重画；画在脸上时实心块填满、墨是白。全文在 `Avatar`「类型标记的两种画法」。

## 三种页型

右边的内容只有三种搭法，每个落地页声明自己是哪一种：**A 详情**（选一个看它：机器、额度、更多）、**B 标签**（开几个来回切：会话）、**C 文档**（这一行本身就是活页面：浏览）。三种都守同一批规矩：身份只出现一次、页面级按钮只在 R0 右端、每个落地页有一个总览、窄档一律变成「列表 ⇄ 详情」。A 页型打开一台机器、一个额度账户时，R0 左端多一枚占两行的**类别头像**——系统或厂商的标记，不是那样东西的脸（2026-10-01）。细节在《骨架与三种页型》。

**一个动作只有一个家**（2026-09-30，负责人：「订阅页右上角不要有登记按钮，这个功能属于搜索框旁边的 ＋。类似的冗余不要出现在 app 里」）。会让一样新东西出现的动作——新会话、导入、邀请设备、加入网络、登记账户、添加工作区——只在 L0 搜索框旁边的 ＋（一个时直接做，几个时落菜单）；R0 右端只放**打开的那一样东西**的动词（上一段的「页面级按钮」就是这些：机器的四颗、工作区的两颗、「立即锁定」），总览的右端是空的；一行的动作在它的右键菜单。**空状态也不摆**（2026-10-01，负责人：「空状态不加添加工作区和登记」）：一句话，下面一行指路到 ＋。《骨架与三种页型》D9。

**一种弹窗**（2026-09-30，负责人：「整个 app 所有点击的弹窗，比如新建 session，是要来一个弹窗，而不是现在这样从标题下长出来的奇怪东西」）。按下去会问你事情的，一律是居中的对话框，遮罩压暗窗口；带表单的只是宽一档、按在外面不关。从 R0 落下的 sheet 撤了——下文「浮起来的东西」那几处列到的 sheet，今天就是这种对话框。《骨架与三种页型》D10，`Dialog`。
