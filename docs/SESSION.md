# Session

一切交互都是 session：shell、智能体 TUI、对话（对端是设备或智能体）、
文件传输，以及未来任何形式。像微信的会话列表——机制各异，同一张脸。

## 抽象：每个 session 回答五问

| 问题 | 字段 | 约束 |
|---|---|---|
| 你是谁 | id, kind, title | id 全网唯一、跨重连稳定；怎么造由 kind 定 |
| 你在哪 | home | 对它负责的设备：执行与应答在这儿。哪台由 kind 定：传输在发端，广播每台都替自己答 |
| 你怎么样 | state | 六词之一 + 时间戳，映射见下表 |
| 发生了什么 | events | 统一信封。走向由 kind 定：CRDT 全网复制（离线可读写），或问 home 现拿 |
| 看过没有 | unread | 全 kind 同一套已读语义 |

## 开放性：新 kind 不改协议

老端收到没见过的 kind，渲染成基本行（title + state），不崩不藏。
kind 专属细节走各自 payload，列表层永远只有五问。

## 六词映射

**待批 = 有动作被卡住，你的准许是唯一解药。** 排最顶、亮角标。
「等你看」「等你说下一句」不算——那样角标常年不为零，等于没有角标。

| | 忙碌 | 待批 | 完成 | 中断 | 失败 | 空闲 |
|---|---|---|---|---|---|---|
| shell | 前台有进程 | — | 正常退出、未看 | — | 非零退出；**活着的 shell 上一条命令失败了、未看**（见下） | 无前台进程 / 看过了 |
| 智能体 TUI | 在跑 | 等准许 | 这轮完、未看 | API 错、进程活 | 非零退出 | 正常退出 / 看过了 |
| 对话·对智能体 | 在答 | 等准许 | 答完、未看 | API 错、进程活 | 执行进程死 | 看过了 |
| 传输 | 传着 | 摘要到了，等你许可收全量 | 传完、未看 | 断了可续 | 断了不可续 | 看过了 |
| khor 频道（原广播，只看最新一条） | 命令执行中，或本机文件正在拉 | — | 新内容未看 | 本机文件拉断可续，或命令执行中断 | 命令失败 | 看过了 |

「—」= 到不了这档，情形落到哪写在这儿：shell 等输入（sudo 要密码）算忙碌
——判据只看前台有无进程，交互式程序等输入是常态，判成待批会让角标常年不为零；
断连不是中断，走离线那条轴。khor 频道的状态来自最新消息中的命令回执或
本机传输；持续终端操作的任务卡引用真实 session 状态。传输失败在收端是中断
（重试从已有字节接着拉）。

**一个频道（2026-10-13）**：原广播显示名改为 khor，身份仍为 `wide/all`。
GUI 普通文字是原样留言，附件是邀约；`/命令` 调用共享 CLI 执行器并产生同步回执，
`@` 预留智能体入口，详见 [CONSOLE.md](CONSOLE.md)。

**显式 CLI 传送语法**：`tell` / `send` 内部仍支持目标和远端文件。
`@turing` 点名设备，`@turing:~/data` 还指定接收目录；可以点多台。
`hinton:/data/x.bin` 表示别的机器上的文件。写入时解析为设备 id、路径、digest
与持有者，读取时不重新解析。GUI 不再把普通文字中的这些片段解释为传送命令。
**目标被推送**：写进广播之后，发端
立刻和每台目标同步一轮、请它接收，目标从文件的持有者那里拉（不经发端），落到点名的
目录（没有就建），谁都不用按；怎么样了写在消息上**那台自己的一格**。**发的时候目标不通
就拒绝**：那句话点名是哪台，文字也不写进去，等它上线还是发给别的机器由人决定；不存转、
不找别的持有者代收。别的机器看到的是文字和一份邀约（接收后从发端或任何持有者拉）。手机
发出的推送在后台任务下撑过锁屏的宽限期，超时就如实写「发送中断：手机已挂起」（IOS.md）。
找推给一台的消息用广播里按 `@机器` 过滤（`khor log <机器>`），机器页上没有「发给这台的」。
⚠️ 墓碑：机器自己的留言会话 `chat/<机器>`（一台一行，2026-08-23 起文件消息也在里面，
2026-10-07 起直接传、`into` 选目录）；旧的 `chat/` 文档不显示、不同步、不迁移（v1 前
不做兼容）。

**广播：属于整个 khor 的 session（2026-10-08，STORE-BRIEF 第三阶段与基础 B）**。
session 分两种范围：**机器的**（终端、智能体——home 是那台）和 **khor 的**
（广播，以后的 khor 智能体）。khor 的 session 是一份每台机器都保存、每轮都同步的
CRDT 文档（线上名字 `wide/<名字>`，存在 `~/.khor/wide/<名字>`，和机器的频道分开放），
它那一行每台机器从自己那份文档推出来，不作为报告传。广播是 `wide/all`：全网机器的群聊，
文字、文件和命令回执都有；单设备也有这一行，不用建。消息走文档，
同步一轮就一台传一台，发的那台下线也不丢；发了就立刻和
每台在线的机器同步一轮。**广播里的文件对目标是推送、对别的机器是邀约**（上面「一个频道」）：
不是目标的机器自己接收，接收以后从发端或持有者按 digest 拉到自己的接收位置；怎么样了写在消息上**每台收端自己的一格**（`fate:<设备 id>`，
只由那台写，并发不打架），所以每台都看得到每台的状态，发端数出几台收到了（3/5）。
这一行的词是**本机的座位，只看最新一条消息**（2026-10-12，p5-row）：最新一条的文件本机
在拉是忙碌，拉断了是中断（重试从已有的字节接着拉）；命令回执执行中是忙碌，
失败或中断按回执显示；没看是完成，否则空闲。更早消息的
状态留在它自己的气泡上。没接收的邀约不是待批，是一条可以拿的消息。同一份字节（同一机器、
同一组 digest）在哪条消息下落了地，别的消息也算落地。
khor 的文档有一个**文档头**（`head`），写着跑它的那台机器（`home`）；广播不写——每台都替
自己答。khor 智能体会是第一个写 home 的（docs/AGENT.md）。iroh-gossip 现在不用，留着位子。

**传输不另占一行（2026-08-23，传输并入对话批）**：文件是对话里的一条文件消息，档记在
对话行上；表里「传输」那一行留着，因为老端仍会派生它并报过来。⚠️ 墓碑：那时的对话是
`chat/<机器>`，第五阶段起是广播。

**shell 那格的「中断」有一个例外，是 2026-08-16 补的改口**：持久 session 的
**宿主死了而孩子还活着**时，那一行是**中断**。上面那格写「—」，说的是
*shell 自己*的词汇——一条命令出错就退出了，没有什么能在出错之后还活着。
而宿主是 shell 不知道的第三方：坏掉的是 khor 的管子，不是 shell。
判据不是选的，是从这一对推出来的——**中断和失败的分界是进程还在不在**
（`khor_core::State::Errored` 自己的注释：名字里不能有「停下」的意思），
而那个进程正跑着，说失败等于叫人把没丢的活重来一遍。
实现与推导写在 `crates/node/src/live.rs::face`。
**这个洞很窄**：实测杀掉宿主会关掉 pty 主端、内核给前台组发 SIGHUP，
一个普通的 `sleep 300` 和一个交互式 `zsh` 都会跟着死；只有**忽略 SIGHUP**
的孩子活得过它的宿主。

**shell 那格的「失败」也说上一条命令**（2026-10-08，负责人：「命令执行完了还显示命令行，读起来像还在跑」）：
活着的 shell 回到提示符（空闲），它上一条命令的退出码不是 0、也不是 130（自己按的 ⌃C）或 141（管道那头关了，`cmd | head`），
这一行就说**失败**，`dead` 仍是 false——进程好好的，什么都不提议重开；下一条命令一开始、或者有人看过这一行（看的水位越过那条命令结束的时刻），
就回到空闲。行的时刻是那条命令结束的时刻。这一行的第二行同时换成那条命令最后输出的一行；什么都没输出就说「<命令> 执行失败」。
不用中断：中断说的是 khor 丢了宿主而孩子还活着，这里什么都没丢。实现：`crates/node/src/live.rs::failed_command`、`commands.rs` 的 `Tail`。

## 离线不是第七个词

六词答「它怎么样」，离线答「这个信息多新」——两条轴。
够不着 home 时：显示上次的词 + 多久没联系上，灰显。
不许把「不知道」画成一个具体的词。
CRDT kind 灰一半：历史照读、还能写，送达等 home 回来——
灰的是「它在干嘛」，不是整行。

## 寿命:持久是默认,临时是选择

- **持久(默认,open)**:宿主进程持有终端,发起它的窗口关了它还在,能重连;
  远程开 session 只有它能接。宿主全内置(不期待用户装任何东西,tmux 也不行)。
  **一个例外,2026-08-26 卫星批**:在卫星上开的终端,宿主照旧内置在
  sponsor 上,但**工作的持久靠卫星自己的 tmux**(有就 `new -A`,连接断了
  下次开原地接回;没有就临时——shell 和连接同寿,行如实终结,不装持久)。
  例外的理由是寄人篱下:卫星上没有 khor,持久没处内置,借宿主机现成的
  是唯一诚实的路。行星判据不变:自己说话的机器,宿主永远全内置。
- **临时(run)**:跟着发起它的终端活,全程网里可见,退出码记档。
- **观察**:智能体在自己的终端里跑,靠钩子汇报(见 [HOOKS.md](HOOKS.md))
  ——khor 什么都不宿主。

三种同一张脸,状态都从 home 现拿。

## 形态随进程变（2026-09-30）

**一行是一个宿主，形态是宿主里现在跑着的东西。** 宿主是会话外面那层壳：
khor 自己的终端宿主（pty）、一个 tmux 会话；khor 摸不到终端的智能体（iTerm
里直接跑的 claude），宿主就是它自己的进程。宿主定这一行是谁、什么时候结束；
宿主的进程树定这一行**现在**是什么——kind 和类别跟着进程树走，不在开的那一刻
定死（用户 2026-09-30：「类别随进程状态更新，会话本身不结束」）。

| 宿主里现在 | 这一行的形态 |
|---|---|
| 一个认得的智能体 | 智能体：kind `tui`，类别是它的（claude、codex），词、预览、未读是它的 |
| 没有 | 普通终端：kind `shell`，类别 `shell`，词是终端自己的（前台有没有进程），不带未读 |

**类别与对话绑定分开**：进程树里的交互 Codex 可证明终端运行 Codex，不能证明
它当前选择哪个线程。新版 Codex 的 writer lock 只证明线程加载，也没有前端 PID。
默认 daemon 模式无法绑定时，行回退为普通 shell，保留终端入口、当前命令和目录；
不借用邻近线程的状态、消息或未读，也不显示「识别受限」。shell 的忙碌表示前台
命令仍运行，不代表智能体正在生成。旧 peer 的受限快照也在公共列表入口归一成 shell。
已经以智能体 ID 导入的 tmux 行回退后仍能重新连接原宿主；只允许当前实际为 shell
的行使用原 seat，不给已经加载的旧线程冒认另一智能体线程的终端。
用户通过「设置 → 终端 → 智能体识别」或自己配置原生 thread-id 标题后，
新启动的客户端才用标题与活写入根线程唯一匹配，并与
终端里的 Codex 进程交叉确认；不自动改用户启动参数。Claude 继续按自己的可靠
pid／session 证据关联。`khor_detect` 的表只挑读屏规则，不代替对话身份。

**暂停作业不占终端选择**：Ctrl-Z／调试器暂停的 Codex 仍是活进程，不能与同一
终端里新启动的客户端竞争标题归属。识别从同一份 OS 进程快照读取暂停状态，
只在未暂停的交互客户端中做唯一匹配；暂停客户端的旧绑定同时清除。`fg` 恢复后
下一轮重新参与匹配；若仍有多个未暂停客户端，继续拒绝猜测。不终止或自动恢复作业。
选择层与终端宿主最终聚合层使用相同的暂停过滤；未绑定的暂停作业不能把已正确识别
的前台客户端再次降回 shell。完整宿主回归覆盖暂停、恢复、歧义及旧绑定清除。

**已验证客户端的标题契约独立记录**：`.khor/codex-title-clients.json` 只保存
vendor home、TUI PID 和进程启动时间；不保存消息或固定线程归属。Codex 从自己的
运行时设置渲染标题，盘上配置不能代替当前终端读数；`/new` 会重新加载标题设置。
已验证客户端撤销／重开配置后仍须每次用当前有效标题唯一匹配活写入根线程，`/new`、`/resume` 重新选择；新 PID、
复用 PID 的新启动时间、其他 vendor home、空标题或歧义均不能继承旧线程。

**标题配置的生效时间独立记录**：改模型、状态栏等无关设置会重写 Codex 的
`config.toml`，不能据整个文件的修改时间撤销已生效的识别。khor 在本机
`.khor/codex-title-observed.json` 只记录标题设置的连续启用时间和配置目标，
重开 app 后继续使用；不保存配置内容、凭据或对话。读取到关闭、损坏、删除配置、
启用 profile 或配置链接换目标时，配置时间记录失效。首次验证仍要求客户端在
配置生效后启动；已验证过的同一客户端使用上面的运行时契约。每次都通过原生标题
唯一匹配活写入的根线程，不沿用旧线程选择。
升级时可从已有的 khor 安装记录恢复启用时间；自行配置且没有既往记录时，
首次读取仍以配置文件时间为保守依据。

**变形态不是结束**，两个方向一样：

- **tmux 里的智能体退出了**（`/exit`、崩了都算），tmux 会话还在：这一行变成
  普通终端。不落完成、不落失败、不退场；khor 开着的终端接着连，用户自己的
  tmux 一点不动。
- **普通终端里起了智能体**：这一行变成智能体，侧边栏的分类随之换；khor 开着
  的终端接着连。2026-09-30 以前反过来：tmux 那一行被收进智能体那一行，khor
  的终端桥被当成重复收掉（`reap_folded_bridges`），连接当场断，而智能体那一行
  不在列表上（第八轮：找到的不自动上列表），整行从侧边栏消失。
- **钩子只替智能体自己的那一行说话。** khor 开的终端里起了 claude，环境里的
  `KHOR_SESSION` 指的是那个终端；钩子写 claude 自己的行（它的 id 由 claude 的
  会话 id 算出，和状态文件那一路同一个），不写终端。以前写终端，claude 的
  `SessionEnd` 就把终端记成退出了——shell 明明还在提示符上。

**「已结束」只在宿主没了时说：**

- khor 的终端宿主：pty 里那个孩子退出了，按退出码落 完成 / 失败（上面六词表
  shell 那一行）；宿主死了孩子还活着是中断（同一节）。
- tmux 会话消失：它的行不再列出（tmux 行没有结局可记，`adaptor::tmux` 模块头）；
  坐过它的智能体行这时才按原规矩结束。
- 宿主就是智能体自己的进程（khor 摸不到它的终端）：进程没了就是宿主没了，
  原规矩不变。`khor run` 的临时会话也不变：它的宿主是包它的那个进程。

**一个宿主一行，谁占这一行按先后：** ① khor 在它上面开着终端的那一行（终端
宿主自己、tmux 的桥、看着它的镜头）——标签页和连接都挂在它上面；② 在列表上的
那一行（新建的、导入的）；③ 里面现在的智能体；④ 宿主自己的行（tmux 会话）。
占座的那一行穿上宿主现在的形态，同一宿主上其余的行收起。**id、标题、位置、
置顶是占座那一行自己的**，形态不带走它们；穿着智能体的形态时，未读按占座那一行
的已读水位算（看过它就清掉角标）。同一个 tmux 会话里同时跑着两个智能体，各是
各的行（两段对话），占座那一行穿最近动过的那一个。

**记住坐在哪儿。** 智能体一退出，它的状态文件就没了，进程树里也找不到它；所以
一个登记过的智能体行每次被看到坐在某个宿主里，登记目录就记一笔（`seat`），
退出之后靠这一笔找回宿主——宿主还在就收进宿主那一行（或自己占座、穿普通终端
的形态），宿主没了才结束。它在任何宿主外面被看到活着时，这一笔擦掉。没登记过
的智能体（没钩子、没打开过）没有登记目录，这一笔记在 `.khor/seats/` 里
（`SeatNote`）——只给**在列表上**的行记，别人不惦记它；连同它当时的名字、类别、
位置，因为它一走就没人说得出这些了。退出之后和登记过的一样：宿主还在，就收进
宿主那一行或自己占座、穿普通终端的形态；宿主也没了，按没登记的行原来的规矩收尾
（状态文件还新鲜就是失败，没了就不再列出）。在 khor 里打开它的终端时，照发现的
行的规矩临时立一个登记目录挂镜头，镜头走了目录跟着走，那一笔还在。

## 接入 tmux：滚轮翻 tmux 的历史（2026-10-01）

khor 打开一个 tmux 会话的终端，不是 `tmux attach` 到用户的会话上，而是在
自己的宿主（pty）里起一个**分组会话**的客户端：`tmux new-session -t <会话>`，
再 `set-option destroy-unattached on`（`Tmux::grouped_attach_argv`）。分组
会话和用户的会话共用窗口和窗格，但有自己的客户端、尺寸和**会话级选项**；
khor 的客户端一断开，分组会话就随之销毁。三条接入路（tmux 行自己、坐过它的
智能体行、tmux 里的智能体行，`LiveKind::attach_multiplexed`）都走这一条命令。

**负责人 2026-10-01 定：「滚轮翻 tmux 历史这，自动打开吧」。** tmux 的
`mouse` 默认是 off；tmux 客户端停在备用屏里，终端在备用屏里的滚轮等于按
↑ ↓（Terminal.app 也一样），落到窗格里的 claude 或 shell 上是翻输入历史，
翻不了 tmux 的画面。所以这条命令最后加了一句 `set-option -q mouse on`：

- **设在 khor 自己的分组会话上，不设在用户的会话上。** `mouse` 是会话选项，
  tmux 按**客户端所在的会话**读它；分组会话的选项是它自己的（继承全局，
  不继承被分组的那个会话）。所以只有 khor 的客户端开了鼠标：用户的会话、
  用户的其他会话、`-g` 全局都不动，不写任何配置文件。实测（私有 `-L`
  服务器）：接入后分组会话 `mouse on`，被接的会话和旁边的会话仍是 `off`，
  `show-options -g` 仍是 `off`。这比派活时设想的 `set-option -t <会话>`
  更窄：用户在别的终端里接同一个 tmux 会话，鼠标照旧是关的。
- **开了以后**：tmux 向 khor 的终端要 SGR 鼠标报告（`ESC [ ? 1006 h`），
  xterm 把滚轮当鼠标报告发过去，tmux 进复制模式往上翻；翻回底部自己退出
  （`copy-mode -e`），`q` 也退出。**复制模式是窗格的**：用户在别的终端里
  看着同一个窗口，会看到窗格也进了复制模式。
- **拖选变了。** 鼠标开着时，普通的拖动归 tmux：它在复制模式里选、松手拷进
  **tmux 自己的粘贴缓冲**（`prefix ]` 粘），**进不了 Mac 的剪贴板**——那要
  OSC 52，khor 的终端不接。要 khor 自己的选择（选中即拷进剪贴板，
  `TerminalPane`），**按住 ⌥ 拖**（Mac 以外按住 ⇧）。⌥ 拖在 Mac 上要 xterm 的
  `macOptionClickForcesSelection` 才生效，这一天起打开；代价是 ⌥ 拖不再是
  xterm 的列选择。右键也归 tmux（tmux 3 弹它自己的菜单）。没开鼠标的终端
  （khor 自己的 pty、没经 tmux 的）照旧：拖就是选。
- **断开后不设回去**：设在分组会话上，khor 一断开分组会话就销毁了，选项跟着
  没了，用户的会话本来就没被写过——没有什么要还原。即使将来改成设在用户的
  会话上，也不该设回：会话是用户的，下次接入还得再开，来回切只会让用户在
  别的终端里看到鼠标时开时关。
- **失败不挡接入**：这一句在命令链的最后，tmux 的命令链里一句失败只跳过
  它后面的（实测：放在 `destroy-unattached` 前面失败，那一句就没设上），
  放最后只可能赔掉它自己；`-q` 让没有 `mouse` 选项的 tmux（早于 2.1）不在
  状态栏上报错。这种情况接入前先问一次（`Tmux::knows_mouse`），日志里留
  `tmux-no-mouse-option` 一句。会话已经没了的话，接入本身就失败，原来的话
  （`tmux-session-gone`）不变。
- **不涉及**：khor 自己开的终端（pty 里直接是 shell / 程序）；卫星上 khor
  自己起的 `tmux new-session -A -s khor`（那是 khor 的会话，另一回事，未动）。

测试：`cargo test -p khor-node --test tmux_mouse`——私有 tmux 服务器上走一遍
真的接入（`attach_multiplexed` → 真宿主 → 真 tmux 客户端），断言分组会话
`mouse on`、被接的会话和另一个会话仍 off、全局 off，宿主流里出现 1006h，
从宿主送进一个 SGR 滚轮后窗格进了复制模式、`scroll_position` > 0。

## 动作

通用四个：open、close、seen、rename。
kind 专属（resize、send_keys、续传…）走 kind 命名空间，不进通用面。
动作从哪台设备发都行，送到 home 执行；seen 与 rename 例外——已读和名字
都是决定不是执行，走 CRDT，不经 home（NET.md 同步一节）。
rename 是覆盖不是改写：kind 派生的名（开时给的、vendor 状态文件里的）
一直在底下流，显示时才盖上去——sweep 重算多少轮都盖不回来；
清空名字就是撤销覆盖，派生名原样露出。
close 的收尾由 kind 定；广播的 close 是收起那一行、**什么都不删**（2026-08-23 改口，
传输并入对话批；下一条消息让它回来）：它是全网往来的长期账本，收下的文件已经落地归
文件系统——早先「close 删收下的文件」写于传输另占一行的年代，账本自己
成为文件的落点之后，关账本不能吃掉账本记下的东西。
**传输那一行的 close 也不删落地的文件**（2026-10-07，领队裁定，STORE-BRIEF 第一阶段）：
收下的文件落在看得见的接收位置（`~/khor-drop`，或那台机器设的位置），归人所有；
close 只清没传完的半截（`.khor/received/` 下的 partial 和 pid 标记），落地的文件和它的
收据都留着。删一个收到的文件在「更多 → 存储」或文件树里做。⚠️ 墓碑：store-a 那一版
close 连落地的文件一起删（文件还藏在对话目录里的年代的习惯）。
全网复制的历史也不随 close 消失，瘦身走清理（NET.md 同步一节）。
不删之外它有一个可见的动作（2026-08-24，chat 收起批）：**这一行从列表
收起，下一条消息越过收起点它就自己回来**——收起点是发送方时钟上的水位，
和已读同一份文档、同一条单调规则，全网一份，所以哪台收起哪台都收起、
回来也一起回来。重新打开，历史一字不少。

## 当前目录（2026-10-14）

`place` 保留会话登记时的目录，`doing.cwd` 是宿主读到的当前 shell／活动 tmux pane
目录。药丸、地点筛选、按地点分组、目录搜索和工作区里的 session 列表，统一优先用
非空的 `doing.cwd`，未知时回退到 `place`；两者都未知就不归入任何目录。
`cd` 或切换 pane 后随下一次 session 快照更新，远端也使用来源机器上报的快照。
主动导航到的工作区仍固定；“常去的地方”仍是历史建议，不因本规则改写。
