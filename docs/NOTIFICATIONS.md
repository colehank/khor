# App 内通知

入口是「更多 → 通知」。待处理和最近使用同一套列表；点击只按会话 ID 与执行机器 ID 定位。目标已离开列表时提示不可用，不猜另一个目标。读取不等于同意或处理；审批仍回到会话上下文。普通切回 App 不再按最近一分钟的系统通知猜测跳转。

宿主在已有行写锁内记录明确报告的等待输入、回复结束、执行错误；GUI 记录与当前 run 的状态一起原子写入，旧 run 不能产生新事件。屏幕猜测、忙碌变空闲、没有输出均不作为完成证据。终端长命令从现有 commands.json 读取已结束记录，默认 30 秒，沿用现有阈值；程序明确发送的 OSC 通知也可记录。异常退出与同一失败报告合并，取消不当成失败。

每个会话保留最多 24 条事件，命令仍沿既有 50 条 ledger；向客户端投影同样有界，并优先保留请求及处理记录。客户端保留 200 条通知、1024 个来源游标与偏好，优先保留待处理。离线超过宿主保留窗口的旧完成记录不保证全部补齐；已保存的记录不依赖终端历史重放。新订阅第一次读到的历史完成项作为已读基线，未处理请求仍保留。之后断线重连按事件身份去重；更新不会把已处理请求恢复成待处理。

自有会话默认启用；外部只读导入不自动订阅。支持的会话可在列表右键/长按菜单切换通知。静音保留自有记录并停止未读提醒，也应用于已有长命令系统通知。没有可信事件源的第三方会话不伪造完成记录。

记录存在本设备 WebView 的持久存储中，同源窗口通过 storage 事件更新；写入前重读最新存储。记录 ID 去重，不承诺跨进程同时写入的全局事务语义。存储不可用时仅保留当前窗口记录。没有新增网络服务、APNs 或系统通知权限请求。手机挂起期间不承诺实时提醒；恢复连接后读取有界事件尾。现有系统通知渠道保留。

本轮沿已有状态、未读及更多列表呈现，不增加常驻铃铛、状态条或轮询差分横幅。UI 参考为 `apps/gui/lab/notifications.html`，操作均为私有模拟记录。

验证：`npm run notification-inbox` 检查纯规则；`NOTIFICATION_UI_DIR=<证据目录> npm run notification-ui` 检查实际组件、宽窄布局、点击定位、跨窗口及重开。宿主运行 `cargo test -p khor-core -p khor-node --lib activity` 和当前 GUI run 所有权回归。浏览器 fixture 不代替真实 App、多机断线和手机后台验收。
