# 设计系统:出处与守门

> 数值和逐条理由**不在这里**——它们住在 `apps/gui/src/styles/tokens.css`
> 的注释里,判断写在实现旁边,改值的人才看得见。这份只写 tokens.css
> 装不下的三样:什么必须走 token、两道守门各守哪半、怎么加新档。
> 把数值抄进这里,它就是第二出处,会先过期再骗人。

## 一、什么必须走 token

字号、行高、字重、圆角、间距、像素尺寸、动效时长——组件里出现这几类的
字面量就是在 tokens.css 之外新开了一个出处。写法上:

- 字号/行高:`text-xs/sm/base/lg/hero` 或语义层 `text-title/fact/aux`,
  每档自带行高;
- 字重:`font-body/label/title`,**不用数字名**(`font-medium` 这类)——
  数字说的是「多重」,语义层说的是「这行是什么」,前者每个人手感不同,
  后者查一次表就一致;
- 读数(百分比、token 数、字节、时刻)一律加 `tabular-nums`:
  数字不齐列,扫读就得逐个对齐小数点;
- 动效时长:CSS 侧 `--time-yield`,TS 侧 `lib/tempo.ts`——同名同值,
  型式守门核对(setTimeout 读不了 custom property,这是那对双胞胎
  存在的原因,不是允许再生一对的先例);
- 触控热区:凡手指要落的控件,热区不低于 `--touch`
  (`min-h-touch`/`min-w-touch`;依据与出处在 tokens.css 注释)。
  **扩的是热区不是图形**,且按下/选中的底色要画在扩后的盒上——
  否则手指找得到的目标,眼睛没被告知过。

**它挡不住的**:选错语义档(标签穿成标题)编译照过、守门照绿——
那要靠「一个块一个 title」的版式判断,写在 tokens.css 的 ink weights
注释里,没有机器能替人读意图。

## 二、两道守门,各守半边

- `npm run type`(`scripts/check-type.mjs`,静态):源码里 token 之外的
  字号/字重/圆角字面量、数字名字重类、tempo 双胞胎漂移 → 红。
  **挡不住**:规则写了但没落到屏上(层叠被盖、字体缺重、purge 误删)。
- `npm run face`(`scripts/check-face.mjs`,渲染):真页面上量——
  token 类逐个 computed 核值,注入一行数据后列表标题必须是 title 重,
  全脸 weight 分布必须含 {400,500,600},opt-in 了 `tabular-nums` 的
  元素必须真的拿到,rail 每一项的热区在窄宽两档姿势下都不低于
  `--touch`(阈值从页面上读回,不在守门里抄第二份)。**挡不住**:没 opt-in 的读数(它只验声明了的),
  以及注入样本与 SessionRow 形状漂移——那会以「行画不出」的红出现,
  是响的那种漂移。

两道都在出生时证明过会红(静态半:首跑抓到三处存量违规;渲染半:
把 title 调回 400,两条断言当场咬住)。改守门的人要重做这一步——
拆掉不算,要造一个它声称能抓的错(见 memory: 新守门怎么证明它会红)。

## 三、加新档的路

先问三句,答不上就不加:
1. 现有档为什么装不下——「差 2px」不是理由,「这一档的语义它不是」才是;
2. 新档的语义名是什么——名字里带数字或带「大/小」的,还没想清语义;
3. 谁是第一个真实用户——没有落点的档是给未来的自己挖的坑。

答上了:值和理由写进 tokens.css(带「它挡不住什么」),tailwind v4 的
`--text-*`/`--font-weight-*` 命名空间自动生成 utility,两道守门不用改
(它们读 token 不背数值)。

## 四、浏览型外壳:什么必须走外壳

**为什么这一节在这份文档里。** 「哪个落点是浏览型」是界面判据,在
[UX.md](UX.md) 姿势一节,这里不重复一遍。这一节答的是另一个问题:一个
浏览型落点是**由什么拼出来的**——和第一节「什么必须走 token」同一个形状
(一件事只许有一处出处),所以住在同一份文档里。两个问题,两处,互不抄写。

浏览型落点今天有两个:文件(已落地)、浏览器(二期)。**各写一套就是把
同一件事写两遍,第一次改动就漂移。** 所以有一份外壳,落点是它的实例。

### 外壳拥有(`apps/gui/src/browse/`,一处实现)

- **标签模型**与它的存续:开/关/切、关掉最后一个补一个新的、
  localStorage(按 kind 分 key,`khor.browse.<kind>.tabs`)、
  读不出时退成一个新标签——`use-browse-tabs.ts`;
- **标签栏**(宽档)与**切换器**(窄档)——`TabStrip.tsx`;
- 地址栏的壳与**机器那一段**:补全、选定变 chip、去掉 chip 回到新标签页
  ——`AddressBar.tsx`。机器是每个浏览型落点都要问的同一个问题;
- **新标签页骨架**:钉住恒在顶、最近按时近、跨机器混排、去重、
  「还没答上来别画空态」——`NewTabPage.tsx` + `use-places.ts`;
- **「到不了」的呈现约定**:机器不答话时那一段换成记忆里的地址,灰显、
  标来源(`AddressBar` 里那一处 `second.failed` 分支);
- **记一笔去过**:落地成功后调 `recent_visit`,并重读自己那份记忆
  ——`BrowseLanding.tsx`。实例不碰这个账本。

### 实例必须提供(`browse/kind.ts` 的 `BrowseKind`,七项)

`kind`(recents 契约那个词,同时是标签存储的 key)、`segmentLabel`、
`pins()`、`useSecond()`(第二段的补全器)、`leafOf()`(一个地址叫什么)、
`Rest`(地址歇着时长什么样)、`Body`(内容渲染器)。
文件那份是 `views/FilesKind.tsx`。

**第二段只收成 provider,不许强行同构。** 路径和 URL 不是一个形状;
docs/KHOR.md 那句「统一的是呈现与协议,不是实现,硬统一会毁掉第一个」
在这儿一字不改地成立。外壳只拿走**两边确证一样**的部分,就是上面那份清单。

**`Rest` / `Body` 是组件,必须当元素渲染**(`<Rest …/>`,不是 `Rest({…})`)。
当函数调的话它们的 hook 会并进地址栏自己那串,而地址栏只有一半时间画歇着
那张脸——第一次打开输入框就是「这次的 hook 比上次多」,整个落点当场塌掉。
这不是推演,是这一批实测撞到的。

### 验收判据(可证伪)

**外壳的契约面可以长,外壳的实例知识不许长。**
接一个新落点 = 交一份 `BrowseKind` + 一个 `Body`;要动 `src/browse/`,
先看方向:

- **把实例知识往契约外推**(词归实例、记忆递给补全器)——**可以**,
  外壳因此更不懂「目录」「网页」,和守门守的方向同向;
- **往外壳里焊第二个实例的知识**(`if (kind === "page")`、在外壳里拼 URL、
  在外壳里 import 一个实例)——**这才是破线**,停下来谈。

守门在 `scripts/check-tabs.mjs` 第 0 节:`src/browse/` 下不许出现
`fetchLs`/`fetchDirPins`/`DirListing`/`DirRow`,也不许 `from "@/views/"`。
否定式断言配了活探针——同一个找法对着实例跑一遍,必须命中,
否则「外壳干净」和「我找错地方了」是同一个读数。

**墓碑:上一版这句写的是「`src/browse/` 零改动」,二期把它改口了。**
浏览器接壳时契约长了两项,线本身一寸没动:

1. `segmentLabel` 长成 `words`(六个词)。**上一版只把一个词放进契约,
   另外五个留在外壳里**,于是浏览器落点挂上去之后照样说「还没有钉住的目录」
   ——`data-browse-landing="page"` 是对的,底下的句子是文件的。同一条判据
   只执行了六分之一。
2. `useSecond` 多收一个 `remembered`。文件那一段问机器(`ls`),网址那一段
   没有机器可问——没人能枚举万维网——它要补的就是外壳手里已经握着的那份
   记忆;不递进去,实例只能再 fetch 一遍,破掉「一次 fetch,两个消费者」。

**它挡不住的**:参数面不够用。`BrowseKind` 是照真实需要长的,没为想象中的
第三个落点预铺——少一项就加一项,按上面那条方向判。**反过来才是要防的**:
为「以后可能要」加一个没有消费者的参数,那种参数以后谁也删不掉,因为谁也
证明不了它没人用。
