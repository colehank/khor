## 0. 一页结论

1. **你看到"只有只读对话"，有三个具体原因**，都不是"khor 只能看"：
   - 那一条 `observe/` 是**导入的厂商记录**，按设计只读（`SESSION.md`：查看身份不建可写后端会话）；
   - 会话列表里"继续"的动作**只对 Codex 开放**（`SessionsList.tsx` 的 `category === "codex"`），
     而你这台机器上那条是 **DSH**；DSH 的"在终端继续"其实**已经实现**，只是在「更多 → agent 名册」里，
     会话行里没有；
   - **Codex 的"接管为活对话"内核已经实现**（`codexagent.rs` 的 `LoadSessionRequest` /
     `thread/resume`），但**没有任何界面暴露它**。
2. **所以"遥控"缺的不是能力，是契约与入口**：同一件事散落在三个界面、只覆盖部分厂商，
   且没有一处说清"这个按钮给我什么控制权、在哪台机器上、谁在写"。
3. **第一步不该是继续做功能，而是证明一条遥控链路**：手机 ↔ 这台 Windows 上的一台
   **已在运行的 khor 对话**——发送、批准、中断、断线重连、重试不重复执行。
   这是 Astra 三轮后给出的首步，也是唯一能直接回答你"能不能遥控"的验证。
4. **工作区**采用**一个模型**：工作区 = 有名字的**作用域**，成员是 0..N 个 `(机器, 目录)`。
   现有单目录记录**增量迁移**为单成员作用域（保留置顶与移除）；目录候选**自动发现**，
   但发现只**提议位置**，命名与建作用域由人做。
5. 发现必须带**覆盖率数据**（每台机器、每个来源的完成/失败/跳过/截断），否则"没找到"和
   "没查成"分不开——这正是本仓库最老的毛病："答不了的分支不留白，变成它的邻居"。

**结论**：不是"只能看"，而是**能力分散、厂商不对称、契约缺失**。

## 2. 理念基线（来自仓库，不是本文发明）

- 一切交互都是 session，五问 + 六词（`docs/SESSION.md`）。新 kind 不改协议，老端渲染成基本行。
- **工作区是人立的**（2026-09-14）：不能从 cwd 折 git 根推。但 `place.rs`（常去的地方）
  **保留**了派生——因为它是"建议从哪开始"，不是"什么是你的工作区"。
  **派生可以提议，命名必须由人。**
- 只读的边界是**查看身份**：`SESSION.md` 说子会话标签"不显示回复输入框、审批或任务操作"，
  这是查看器的规矩，不是"厂商对话永远不可控"。可写控制要走**受支持的通道**，并说明通道。
- **遥控不是新功能**：同一 session 从任意设备操作。

## 3. 方案 A：续接契约（每一条"继续"都要能兑现）

### 3.1 一条续接路线 = 一次操作 + 一台机器 + 一组具名控制权

每个可点的"继续"必须绑定以下八项（缺一项就不许上界面）：

| 字段 | 含义 |
|---|---|
| 身份 | 会话行 id；有原生 id 时一并给出 |
| 执行机器 | 进程所在的设备 id（不是显示名） |
| 当前写者 | 谁正在写：khor 主持的会话 / 厂商守护进程 / 终端 / 未知 |
| 归属转移 | 采用本条路线时写者如何变化（取得、排队、拒绝） |
| 新身份 | 该操作产生的 id（新会话 id、被续接的原生 id） |
| 就绪条件 | 按钮可点之前必须为真的事 |
| 失败语句 | 每个具体原因对应一句人话 |
| 控制权 | 明确列出：发送、批准、中断本轮、终止进程、键盘输入 |

**成功必须有定义**：入队 / 已开始 / 已完成是三件事，界面要说清按钮承诺的是哪一个；
确认丢失（ack 不明）时的结果也要写清，且重试**不得重复执行**。
审批、中断、终止必须指明**作用于哪一轮/哪个进程**。
**归属未知时，需要独占取得的路线一律禁止**。

### 3.2 路线表（每行最终要标注：已实现 / 提议 / 已验证）

| 行 | 路线 | 控制权 | 归属 |
|---|---|---|---|
| 活的 khor 对话（`gui`） | 打开 | 发送、批准、中断、终止 | khor 拥有，单写者，多设备共享 |
| 活的终端（`shell`/`tui`） | 附着 | 键盘输入、终止 | khor 拥有 pty，单写者 |
| 观测到的 codex 线程（未运行） | 厂商 TUI 续接 `codex resume <id>` | 键盘输入 | 厂商进程，khor 提供窗口 |
| 观测到的 codex 线程（未运行） | **接管为活对话**（`thread/resume`）— *提议* | 发送、批准、中断 | khor 取得；厂商守护不得同时在跑该线程 |
| 观测到的 codex 线程（**他处运行中**） | 独占接管 **拒绝**并说明；可改用"发一条消息"（厂商队列） | 发送（排队） | 厂商守护持有 |
| 观测到的 dsh 线程 | TUI 续接 `dsh tui --resume <id>` — *能力已有，入口待统一* | 键盘输入 | 厂商进程 |
| 观测到的 dsh 线程 | 发一轮（headless turn） | 发送 | khor 的无头执行写厂商自己的库 |
| 无原生 id 的观测行 | 无；写明"仅查看记录" | 无 | — |
| 离线机器上的任何行 | 拒绝，**报连接失败**（离线机器无法提供"它此刻的原因"） | — | — |

**明确"不提供"**（相关处写明，而不是静默消失）：
附着到任意外部 Windows 终端；对 khor 不拥有的进程做批准/停止；把对话自动迁移到另一台机器。

### 3.3 "只读"的定义与呈现

- **只读 = 内容可读，且已知控制权集合为空**。重命名/置顶/复制**不算**控制权。
- 离线、检查中、凭据缺失、写者被占用，各有各的句子，**不能都表现为"按钮全灰"**。
- 六词状态**保持原样**；控制权以**具体动词**（动作集）呈现，不另造一套状态词。

### 3.4 空态（修正上一版的错误）

列表里应说「没有匹配的会话」（筛选造成）或「还没有派发过任务」（确实查过且没有）。
**导入的记录也是会话**，不得说"列表是空的"。

## 4. 方案 B：工作区 = 有名字的作用域（一个模型）

### 4.1 一个概念，增量迁移

- **工作区 = 作用域**：`name`（人写）+ 成员 0..N 个 `(device, path)`。
  单目录声明就是只有一个成员的特例。
- **不另设"集合/事业"第二层**：那会变成两个概念都叫"有名字的多成员作用域"。
- **迁移**：现有 `khor_sync::workspaces`（按 device/path 的整数状态）**增量演进**——
  先让现有条目以"单成员作用域"呈现并**保留置顶与移除语义**，再加稳定 id 与成员表，
  并写明旧版本 khor 读到新文档时的行为（忽略未知字段 ≠ 旧写者能理解作用域）。
- **作用域身份不能锚在第一个成员上**（成员可被移除），必须有自己的稳定 id。
- 成员数 **0..N**（空作用域是"构建中"的真实状态，可见）。

### 4.2 操作语义（现在就要定，不留到第三期）

| 操作 | 结果 |
|---|---|
| 重命名 | 只改名，不动成员 |
| 加成员 | 加一条 `(机器, 目录)`；同一对去重 |
| 移除成员 | **只删作用域边**：不动文件、不动会话、不删目录；这些会话仍在会话列表按地点显示 |
| 删除作用域 | 同样只删边；与"移除最后一个成员"**必须可区分**（前者删条目，后者留下空作用域） |
| 重叠 | 允许。一个会话出现在所有包含它的作用域里，按会话 id 去重 |
| 右栏 | 永远是显式查询："成员 M 所在机器上、cwd 在 M 之下的会话" |

### 4.3 发现：覆盖率是数据，不是脚注

发现只能**提议位置**。但"没找到"与"没查成"必须分开，因此发现结果要自带：

```
Discovery {
  coverage: [{ device, source: claude|codex|live|dsh, state: done|failed|skipped|pending,
               why, scanned, truncated, checked_at }],
  rows:     [{ device, raw_path, chosen_path, folded, sessions, last_ms, agents }],
  limits:   { 每厂商的扫描上限与实际截断 }
}
```

- **每个来源一条覆盖记录**，即使它返回 0 行；`done` 不等于"扫完了"。
- 摘要一行：「依据 Claude、Codex 与 khor 记录 · 按仓库归并 · 已查 2/3 台机器」；
  展开显示：未扫描 DSH、扫描上限与截断、缺失根、每台机器失败原因与重试。
- **拒绝的机器是"未查"，不是"没有"**。今天远程把任何拒绝都翻成空列表（`link.rs`），
  必须先改成"带原因的应答"，否则这条面板一定说谎。
- **位置发现不能证明某个作用域没有会话**——那是会话查询的事，两者不混用。
- 折叠过的路径要能取回原始路径；无仓库根时给出非仓库的显示名；没有历史记录的目录可手工添加。
- 发现流程**独立于"＋"弹窗**（2026-09-27：那个弹窗只留一个空输入框、不推荐路径）。

## 5. 分期与验收

### Stage 0 · Windows 前置（小、可测、无产品争议）

1. **路径身份归一化**：分隔符、大小写、`\\?\` 前缀、尾分隔符、根边界；按**执行机器**的规则比，
   而不是查看端平台。先修 `sessionInWorkspace`。
2. **绝对路径上线**：显示形态（`~/…`）不得被敲进 `cmd.exe`。
3. **厂商解析统一**：所有 spawn 走 `vendor_bin`（现在只覆盖两个 shim；Codex 装在 PATH 之外）。
4. 不假设 tmux：Windows 上没有"附着到任意已有终端"的路，khor 自己托管它续接的会话。

**验收**：`check-session-cwd` 增加 Windows 归一化用例；厂商路径解析用例。

### Stage 1 · 证明一条遥控链路（**Astra 三轮后的首步**）

**只做一条**：**手机 → 这台 Windows 上已在运行的 khor 对话**。

- 配对手机与 Windows 节点；
- 同一执行设备、同一会话；
- 发送 → 收到回复；批准；中断；
- 断线重连；重试**不重复执行**。

**为什么是这条**：它不涉及"取得外部写者"（没有归属竞争），却能直接回答"能不能遥控"。
DSH 扩展、观测线程接管、厂商铺开**全部延后**。

**验收**：一份逐步记录（含失败重试），手机与桌面同时操作时的行为，以及"确认丢失后重试"。

### Stage 2 · 声明工作区（单成员即可用）

- 工作区页入口：发现结果（带 §4.3 覆盖率）+ 多选精确成员 + 命名 + 创建；
- 单成员作用域**独立可用**；现有条目迁移并保留置顶/移除；手工添加可用。

### Stage 3 · 成员与查询

- 加/移除/重命名/删除/空作用域；右栏按成员查询；重叠；
- 会话列表**不**改成"事业优先"全局分组（那是另一种产品决定，明确不做）。

## 10. 补记（2026-11-18 晚）：本地 agent、Android、与前台 router

业主提出三点，其中两点改变方案，一点是**交付缺陷**。

### 10.1 「本地 agent 被取消」——不是取消，是构建漏了

**事实链**：

- `khor` 对话（新建会话里的 `khor`、主对话 `wide/all`）由 **Pi 运行时**回答；
- 该运行时**编译时嵌入** khor 可执行文件：`crates/node/build.rs` 读 `KHOR_AGENT_BUNDLE`，
  `khor_agent.rs` 用 `include_bytes!(env!("KHOR_AGENT_BUNDLE"))` 把它塞进二进制；
- 发布流程（`.github/workflows/release.yml`）先 `npm ci --prefix apps/agent`，再用
  **Bun 1.3.14** 跑 `node apps/agent/build.mjs <target> agent-runtime/khor-agent`，最后带
  `KHOR_AGENT_BUNDLE` 编译；
- **我这轮所有 release 构建都没有设这个变量**，也没有构建过 `apps/agent/dist/khor-agent`。
  于是二进制里没有 agent，点「创建」必然失败 —— 看起来就像"本地 agent 被取消"。

**判定**：这是**发布缺陷**，不是产品决定，也不是任何一次改动删掉的。

**已做**（本轮）：

- 取到 Bun 1.3.14（npm 包 `@oven/bun-windows-x64`），构建出
  `apps/agent/dist/khor-agent`（105.5 MB，bun-windows-x64-baseline）；
- 带 `KHOR_AGENT_BUNDLE` 重建 GUI（进行中，见 §10.5）。

**应有的硬性要求**：任何交付产物必须带 agent 运行时，并在启动日志/自检里报出 bundle 哈希；
发布检查要把它列为必过项（与 §4 的前置同级）。这条应写进 release 清单，否则下次还会漏。

### 10.2 Android：没有 app，但不需要 app

- Khor 只有 **iOS** 应用（`docs/IOS.md`），**没有 Android**，所以"手机"不能用 app 验证。
- 但节点自带**网页面**：启动日志 `khor web face: 0.0.0.0:5467`；`window_transport.rs` 记录
  "同一份前端在普通 HTTP 下工作，网页面在真实浏览器里渲染出完整会话列表"；`api.ts` 的 `call()`
  本来就有第三条通道（网页面的 `/api/`）。
- 所以远程控制的载体改为：**Android 手机浏览器（或任一台电脑的浏览器）打开网页面**。
  Stage 1 的验收对象相应改为「浏览器 ↔ Windows 节点」，不再依赖不存在的 Android 应用。

**入口已经现成**（`khor web`，`crates/commands/src/lib.rs`）：打印一条带 key 的局域网地址，
并渲染**终端二维码**（`web_qr`：每个模块自带黑白，深浅背景都能扫；两行一个字符格避免拉伸）；
关键的是它会**先探测即将打印的那个地址**（不是 loopback）——loopback 不受防火墙管，探 loopback
会给出一个手机打不开的链接。所以 Android 的路径就是三步：Windows 上跑 `khor web` → 手机扫码 →
网页面。`khor web --new` 可轮换 key。

**待验证**（决定 Stage 1 是否可行）：

1. 网页面的登录/凭据（`node lock` 与记住的 cookie）在 Windows 构建上是否可用；
2. 网页面能否**发送、批准、中断**（不只是看）；
3. 局域网内手机浏览器访问的地址与证书/端口注意事项。

若网页面只能看不能动，Stage 1 改为「LAB（另一台电脑的浏览器）↔ Windows」，并把"网页面可操作"
列为独立修复项。

### 10.3 方案 C：Khor agent 作为前台 router

这是本次新增的产品需求，也是 Khor 理念的自然延伸：**用户不需要先想清楚要开哪种会话**，
他只需要说要做的事。

**角色**：khor 主对话里的 agent 作为前台 router——理解需求 → 拆解 → 调度可用资源 → 汇总回报。

**与现有机制的关系**（全部已存在，router 是它们之上的编排，不另造一层）：

| 现有 | router 如何用 |
|---|---|
| `/命令`（共享 CLI 执行器，回执进会话） | 查状态、开会话、发消息 |
| `@机器` / `@agent` / `@工作会话` 引用 | 指定调度目标 |
| A2A task | 智能体之间的委派 |
| 每个 session 的五问 + 六词 | router 汇报进度与等待的载体 |

**原则：router 不绕过会话。**它发起的每个子任务仍然是一个 session——可看、可停、可续、
可从别的设备接管。这一条同时保证了三件事：可遥控（同一会话）、可审计（会话记录）、可中断
（六词状态里的"中断/失败"不是黑箱）。

**需要补的四件事**：

1. **可用**：产物嵌入运行时（§10.1）+ Windows 上 provider 登录（Pi 账户与模型）；
   khor 对话创建成功后，至少能回答"还没有登录/请选择账户"，而不是无声失败。
2. **可看**：资源发现——可用机器、可用 agent、可用工作区/目录。与 §4.3 的发现**共用同一份
   覆盖率数据**（不另造一份"router 视角"的资源清单）。
3. **可调度**：给 router 的工具集要有明确边界——开对话/开会话、给会话发消息、读会话状态、
   等待批准；**不提供**：越过会话直接跑命令、对 khor 不拥有的进程做批准/停止。
4. **可解释**：拆解结果以什么形式出现——建议：先给**计划**（要开几个会话、各自在哪台机器、
   哪个目录、用哪个 agent），人确认后再执行；执行中以父子会话关系呈现，而不是一段文字日志。

**分期**：

- **C1**：嵌入运行时 + `khor` 对话可用 + 未登录时给出可操作的提示（本轮已做一半）。
- **C2**：router 工具集与系统提示（资源发现、开会话、发消息、等待批准）。
- **C3**：计划与任务树（父子会话、并行、失败重试）的呈现。

**待裁决**：

1. router 用哪个供应商账户与模型？（Windows 上现在只有 Codex 可用；Pi 需要登录）
2. 自动执行还是先给计划让人确认？建议默认"先计划"，可记忆为"不需要确认"。
3. router 是否允许跨机器开会话？（建议：允许，但每次都在计划里列出目标机器）

### 10.4 对 Stage 1 的修订

| 原 | 现 |
|---|---|
| 手机（iOS app）↔ Windows | **浏览器**（Android 手机或电脑）↔ Windows 节点 |
| 只验证一条宿主对话的遥控 | 同左，且**先验证网页面能否操作**；不能则改用 LAB 的浏览器 |

首步不变：证明"发送 → 回复 → 批准 → 中断 → 断线重连 → 重试不重复执行"，只是载体换成浏览器。
