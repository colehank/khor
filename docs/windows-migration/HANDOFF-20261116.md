## 3. 环境事实（下一轮先读）

1. 会话是 **full access**，审批关闭；`dsh-delete-guard` 仍拦截提及 C: 的命令，这是有意的 C 盘边界。
2. **工作区被打 Low 完整性标签**：在其中构建的可执行文件是 Low 进程，写不了 `%LOCALAPPDATA%\Khor\runtime`。
   CLI/进程/网络/GUI 的验证一律用 `CARGO_TARGET_DIR=F:\Temp\khor-target`（工作区外构建）；库单测可在 `.cache/target`。
3. **终端输出**：已修，见 `vendor/portable-pty/KHOR.md`。改 `portable-pty` 后必须用工作区外 target 重建。
4. **ConPTY 不转发 `ESC [ ? 1 h`（DECCKM）**：`host_replay` 的该用例保持 `#[cfg(unix)]`；这是 conhost 的流翻译，不是 Khor 的解析问题。
5. **GUI 构建**：Vite 7 拒绝含 `#` 的工程根 → 用无 `#` worktree（本轮 `F:\Temp\khor-gui`，分支 `w5-gui-check`）。
   本机**没有 npm**；GUI 有 npm 提升才成立的幻影依赖（`@shikijs/langs`、`@shikijs/themes`、`hast`），
   所以 `pnpm install` 要加 `--node-linker=hoisted --shamefully-hoist`，并直接跑
   `node scripts/generate.mjs`、`node_modules/.bin/tsc.cmd --noEmit`、`node_modules/.bin/vite.cmd build`。
