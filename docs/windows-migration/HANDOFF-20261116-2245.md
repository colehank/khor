## 二、本会话解决的核心问题

### 2.1 会话列表不渲染（W5 的拦路虎）

不是列表的代码。Tauri 的 **custom-protocol IPC 在 Windows 上启动后即停摆**：每次运行只到达 9 条命令，
之后永远为空；页面同时发 38 次 `sessions`，Rust 一次没收到，两边都无报错。决定性实验：页面直接
`fetch('http://ipc.localhost/lock_state')`——不经过 invoke、不涉及命令——**40 次全部超时**。

修法：窗口内起一个 loopback HTTP 服务，页面改用 `?bridge=`，命令走本机 HTTP，分派到与 web face
完全相同的 `khor_gui_core::api::answer` 表。**只在 Windows 生效**（`cfg(target_os)`），macOS/Linux 保持原路径。

### 2.2 终端面板空白

**资源协议同样停摆**：懒加载的 `TerminalPane` chunk 永远载不进来，`Suspense fallback={null}` 让它无声地空白。
先试过把全部动态导入内联成 14 MB 单包（能修好，但 FCP 1280 ms，太慢），最终改成
**分块 + 启动期 `modulepreload` 预取**：在协议还活着的时候把所有 chunk 取回来。

### 2.3 会话不稳定（用户点名最高优先级）

Windows 上的会话宿主**从未 detach**——unix 有 `setsid()`，Windows 分支缺失。于是宿主是开启者的普通子进程：
CLI 退出、`khor serve` 停止都会带走它，会话回来即 `Failed / 宿主被结束`，**永久**不可恢复。

两处都补上 `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`：终端宿主（`host.rs`）与对话宿主（`gui_host.rs`），
并解决了与 `prepare_durable_child` 互相覆盖 creation_flags 的问题。

### 2.4 界面卡顿（用户点名第二优先级）

两个真因，都量化后修的：

| 项 | 前 | 后 |
| --- | --- | --- |
| 首屏 FCP | 1280 ms | **664–712 ms**（预热后；冷启动 2844 ms，见下） |
| 首屏 JS 堆 | 51 MB | 32 MB |
| 慢命令阻塞轮询 | 单线程，一条 6.4 s 命令冻结所有轮询 | 4 worker：`doctor` 在飞时 `sessions` 仍 174–312 ms |
| 会话轮询 | 每 2 s 无在途保护 | 有在途保护 |

### 2.5 窗口自身（用户看出来的三个）

两重标题栏（缺 `decorations(false)`）、自绘控件失效（`window_minimize` 等不在 `api::answer` 里，
改由传输层转给真实窗口）、无边框后**拖不动**（Tauri 的 `drag.js` 走的是失效的 invoke，
用 capture 阶段 shim + `window_drag` 动词修好）。

## 六、环境事实（避免重复踩坑）

- **构建**：`CARGO_TARGET_DIR=F:\Temp\khor-target`。工作区被打了 Low integrity 标签，在里面构建出的二进制
  写不了 `%LOCALAPPDATA%\Khor\runtime`，会满屏 `os error 5`。
- **前端构建**：必须在**无 `#` 的路径**（Vite 7 拒绝含 `#` 的根），实际用 `F:\Temp\khor-gui`；
  改完 `apps/gui/src` 或 `src-tauri` 要同步过去。**本机没有 npm**，只有 node + pnpm：
  `node_modules\.bin\tsc.cmd --noEmit`、`node_modules\.bin\vite.cmd build`。pnpm 装依赖要
  `--node-linker=hoisted --shamefully-hoist`。
- **打包**：`cargo-tauri`（已 `cargo install`，v2.12.4）。WiX/NSIS 的内置下载在本次网络下会
  `timeout: global`，先跑 `scripts/ensure-bundler-tools.ps1` 预置缓存。打包要
  `--config tauri.windows-build.conf.json`（跳过 `npm run build`）。
- **`cargo test -p khor-gui --lib` 在本机跑不了**：测试二进制加载失败 `0xc0000139`（cdylib 缺入口），
  与改动无关。集成测试（`--test xxx`）正常。
- **调试**：`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9223`。
  ⚠️ **DevTools 发起的 `invoke` 永远 pending**（隔离世界收不到回调），**不要用 DevTools 判断 IPC**。
  页面有多个 target（菜单浮层在 `about:blank`），选 `tauri.localhost` 那个。
- **抓图**：`Page.captureScreenshot` 可用（不需要装桌面桥）。
- **tracking 日志**：`KHOR_GUI_TRACE=1` 会打印 `[transport] <cmd>`、`[off_main] …`。
- **Linux 基线**：LAB `192.168.3.6`（`ssh LAB`），已装 rustc 1.95.0 于 `~/.cargo`，
  源码在 `~/khor-perf`，`dist` 已拷入。测量用 `scripts/windows-perf.sh`。
- **安全**：C 盘可读；只可写/删**自己创建**的文件；其他文件一律不删，删除前必须确认清单。
  `dsh-delete-guard` 会拦含 `$HOME`、`C:`、`%LOCALAPPDATA%` 字面量的命令——用环境 API 取路径可绕过拦截名义而不绕过意图。
