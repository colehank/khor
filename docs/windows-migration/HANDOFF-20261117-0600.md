## 3.5 业主三项意见的处理（2026-11-17 傍晚）

### ① 左上角关闭无效、无法退出 → **已修，5/5 通过（不到 1 秒）**

真正的根因不在前端：**窗口动词根本找不到窗口**。一个挂了子 webview（浏览面用 `add_child` 加入）的 Tauri 窗口，不再被 `get_webview_window("main")` 返回，于是关闭 / 最小化 / 最大化 / 拖拽全部回答 `no main window`，而页面丢弃了这个答案 —— 按钮看起来「没反应」。菜单代码早就避开过这个坑（用 `get_window`）。

同时清理了两个我自己引入、被独立审阅正确标为 P1 的危险做法：4 秒看门狗强制销毁（会跳过草稿对话框，导致丢数据）与 1.2 秒后 `process::exit`（会打断真正的关闭清理）。现在的链路：页面按草稿数选择 —— 无草稿 → `window_destroy`；有草稿 → `window_close` + 对话框；Alt+F4 / 标题栏仍走 `close-requested` 守卫。主窗销毁后：编辑器/设置窗口用 `close`（保护未保存文字），菜单浮层直接销毁；随后在独立线程里做退出处理器那件事（`link::shutdown`，限 3 秒）再离开 —— 因为**这个平台在最后一个窗口关后不会交付 `RunEvent::Exit`**（实测：20 秒内无 `exiting` 行，端口 1432 一直被占）。

证据（release，CDP 按页面自己的按钮，5 次启动）：**5/5 退出、端口全部释放，877–918 ms**。修复前同一方法 —— 1/5 或 0/5，失败轮次连 `main window was closed` 都没有。当时使用 CDP 和 `scripts/windows-close-check.ps1`（WM_CLOSE）；当前 MSI 检查由 `scripts/check-desktop-installer.py` 验证原生窗口关闭。

⚠️ 同时发现：**前端 dist/ 自 05:41 起从未重建**（tauri 配置里 `beforeBuildCommand` 被清空），所以早先的前端修复根本没进包。现已重建并记入构建陷阱。

**审阅发现但本轮未修**（不当作已完成）：`vendor_bin` 只接入了两个对话 shim —— 拿下预检、会话转终端、原生消息投递、向导里的 Codex 终端选项仍解析裸 `codex`；先选远程机器再切回本机时 roster 仍为空。

### ② 会话板块不该默认 CLI → **根因是 roster 找不到已安装的 Codex**

实测向导默认是 **「Claude · 对话」**，而本机只装了 codex 和 dsh。原因链：

- Codex 装在 `%LOCALAPPDATA%\OpenAI\Codex\bin\<hash>\codex.exe`（版本子目录，且不在 PATH）；
- `locate_program` 只查 `dir/command`，看不到 → `khor agents fleet` 报 1 installed（只有 dsh）；
- roster 为空 → `preferredLaunch` 回退到写死的 `claude` → 默认指向一个没装的 agent。

修法（`8899f1db`）：`Known` 增加 `versioned_dirs`（子目录是版本），Codex 在 Windows 上指向 `AppData/Local/OpenAI/Codex/bin`；查找支持下一层并以目录名倒序取最新；路径按段拼接避免 Windows 混用分隔符。另：roster 全无 ACP agent 时回退到「本机真有的第一个程序（终端）」，不再点名不存在的 agent；本机已装但不在 ACP 注册表的 agent（DSH）现在作为终端选项进入向导。

证据：`khor agents fleet` → **2 installed**（codex 带路径）；GUI `/agent_fleet` → `codex(builtin), dsh(terminal)`；向导截图 → 启动方式 **「Codex · 对话」**；下拉含 **「DeepSeek Harness · 终端」**。

实测（两边常驻后）：Windows 的 `/quota_board` 已返回 LAB 的两条账户（`home_name: gongzhengxin-MS-7E92`, `mine: false`），额度页按机器分组显示：
