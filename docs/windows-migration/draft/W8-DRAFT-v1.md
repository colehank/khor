# 草案 v1 · 会话区与工作区（Windows）

状态：**讨论稿**（供 6.2Astra 审阅）。不是最终方案。

## 0. 一句话

会话区是**派发与接手**的地方：每一行要么能说话，要么明确标着"只能看"；工作区是**人给目录起的名字**，
但目录候选可以自动发现——发现归发现，命名为事业归人。

## 1. 理念基线（来自仓库文档，非本文发明）

- 一切交互都是 session，五问（你是谁/在哪/怎么样/发生了什么/看过没有）+ 六词状态
  （`docs/SESSION.md`）。列表层只有五问，新 kind 不改协议。
- **工作区是人立的**（`docs/WORKSPACE.md`，2026-09-14 裁决）：不能从 cwd 折 git 根推。
  但 `place.rs`（常去的地方）**保留**了派生——因为它是"建议从哪里开始"，不是"什么是你的工作区"。
  这条边界是本文 B 部分的基础：**派生可以提议，命名必须由人**。
- 会话有两种面：**可对话**（khor 主持的会话，有输入框、可批准、可停止）与
  **只读记录**（厂商自己的对话，khor 只读；`SESSION.md`: 委派子任务的只读对话
  "不显示回复输入框、审批或任务操作"）。
- **遥控**不是另一个功能：同一 session 从任意设备操作。`AGENT.md`: "手机和浏览器通过认证后的
  khor 网络向该节点发任务、批准或停止操作"。

## 2. 现状（本机实测，2026-11-18）

- 会话 4 行：3 个 shell（`gui cross`、`gongzhengxin`、`onlinenpx` 失败）+ **1 个 `observe/` 只读记录**
  （onlinenpx）。开启"只看对话"后只剩那条只读记录。
- **只有只读对话，是因为这台机器上没有任何"khor 主持的活对话"**：`gui`/`chat` 类的会话一个都没建过。
  `observe/` 是**导入的厂商记录**（Codex/DSH 的 transcript），按设计只读——能读、不能遥控，
  因为它不属于 khor，输入框无处可发。
- 创建活对话的路径已经存在：新建会话 → `Codex · 对话`（上一轮修好默认）。创建后它就是一个
  `gui` 会话，有输入框，手机/浏览器可以继续它。
- 已有厂商对话的"接手"路径也存在：终端 `tui`（可遥控，因为它就是一个终端会话）、
  `codex resume`（在终端里续上）、`khor agents tell`（给 codex 线程发一条消息）。
- **候选目录的派生已经存在**：`khor places` 在本机给出
  `F:\#Gong\#AI4S\onlinenpx 22`、`…\worktrees\s2-windows 3`、`E:\CodeBase\pynpxpipe 1`、
  `~/AppData/Local/Temp/exec-probe2 1`、`~/Documents/Codex/2026-11-10/neuroloop-readonly-handover 1`、
  `F:\#Gong\Change 1`（数字 = 会话数）。协议层 `Request::Places` / `Response::Places` **已存在**，
  即可以向任何一台已添加的机器要它的候选。

## 3. 方案 A：会话区（Windows）

### A1. 派发任务 = 建一个活对话，而不是一条记录

- 会话页与工作区右栏的「＋」都直接进入向导，默认 `Codex · 对话`（已实现），创建后落在对话面。
- 列表里 `gui`/`chat` 行有输入框入口；`observe` 行没有，且**行上写明"只读"**（已有 `只读记录`
  的状态词，但只有打开后才知道——要提到行上）。

### A2. 行上先说清"能不能动"

三态显性，一行内可见（不用点开）：

| 面 | 行上标记 | 能做什么 |
|---|---|---|
| 对话（khor 主持） | 「对话」 | 输入、批准、停止；任何设备可继续 |
| 终端 | 「终端」 | 键盘输入；任何设备可接管 |
| 只读记录 | 「只读」 | 只能看；关闭不影响它 |

理由：用户问题"为什么只有只读对话"本质是**行没说清**。`SESSION.md` 的开放性只要求不崩不藏，
没要求不说清。

### A3. 遥控要可见

- 对话/终端的详情里显示「在 <机器> 上运行」，并给出「用手机继续」的入口（会话详情的一条说明 +
  二维码/配对提示）。手机端能力已经存在（AGENT.md），缺的是**桌面这侧把它说出来**。
- 只读记录不显示该入口（它不可遥控），并在同一位置写「这条记录由 Codex 持有，khor 只读」。

### A4. 已有厂商对话：接手入口放在会话上

- 行动作：「在终端里继续」(`resume`)、「发一条消息」(`khor agents tell`)。**已实现**，问题在
  入口只出现在行菜单里，第一次用的人找不到——把它们在只读记录行的详情里做成两个显式按钮。

### A5. 空态

- 会话页没有活对话时，空态写「还没有对话，派发第一件任务」，按钮 = 新建（向导）。
  不要把"导入的记录"算作"有对话"。

## 4. 方案 B：工作区（自动发现候选 + 人分组）

### B1. 候选从哪来

- 来源：每台**已添加机器**的 `places`（协议已有）。候选 = 目录 + 证据
  （会话数、最近时间、涉及哪些 agent、哪台机器）。
- 只做**候选**，不自动成为工作区——这条守 `WORKSPACE.md`：派生只提议。

### B2. 首次进入工作区页

- 空态不是空白，而是「发现 N 个候选项目目录（来自 2 台机器）」+「开始分组」。
- 点「开始分组」→ 一张面板：按机器分组列出候选（可搜索），多选；
  顶部一个输入框「事业名」；底部「创建」。

### B3. 分组 = 事业（多文件夹工作区）

- 数据：`Workspace { id, name（事业名，存库）, folders: [{device, path}] }`；
  现有单目录工作区读作单成员集合。
- 右栏 = 任一成员子树里的会话并集（跨机器时按机器分组）。
- 未分组的候选继续在「未分组」区可见，可随时拖/选进某个事业。

### B4. 日常入口

- 会话列表分组：**事业优先，未分组按地点**（Windows 默认）。
- 目录组头 / 会话详情里一个「加入事业…」。

### B5. 发现是持续的

- 新出现的候选（例如某台机器上新开了 Codex 会话）在「未分组」里冒出来，不打扰。

## 5. 分期

1. **A2 + A5**（行上三态 + 空态）：小，纯前端 + 词条。
2. **A3 + A4**（遥控可见 + 接手按钮）：详情面板，中等。
3. **B2 + B3**（候选面板 + 事业数据模型）：需要 schema + 协议（`Request::Places` 已存在，
   但 GUI 侧要调它）。
4. **B4**（分组轴）：需要 list 层支持"按事业分组"。

## 6. 风险 / 反例

- **A2 的三态可能与"六词状态"打架**：状态词在右侧，面在左侧，两套词会不会让人读两遍才懂？
  需实测。
- **B 的候选可能是噪音**：`places` 里有 `Temp/exec-probe2` 这种测试目录；需要过滤（临时目录、
  不存在的目录、"随手打开"的低频目录）。
- **事业名存库**破例；如果坚持不存，就只能用"第一个文件夹的 basename"当名字，事业会叫
  `onlinenpx`——不可接受。
- **跨机器候选**需要网络往返，离线机器会拖慢面板；必须允许"先显示本机，远端陆续到"。
