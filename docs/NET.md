## 身份与配对

- 一台机器一把**设备钥匙**，公钥即机器 id。私钥永不离开本机，丢了 = 重新配对。
- 设备钥匙之上有一把**用户根钥匙**（2026-09-30 落地，CONNECT.md 分期 2）。它只签字，
  不连网、不加密；签的是**证书**（「设备 X 是我的」）和**名单**（「我有这几台、这几台
  撤销了」），格式在 `khor_net::trust`，只凭根公钥就能验（`verify_cert` / `verify_roster`，
  给以后中继按证书放行用）。
  - **谁有根**：第一台机器——打开时设备表里只有自己、手里也没有根——自己生一把，存
    `.khor/root.key`（0600，权限松了拒用，和身份文件同一条规矩），并签一份只有自己的名单。
    命令行在生成的那一下提示抄恢复词；app 不弹（2026-10-01 起按需），持根机在「…」→ 安全
    的「恢复词」一行按「显示…」才显示，只给 app 不给网页脸。其余机器只存根公钥
    `.khor/root.pub`（锚），拿它验名单。根私钥不进任何同步文档、不上线路、不进日志。
  - **恢复词**：标准 BIP-39 英文 24 词，与 32 字节原样互换。`khor root show` 看本机认哪把根、
    持不持、名单第几版；`khor root words <本机名>` 看词（把本机名字打一遍才给）；
    `khor root recover <24 词>` 把根找回到这台。
  - **名单是信任的唯一出处**：名单随设备表同步（表旁一张图，每签一版一个键，合并不丢），
    读时逐份验签、取 seq 最大——设备表的「后写赢」不参与。每行另存那台机器的证书（不透明字节）。
    名单比证书旧时，行上出示的更新证书在名单新鲜期内也算数。
- **门**：除了配对，每个请求先过一道门，两句拒绝各说一件事——不在设备表里：「这台机器不在
  机器列表中，需要先配对」；在表里、不在名单上或已撤销：「这台机器不在名单上」。同步时对不在
  名单上的机器也不拨；借网隧道同一道门。
- **拒绝用看的那台的语言说**（NET-9）：拒绝在线路上仍是对方的句子（`Response::Refused { why }`），
  读的一方拿它对一遍目录里 msg、cli 两节每条的中英两版，认出键和参数，用本机语言重说一遍
  （`khor_catalog::reword`；读远端应答处和 ipc 回复处各一道）。线路不加字段：旧机器读不了
  更长的帧，会连句子一起丢。目录外的句子（系统错误）原样显示。
- **表丢了行**（NET-10）：门还放一种请求进来——担保（`Request::Vouch`）。一轮的开场被拒、
  而本机在自己的名单上时，拨号方把自己的行和最新名单递过去；对方只在这份名单用它自己的锚
  （`root.pub`，在表外，表丢了它还在）验得过、新鲜、不比它手里的旧、同时写着两台、它没给
  对方立墓碑时收下，写上对方的行和名单，下一轮把其余的带回来。每台对每台五分钟最多担保一次。
  起因：hinton 的设备表只剩自己一行，门拒所有机器，泵又没人可拨，两边都起不了那一轮。
- **每台机器报自己的路**（NET-12，我的 khor 的表盘与矩阵）：设备表里每台机器一行一组寄存器
  `<id>/road/<对方 id>`，值是 `{road: direct|relay|none, relay, ms}`，只由这台机器自己写
  （`khor_node::roadbook`，常驻每拍读一遍线）。写得极少：路的种类变了且稳住 12 秒才写；从没写过的
  对方要 `none` 稳住 2 分钟才写（刚配对、刚起时还没线）；毫秒只在变动超过四分之一且至少 5 毫秒时写，
  每台对每台十分钟最多一次；表里已有的不重写。本机自己的边永远看活线（`rtt_ms`），不读自己的行。
  `khor devices --roads` 打出整张矩阵。四台的网实测见 audit/net-12.md。
  - **路可以有两段**（2026-10-08，ROAD-1 轮）：sponsor 给它的每台卫星也写一格，种类是 `ssh`
    （最近一次采样不超过 2.5 轮）或 `none`，同样的稳住规则。别的机器到卫星的路不写进表，
    读时拼：第一段是这台到 sponsor 的路，第二段是 sponsor 那格；拼出来的路带 `via`（经哪台），
    断了带 `broken`：哪一段（`to-sponsor` 本机到 sponsor、`to-jump` sponsor 到跳板、
    `jump-to-target` 跳板到卫星、`ssh` 说不清的 ssh 失败、`auth` 只接受密码）和两端的机器 id——
    跳板不是机器，那一端是空。sponsor 那格的段由最近一次失败采样里 ssh 自己的话读出
    （`satellite::broken`），跟着寄存器进表。哪一段都没读数就不说话，和空闲的线一样。旧版 khor
    读到 `ssh` 当没有这条路。断的那段另带 `said`（join-e 轮）：ssh 自己说的原因，只取最后一行
    冒号后的那句（`Connection timed out`），一行、最多 80 字，带指纹、公钥或 khor 口令提示的行
    一律不写——这张表每台机器都读。机器页把它画在那句说明下面。旧版读不到这个字段，照旧只有那句说明。
- **配对**：票照旧（15 分钟、用一次就烧、没有方向），多一步定根：两边交出各自最新的名单，
  两边各跑同一条规则（`khor_net::trust::settle`）得出同一个结论——只有自己一台的根让给多台的网；
  两台都只有自己时，拿票拨号的那台让；两边都是多台的网就拒绝配对，不合并两张网（票不烧，
  那台先 `khor leave` 再来）。让出的一方删掉自己的根。然后持根的一方当场给对方签证书，
  持根的是拨号方时经同一条连接把名单推过去；两边都不持根时，两边都记「待批」
  （`.khor/pending/<id>`）。**配对完成的判据是新机器拿到证书**：只配上、没证书的机器处处被拒。
- **待批**：`khor pending` 列出等持根机器批的——没证书的机器（含本机自己）、不持根的机器领进来
  的卫星、在别处删掉还没撤销的机器；`khor approve <机器>` 只在持根机上能批，签完立刻同步一轮。
  app 的机器列表顶上有人等批时出一条，持根机每行一个「批准」。等批的机器被全网拒绝是本分，
  不算「serve 聋了」、不因此重启。
- **撤销**：`khor revoke <机器>` 在持根机上发新一版名单（seq+1）：删它的证书、记它的 id；
  拿到这版的机器都拒它。它还留在设备表里；`khor forget` 仍是设备表墓碑（全网不再列它、
  不再应答），在持根机上同时撤销，在别处进待批等持根机点头。
- **新鲜**（CONNECT.md「撤销要新鲜」）：名单带签发时间。持根机在线时每 7 天把同一份名单重签
  一次；超过 30 天没见新名单算过期——照旧信旧名单上已有的机器、不收行上出示的新证书，
  `khor doctor` 的「名单」一行说「名单已过期 N 天」。时钟用本机系统时间，签发时间在未来的
  名单按零天算。
- **有根以前的网**：设备表里有别的机器、谁也没有根时，照旧以设备表为信任，直到有一台跑
  `khor root init`：它生根，把设备表里的机器（卫星作卫星）都签上；别的机器下次同步见到点名
  自己的名单就认上这把根。
- **离开**（`khor leave`）：持根机保留根钥匙——那是整张网的；别的机器丢掉锚和名单，下次独自
  打开就是一张新网的第一台。`khor id --reset` 后持根机以新 id 把自己重新签上。
- 入网即全信：这是一个人的设备网，不是多用户系统（共享的去处见 CONNECT.md「身份」）。
  在名单上的设备间互相开 session、跑命令不设防；待批管的是智能体的动作、全量文件的拉取
  （省的是流量磁盘，不是防谁），以及上面那种还没拿到证书的机器。
- 被移除或撤销的设备，它钥匙串里已存的凭据收不回——真丢了去提供商换 key。

## 卫星：只有 ssh 可达的机器（附属机器批，2026-08-26）

**卫星 = 看得见、够得着，但不是它自己在说话；行星 = 它自己在说话；
转正 = 一条命令。** `khor add <ssh主机> --no-install` 在任一 khor 机器上把它领进
网，领它的那台从此是它的 **sponsor**：卫星的 home = sponsor，一切对
它的操作路由到 sponsor、由 sponsor 经 ssh 代跑。这天然使 C→B(sponsor)
→A(卫星) 跨内网可达——不需要新传输，就是既有的「问 home」。

- **身份**：它 ssh host key 的 SHA256（转 hex）——恰好 32 字节，与设备
  id 同形，所以设备表、脸、全部现有管道照用。指纹从 **known_hosts 读**
  （只信用户已经给出的信任，不 keyscan）；没连过的机器指路先手动
  ssh 一次。它不是 iroh 钥匙：addrs 恒空，谁也拨不到它，同步循环
  天然绕行。
- **只借用户现有 ssh 通路**（~/.ssh/config、agent、known_hosts）：khor
  不存不碰任何凭据，全部 BatchMode（serve 里没有人能答密码）。
- **信任面**：sponsor 不是盲转发——ssh 客户端在它身上，内容过手明文。
  但它本来就拿着开那台机器的钥匙，经它没有新增信任面；变的只是
  「谁替卫星发声」，而那正是 sponsor 一词的意思。
- **进名单**（2026-09-30）：sponsor 持根就当场签（类为卫星，对象是上面那个指纹，
  sponsor 是本机）；不持根就进待批，等持根机 `khor approve`，期间 sponsor 照常代它跑
  （ssh 通路本来就在它手里，不新增信任）。名单撤销了的卫星，sponsor 不再代它跑任何操作。
- **单点语义（一期单 sponsor）**：sponsor 掉线，卫星就没人代跑也没人
  采样——行走离线轴（读数只变老，不装在线），从别处对它无路可退。
- **读数**：sponsor 每分钟经 ssh 采一轮（CPU/内存/磁盘，nvidia-smi 有则
  GPU），存在自己的 vitals 缓存；别的机器拜访 sponsor 时把读数连同
  **采样时的年龄**一起带走——一个读数永远穿它出生那一刻的新旧，
  不穿到达那一刻的。
- **它身上不留东西**（工作区批7 立成规矩）：至今每一个卫星动作——采样、
  列目录、git、读文件、存文件——都是一条 sh 或一次 scp，跑完那台机器
  上和之前一样，没有进程、没有装下来的东西、没有 khor 的目录。这条不是
  实现的巧合，是 adopt 的承诺「一切操作经本机代跑」的另一面：人之所以
  adopt 而不是装 khor，往往正是因为不能往那台机器上装东西。
  - **能不能做到不是判据，留不留下才是。** 卫星上的保存本来因为
    「摘要那边算不了」被拒过，后来发现把比对搬到那台机器上就守得住，
    于是做了（批7）——它跑完不留东西。
  - **VS Code 的开关因此不给卫星**，而理由不是 ssh 架不了管子（`ssh -L`
    正是管子）。是 `code serve-web` 要往那台机器上落约 640 MB 的微软
    服务端、再留一个长活进程，而那是 khor 第一次在卫星上留下东西。
    要 VS Code 的人，装 khor 比这便宜。
- **出网**：就是 forget（同一张表、同一个墓碑、同一句广播）。一条实测
  边缘：sponsor 离线期间别处 forget 的墓碑后到，会压掉离线期写的
  re-adopt（删除赢过修改的正确后果）；那时行已消失，人再 adopt 一次
  即赢——墓碑此刻已合并，新写的时钟高过它。

## 添加机器：经 ssh 装成成员，留不住才作卫星（2026-10-08，join-a）

`khor add <SSH主机> [名称] [--port <端口>] [--via <跳板机>] [--password | --key <密钥文件> [--passphrase]] [--no-install]`（取代
`khor adopt`；v1 前不留旧词）。`khor_node::join`。界面上成员叫「khor 主机」、卫星叫「SSH 主机」，
转正叫「安装 khor」（2026-10-08 负责人定的正式用词）；代码里的名字不变。

- **默认是成员**：本机经 ssh 跑四步——连接（一条连接看清那台：系统、tmux、哪些东西本来就在）、
  放 khor（`install.sh` 经 ssh 的标准输入跑，`KHOR_NO_SERVE`；版本是本机自己的
  `v<VERSION>`，本机设了 `KHOR_MIRROR` 就一并带过去；那台拿不到就由本机送：同平台送本机这份
  程序，否则本机去下那台的资产，经 ssh 推到 `~/.local/bin/.khor.push.gz`，`KHOR_ASSET_FILE`）、
  启动（同一脚本 `KHOR_SKIP_FETCH`，用户级常驻：macOS LaunchAgent、Linux `systemd --user`，
  否则登录脚本一行；**不要 root**）、配对（本机出票，票走 `khor pair -` 的标准输入，不进任何
  命令行和日志，`PAIR_WAIT` 60 秒）。
- **留不住就作卫星**：`~/.local/bin` 写不进、没有这种机器的版本、放不上、会话一断常驻就停
  （从一条新连接看 pid）、60 秒内没连回来——先把这次放上去的东西逐样撤掉（连接那一步记下了
  哪些本来就在，只撤新放的：程序、`khor-serve-up`、LaunchAgent / unit、`.profile` 里加的行、
  存储、新建的空目录），再领成卫星。一句话说为什么。
- **装不装由人定**（2026-10-08 负责人「为对方下载 khor 是用户行为」）：表单上一行「在 <主机> 上
  安装 khor」，默认打开；关掉 = `--no-install`（原 `--satellite`，改名是为了和界面同一个说法），直接作
  卫星，不在那台上留任何文件。打开而没装成，就是上面的自动回退。
- **退出登录**：常驻照常运行（从一条新连接验过）；重启后谁拉起看 `install.sh` 报的
  `khor: keeper <词>`：launchd / systemd 开机拉起，`systemd-login` / `login` 要登录一次，`none`
  要手动 `khor-serve-up`。
- **经由**：`--via` 每条 ssh 和 scp 都带上跳板，写成 `ProxyCommand=ssh -o BatchMode=yes -W %h:%p
  <跳板>`——`-J` 起的第二个 ssh 不继承 `-o`，实测会对跳板要三次密码。不改用户的 ssh 配置；
  跳板记在卫星那一行、ssh 地址旁边（`ssh_jump`）。经一台 khor 机器添加（`-m <机器>`，界面「通过 khor
  主机」）= 在那台上跑 add，它当 sponsor：本机发 `Request::AddOverSsh`（按 token，像投递），那台
  在自己的线程里跑，本机每 500 ms 再问一次，拿回到目前为止的每一步（`join::Run`）。只能用密钥。
- **哪一段断了**：读 ssh 自己的话（`satellite::broken`，OpenSSH 10.3 实测）：`ssh: connect to host`
  / `Could not resolve hostname` / 跳板拒钥匙，且外层说 `UNKNOWN port 65535` = 本机到跳板；
  `channel 0: open failed` / `stdio forwarding failed` = 跳板到目标；没有 UNKNOWN 的
  `Permission denied (…)` = 目标只认密码。代理上的 banner 超时分不出哪边，原话照给。
- **端口**：`--port` 每条 ssh 和 scp 都带 `-o Port=<端口>`（两者共用这一种写法，`-p` 和 `-P`
  正好相反），命令行压过用户配置；不填就是 22 或用户配置里的值。记在卫星那一行（`ssh_port`）；
  非 22 的端口在 known_hosts 里是 `[主机]:端口`，取身份时照这样找。
- **认证方式：密钥或密码**（2026-10-08 负责人「密码可以保持」）。密钥是上面的 BatchMode 路；
  不认密钥时一句话加修法 `ssh-copy-id [-p <端口>] [-o ProxyJump=<跳板>] <主机>`，app 的动作开一个
  khor 终端跑它（`satellite::copy_id_argv`）。密码（`--password`，从标准输入读）**只存进跑 ssh 的
  那台机器的系统钥匙串**：macOS 钥匙串，Linux 经 `secret-tool` 的 Secret Service；没有就一句话
  拒绝，不存别处。从不进同步的文档、线路、日志和票；行上只记 `ssh_password`（走哪条路），不记
  密码。ssh 经 `SSH_ASKPASS`（`SSH_ASKPASS_REQUIRE=force`）向 khor 自己要：`SSH_ASKPASS` 指向本
  程序，`KHOR_ASKPASS` 指明哪台，每个 khor 的 `main` 先 `secret::answer_askpass_if_asked`。只答
  密码提示、只答父进程是 ssh 的；主机密钥的 yes/no 不答（归 known_hosts），每次要一次性验证码
  的主机一句话说不支持。一次机会（`NumberOfPasswordPrompts=1`），错了就说密码不对。跳板仍只走
  密钥。**密码只留到用不着**：卫星一直要 ssh，行在密码在，行撤了（`forget_id`）密码一起删；成员
  走 iroh，加成了就删；没加成也删。经 khor 主机添加时不能用密码（密码不上线路）。
- **自己选的密钥文件**（2026-10-08 负责人「密钥也是可以自己传的」）：认证方式 密钥 = 默认（ssh 配置
  和 ssh-agent）或一个密钥文件（`--key <路径>`，跑 ssh 那台上的路径）。每条 ssh 和 scp 都带 `-i <路径>
  -o IdentitiesOnly=yes`；行上只记路径（`ssh_identity`），**从不复制、同步或上传密钥**。
  有口令的密钥：`--passphrase` 从标准输入读一次，和密码存在同一个钥匙串、同一个名字下（一条路要么
  密码要么密钥），经同一条 askpass 路交给 ssh；这时只出示这把密钥（`PreferredAuthentications=
  publickey`），免得目标的密码提示被拿口令去答。行上记 `ssh_passphrase`。没给口令而 BatchMode 下
  被拒时，用 `ssh-keygen -y -P ''` 在本机问一句这把钥匙有没有口令，有就说「设有口令」，没有就给
  `ssh-copy-id -i <路径>` 的修法。经 khor 主机添加时 `--key` 是那台上的路径，有口令的密钥不行（口令
  不上线路）。
- **扫除**（2026-10-08）：本机存过的每个名字（只有名字和时间，不是密码）记在 khor 家目录的
  `ssh-secrets` 里。sponsor 每分钟采样卫星时顺便扫一遍：本机 sponsor 的、仍要密码或口令的卫星行里
  没有的名字，连同钥匙串里那一项一起删——行在别的机器上被删掉也一样，最迟一分钟。15 分钟内刚存的
  不扫（添加还在进行，行还没写）。

  系统会问一次「khor 想要使用钥匙串」；负责人认可（2026-10-08）。
- **转正**：`khor promote <卫星>` 走同一条安装路；成了，卫星那一行按 id 撤掉、名字带到新机器上；
  没成，撤掉放上去的东西，它还是原来那颗卫星。

## 中继

只转发不存内容。三档（2026-09-30 负责人定：n0 留作兜底，不去）：

| 档 | 何时 |
|---|---|
| Khor 中继（现只有国内 aliyun 一台；海外那台还没有） | 默认就在表里 |
| n0 公共中继（四台，海外） | 默认跟在 Khor 档后面兜底；大陆不通，海外设备靠它 |
| 自己的（设置→网络、`KHOR_RELAY`、自己跑的 `khor relay`） | 配了就在表里；「只使用自己的中继」打开时只剩这一档，n0 和 Khor 都不挂 |

落档就是「都挂上、iroh 按可达性挑」：表里每一台都探，住离自己最近、答得上的那台。
n0 的 DNS / pkarr 发现服务随 n0 档一起挂（`endpoint::bind_with` 的 n0 开关：开就是
iroh 的 `N0` 预设，关就是 `Minimal` 只留 mDNS）；大陆侧查不到它，所以中继地址仍随
设备表的地址提示与配对票同行，同网段之外光有对方 id 拨不出去，要靠这些提示。
测试 `a_hermetic_bind_has_no_n0_and_the_n0_switch_adds_it_behind_ours` 守两半：
不开就一个 n0 服务都没有，开了 n0 排在自己的后面。

**`KHOR_NO_MDNS=1` 连 mDNS 也不挂**（`endpoint::NO_MDNS_ENV`，2026-10-05 TERM 38）：
不广播、不监听。给临时节点用，不给人用——同一个 Wi-Fi 上每台机器都要解码每条广播，
各车道留着的临时节点会算到负责人自己的 app 头上（term-cpu.md）。测试的 harness
（`scratch::off_the_segment`、`util::off_the_segment`、`fake-home.mjs` 等门）都设它；
`tests/mdns.rs` 是唯一要 mDNS 开着的地方。

**中继名单归设备，只往外走**（2026-09-29 按代码更正；这里原写「名单全网
一份，CRDT 那行管这个」，代码从来不是那样）：每台自己的 `.khor/relays.json`
（设置→网络）加 `KHOR_RELAY`，写进设备表的地址提示和配对票，别人拨它时
带上；**别的机器改不了这台用哪些中继**——谁能改你的中继名单，谁就能把你的
流量引到他的机器上。全网一份、由管理者签名的中继池是去处，见 CONNECT.md。
家是每台设备按远近可达性自己挑的——国内桌面和海外笔记本本该住不同的家。
「只使用自己的中继」现在的意思是**不用 Khor 档**：留下 `KHOR_RELAY` 和设置里填的。

### 准入：中继的密钥怎么填

一台用共享密钥准入的中继（iroh-relay 的 `shared_token`，或 `khor relay --token`），
客户端要出示同一把密钥（iroh 的 `RelayConfig::auth_token`，走 `Authorization: Bearer`）：

- **设置→网络**：「添加中继…」的窗里第二格填密钥，没有就留空。之后页面只说这台
  「带密钥」，不再显示密钥本身。
- **`.khor/relays.json`**：每条是 `{"url": "https://…", "token": "…"}`，没有密钥就
  只写 `url`；旧的纯字符串写法照样读。文件 0600。
- **`KHOR_RELAY_CA`**：一个 PEM 文件，里面的证书和 Mozilla 的根一起被信任——自己签的中继
  证书、私有 CA，和测试里的自签证书（NET-7）。
- **`KHOR_RELAY_SUCCESSOR`**：`旧|新`，逗号分隔多对：住旧那台时，量得到新那台就住新那台
  （和 `KHOR_SUCCESSORS` 同一条规矩，给自己跑的中继和测试用）。两台都要在中继表里。
- **`KHOR_RELAY`**：逗号分隔，每条是中继地址，密钥挂在 `token` 查询参数上：
  `KHOR_RELAY="https://relay.example.com?token=密钥,http://10.0.0.5:3340"`。
  这是 iroh-relay 自己认的写法；khor 把它从地址里摘出来当密钥用，地址本身不带它。
  密钥里不能有逗号。
- **Khor 档的内置密钥**：跟着每台中继的地址写在 `endpoint::KHOR_RELAYS` 里
  （2026-10-01 起），两台各一把、不相同——北京那台是明文 HTTP，它的密钥在路上看得见，
  不能同时是香港那台的钥匙。内置的密钥能从二进制里抠出来，只挡随手白用（CONNECT.md 分期 0）。

**密钥不出本机。** 设备表的地址提示、配对票、`endpoint.json` 里只有地址，没有
密钥——那些会复制到网里每一台、并留在删不掉的历史里。后果是故意的：别的机器
要经一台带密钥的中继找你，它自己也得配上这把密钥。给自己的设备跑中继，用
`khor relay --only-mine`，谁也不用填，按名单放行。

### `khor relay`：自己跑一台

嵌的就是 iroh-relay 1.2 的服务端（和 `iroh-relay` 二进制同一份代码）：

| 参数 | 做什么 |
|---|---|
| `--dev` | 明文 HTTP，默认 `[::]:3340`（和现在 Khor 档那台一致）。转发的内容端到端加密、中继看不到；但 `--token` 的密钥在明文 HTTP 上也是明文 |
| `--tls-cert 证书 --tls-key 私钥` | HTTPS，默认 443；另开一个明文口给强制门户探测，默认 80（`--http` 改）。证书续期不用重启：收到 `SIGHUP` 就重读这两个文件（另每 6 小时自己读一次），读坏了继续用旧的并在日志里说 |
| `--tls-check`（和上面两个一起） | 照中继读的方式读一遍证书和私钥，不起中继：能用就说能用，不能用就说为什么 |
| `--acme 域名 [--acme-contact 邮箱]` | 找 Let's Encrypt 要证书，缓存在 `--state` 下的 `acme/` |
| `--token 密钥`（可多把） | 只放行带其中一把的客户端 |
| `--only-mine` | 只放行这张网信任的设备：按中继握手已验过的 endpoint id，用和每个请求那道门（`Node::admit`）同一条规矩——在设备表里，且在最新名单上、没被撤销（有根以前的老网只看设备表）。待批的、撤销的都拒。每 5 秒至多重算一次，读不了就谁也不放。和 `--token` 二选一 |
| `--rate 字节每秒` | 每个客户端的上行限速（iroh-relay 的 `client_rx`，整台一个值） |
| `--metrics 地址` | iroh-relay 自带的指标页 |
| `--bind 地址` | 中继主口（`--dev` 时是 HTTP，TLS 时是 HTTPS） |
| `--state 目录` / `--stats` | 计量文件的目录（默认 `.khor/relay`）；`--stats` 只打印计量、不起中继 |

启动时打印在哪听、谁能进、限速、指标、计量文件在哪。QUIC 地址发现（iroh-relay 的
7842 口）不开：khor 的客户端把每台中继都当没有 QAD 用。

**计量只存总数**（CONNECT.md「计量只存总数」）：`relay-stats.json` 里只有每个
endpoint id 的连接次数和在线秒数，加整台中继发出 / 收到的总字节，跨重启累计。
不存「谁连谁」。**字节没法按设备记**：iroh-relay 的 `bytes_sent` / `bytes_recv`
是整台一对计数（`server/metrics.rs`，在 `server/client.rs` 里累加时不带 endpoint），
`AccessControl` 和 `Clients` 都看不到包。

### 自己的中继：在一台有公网地址的机器上跑 `khor relay`（2026-10-03，NET-2 轮）

负责人已经有一台当 SSH 跳板的 aliyun 机器，那就是最合适的家中继：它离自己的设备近，只给
自己的设备用。在那台机器上：

1. 装 khor（`scripts/install.sh`；只要 `khor` 这一个二进制，不必跑 serve）。
2. 跑中继，只放行自己的设备（按名单，不用填密钥——见上表的 `--only-mine`）：
   `khor relay --dev --bind 0.0.0.0:3340 --only-mine`。`--dev` 是明文 HTTP：转发的内容端到端
   加密，中继看不到；要 TLS 就用 `--acme 域名` 或 `--tls-cert/--tls-key`（443，域名指向大陆
   机器要备案）。`--only-mine` 读的是那台机器自己的 khor 名单，所以那台机器得先配进网（`khor pair`）。
3. 在 aliyun 的安全组放行 TCP 3340（或 443/80）。
4. 常驻：用 systemd（照 `khor-relay.service` 的样子，见上「Khor 档现在是两台」那段的服务器设置）。

然后在每台自己的设备上：设置 → 网络 → 中继 → 自己的中继 → 添加 `http://<公网 IP>:3340`；
要让它当家，就在「首选中继」里选它（`.khor/relays.json` 的 `preferred`）。首选的中继能连上时
就住在它上面，连不上时照常住最近的那台（`vendor/iroh/KHOR.md` 补丁 3）；改了之后下次重连生效
（重启 app，或手机回到前台）。「只使用自己的中继」打开时 Khor 档和 n0 都不挂——网里每台都要
能连上这台，否则彼此找不到。

**为什么这样比 Khor 档好**：家中继决定别人从哪儿找到你。手机在蜂窝网上、Mac 在家里时，两边只能
经家中继牵线；一台离两边都近、只为自己的设备服务的中继，往返最短，也不和别人分 1 MB/s 的限速。

**`hk.relay.khor.cloud` 是什么、为什么量出 2040 ms**（2026-10-03 从开发 Mac 上量）：它是香港那台
（`47.242.108.241`，阿里云香港），本身是好的。从这台 Mac 上 `curl` 它：TCP 握手 3.7 ms——到香港
不可能这么快，是本机代理的 TUN 接管在本地就把连接接下了——TLS 握手 2.4 s，是代理把流量绕到它自己
的上游再回来。所以 2040 ms 是代理的绕路，加上 doctor 的「中继」行量的是**首个请求**（DNS + TCP +
TLS + 请求），不是往返（网络页的「连接」组改量热连接上的第二个请求，`doctor::relay_round_trip`）。
它对海外设备有用，**不建议从默认档里拿掉**；该做的是在代理规则里把 `hk.relay.khor.cloud` 和
`47.242.108.241` 设成直连（上面「还没做的」已记）。

### 代理

iroh 的 `Builder::proxy_from_env` 已开：中继连接和中继探测经环境里的 HTTP 代理走，
按 iroh 的顺序读 `HTTP_PROXY`、`http_proxy`、`HTTPS_PROXY`、`https_proxy`。
**iroh 不读 `NO_PROXY`**：整个 shell 设了代理，同一局域网里的中继也会绕代理。
桌面 app 从 Dock 起时通常没有这些变量。

**三条路一种规矩**（2026-10-01 负责人定，「可以，这个记上要做」）：直连是 UDP，
不经任何代理；连中继只读环境变量（`proxy_from_env`）；**探测也只读环境变量**——
vendor/iroh 的 `reqwest_client_builder` 打了 `.no_proxy()`（补丁 2，`vendor/iroh/KHOR.md`）。
⚠️ 墓碑（2026-09-30 查，10-01 还）：之前探测读的是 macOS 系统设置里的代理——工作区为
额度页给 reqwest 开了 `system-proxy`，feature 合并后 iroh 的探测也读它，而 hyper-util
读系统代理不看例外表。后果是系统设置指着一个挂了的代理时一台中继也量不到、选不出家；
代理把 39.97.7.248 路由到海外时量到的延迟是错的。本地中继的测试当时都设了
`NO_PROXY=127.0.0.1,localhost,::1` 堵着，10-01 随补丁撤掉。

**Khor 档现在是两台，都要密钥**（2026-10-01，负责人买的两台阿里云轻量）：

| 中继 | 地址 | 模式 | 给谁 |
|---|---|---|---|
| 北京 | `http://101.200.80.77:3340` | 明文 HTTP + 密钥 | 出不了境的机器 |
| 北京（TLS） | `https://pk.relay.khor.cloud:3341` | TLS（acme.sh 按 DNS 签）+ 另一把密钥 | 同上；答得上时替掉上一行 |

## 可达性

- 直连优先（打洞），不通走中继。
- 直连、中继都够不着，但网内有机器够得着它：经那台代问，只一跳。
- 够不着 ≠ 不存在：显示上次状态 + 时长（见 SESSION.md 离线一节）。
- 借网访问：把一台设备当网络出口。**消费者有两个**（2026-08-16 定）：
  浏览器落点，和 **session 本身**——开 session 时**发起设备**与
  **网络出口**是两个独立的选择（在 A 上跑、从 B 的网出去，正交组合
  都合法）。所以出口能力是一层，不长在浏览器里，它不知道消费者是谁。
  **一层不占会话列表**（2026-08-17 定形，取代早先「形态是一种
  session kind」）：走出口的 session 在自己那行戴出口记号；网页只是
  khor 界面里的一个标签体，跨端记忆走置顶（键=URL+机器）。唯一占一行
  的是**手动持有的借口**（要一个本地代理口自己拿去用）——没有别的行替它露脸、
  寿命也没处挂，所以它才是一条 session。
  **一台出口一个借口**，几个页面指着它都一样：以前每开一个地址
  就新拨一条租约、新绑一个口，三个页面留下三份谁也分不出谁。

- **浏览这一屏一次只有一个出口**（2026-09-09 定）。不是「一个标签
  一个借网」——那条在 Android 上结构性地不成立：它的代理是**进程级**
  的，整个 app 一次一个出口。定案的不是「做不到」，是**它失败的方式**：
  照「哪个标签在前台就转发哪个」实现，一个后台标签发请求会**从错的
  那台机器出去而且不报错**，走的是这仓那条「一档接不上会变成旁边那
  一档」。收成一句五端都成立的话之后，走错网这件事不可能发生。
  换出口 = 重新加载全部标签，**因为它们的页面是从旧出口取回来的**。

- **代理说两种话，而它们的私密性不一样**（2026-09-09 补上明文那半）。
  `https` 走 `CONNECT`，khor 只是一根瞎管子，看不见里面。**明文
  `http` 看得见**——目标就写在请求行里，代理不读就不知道往哪儿送，
  这是任何明文 HTTP 代理的性质，不是 khor 的选择：另一条路不是更私密，
  是页面打不开。而校内自建的那些（notebook、看板、路由器）恰恰大量
  是明文，所以不补这半等于把借网的主场景关在门外。
  **明文那条一次一请求**（发 `Connection: close`）：keep-alive 会让
  客户端把下一个**别的主机**的请求塞进同一个已经认定了目标的口子。

- **页面自己有几条路绕开借网，而绕开的时候它不报错**（2026-09-10 落 shim，
  `apps/gui/core/src/page_shim.js`）。WebKit 上有几个 API 走的是**这台设备
  自己的网**——页面照常用、什么都不失败，唯一看得见的地方是别人日志里的
  一个地址。这正是「一档接不上不会变成没有值，它会变成旁边那一档」：
  不是借网失败了，是**成功地从错的那台机器出去**。三条，Mysk 2026-08-04
  报，当时全未修。

  | 漏在哪 | 怎么漏 | 现在 |
  |---|---|---|
  | `WebTransport` | QUIC 走 UDP，而 HTTP 代理不带 UDP，数据报从本机出去 | **删掉**，站点走它的 WebSocket 那条路 |
  | WebAuthn | 答一次调用，WebKit 就直连去取对方的 `.well-known` | **删掉** `PublicKeyCredential`，`credentials` 的 `publicKey` 那支答 `NotAllowedError` |
  | `<link rel="dns-prefetch">` | 走这台设备自己的 DNS | **没堵，也堵不了**（见下） |

  **删掉而不是拦下**：站点探测不到就走自己的另一条路（密码表单、
  WebSocket），那是一张能用的页；半路失败的那种是一张坏页，而且站点
  说不出为什么。代价明摆着——**借网标签里 passkey 用不了**。方向是对的：
  一个一边能登录、一边报出这台设备地址的 passkey，不如一次密码登录。

  **`dns-prefetch` 堵不了，而且不是「还没做」。** WebKit 在那个元素插进
  文档的**同一瞬间**就去解析了，同步的，在解析器里；`MutationObserver`
  的回调晚一个微任务，查询早发出去了，而改 `setAttribute` 只够得着脚本
  插进去的那一半——真实站点的 `dns-prefetch` 绝大多数写在 HTML 的 head 里。
  **没有更早的钩子。** 漏的是**主机名**不是流量：这台设备在看哪些站，
  以及校园网、家里那些内网机器的名字，交给了这台设备用的那个解析器。
  要堵它得有一层在 WebKit 解析之前看得见 HTML（账本里那个改写网关），
  或者等 WebKit 自己修。

  **删掉的那两条也挡不住一件事：一个存心要查你的页面。** 2026-09-10 用
  `npm run wk` 在真 `WKWebView` 上量过（同一页加载两遍，一遍不带 shim）：
  脚本**进得去**页面本身、解析器建的 `about:blank` iframe、真子 frame、
  脚本建的空 iframe、以及 `srcdoc` iframe **加载完之后**——五处带 shim
  全是 `undefined`，不带 shim 全是 `function`。**进不去两处**，而这两处
  是真的出路：`Worker` 的全局（`typeof WebTransport` 一直是 `function`），
  以及 `srcdoc` iframe **在它的 load 事件之前**那个同步窗口（设了 `srcdoc`
  就 append，当场读 `contentWindow.WebTransport` 拿得到）。
  ⚠️ **这一段之前写的是「`about:blank` 没量过」，而量下来 `about:blank`
  是好的**——照着那句猜去加固，会去堵一个没坏的地方，而真正开着的那两处
  原样留着。所以这条 shim 挡的是**站点自己撞上去的那种漏**，不是对抗性的
  去匿名化——把它说成后者，是这两种错里贵得多的那一种。真要堵死得换形态
  （整机 VPN，或者那个网关）。

  **什么时候这段话会失效**：WebKit 修了任何一条，对应那一行就从「删掉」
  变成白白的破坏（passkey 白白用不了）；而新加一个走设备网的 API，
  这张表不会自己长出一行——`npm run shim` 守的是已经写下的这几条，
  不是「还有没有别的」。

### 给一个地址，全网都去够它（2026-10-08，ROAD-1 轮）

`khor reach <主机> [--port 端口]`（app 里是 `reach_probe`）：每台在线的机器（卫星除外，
名单撤销的除外）**各用自己的解析器**解析这个名字，连一次 TCP（3 秒），读对方先说的第一行
（ssh 的版本行，1.5 秒），再在**自己的** known_hosts 里查这个名字的钥匙（只查，不 keyscan，
和卫星同一条规矩）。**第一行以 `SSH-` 开头才算可达**；连上了却没有 ssh 版本行是另一种结果
「无 ssh 应答」（`silent`），永远不当入口。可达的里最快的是入口，平手归本机——不绕路的赢。

- 只在人给地址时问，只问这一个地址和端口（默认 22）。没有「khor 的端口」可探：khor 机器
  本来就按 id 认。
- **名字只是提示，钥匙才是机器**：几台机器的 known_hosts 给同一个名字记着不同的钥匙，就
  标出来——它们说的不是同一台机器（两个局域网里各有一台 `192.168.1.5`）。这时入口只在
  钥匙和本机一致的那几行里挑；本机没有它的钥匙就不挑，由人选。钥匙正好是某台
  卫星的 id 时，报「这把钥匙是 X 的」。
- 线路上是新词 `Request::Probe` / `Response::Probed`；旧版 khor 按名字拒，那一行读「版本过旧」。
- ⚠️ 实测：开着 fake-ip 代理（TUN 模式）的机器，**任何名字都解析得到**（`.invalid` 也给
  198.18.x），连接也会被代理接下，而且没有 ssh 版本行——所以由第一行定，不猜地址段。
- 只在 app 里有（`reach_probe` 不上网页脸）：拿着网页脸钥匙的浏览器不能让全网替它去连地址。

### ssh 走 khor：经一台 khor 机器的出口（2026-10-08，ROAD-1 轮）

`khor pipe --via <机器> <主机> <端口>` 把标准输入输出接到「那台机器的网够得着的 主机:端口」，
正好是 ssh 的 `ProxyCommand`：

    ssh -o ProxyCommand='khor pipe --via 实验室 %h %p' 内网机

- 走的就是借网的出口：同一个 ALPN、对端同一道门（在表里、在名单上、没暂停）、同一个状态字节。
  ssh 自己的钥匙校验端到端照做，出口只看见密文。
- 有常驻时，常驻先把到目标的流拨好（拨不通当场用话说出来，ssh 原样打印），再开一个只收一次
  连接、要先报一次性暗号的回环口给命令接；没有常驻时命令自己绑一个端点去拨。
- 经本机就是不绕：直接从这台连。经卫星不行（它不是 khor）：那条路是 `ssh -J`。
- **khor 从不写用户的 ssh 配置。** app 的「经由」给出现成的一行（`proxy_line`：配置里的
  `ProxyCommand …` 和一次性的 `ssh -o 'ProxyCommand=…' 主机`），带复制按钮；khor 自己跑 ssh
  时按命令传。
- 和 adopt 的区别：adopt 让 sponsor 替那台机器说话（读数、文件、会话都经它）；pipe 只是一根
  管子，那台机器不进设备表。只想 ssh 过去，用 pipe；要 khor 看得见它，才 adopt。

### khor 走 ssh：连不上互联网的 khor 主机，经能登录它的机器转连（2026-10-08，ROAD-2 轮）

`khor carry <机器> <SSH主机> [--port N] [--via 跳板] [--password | --key 密钥文件 [--passphrase]]`
（关：`khor carry <机器> --off`）。
那台机器装着 khor、常驻在跑，但到不了互联网和任何中继；本机能 ssh 登录它。从此本机（转连的
那台，行上的 `carrier`）一直挂着 `ssh <路> khor _carry <本机 id>`，ssh 的标准输入输出就是一条
iroh 路（`khor_net::carry`，iroh 的 `unstable-custom-transports`）。

- 那头的 `khor _carry` 像 `khor pipe` 一样经一次性回环口和暗号把标准输入输出交给自己的常驻，常驻
  把它当成到转连那台的路。iroh 的握手两端照做，ssh 和 sshd 只看见密文。
- 路就是 `khor add` 记下的那条：端口、跳板、密钥或密码（askpass）都照用；断了按 2、4、8……最多
  60 秒重连，连上过一分钟的从头数。`khor carry` 的登录参数和 `khor add` 一样（ROAD-4 轮）：密钥文件
  只记路径；密码和口令从标准输入读，只存进本机的系统钥匙串。转连的那台和卫星的担保机一样留着它，
  不再转连（`--off`、行删了）后由每分钟的清扫删掉。
- **只有转连的那台有这条路。** 别的机器经它转发去够（下一节）。
- 走这条路时连接读数是「经 SSH」（`Hop::Ssh`），设备表里转连那台到它的路是 `ssh`。
- 选路（`khor_net::carry::RoadOrder`）：直连、转连、中继依次；直连随时可以升上去；转连和中继之间，
  只在连接开头 3 秒里中继可以让给转连，之后只在用着的那条断了时才换。
- **添加机器时也走这条**（ROAD-3 轮）：`khor add` 装好、启动了 khor，配对却没连回来（「未在 60 秒内
  连接回来」）时，先不退回 SSH 主机：本机常驻经同一条 ssh 起一条转连（`ipc::Op::CarryFor`，它还
  不在表里，对面常驻也接——只有登录进去的人能让它的 `khor _carry` 走到这一步），稳住 3 秒后对面的
  `khor pair -` 经这条路再配一次（最多两次）；配上了就在它的行上写 `carrier` = 本机，从此照常转连，
  步骤「配对」后面写「经 SSH 转连」。都不成才退回 SSH 主机（`Node::pair_carried`，测试
  `a_machine_that_cannot_connect_back_pairs_over_the_ssh_it_was_added_by`）。
- **够不着中继就不等那 60 秒**（ROAD-4 轮）：「启动」之后、配对之前，开关开着时先经同一条 ssh 问对面
  `khor _relay-check`：本机的中继各发一个 GET，有一个答了说 yes，都没答说 no（10 秒为限，
  `join::RELAY_ASK`）。说 no 就直接走上面的转连配对；说 yes 或没说清，照常先等普通配对。
  同一局域网里没有中继的机器因此也是转连的成员，行上记着 `carrier`；iroh 找到直连时选路照样升上去
  （选路规则见上；局域网上没有实测）。
- **别的机器只读设备表时也写「通过 <转连那台>」**（ROAD-4 轮）：像卫星经担保机那样，一台机器到被转连
  成员没有自己的路时，由它到转连那台的路加上转连那台的 `ssh` 路拼出来（`roadbook::in_the_middle`、
  `through_sponsors`）。自己有路（直连、中继、转发、连不上）时用自己的。
- 开关：`khor config set ssh-carry on|off`（默认开，重启常驻生效）。两个开关都关时这个传输根本不注册。
- 测试：`crates/net/tests/carry.rs`（内存里的一条流），`crates/cli/tests/carry.rs`（真的非特权 sshd，
  被转连那台挂在不存在的中继和不存在的代理后面）。

### 经其他机器转发：两台够不着的机器，经一台两头都够得着的 khor 机器相连（2026-10-08，ROAD-3 轮）

甲要拨乙，和乙之间没有直连（上次不是直连，或者上次没拨通），网里有一台丙：设备表里丙到乙的路
是直连或丙自己的 ssh（丙转连乙），甲自己到丙有直连。甲就先在到丙的借网连接上开一条流说
「hop <乙>」，丙在自己到乙的借网连接上开一条流说「hop-in <甲>」，乙答应后丙把两条流对接、
两头来回拷字节。甲和乙在这条流上照常走 iroh 握手，丙只看见密文（`crates/node/src/hop.rs`）。

- **挑中间那台**：不是两端、不是卫星、本机没暂停它；它写的到乙的路是直连或 ssh，而且不是转发来的；
  甲到它是直连——或者经中继，但只限它用 ssh 转连乙时（那时乙谁也够不着，别的路都没有；它直连乙时，
  经中继到它不比经中继到乙强）。甲到它的路也不能是转发或 ssh。先挑甲直连的，再按两段往返之和。
  最多试两台，3 秒内没成就不转发，照常拨。
- **只转一次。** 丙到乙的路要是转发来的，丙不会被挑中，被问到也拒绝；丙给自己拨乙时也不再转发。
  主人说的「最多两跳」里，另一跳是局域网入口（`khor pipe --via`），不是再转一次。
- **选路**：和「khor 走 ssh」同一个 `RoadOrder`，转发和 ssh 都算「转连」一档：直连、转连、中继。
  甲拨乙时转发的地址和直连、中继的一起发出第一个包；中继先答也不要紧——vendor 的 iroh 打了补丁 6
  （`vendor/iroh/KHOR.md`），握手后仍把转发这条路补开，开头 3 秒里转过去，之后只在断了时才换。
  直连随时可以接手（iroh 自己打洞）；直连连着两次看（每 5 秒一次）都在，甲就放掉转发，丙不再替它拷。
- **门**：和借网同一条连接、同一个每条流的门（在名册上、没被暂停），再加两端各自的 `peer-hop` 开关和
  名册检查：丙要甲和乙都在自己名册上，乙要甲在自己名册上；乙已经用 ssh 转连着甲时不接转发。
  两句话里都有空格，不会被当成 `host:port`；老版本的出口把它当主机去连、连不上，答「无路」。
- **读数**：连接读数是「转发」（`Hop::Forwarded`），`Link.via` 是中间那台；设备表里甲到乙的路写成
  甲到丙那一段（直连或中继），`via` 写丙。本机那一行由 `roadbook::own_roads` 从活连接画出来，
  CLI 和 app 用同一个函数。
- **开关**：`khor config set peer-hop on|off`（默认开）。传输在常驻起来时注册（两个开关都关就不注册），
  `peer-hop` 本身每次拨号时读，所以关掉立即不再求转发、不再当中间那台。
- **测试**：`crates/cli/tests/carry.rs` 的 `a_third_machine_reaches_a_carried_member_through_its_carrier`
  （乙被切断、丙用 ssh 转连它；甲先关着开关够不着，开了之后经丙够到，两边都读「转发」，甲的路写上
  `via` 丙）；`crates/net/tests/carry.rs` 的中继先答那个测试。回环上量不出丢包和队头阻塞，要在机群上量。

### 长连接：每台对端一条，一直挂着（2026-10-03，NET-FIX 轮）

每台机器对网里每台对端**只拨一次**，之后所有请求——同步、列目录、拉文件、收下、
开会话、借网的管子——都走这条连接上的新流（`crates/node/src/wires.rs` 有全部规矩）。
以前同步泵每 5 秒拨一条、用完就扔，一分钟 12 次握手；iroh 只在**还有连接开着**的时候
记得打通的那条洞，最后一条一关它就忘，下一条连接把首包撒向所有地址（中继也在内）
再打一次洞。所以「打通了就复用」以前只在一条连接的寿命里成立，现在才真成立。

- **谁持有**：节点的 `Wires`，按（对端、协议）一条；借网的管子走另一条 ALPN，两条
  共用 iroh 对这台对端的同一份路径状态。各拨各的：别人拨进来的连接只应答，不借来问
  自己的问题（那头可能是个没人应答的一次性命令）。
- **保活**：iroh 自己每 5 秒一个 PING；对端的每个数据报（答复、保活的 ACK）都算「听到」。
- **退役**：15 秒没听到任何东西；发出请求 4 秒内什么都没回；QUIC 自己关了；网络变了
  （或刚睡醒）之后 3 秒没听到；端点换了。退役的那条上正在跑的请求立刻失败——读类请求
  在新连接上再问一次，写类不重问，说没连上，由人决定。别人拨进来、同样静默的连接也一并
  关掉：开着的旧连接会把下一次拨号引到死掉的那条路上（实测：对端重启后拨号整整 10 秒超时）。
- **退避**：拨不通的对端，后台的泵按 5、10、20、40 秒、最多 60 秒再拨；人点的请求不受退避。
- **请求的期限**：每种请求有自己的预算（`Request::budget`），但连接死没死不靠它，靠
  「听到没有」；对端处理请求是并发的（每条连接 32 个），慢的不挡快的。
- **同步**：所有对端并行，各自的预算；正在同步的对端被并入而不是再同步一遍；「立即同步」
  从不排在一轮后面；一台对端拨进来、本机又没有到它的连接，马上同步它一轮。

### 重拨时第一个读请求随握手走（0-RTT，2026-10-04，NET-3 轮）

连接退役后的下一个请求要重拨。如果这台常驻进程跟对端连过（手里有上一条连接留下的
TLS 会话票据），而这个请求是只读的（`Request::rides_early`：列目录、读一片文件、
读数、`git status`、比版本……），它就作为早期数据和握手一起发出去，对端收到马上答：
一个往返而不是两个（中继加 200 ms 往返实测：重拨后第一个答复 462 ms → 243 ms）。

早期数据谁截到了都能重放（RFC 9001 §9.2、RFC 8446 §8），所以规矩跟 HTTP 的
`Early-Data`（RFC 8470）一样：只放什么都不改、重答一遍也便宜的。同步（会合并）、
拉传输片（会记「开始了」）、要会话的 cookie、搜索（走一遍树值得重放）都不随握手走。
写类请求两头都等握手：本机握手完了才发；对端若收到一条随握手来的写请求，压着等
握手完成，握手没完成（重放永远完成不了，它没有密钥）就丢掉。实测：一个握手被截断
的早期「建目录」没有建出来，同样的请求握手完成了就建了（`crates/node/tests/early.rs`）。

一处 iroh 的行为要知道：对端那头的 `handshake_completed`，连接在握手完成前就断了，
它也回 `Ok`（丢了 noq 的那个布尔值）。所以「握手完成」在这里还得加一条：连接还开着。

### 文件和目录：没变的不送（2026-10-04，NET-4 轮）

- **打开的文件，回到窗口时**：只问「它现在是什么」（`Stat`：大小、修改时间、装得进
  一片的文件的摘要），变了才重读；最近读过的 24 个文件在脸上记着，再打开先问一句，
  没变就直接用。
- **目录树**：对端用系统的文件监视（`notify`：macOS 是 FSEvents，Linux 是 inotify）
  看着树上开着的那几层，变了就在长连接的一条流上说一声；常驻进程记着每台对端的变化
  计数，树来问「从计数 N 以来哪几层变了」，只重列那几层。回到一棵树、自己改了东西，
  都不再整棵重问；一分钟没人问的层放掉。看不了的（本机、卫星、网页脸、老版本）照旧问。
- **机器卡片的「一天」**：带上手里那份的戳，一天没动就不再送（每分钟最多动一次）。
- **按路径拉文件**：八片同时在路上；断了留着 `.khor-pull-<名>` 和旁边一张说明它是
  哪台、哪个文件、多大、何时改的纸条，再拉同一个文件就从断处接着拉，对端文件变了才从头。

### 走的是哪条路，看得见（批⑦，2026-08-21；2026-10-03 改为读长连接）

「同一个网络还需不需要中继」——用户问过，而 khor 以前答不出来。现在
`khor devices` 和机器卡片每台机器后面带一个读数（`khor_core::Link`）。

**读的是那条长连接选中的路**，两次采样（相隔 1 秒）一致才换词，路被重新选的那一瞬
不算换路。三个词：`直连`、`中继`、`未连接`（没有连接，或连接静默被收回），外加
`serve 未运行`（本机没有常驻——**有解**）。活性在词旁边另一根轴上：多久前听到它；
未连接的行写成「未连接 · 上次 3 分钟前」，连着的行不写（保活每几秒就听到一次）。

⚠️ 墓碑（2026-10-03）：这里原来读 iroh 的 `remote_info`，数它还标着「开着」的地址。
那张表连接关了也不清，所以冻住 40 秒的对端 225 次采样全报「直连」；当时的第五个词
`说不出` 代表五件不相干的事（表里没有、状态查询失败、答得晚、少一行、手机换了端点），
没有一件是「路不知道」。现在各说各的；常驻没答上来就保留上一次的读数（按过去的时间
加龄），一次读数都没有就不写词。`khor doctor` 的「连接诊断」一行带长连接的计数
（拨号、各种退役、答得晚、重问、各个词出现了几次、网络变化、状态查询超时），
以后谁的屏幕上出现了什么词，查得到是哪里来的。

读数只有活着的 endpoint 答得出，所以走 serve 的 handoff（`ipc::Op::Hops`）。

**另两个读数：首包时间和直连占比**（2026-09-30，CONNECT.md「度量与验收」）。
serve 在拨号的那一道门（`Node::dial_with`）上记：从发起到对端第一次应答（握手
完成，含中继让直连先跑的那段）的毫秒数，和这条连接最后落在哪条路上——看它
10 秒，期间直连选中过就算直连，否则算它最后在的那条。每台对端留最近 20 次。
有了长连接以后拨号很少，这两个数记的是每条长连接开头的那几秒。
只记本机**发起**的连接，只在内存里，serve 重启就重新数。`khor doctor` 的
「连接诊断」一行逐台打印（`alpha 首包 15ms，直连 1/1`），设置→网络的「状态」组
有一行全网汇总的「直连占比」。同样只有 serve 答得出（`ipc::Op::Roads`）；
没有 serve 就说 serve 未运行，不画成零。
**没有「自己 bind 一个 endpoint」的回退**：刚 bind 的 endpoint 谁也没聊过，
会把整个网报成「没在连」——一个自信的、错的、而且完全说得通的答案。

挂账：只在一台机器上的本地节点验过（`crates/cli/tests/wires.rs`，只用本机回环上的
临时中继），**没有跨机器的真中继样本**，所以「中继」那一档和直连、中继之间的切换是按
代码路径推的、不是量到的。

## 网页脸的暴露面

**这一段和上面几段不是同一张网。** 上面讲的是 iroh：加密、认设备身份、
打洞或走中继。网页脸是一条**普通的局域网 TCP 口**（默认 5467，
`KHOR_WEB_PORT` 可改），由 serve 常驻开着，给的是浏览器——它不走 mesh，
也不认设备身份，所以它的安全性一条都不能从上面几段推。

- **直接听局域网，不做「默认 localhost、说一声才开」。** 这张脸的用处
  就是一台不是本机的手机，那个默认等于功能默认关着。
- **钥匙一律要，localhost 也要**（2026-08-21 用户裁）。两个洞：
  turing/hinton 是多用户机器，`127.0.0.1` 对同机每个账号都可达；
  以及 DNS rebinding——恶意网页借你自己的浏览器发请求。
- 钥匙是 khor 发的不是用户设的：128 位随机，`.khor/web.key` 0600，
  **不进任何同步文档**（复制文档不携带秘密）。`khor web` 打印带钥匙的
  链接和二维码，`khor web --new` 换一把、旧链接当场作废。
- **Host 必须是地址不是名字**：rebinding 时页面在 evil.com、名字解析到
  你的内网 IP，而请求里的 `Host:` 仍是那个名字。localhost 和 `.local`
  是仅有的例外——网外的人解析不到它们。
- **Origin 同源或没有**；一个 CORS 头都不发。没有它正是保险：即便钥匙
  泄了，外部页面也读不到应答。
- **不做 TLS、不碰公网**（挂账）。这张脸是给机器已经在的那张网的；
  往外暴露是另一个产品、另一套威胁模型，而且给一个私网 IP 签证书
  这件事本身就没法诚实地做。
- **macOS 上第一次会被系统拦一次**：应用防火墙对没签名的二进制豁免
  loopback、吞掉别的——症状是握手连得上、数据一个字节不来。所以
  `khor web` 探的是**它要印出去的那个地址**、而且探一次完整的请求-应答，
  探不通就拒绝印链接并说出这两种成因。

## 同步

走 CRDT：无中心 + 离线可写 + 合并不丢，三个约束的唯一交集。
代价是历史不可删、每台全量副本——所以只放小的决定类数据。

| 数据 | 怎么走 | 为什么 |
|---|---|---|
| 设备表 | CRDT，全网复制 | 入网即见全网靠它 |
| 名单（根签名，2026-09-30） | 随设备表的文档走，在表旁一张图里，每签一版一个键；各行另带那台的证书 | 读时验签取 seq 最大，后写赢不决定信任：谁都能往文档里写一份旧名单，但写不出一份新的 |
| 中继配置 | 不同步：每台自己的文件，地址随设备表的地址提示与配对票外传 | 改名单等于改流量去向，只许本机改（2026-09-29 按代码更正，原写「CRDT，全网复制」） |
| 账户表（有哪些智能体账户） | CRDT，全网复制 | 是决定，不是凭据 |
| 对话 | CRDT，全网复制 | 离线可写 |
| 已读状态 | CRDT，全网复制 | 看过是决定：手机看了，桌面角标同步清 |
| session 名字（用户起的） | CRDT，全网复制 | 起名是决定，盖在派生名上；派生名照常在底下流（sweep 每轮重算它），显示时才盖——所以清空即撤销，派生名原样露出 |
| 机器名字（用户起的） | CRDT，设备表的一个字段 | 和 session 名字同一条规矩，而这里有一层它没有的：机器还有一个**频道名**，是 `chat/<名字>` 那个目录、以及已读水位和置顶跨网一张表的键。频道每个店只定一次，改名只动人看的那个，所以改名动不了任何目录或键。改 OS 主机名从此不改 khor 显示的名字——那是这条的代价，也是它成立的原因 |
| 卫星标记（sponsor/ssh 目的地/tmux 探测） | CRDT，设备表的三个字段 | 领养是决定；ssh 目的地只在 sponsor 的 config 里有意义，但它是决定不是凭据，进表让 sponsor 重启后还认得路 |
| 工作区（哪台机器上的哪个目录） | CRDT，全网复制。键 `<机器 id>:<绝对路径>`，一个键三态：不是 / 是 / 是且置顶 | 工作区是人立的，不是推出来的（[WORKSPACE.md](WORKSPACE.md)）——立一个是决定，所以在手机上加的目录，桌面打开就在。id 不用名字：改名不能孤儿化。移出写墓碑值（0）而不删键，跟置顶同一个寄存器同一条合并规则 |
| 最近去过（目录 / 网页） | CRDT，全网复制 | 人的记忆跨设备，屏幕的状态归屏幕：标签页开着什么是那块屏的事（存本地），去过哪儿是这个人的事。「别再提示这个」是墓碑（值 0），跟着一起走 |
| API 密钥（账户凭据） | 点对点直传，落本机钥匙串：入网拉全量；账户表行带 key 指纹，见新账户或指纹变了补拉 | 效果同全网同步；不走 CRDT 因为历史删不掉，换 key 会永久留旧的 |
| session 状态 | 不同步，问 home 现拿 | 活的，存副本必过期 |
| 机器状态（CPU/GPU/内存/磁盘） | 不同步，问现拿 | 同上 |
| 文件内容 | 摘要（名、大小、缩略图）先到；字节等许可，从发端拉 | 大件落盘要经人手，不自动吃流量磁盘 |

### 一轮先比版本，只送不同的（2026-10-03，NET-3 轮）

泵每 5 秒对每台对端一轮。一轮先问一句 `Versions`：本机每份文档的版本
摘要（版本向量按 peer 排好再取 blake3 前 16 字节——loro 自己的编码走哈希表，
两台同版本也可能编得不一样），加上本机手里那台的每项读数（行、体征、关注
目录、一天、额度、花费、卫星体征）上回答案的摘要。对端只回不同的：版本不同
的文档带上它的版本向量，本机对这几份各同步一次（已知对端版本，第一次就推，
不用先拉一轮）；变了的读数整份回在答案里，没提到的读数就是手里那份，原样再
写一遍缓存，年龄照旧是这一轮的。一天这项读数按分钟追加，问的时候带上手里那
份的最后一分钟（`days@<分钟>`），回的是那之后的格子；本机拼好后对一遍整份的
摘要，对不上就整份再要。一轮推过东西，读数再问一次：对端的行是从刚推过去的
文档里推出来的（看过的水位把「完成」变成「空闲」）。

同 CouchDB 的 `_revs_diff`、Syncthing 的索引 id 加最大序号、Automerge 的
heads 一个形状：先说自己在哪儿，再只送差的。不同的是版本是文档本身的摘要，
不在两轮之间记任何标记，所以重启、重连、第二个提问的都不会因为记错了而少送。
老版本的 khor 不认这句话，整帧拒掉，本机就照老办法同步（每份文档两次往返、
每项读数都问），两边照样收敛（`crates/cli/tests/sync_mixed.rs`）。

冲突规则设计时定死，运行时不问用户：追加取并集，字段各自合，
同字段后写赢（逻辑时钟），删除赢过修改。两边必然收敛到同一结果。

历史清理是显式动作，不自动跑：loro shallow snapshot 截掉修剪线之前的
历史（官方实测省七到九成，撤回的正文也在这时才物理消失）。修剪线必须
划在**全网每台都同步过**的版本之前——落在线后的设备，旧增量进不来、
新增量算不出，只能全量重置。所以清理线 = 各设备已确认版本的交集，
离线的设备会把线钉住；强制越线要把代价说破。

## 验收

网络类改动必须真连验证（同机双配置目录即可），且带对照组：不该通的真的不通。
编译绿、单测绿挡不住这一类。
