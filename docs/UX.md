# UX

界面的判据，每条可证伪：新界面过不了哪条，改界面或改这条。

## 姿势

- 手机是「处理一件事」：一次一屏，有退路。
- 桌面是「在这里工作」：列表常驻，没有「返回」——要看别的，点列表。
- 两端对齐的是事实，不是控件：同一台机器同一张脸、同一状态同一个词、
  同一颜色同一含义；但一端的返回按钮不因另一端而存在。

## 状态呈现

- 状态词只从状态机出，界面不许自己推一遍。六词之外无第七词。
- 角标可归零是铁律：只数待批与未读的变化——一个答了清，一个看了清。
  看了也不清的事实（失败沉底）占列表，不占角标。
- 「做了但没变化」和「失败」长不一样的脸——都不报错，但用户分得出。
- 不知道就说不知道，判据在 SESSION.md 离线一节。

## 文案

- 全部界面词汇出自一份语料库：线上传稳定键，词在呈现层最后一刻查表。
  语料库是数据文件（`crates/catalog/zh.toml`），构建时生成 Rust（CLI）与
  TS（GUI，`gen_ts` 印出）两份常量——改措辞、加语言只动一个文件，
  两端永不漂移。同节内两个键不许共用一句话（构建期报错）：
  按名拒绝，名字得真的不同。
- 不解释实现：用户的词汇表里没有 CRDT、中继、tmux。
- 装饰性说明归零：需要说明文字的设计，先改设计。
- 状态词是名词短语不是口语：「忙碌」，不是「跑着呢」。

## 设置

- 默认优先于设置：行为对齐成熟产品，不开开关。
- 一个点要升成设置，两判据同时满足：真实用户站在两侧，
  且没有一个默认能同时伺候两侧。
- 升成了也藏深，不上首屏。
