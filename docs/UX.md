# UX

界面的判据，每条可证伪：新界面过不了哪条，改界面或改这条。

## 姿势

- 姿势跟宽度走，不跟设备走（2026-08-16 改口，微信 4.0/Telegram 先例；
  上一版按设备分）。**宽档**是「在这里工作」：细栏、列表、详情并列，
  列表常驻，没有「返回」。**窄档**是「处理一件事」：一次一屏，有退路。
  手机永远是窄档；桌面窗口缩过阈值也落进窄档。
- 返回只存在于窄档：那里列表真的不在屏上，返回才有对象。
  宽档出现返回按钮即是 bug。
- **落点分两种语法，判据是「那张列表要不要一直盯着」**（2026-08-25 裁决）。
  **收件箱型**（会话、机器）：列表本身就是在看的东西——它会变，变了要知道——
  所以列表常驻，详情并排。**浏览型**（文件、浏览器）：列表只是「去哪儿」的
  前置一问，答完就没用了，所以不给它留一栏，改用标签页 + 地址栏
  （一个标签 = 一台机器 + 一个地方）。
  两个方向都可证伪：收件箱型在宽档一次一屏是 bug；浏览型留着常驻机器栏也是 bug。
  它挡不住的是「列表其实要盯着而我判成了浏览型」——那要靠问一句
  「不看它会漏掉什么」，漏得掉的才是收件箱。
  （窄档的浏览型同样没有返回：它没有列表可退，退路是标签切换器。
  文件落点和浏览落点都已经这样了——**「浏览器还穿着旧壳，二期换」
  这句 2026-09-11 结掉，壳早换了**；欠的是标签体自己的几处
  （地址栏不跟 `pushState`、后退判据、换出口要重载全部标签），
  那几处记在 `docs/handoff/001.md`，不是壳的事。）
- 断点只有一份出处（壳从它打 data 属性，CSS 不另写 @media）。
- 两端对齐的是事实，不是控件：同一台机器同一张脸、同一状态同一个词、
  同一颜色同一含义；控件的去留由宽度档定，不因另一端而存在。

## 状态呈现

- 状态词只从状态机出，界面不许自己推一遍。六词之外无第七词。
- 角标可归零是铁律：只数待批与未读的变化——一个答了清，一个看了清。
  看了也不清的事实（失败沉底）占列表，不占角标。
- **角标数的是行，不是事。** 一行既待批又未读，它只想要你一次；原来那份
  实现把两个条件相加，于是两行能显示成 4——一个在列表里指不出对应物的
  数字。「有几件事想要你」的答案上限永远是行数。
- 「做了但没变化」和「失败」长不一样的脸——都不报错，但用户分得出。
- 不知道就说不知道，判据在 SESSION.md 离线一节。

## 文案

- 全部界面词汇出自一份语料库：线上传稳定键，词在呈现层最后一刻查表。
  语料库是数据文件（`crates/catalog/zh.toml`），构建时生成 Rust（CLI）与
  TS（GUI，`gen_ts` 印出）两份常量——改措辞、加语言只动一个文件，
  两端永不漂移。同节内两个键不许共用一句话（构建期报错）：
  按名拒绝，名字得真的不同。
- 不解释实现：用户的词汇表里没有 CRDT、中继、tmux。
- 装饰性说明归零：需要说明文字的设计，先改设计。
- 状态词是名词短语不是口语：「忙碌」，不是「跑着呢」。

## 设置

- 默认优先于设置：行为对齐成熟产品，不开开关。
- 一个点要升成设置，两判据同时满足：真实用户站在两侧，
  且没有一个默认能同时伺候两侧。
- 升成了也藏深，不上首屏。
