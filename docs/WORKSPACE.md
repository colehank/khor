# 工作区

一个工作区 = **一台机器上的一个目录**，由人指定。

## 为什么是人立的

khor 原先是推的：读各家 agent 的会话记录，把 cwd 沿 `.git` 往上折到仓库根，
是仓库的就当工作区。2026-09-14 用户否掉了这条路，两句原话：

> 用户有agent记录的目录不一定是工作区.可能只是随手打开的

> git目录也不一定是工作区.很多工作区开始的时候不是git目录,或用户根本就没想着用git管理

盘上没有任何东西能说明「这是我在做的事」。所以工作区是一条**决定**，
决定就复制（[NET.md](NET.md) 同步），和置顶、已读、起名同一类。

派生的那条路整段删了（`Node::workspaces_shown`、`Request::Workspaces`、
`Place.checkout`）。**留下来的是 `crates/node/src/place.rs`**：
它现在只喂新建会话向导的「常去的地方」——「可以从哪儿开一个会话」是建议，
和「我在做什么」是两回事，前者推得出来，后者推不出来。

## 身份与名字

- 身份是 `(device_id, 绝对路径)`。同一个仓库 clone 到三台机器上就是三个工作区：
  三块盘、三份未提交的改动、三个「什么时候改的」。
- **名字就是目录的 basename**（`~/working/test` → `test`），不另起、不改名。
  存下来的名字会和它指向的目录漂移，而识别这一行的是路径。
- 机器从设备表里没了（`khor forget` 之后），行还在，机器名留空：
  目录还在那块盘上，藏掉这行等于让它再也移不掉。这种行有两条硬规矩：

  - **不问它任何问题。** 空机器名在节点端的意思是「本机」，所以拿它去问
    git 或者上次改动，答回来的是**本机**的分支和时间，画在别的机器的路径
    下面。这正是这仓库命名过的那个病：答不了的分支不留白，变成它的邻居——
    而这里的邻居是可信的，所以更糟。列表两个角直接留空，一个请求都不发。
  - **置顶和移出按 device id 走，不经过机器名。** 名字是空的，
    `resolve` 会把空名解析成本机，于是写到另一块盘的键上去。
    `Node::ws_rm` / `ws_pin` 收的是 id；`khor ws ls` 在这种行的机器列里
    印完整的 id（屏幕上留空，因为那一列是给人读的，不是给人敲的），
    `khor ws rm -m <id> <目录>` 就能把它摘掉。

## 一行的四个角

| 位置 | 内容 |
|---|---|
| 左上 | 名字 + 机器头像 |
| 左下 | `机器名:绝对路径`（不缩成 `~`——那是对面那台机器的家，这张表里混着好几台） |
| 右上 | git status：分支 + 几个文件改过。**不是仓库就整个留空**，不写「无 git」 |
| 右下 | 上次改动（`ago()`） |

排序：置顶在前；其余按上次改动倒序；问不到时间的排最后；同时间按路径。

右上右下这两个角要问**持有文件的那台机器**，一行一问，
回窗口时重问一遍、不上定时器（和 `WorkspacePane` 的 git 标记同一条规矩）。
**机器答不上来只丢那个角，不丢那一行**：把「拒答」画成「没有」，
会把人支到别处去找，而不是去看那台机器。

「上次改动」= 那个目录下最新的**文件** mtime，不是会话时间——
手改的、用 ssh 改的、工具写的都算，这些都不开 khor 会话。
跳过 `.git`、`node_modules`、`target`、`.venv`、`__pycache__`、`dist`、`build`
（一次 `cargo build` 否则会把整张榜单重排）；走到 20000 个条目封顶，
封顶就答已经见到的最大值——**它是个时间，不是承诺**。

## 同步表

`crates/sync/src/workspaces.rs`，存在 `.khor/workspaces`。

- 键 `<device_hex>:<绝对路径>`。用 id 不用名字：改名不能孤儿化。
  device hex 定长小写十六进制，所以第一个 `:` 一定是分界，路径里带冒号也不怕。
- 每键一个 LWW 寄存器，三态：`No`（不是工作区）/ `Yes` / `Pinned`。
  置顶不另开一张表——「给不是工作区的行置顶」这种状态，两张表才装得下。
- **移出写 `No`，不删键。** 不是因为删不传播（loro 的删除会传），
  而是一个寄存器一条合并规则就够，并且读的人不该分得出「移出过」和「从没加过」。
- 移出**不碰目录**（用户 2026-09-14）。
- 同值不重写：版本向量不会为一次没变化的点击涨一格。

## 命令行

| 命令 | 做什么 |
|---|---|
| `khor ws ls` | 每行：置顶标记、名字、`机器:路径`，制表符分隔 |
| `khor ws add [-m 机器] <目录>` | 加一个。本机可以写 `.`；**会先验证那是个目录**——本机走 fs，别的机器走 `Ls`，卫星经 sponsor 走同一条路 |
| `khor ws rm [-m 机器] <目录>` | 移出这张表，目录一个字节不动 |
| `khor ws pin` / `unpin [-m 机器] <目录>` | 排到最前面 / 放回去（仍是工作区） |

`-m` 认机器名，也认 device id——一行的机器要是已经不在设备表里，
id 就是它仅剩的名字。

只有 `add` 会出网，而且只为了问一句「那是目录吗」。`ls` 读本机自己那份表。

## 怎么加一个

界面上按列表头的 `+`，开跨机器目录选择器（`components/DirPicker.tsx`）：
上面挑机器，中间走目录树（只列子目录，`Ls` 那条路，卫星经 sponsor），
底下一个路径框——树点不到的目录也得能到。**选择器什么都不验证**：
那是 `ws_add` 的事，它拿 `Ls` 去问那台机器，答不上来就把那台机器自己的话
留在对话框里、框不关。

同一个选择器也是新建会话向导「目录」框旁边那个「挑…」——
「哪台机器上的哪个目录」是同一个问题，两块屏幕就会有一块忘了卫星。
向导那个框本身没动：打字、常去的地方、选择器，三条路都写进同一个框。

## 里面的会话

工作区页右栏列的是**在这台机器上、这个目录底下跑的会话**，两个条件缺一不可：

1. `会话.home 频道名 === 这个工作区机器的频道名`
2. `cwd === 目录 || cwd 以 目录 + "/" 开头`

第二条那个斜杠是硬的——`/home/peer/workshop` 是 `/home/peer/work` 的邻居，
不是它的孩子，少一个分隔符就会把邻居收进来。

第一条同样是硬的，因为**工作区的身份本来就是 `(机器, 目录)`**：两台机器上
都有 `~/w/khor` 就是两个工作区，只按路径比会把另一台的活儿列进来——
而这一栏是特意不重复说机器的（下面 `showVia` 那段），屏幕上没有任何东西
会露馅。这就是这仓库最老的那个毛病：**答不了的分支不留白，变成它的邻居。**

**按 id 解析成频道名再比，不按显示名。** `SessionRow.home` 是频道名
（`DeviceInfo::name`），而 `WorkspaceInfo.machine` 是显示名
（`DeviceInfo::shown()` —— 有标签就是标签）。两者在没改过名时相等，
改过名之后不等，于是「拿显示名去比」会一直好用到某一天，然后**静默地
一行都匹配不上**。所以由 shell 拿工作区的 device id 去设备表里查频道名
（`App` 那条「Compared by channel, never by the name on the glass」的规矩），
查不到就是这一栏空着——机器都叫不出名字，就没法说什么东西「在这儿」跑，
空栏是事实，邻居的行是谎。

为此 `SessionRow.place` 从 2026-09-15 起**存原始 cwd，不再折到 git 根**
（`khor_node::live::place_of`）。折叠只剩「常去的地方」还在做，且只在
`Node::places` 那一处做。理由是这条问题折过就问不了：工作区立在
`~/w/paper/data`，而在那儿开的会话折完报的是 `~/w/paper`，对不上；
反过来工作区立在仓库根上，子目录里的会话全归它——看着对，其实是巧合，
因为只有折叠恰好停在那一级时，「折到同一处」和「在子树里」才一致。
**原始路径随时能折，折过的路径回不去。**

代价写在明处：会话列表按「地点」分组，现在一个仓库的两层是两个标题。
这笔账付在那条轴上，不付在数据里。

右栏用的就是 `SessionsList` 本身，只关掉「再说一遍机器」那一项
（`showVia`）——上面的头已经说过这是哪台机器的哪个目录了。行上的置顶、
关闭、转形态跟会话落地页一模一样：同样的行少几个动词，是要人学两遍的东西。

## 删文件

树上右键一个文件或目录 → 删掉（用户裁决 2026-09-14：「khor 可以删文件啊，
用户仍然右键某个文件可以删除。但提示，跟 VS Code 一样，可以不再提醒」）。

确认框按后果分三句，**不是一句换个词**——「进废纸篓」能捞回来、「直接删」
捞不回来，这两件事的差别不该变成措辞的差别：

| 情况 | 句子 |
|---|---|
| 本机的文件 | 「X」放进废纸篓 |
| 本机的目录 | 「X」连里面的东西一起放进废纸篓 |
| 别的机器、卫星、以及**本机但这个平台没有废纸篓**（iOS/Android） | 「X」直接删掉，找不回来；目录连里面的一起走 |

哪一句由**节点**答（`files::TRASH_HERE` + 路径在谁的盘上），不由屏幕猜平台：
同一张网页也会发给一台手机去看某台桌面的脸。

**「以后不再问」只静音废纸篓那一档。** 不可恢复的动作不该被一个勾永久静音——
那个勾没有任何界面能找回来改，所以它绝不能罩住「错了就回不来」的那一档。
勾存在这台浏览器的 localStorage 里（`khor.remove-never-ask`），和列宽同一类：
是习惯，不是关于这张网的决定。

移出工作区仍然不碰目录（上面「同步表」那节）——**移出**和**删掉**是两件事。

命令行是 `khor rm [-m 机器] <路径>`，同样的规矩：本机进废纸篓，别处直接删。

### 废纸篓这个依赖花了多少

三个候选各自量了 `Cargo.lock` diff，不是估的：

| 候选 | 新包 | 覆盖 |
|---|---|---|
| `trash` 5.2.9（MIT） | **+2**（`trash`、`urlencoding`，都是 MIT） | macOS + Windows + Linux |
| `objc2-foundation` 的 `NSFileManager`（tauri 已经带进树里） | +0 | 只有 macOS |
| 自己写（Linux 的 freedesktop `.trashinfo` + Windows 的 `IFileOperation`） | +0 | 手写规范——「尽量用成熟库，不自写」正是用来否掉这个的 |

选了第一个。判据是**覆盖三个桌面**，两个小 MIT 包是最便宜的办法；省下它们
就等于告诉一个 Windows 用户「删了找不回来」，而本来不必如此——
不可恢复的动作是最不该省成本的地方。

## 文件怎么打开

用户裁决（2026-09-14）：「pdf 你咋转成字符了，应该直接预览。还有，所有代码、
md 文件，打开先是源码，要有语法高亮。然后对于支持预览的文件，如 md，显示预览。」

| 文件 | 打开成什么 |
|---|---|
| 代码、md、csv/tsv、任何文本 | **源码**：语法高亮、可编辑、能存、三方合并、git gutter |
| md、csv/tsv | 源码之外还有一个**预览**，头上一个开关切；**默认永远源码，不记忆** |
| png/jpg/… 、svg | 浏览器自己画（svg 走 `<img>`，不让它的脚本跑） |
| **pdf** | 浏览器自己画：`blob:` 喂 `<iframe>`。画不了的平台退回抽字 |
| docx/xlsx/pptx 和三个旧格式 | 抽成 markdown 渲染出来，底下写明「读的是文字和结构，不是排版」 |

**md/csv/tsv 从「文档」路搬回文本路**（2026-09-15）。它们本来就是文本，
被当成文档的代价是：md 存不了、没有保存承诺、三方合并够不着、gutter 不画——
而这个项目本身就是用 md 写的。预览渲的是**当前缓冲区**，一边打字一边动：
这正是它该是一张「脸」而不是一种「类型」的理由——晚一次保存的渲染视图，
显示的是没有人手上有的那份文档。

csv 的表也随之从节点搬到前端（`lib/csv.ts`，RFC 4180），
把 `csv` crate 还了回去：**最后一个调用方走了，依赖也该走**。

### PDF：三个平台原生，两个退回抽字

`preview::PDF_HERE` 是一个 `cfg` 常量：macOS / iOS / Windows 为 true
（WebKit 的 PDFKit、WebView2 的 Chromium 查看器），
Linux(WebKitGTK) / Android 为 false——**那两个平台的浏览器不带 PDF 查看器**。
false 时走 pdfboss 抽字那条路，脸上写明给的是文字不是版式。

**这个常量由节点答、前端问一次**，不从 `navigator` 猜平台：同一张网页
也会发给一台手机去看某台桌面的脸。

**没有引 pdf.js。** 一兆的前端，去做三个平台本来就会做的事；
而剩下那两个平台，正是原本就得把它装进去的两个。那四个 pdfboss 包现在买的
是**退路**，不是脸——数和当初的比价都留在 `preview.rs` 的模块头里。

### 高亮（2026-09-15）

两句裁决：「我说的语法高亮，是有颜色的」「应该用已有成熟工具啊。做到 gh web
预览代码的那种高亮」。落法：**Shiki**——VS Code 那套 TextMate 语法，配 GitHub
自己发布的 `github-light-default` / `github-dark-default` 主题，也就是 github.com
上画的那套颜色，一个都不是 khor 挑的。引擎用纯 JS 正则（不带 wasm、不异步初始化），
语法按需懒加载（一个 .py 只多下 Python 一份语法），`crates/web/build.rs` 递归打包
`dist`，懒加载在网页脸上一样走得通。每个 token 的 span 上带两套颜色的 CSS 变量，
`app.css` 只做亮暗切换（跟 `tokens.css` 同一条 media query）。

装了 16 个 npm 包，全 MIT；highlight.js 与手写的 `--code-*` 调色板一并删除。
中间有过一版手写九角色映射（39eb05f），当天被这两句裁决替掉。

`check-face` 读的是**画在玻璃上的颜色**，不是 DOM 里的类名：.rs 的 span 之间至少
三种着色、且至少一种 ≠ 正文；`check-read` 按文本找到字符串/注释/关键字三个 span，
断言三者互不相同、且都 ≠ 正文。

### 树

- 根就是天花板：没有「上一级」行，没有地址栏，任何操作都走不到根之外。
- 目录行前一个折叠符，点击展开、再点收起；子目录**展开时才问** `ls`，一个目录一次。
  展开状态按工作区记在本机存储里，重开找得回。
- 「浏览」页看整机文件的那棵仍是 `FilesPane`（上一级、地址栏在那儿有意义），
  两者只共用行上的东西：右键删除、git 标记、拉过来。

### git 标记：VS Code 的颜色与字母

- 字母在行末右对齐，**文件名同色**。四种墨各带深色版，都是 git 自己的，不是六个状态词的颜色，
  也不是品牌绿（那条规矩是它不载字）：M 黄、A/U 绿、D 红、C 红。
- 节点补两个字母：`C` 冲突、`R` 改名（以前都折成 M）。`khor git status` 同步打出来。
- 目录行还是「·」，染子树里最重的那种墨（C > D > M > A/U）。
- **拿不到 git 就一个字不说**：没有标记、没有句子。「不是 checkout」和「读不了」在脸上是同一件事：
  没有颜色。

### 文件：随宽度换行

- 默认换行，**没有开关**——行号就是干这个的。
- 代价明说：编辑是「透明 textarea 叠在着色的 pre 上」，行号与 diff 侧栏原来按
  「一行 = 一个行高」乘出来；换行后改为**每行一个块、行号和侧栏读真实行高**。
  pre 与 textarea 用同一套 `pre-wrap` 规则，同宽同字体下两者换行一致，
  `check-face` 原有的「光标对墨迹」探针继续盯漂移，并新增一条：一行超宽的文件，页面不许横向滚。

### 标签页

- 中栏顶上是 `TabStrip`，一个文件一个标签：上行文件名，下行相对工作区根的路径。
  标签 id = `机器:绝对路径`，开着的标签按工作区记在本机存储里。
- 单击树上的文件开的是**预览标签**（斜体），下一次单击替换它；双击、或在里面打了字，就钉住。
- 有草稿的标签戴 VS Code 的实心圆点，代替 ×；**存成功圆点消失**。关一个有草稿的标签问
  「保存 / 不保存 / 取消」。
- 标签右键：关闭、关闭其他、复制路径、复制相对路径。`⌘W` 关当前标签。
- 条的最右三个图标：文件树、会话列、VS Code。**原来的头整行删掉**：名字在侧边栏，分支在侧边栏那行的右上角，
  「N 个文件未存」变成了每个标签自己的圆点。

### 会话列：全功能

- 就是会话落地页那套 `PaneBar` + `SessionsList`：搜索、筛选、排列、`+`。
  选项由两边共用的 `lib/session-filter.ts` 生成，不各算一遍。
- **筛选只给六个状态词。** 另外三根轴（机器、类别、地方）里有两根就是这一栏本身
  ——它是一台机器上一个目录——勾它们只会把栏清空，而屏幕上没有任何东西说得出为什么。
- **搜索框的字是当下的、不记；勾中的词记在这一栏自己的键上**（`khor.filter.workspace-sessions`），
  不跟会话落地页共用：落地页的勾里有机器和目录，搬过来会让这一栏整片空掉。
  一个键管所有工作区，不是一个工作区一个——勾是「我怎么看这张表」的姿势，
  和排布同类，和置顶不同类。
- **排布用的是外面那一个。** 全 app 只有一次 `rows` 轮询，排序是节点做的
  （`khor_node::list::Arrange`），所以这一栏改排布，会话落地页跟着改；这笔账写在明处。
- `+` 开现有的新建向导，机器与目录预填成这个工作区——这就是最早说的「加入我的工作区」。
  传下去的是**频道名**，不是玻璃上那个名字：向导把收到的名字原样交给节点。
- 两条顺手的：这个工作区里的会话从 busy 变到别的状态时，git 标记重问一次
  （khor 里最常改文件的是 agent）；打开的文件在盘上变了，没草稿就直接换新内容，有草稿维持
  「存的时候报冲突」。

## 第三轮：看得清、就地、跟 vscode 一样（2026-09-16）

用户看过第二轮落地的桌面后给了七条，原话按序记下：

1. 「文件 list 的状态点太小了，小到现在都看不清是什么颜色。」
2. 「list 宽度折叠的时候，优先折叠 branch 名，保留工作区名。」
3. （这条问的是标签页，答完了；但顺手抓到一个 bug：单击一个**已经钉住**的标签，
   它会退回成预览标签——VS Code 从不把钉住的标签降级。）
4. 「文件里，有改动或 git 差异的那个竖线，是要有颜色的，和现在的 git 状态颜色
   一致。点击后，不要在下面一行显示情况。就地显示。跟 vscode 一样。」
5. 「一个工作区被选中了没有任何状态。」
6. 「取消源码/预览的按钮，放在页面的右上角那，如果可预览，就是一个预览的 icon，
   再次点击回到源码。」
7. 「取消 git 文件上方的状态栏，比如现在的"1 处改动 第 1 处"。然后，右侧滑动条
   后方，就是全文件带颜色的 git 差异的那个竖线。跟 vscode 一样。」

### 目录那个点：一个看得见的圆

- `fileRow.tsx` 的 `DOT` 从「·」换成一个 `size-2`（8px）的实心圆，画法是
  `size-2 rounded-full bg-current`，不是一个字符。
- **理由是这个标记要说的话全在颜色里**：一个中点在行的字体里只有三四像素的墨，
  量出来 6.6×16——那点墨在列表被读的距离上分不出黄和绿。8 是 VS Code 给它的尺寸。
- **不画成字符，因为「一个 `·` 有多大」是字体的决定**，前端问不到；一个按
  `size-2` 要来的圆在哪台机器上都是 8。字符留在 `data-git-mark` 属性里，
  那是 DOM 里分「折上来的点」和「一个字母」用的。
- 墨仍然是 `markInk()` 一次决定：字母、文件名、这个圆共用它。`bg-current` 而不是
  第二个背景类——同一个选择写两遍，总有一天会在某一行上不一致。

### 一行的两个角：先折分支

「优先折叠 branch 名，保留工作区名。」落成普通的 flex 收缩，但把亏空安排到只有
一个地方可去：

| 角 | 之前 | 现在 |
|---|---|---|
| 名字 | `truncate` | `min-w-0 truncate`（自然基准，唯一能收缩的） |
| 分支 | `ml-auto shrink-0 truncate` | `min-w-0 flex-1 truncate text-right`（基准 0，只吃剩下的） |

分支的 `flex-basis` 是 0，所以它一个像素都不参与分摊亏空：宽的时候它长到剩余
宽度（和 `ml-auto` 画出来一样），窄的时候它先在自己那个盒子里截断，一直截到没有。
名字只有在它一个人都放不下时才开始截。第二行同一形状反过来：路径可以截，
**时间不可以**——一个掉了尾巴的「上次改动」读起来是另一段时长。

### 钉住的标签不会被单击降级

`WorkspacePane` 的 `open()`：一个已经在条上、且不是预览的标签，被单击时
**不再** `setPreview(path)`。原来会，于是从那一刻起，树上下一次点击就会把它
坐掉——一个人特意留下的标签，消失在一个和「留不留」无关的手势下。
VS Code 从不降级任何标签；标签是被关掉才走的。

### 竖线有颜色，原文就地打开

- **gutter 的 bar 穿 git 自己的四种墨**（`tokens.css --git-*`）：改动是 M 的黄、
  纯新增是 A/U 的绿、纯删除是 D 的红。之前是 `--git-mark`（正文色半强度），
  当时的理由是「一条 bar 只说『和 HEAD 不一样』」——**批⑦之后树上的字母已经
  不只说这个了**，它们说「哪一种不一样」，用的就是这四种墨。一个行上戴黄 M 的
  文件，没有理由把自己的改动画成灰的。第四种墨（C 冲突）这儿到不了：
  冲突是关于一条路径的事，不是路径里某一处的事，`git diff` 不交出这种 hunk。
- **点一下 bar，HEAD 里那几行就躺在替掉它们的那几行正上方**，在 sheet 自己的
  流里，红底红字（`--git-deleted` 一成做底、全强度做字）。再点一下、或者 Esc，
  关掉。插进来的那几行**不占行号**（行号列排一个等高的空块），所以文件自己的
  编号一个都不挪。
- 批⑨把「代码是一整个 `<pre>` 装一整串字符串」这条约束拿掉了（换行需要有东西
  可量，于是变成一行一个块），这才轮到「就地」可做——在那之前，往两行之间插
  任何东西都会剪断跨行的 span。
- **代价一条，写在明处：原文开着的时候，编辑器离开玻璃。** `<textarea>` 是
  一个盒子装一串字符串，没有地方放一个块；只往 `<pre>` 里插，就是从那行起
  光标错开一整行，而这正是这套叠法唯一不许犯的错（`check-face` 4c）。
  **它几乎不花钱，而且这是量出来的不是盼来的**：缓冲区和盘上不一样时一条 bar
  都不画（`hunks`），所以有草稿的文件根本没有 bar 可点。放弃的只是
  「一边看着 HEAD 一边打字」——一个 Esc 的距离，而缓冲区全程没被碰过。

### 源码/预览：一个眼睛，在标签条尾

- 文件上方那一行两个按钮整行删掉，换成标签条最右侧一个 `IconEye`
  （`data-file-face-switch`），按下去是预览、再按回源码。可预览的文件才画。
- `face` 从 `FileView` 搬到 `WorkspacePane`：开关在条上，条在上一层。
  **默认永远源码、不记忆**（批⑤那条没动）——原来视图每换一个文件就重挂，
  自己就复位了；搬上来之后这条复位得写出来（一个 `useEffect` 盯 `file`）。
- **它站在 `data-ws-switches` 外面。** 那一组是「现有的文件、session 和 vscode
  切换」，三个都开关一**栏**；这个改的是中栏在显示什么。它们并排是因为用户把
  它们放在一起，但数那三个的门得继续数到三。

### 概览尺，没有 hunk 状态栏

- 「1 处改动 第 1 处」和 ▲▼ 整行删掉。它原来做的事是「够到看不见的那一处」——
  gutter 只能在一行旁边画一条 bar，而八百行以下的那行不在屏幕上——所以那个数
  和那个序号，是没画出那张图之前替它说话的词。
- **概览尺**：文件那一栏最右侧、**滑动条后方**一根 14px 宽的列
  （`--overview-ruler`，VS Code 的宽度），整个文件的滚动高度映到视口高度上，
  每一处一个标记，墨和 gutter 同一套。点一个标记滚过去。
- **标记是比例，不是行高**：top 和 height 都是滚动高度的百分比，所以拖列宽不用
  重新量一次；`--overview-mark`（3px）是地板，免得长文件里的一行改动舍成零。
- **点标记只滚，不展开原文。** 尺是地图，「点哪儿滚哪儿」是一个标记全部的承诺；
  顺手展开会把刚滚到的那个位置底下的行挪走。读 HEAD 里原来是什么，是 gutter 那
  条 bar 的点击，就在那一行旁边。
- 尺**永远在**，干净文件上也在：第一次改动才出现的一列，会在有人保存的那一刻
  把光标底下的文字横向挪一下。

### 撤掉的语料键

`file-face-source`、`git-hunks`、`git-hunk-at`、`git-prev`、`git-next`、`git-was`
六个。`file-face-preview` 留着当那个眼睛的 aria-label——它就是那一面的名字，
和旁边三个开关的写法一样，是哪一面由 `data-on` 说。`git-added` 留着：
一处纯新增没有旧文可躺，那一块得自己说话。
