# 工作区

一个工作区 = **一台机器上的一个目录**，由人指定。

## 为什么是人立的

khor 原先是推的：读各家 agent 的会话记录，把 cwd 沿 `.git` 往上折到仓库根，
是仓库的就当工作区。2026-09-14 用户否掉了这条路，两句原话：

> 用户有agent记录的目录不一定是工作区.可能只是随手打开的

> git目录也不一定是工作区.很多工作区开始的时候不是git目录,或用户根本就没想着用git管理

盘上没有任何东西能说明「这是我在做的事」。所以工作区是一条**决定**，
决定就复制（[NET.md](NET.md) 同步），和置顶、已读、起名同一类。

派生的那条路整段删了（`Node::workspaces_shown`、`Request::Workspaces`、
`Place.checkout`）。**留下来的是 `crates/node/src/place.rs`**：
它现在只喂新建会话向导的「常去的地方」——「可以从哪儿开一个会话」是建议，
和「我在做什么」是两回事，前者推得出来，后者推不出来。

## 身份与名字

- 身份是 `(device_id, 绝对路径)`。同一个仓库 clone 到三台机器上就是三个工作区：
  三块盘、三份未提交的改动、三个「什么时候改的」。
- **名字就是目录的 basename**（`~/working/test` → `test`），不另起、不改名。
  存下来的名字会和它指向的目录漂移，而识别这一行的是路径。
- 机器从设备表里没了（`khor forget` 之后），行还在，机器名留空：
  目录还在那块盘上，藏掉这行等于让它再也移不掉。这种行有两条硬规矩：

  - **不问它任何问题。** 空机器名在节点端的意思是「本机」，所以拿它去问
    git 或者上次改动，答回来的是**本机**的分支和时间，画在别的机器的路径
    下面。这正是这仓库命名过的那个病：答不了的分支不留白，变成它的邻居——
    而这里的邻居是可信的，所以更糟。列表两个角直接留空，一个请求都不发。
  - **置顶和移出按 device id 走，不经过机器名。** 名字是空的，
    `resolve` 会把空名解析成本机，于是写到另一块盘的键上去。
    `Node::ws_rm` / `ws_pin` 收的是 id；`khor ws ls` 在这种行的机器列里
    印完整的 id（屏幕上留空，因为那一列是给人读的，不是给人敲的），
    `khor ws rm -m <id> <目录>` 就能把它摘掉。

## 一行的四个角

| 位置 | 内容 |
|---|---|
| 左上 | 名字 + 机器头像 |
| 左下 | `机器名:绝对路径`（不缩成 `~`——那是对面那台机器的家，这张表里混着好几台） |
| 右上 | git status：分支 + 几个文件改过。**不是仓库就整个留空**，不写「无 git」 |
| 右下 | 上次改动（`ago()`） |

排序：置顶在前；其余按上次改动倒序；问不到时间的排最后；同时间按路径。

右上右下这两个角要问**持有文件的那台机器**，一行一问，
回窗口时重问一遍、不上定时器（和 `WorkspacePane` 的 git 标记同一条规矩）。
**机器答不上来只丢那个角，不丢那一行**：把「拒答」画成「没有」，
会把人支到别处去找，而不是去看那台机器。

「上次改动」= 那个目录下最新的**文件** mtime，不是会话时间——
手改的、用 ssh 改的、工具写的都算，这些都不开 khor 会话。
跳过 `.git`、`node_modules`、`target`、`.venv`、`__pycache__`、`dist`、`build`
（一次 `cargo build` 否则会把整张榜单重排）；走到 20000 个条目封顶，
封顶就答已经见到的最大值——**它是个时间，不是承诺**。

## 同步表

`crates/sync/src/workspaces.rs`，存在 `.khor/workspaces`。

- 键 `<device_hex>:<绝对路径>`。用 id 不用名字：改名不能孤儿化。
  device hex 定长小写十六进制，所以第一个 `:` 一定是分界，路径里带冒号也不怕。
- 每键一个 LWW 寄存器，三态：`No`（不是工作区）/ `Yes` / `Pinned`。
  置顶不另开一张表——「给不是工作区的行置顶」这种状态，两张表才装得下。
- **移出写 `No`，不删键。** 不是因为删不传播（loro 的删除会传），
  而是一个寄存器一条合并规则就够，并且读的人不该分得出「移出过」和「从没加过」。
- 移出**不碰目录**（用户 2026-09-14）。
- 同值不重写：版本向量不会为一次没变化的点击涨一格。

## 命令行

| 命令 | 做什么 |
|---|---|
| `khor ws ls` | 每行：置顶标记、名字、`机器:路径`，制表符分隔 |
| `khor ws add [-m 机器] <目录>` | 加一个。本机可以写 `.`；**会先验证那是个目录**——本机走 fs，别的机器走 `Ls`，卫星经 sponsor 走同一条路 |
| `khor ws rm [-m 机器] <目录>` | 移出这张表，目录一个字节不动 |
| `khor ws pin` / `unpin [-m 机器] <目录>` | 排到最前面 / 放回去（仍是工作区） |

`-m` 认机器名，也认 device id——一行的机器要是已经不在设备表里，
id 就是它仅剩的名字。

只有 `add` 会出网，而且只为了问一句「那是目录吗」。`ls` 读本机自己那份表。

## 怎么加一个

界面上按列表头的 `+`，开跨机器目录选择器（`components/DirPicker.tsx`）：
上面挑机器，中间走目录树（只列子目录，`Ls` 那条路，卫星经 sponsor），
底下一个路径框——树点不到的目录也得能到。**选择器什么都不验证**：
那是 `ws_add` 的事，它拿 `Ls` 去问那台机器，答不上来就把那台机器自己的话
留在对话框里、框不关。

同一个选择器也是新建会话向导「目录」框旁边那个「挑…」——
「哪台机器上的哪个目录」是同一个问题，两块屏幕就会有一块忘了卫星。
向导那个框本身没动：打字、常去的地方、选择器，三条路都写进同一个框。

## 里面的会话

工作区页右栏列的是**在这台机器上、这个目录底下跑的会话**，两个条件缺一不可：

1. `会话.home 频道名 === 这个工作区机器的频道名`
2. `cwd === 目录 || cwd 以 目录 + "/" 开头`

第二条那个斜杠是硬的——`/home/peer/workshop` 是 `/home/peer/work` 的邻居，
不是它的孩子，少一个分隔符就会把邻居收进来。

第一条同样是硬的，因为**工作区的身份本来就是 `(机器, 目录)`**：两台机器上
都有 `~/w/khor` 就是两个工作区，只按路径比会把另一台的活儿列进来——
而这一栏是特意不重复说机器的（下面 `showVia` 那段），屏幕上没有任何东西
会露馅。这就是这仓库最老的那个毛病：**答不了的分支不留白，变成它的邻居。**

**按 id 解析成频道名再比，不按显示名。** `SessionRow.home` 是频道名
（`DeviceInfo::name`），而 `WorkspaceInfo.machine` 是显示名
（`DeviceInfo::shown()` —— 有标签就是标签）。两者在没改过名时相等，
改过名之后不等，于是「拿显示名去比」会一直好用到某一天，然后**静默地
一行都匹配不上**。所以由 shell 拿工作区的 device id 去设备表里查频道名
（`App` 那条「Compared by channel, never by the name on the glass」的规矩），
查不到就是这一栏空着——机器都叫不出名字，就没法说什么东西「在这儿」跑，
空栏是事实，邻居的行是谎。

为此 `SessionRow.place` 从 2026-09-15 起**存原始 cwd，不再折到 git 根**
（`khor_node::live::place_of`）。折叠只剩「常去的地方」还在做，且只在
`Node::places` 那一处做。理由是这条问题折过就问不了：工作区立在
`~/w/paper/data`，而在那儿开的会话折完报的是 `~/w/paper`，对不上；
反过来工作区立在仓库根上，子目录里的会话全归它——看着对，其实是巧合，
因为只有折叠恰好停在那一级时，「折到同一处」和「在子树里」才一致。
**原始路径随时能折，折过的路径回不去。**

代价写在明处：会话列表按「地点」分组，现在一个仓库的两层是两个标题。
这笔账付在那条轴上，不付在数据里。

右栏用的就是 `SessionsList` 本身，只关掉「再说一遍机器」那一项
（`showVia`）——上面的头已经说过这是哪台机器的哪个目录了。行上的置顶、
关闭、转形态跟会话落地页一模一样：同样的行少几个动词，是要人学两遍的东西。
