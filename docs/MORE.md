## 自检 · `khor doctor`

一张清单。每项：名字、状态（ok / warn / fail / 未量）、一句人话、能修的带一个动作。
节点函数 `doctor()` 回 `Vec<Check { key, state, said, fix: Option<FixKey> }>`，CLI 逐行打、
`--json` 出原样；`khor doctor --fix <key>` 跑那一项的修法。GUI 页就是这张表 + 「再查一遍」。
**每项独立超时（3 s），一项卡住不拖累别项；「未量」不是 ok。**

| key | 查什么 | 修法 |
|---|---|---|
| version | 本机 khor 版本；CLI 与 app 是否同一构建 | — |
| identity | 身份钥匙在、可读、权限 0600 | chmod |
| store | store 可开、可写、占用多少 | — |
| serve | `khor serve` 在跑、IPC 答话 | 起它 |
| web | 网页脸端口在听、钥匙文件在 | — |
| relays | 每个中继可达 + RTT | — |
| peers | 每台已配对机器：可达、直连还是中继、对端版本；版本不一致 warn | — |
| hooks | claude 的 hooks 装没装、指向的 khor 还在不在 | `khor hooks` 重装 |
| agents | 登记的智能体命令各自找不找得到 | — |
| vscode | 这台有没有 `code`、serve-web 服务端下好没 | — |
| disk | store 所在盘余量（< 5% fail，< 10% warn） | — |
| launcher | 开启器（`open` / `xdg-open` / `KHOR_LAUNCHER`）在不在 | — |

已有的探测（`devices`、`top`、relays、hooks 的检查）复用，不重写。

> 2026-09-19 批 B 落地时改了三处表，都是「现有探测里问不出来」：
> - **peers 的 RTT 撤了。** 可达和直连/中继来自 `hops()`（常驻那一份读数），对端版本来自
>   `Vitals::version`（它本来就跟着读数走）。**RTT 只有常驻自己那条连接看得见**，
>   要一个新的 IPC op 才拿得到——不在这一批，写在 handoff 的「还欠什么」里。
> - **clock 整行撤了。** 对端的钟在现有任何一份答案里都没有：`Vitals` 不带时间戳，
>   `vitals_of` 的第二个数是**本机收到它的时刻**。要一个新的线上问法才量得到。
> - **perms 撤了。** khor 自己不要辅助功能之类的系统权限（截图脚本要，khor 不要），
>   没有可查的项；等哪天真需要了再加一行。
> - hooks 只有 claude：树里只有 `adaptor::claude` 一套钩子，`khor hooks` 也只装它。

## 安全 · `khor lock`

- **打开密码（app 锁）**：锁的是**屏幕上的脸**（app 窗口与网页脸），**不锁 CLI**——CLI 后面是
  已经登录这台机器的人。开关 + 两种钥匙：
  - macOS app：系统验证（Touch ID / 登录密码，`LocalAuthentication`，走 `objc2`，不加新包则最好）。
  - 所有脸通用：一个 PIN（≥ 6 位，Argon2id 存在 store 里，`argon2` crate，MIT/Apache）。
  - 锁的时机：启动时、闲置超时（可设：1 / 5 / 15 / 60 分钟 / 永不）、手动「现在锁上」（⌘L）。
  - 锁住时：整窗一张锁屏（脸 + 名字 + 解锁），**页面里不留任何会话内容**（不是盖一层——
    卸掉，解锁后再挂）。网页脸同一规则，按 cookie 会话算。
  - CLI：`khor lock status|on|off|pin|timeout <分钟>`。
- **网页脸钥匙**：看现在的（遮住，点了才显）、轮换（已有 `khor web --new`）、「对局域网开放」开关
  若已有就搬来。
- **配对的机器**：列表 + 吊销（已有 `khor forget`）。
- **危险动作二次确认**：接管会话（`confirm-takeover`，默认开 = 现状）、删除
  （`confirm-delete`，默认**开**；docs/SHELL.md 第四轮：每条侧边栏的「删除」都弹同一个窗，
  勾「不再提醒」= 设成 off。它取代了 `confirm-ws-remove`，旧键明确设过的值照旧）。
  删除文件**不进 config**。
- **重置身份**：删钥匙重新生成 = 换了一台机器。红字、输机器名确认。`khor id --reset`（新）。

> 2026-09-19 批 C 落地时的四处改口：
> - **PIN 是前提，不是并列的另一把钥匙。** 没设 PIN 就打不开这个锁（`khor lock on` 按名字拒绝）。
>   理由：手机打开的网页脸没有 LocalAuthentication 可退，一把只长在一台 Mac 上的钥匙会把人
>   关在别的脸外面。系统验证是**额外**的那一把。
> - **「≥ 6 位」数的是字符，不是数字。** 一个更长的口令被挡在外面，挡掉的是更强的那个答案。
> - **「对局域网开放」没有可搬的开关**：网页脸是 `khor serve` 一起开的，绑的是所有接口，
>   树里没有这样一个设置项。不画。
> - **「危险动作二次确认」那三项挪到批 D**：它们本质是 `khor config` 的键（一个存着的偏好，
>   三个调用点读它），跟着 `khor config` 一起落，`khor lock` 里没有它们的位置。
> - 「启动时锁」不是一个单独的开关：每张脸自己起来时读一次 `lock on`，所以开着就是启动即锁。
>
> 2026-09-20 批 D1 落这三项时**只落了两项，而且默认值和这份文档原来写的不一样**：
> - **删除文件不进 config**（验收方 2026-09-20 裁）：它今天已经有一个「不再提醒」的勾，
>   存在每张脸自己的 `localStorage`，`RemoveDialog` 的头注释写明那是「一个习惯，
>   不是一个关于网络的决定」。升成配置键 = 把每张脸各自记的变成每台机器一份，
>   手机和桌面从此共用一个答案。
> - **「默认开（现状）」对移出工作区是错的**：那一项今天**根本没有二次确认**，
>   `WorkspacesList` 里明写「No confirm: nothing is destroyed. The directory is
>   untouched（user, 2026-09-14）」。所以它的默认是**关**——默认开会是这张键表
>   悄悄推翻一条用户裁决。开关留着，是给「我还是想被问一声」的人。

`khor config get|set|list`，键值存 store；GUI 页按节排：

- **外观**：跟系统 / 浅 / 深（`theme`，默认跟系统 = 现状）。密度与代码字号不画，见下面那条注。
- **语言**（用户 2026-09-19：「这个语言是可以在设置里设置的，自动跟随系统语言，我们支持英语与
  中文。失败会退英文」）：跟随系统（默认）/ 中文 / English。`khor config set lang auto|zh|en`。（`lang`，默认跟随系统 = 现状）
  - 文案两份：`crates/catalog/zh.toml`（原文，唯一的真源）与 `crates/catalog/en.toml`（译文，
    由一个 sonnet 译者先译出来，键、节、`{0}` 占位与 zh 逐一对应）。
  - **回退是英文**：系统语言不是 zh* 的一律英文；`en.toml` 里缺的键回退到……也是英文——所以
    **缺键是编译错**：`build.rs` 在编译期对齐两份的键集与每条的占位符集合，对不上不给过。
    zh 里新加一条而不加 en，树就不编译。
  - 「同一节里两个键不许共用一句话」那条规矩两份都守。
  - 取系统语言：CLI 读 `LC_ALL` / `LC_MESSAGES` / `LANG`（macOS 上再问 `AppleLanguages`）；
    脸读 `navigator.language`。显式设了 `lang` 的以它为准，CLI 与两张脸同一个键。
  - 线上传的是键不是字（现状），所以两台机器语言不同互不影响。
  - 六个状态词、git 的字母、专有名词的规矩不变：状态词有英文（Busy / Blocked / Done /
    Errored / Failed / Idle），git 字母与 claude / codex / VS Code 原样。
- **这台机器的脸**、**中继**：现有 `FaceSettings` 两节原样搬来。
- **通用**：标签页上限（`tabs-limit`，off 或 4–50，默认 off；docs/SHELL.md 第三轮）。
- **会话**：新会话默认是对话还是终端（`session-form`）。
- **工作区**：单击文件是预览标签（现状）还是直接钉住（`files-click`）。
- **存储**：store 位置与占用（只读 + 一个「打开这个目录」走 `launch`）。
- **关于**：版本。

**分两栏的事这一轮不做**（「本机的 / 全网同步的」要等网络宏图），全部是本机的。

## 单网络做通 · `khor leave` / `khor pause`（2026-09-20）

用户原话：「网络暂时不做超图。但把单网络的做通呀」，对下面的落法回「做吧」。
超图仍是宏图；这一节只补用户第 3 条在**单网络**下还缺的两件。

现状（2026-09-20 真机）：四台机器用 `khor invite` / `khor pair` 配成一张网，全直连。
「接入已有网络」= `khor pair`，「建立新网络」= 单网络下一台机器自己就是一张网，
建立就是 `khor invite` 邀请别人——两件身份卡上都已经有。缺的是**退出**和**暂停**。

### 离开 · `khor leave`

- 先给全网发「我走了」：把**自己**那一行 `set_gone(true)`，趁还连着的时候同步出去
  （和 `khor forget` 走同一条路、同一块墓碑）；再把本机的设备表清到只剩自己、`peers/` 缓存清空。
- **别的机器留在本机的会话行、工作区一并清掉**（用户裁：和被 forget 的机器的行现在的处理一致）。
  本机自己的会话、工作区、身份、设置一样不动。

  > 2026-09-20 批「离开」就地更正括号里那半句：**只有会话行是这样，工作区不是**。
  > 会话行确实随表走（每一行都是经设备表推出来的，`a_forgotten_machines_rows_leave_the_list`
  > 量的就是这条）；**工作区行今天在机器被 forget 之后留在列表上，机器名一栏是空的**
  > ——`Node::workspaces` 的注释写明了为什么：目录还在那块盘上，把行删掉它就再也移不掉了。
  > 那条理由在 leave 上不成立（是本机自己在删，不是替一台还在的机器做主），所以
  > leave 把别的机器的工作区行也清掉，而 forget 照旧。两个动词在这一点上不一致，
  > 是因为两件事本来就不一样：forget 是「这台机器走了」，leave 是「这张网跟我没关系了」。
  >
  > 另外 **`peers/` 之外的两个缓存（`vitals/`、`watched/`）也一并清掉**。它们和
  > `peers/` 同一类——都是别人留在这块盘上的、按设备 id 存的缓存，没有一个读者
  > 不先走一遍设备表。分三处清和分三处留一样没人看得见，写成一处
  > （`Node::peer_caches`）是为了「以后新加的第四个缓存不会被忘在这儿」。
- `Node::forget_device` 拒绝本机的理由（「自己走了却留着满表的行，是没有词能说的坏」）
  正是 leave 补上的那一半：表也清了，就是「离开了」。`forget <本机>` 仍然拒绝，
  拒绝句里指路 `khor leave`。
- 拿新票 `khor pair` 能再加入（配对本来就会清墓碑，`DeviceDoc::set_gone` 的注释写着）。
- **一台对端都连不上时照样能走**，但如实说：别人那边还会看见你离线，要他们 `khor forget`。
  两种结局各一句话，不合成一句。
- 本来就是孤身一台：按名字拒绝（没有网可离）。
- 身份卡上「离开这张网」，二次确认永远有（不进 config 键表——这一件不可撤回）。

  > 2026-09-20 就地写明这个「二次确认」落成什么形状：**把本机的名字原样打一遍**，
  > 而且**规矩在节点里**（`Node::leave`），不在页面上。理由是 `lock::reset_identity`
  > 已经写过的那条：一个命令行标志加一个对话框，就是同一件不可撤回的事有两套规矩，
  > 而漂掉的那一套正是没人跑的那一套。于是 CLI 也有确认（`khor leave <本机名>`，
  > 和 `khor forget <机器>` 一条规矩——「把名字打出来就是确认」），两张脸不可能
  > 各自长出一套。行菜单那种「按两下」在这儿不合适：按两下确认的是**这一行**，
  > 而这一件的对象是你正站着的这台机器，名字打出来才说明你说的是它。
  >
  > `khor leave beta`（打了别台的名字）**按名字拒绝并指路 `khor forget beta`** ——
  > 那不是打错，是伸手去够另一个动词。和 `forget <本机>` 指路 `khor leave` 正好对称。

### 暂停 · `khor pause` / `khor resume`

- 暂停 = 不收不发：serve 不再接受对端连接、不再主动同步，对端看到的就是「离线」。
  本机功能（会话、工作区、网页脸）照常。
- 状态存盘（`khor config` 同一个 store，但**不是**键表里的一项——它是动作不是偏好；
  builder 若发现放进键表更顺，就地改这句并写明理由），重启 serve / app 后仍是暂停。
- 正在跑的 serve 要**立刻**生效，不等重启。
- `khor devices`、身份卡、侧栏头像上都看得出「已暂停」；`khor doctor` 里相关那一项
  在暂停时说「已暂停」而不是报红。
- 暂停时 `khor invite` / `khor pair` 按名字拒绝，指路 `khor resume`。
