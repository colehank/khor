# 智能体状态：读取原生证据

Khor 不安装智能体状态 Hooks，也不要求用户审阅或信任 Khor 的生命周期脚本。`khor hooks install`、界面安装开关和 Hook JSON 状态入口已经退役。

## 状态来源

- ACP GUI：回合请求、权限请求与回合结束结果。正常回合结束为完成，取消为空闲，协议或执行错误为中断。
- Claude 终端：读取智能体自己的 `sessions/<pid>.json`，判断忙碌、空闲和等待权限，并核对进程身份。空闲时读取对应原生 transcript 的明确 `end_turn` 或 API 错误证据。新用户消息、工具调用、未明确结束的输出和压缩边界会阻止使用旧完成记录。
- Codex 终端：读取原生 rollout 的回合开始、完成、取消与错误事件，不安装 Hook。
- 终端画面识别：仅为较弱的兜底，不凭静止的画面宣告完成。
- 进程是否存活、网络是否可达，与回合状态分别判断。

Claude 历史读取有固定字节上限，并缓存未变化文件；不会为了状态扫描完整长历史。找不到明确结束证据时保留空闲，不将所有 busy→idle 或历史正文当作成功完成。某些 Claude 版本不写 `end_turn`，这类终端目前可以显示忙闲与待批，但不能保证每轮都有完成提醒；ACP GUI 不受这个限制。

`完成` 同时表示等待阅读的本轮结果。阅读 watermark 覆盖该事件后显示空闲；后续 bookkeeping 不产生新的完成提醒。旧 Hook 的持久状态不能压住 Claude 当前的原生终端状态。

## 旧安装迁移

可托管智能体的节点启动时，只清理能确定为 Khor 自己的 `khor state --hook` / `khor-gui state --hook` 旧配置。其他 Hooks、环境变量和插件不动。清理使用配置冲突检查、保留权限和符号链接，并在私有迁移回执中保存移除项；不复制整个配置或账户凭据。配置损坏时保留原文件，记录错误，不阻止正常启动。

已经运行的旧 Claude 可能仍缓存着 Hook。新版原生程序遇到精确的 `state --hook` 参数立即成功退出，不读取 stdin、不打开节点、不创建窗口；这只是退役残留入口，不再处理或执行 Hook。旧进程是否重新读取配置由智能体自己决定，不自动终止用户任务。

Codex 插件和代码图谱可以有自己的 Hooks，它们不属于 Khor 状态集成。移除 Khor 状态机制不等于禁用第三方插件，也不会替用户信任这些 Hooks。
