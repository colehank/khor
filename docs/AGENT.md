## 入口与上下文

- `@khor` 调用当前操作节点的默认智能体；`@machine/agentName` 指定远端智能体。
- 每次新任务单开 session，属于 khor，并进入 session list。控制频道只保留引用
  同一 session 的任务卡；其状态和最新消息直接来自 session。
- 初始上下文包含本次请求、附件和显式引用；不默认塞入整个频道历史。
  后续对话在该 session 内继续，长期记忆归智能体身份。
- slash 和 pi 工具共享 khor 能力层；pi 工具使用结构化参数。

网的调度员：用户指派任务，它动用网内的设备与 session 完成。
不是新形态——就是一个对话 kind 的 session：消息 CRDT 全网复制，
哪台设备都能留言；执行进程在 home（发起那台）。

## 权限：读免批，动作按档

看（设备状态、session 列表与内容、事件流）一律免批。
动作（开/杀 session、传文件、跑命令）分两档，按任务选，默认 manual：

| 档 | 规则 |
|---|---|
| manual（默认） | 先列计划，待批；批了计划内免批，计划外回来重批 |
| bypass | 全免批，用户显式选了才进这档 |

待批走 session 原语那一格。

## 执行

- home 是用户发起任务的那台。它离线：执行停在原地、灰显，消息照收（CRDT），
  等它回来——不悄悄换机器接着跑。
- 后果说破：从手机发起 = 手机是 home，锁屏即暂停（iOS 杀后台）。
  长任务从常开的机器发起；移交机制挂账以后。
- 用账户表里的账户（用户指定或默认），额度算在该账户头上。

## 怎么接上（2026-10-08，STORE-BRIEF 基础 B，未建）

khor 智能体是一个 **khor 的 session**，和广播同一条路（docs/SESSION.md「广播」）：

- 一份 `wide/<名字>` 文档（`khor_sync::chat::ChatDoc`），每台机器都存、每轮都同步，
  所以消息哪台设备都能留、离线照收；行在每台上从自己那份推出来（`khor_node::wide`
  加一臂，和 `WideKind` 同形）。
- 文档头写 home（`ChatDoc::set_home`）：跑执行进程的那台。换机器就是写另一个 id，
  不悄悄换——home 离线时行灰显、执行停在原地，和上面「执行」一节一样。
- 执行只在 home：别的机器上的这一行只读文档；动作经 `Reach` 送到 home。
- 传文件走同一条文件路（`road::Parcel`）：直接传或邀约，落在收端的接收位置，
  每台收端各一格记录。
