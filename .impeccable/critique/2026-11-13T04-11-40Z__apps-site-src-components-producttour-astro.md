# Khor 功能介绍段：成熟度与下一版方向

范围：ProductTour 三项亮点及 Meet Khor 的衔接，当前源码 a9033f376fc7aea6cf909552d83f8112b7c409cb。这是设计讨论，没有修改产品实现或发布。

## 设计判断

当前这一段已经整齐、可理解，但仍像三张交互技术说明图。产品专属性主要靠标记和文字，而不在构图中。最重要的优化是让图直接展示 Khor 连接的内容、交给智能体的任务，以及继续运行的会话，同时延续前段的品牌画面。

iroh 的启发应是用可见关系和状态说明一个具体机制，而不是照搬浅底、圆点和细线。官方参考：https://www.iroh.computer/

## 两项优先问题

### P2 · 画面的主次和材质不连贯

近白的大画布是每屏最醒目的元素，实际节点只有约 44 px。Meet Khor 的大标记与光感结束后，三个相同的白色圆角面板、底栏和分隔线令整段显得像组件说明。Agent 标题换行也受容器牵制。

下一版延续黑色背景，让线条退为暖灰辅助，只在当前活动或完成位置使用橄榄绿。移除统一的大浅色面板和重底栏，只给文件片、任务片、进程片这些实际内容对象局部实体底。保留一套对齐关系，以图的不同结构建立节奏，不机械左右翻转。放大关键对象、缩短路线、调整空白，确保主要文字和图的主体先进入视线。

标题收成稳定的两行或更短，不让灰色副标题成为更大的视觉主体。Example 保留为轻量说明，选择和重播靠近被改变的内容。Terminal 的倾斜没有功能含义，改为正立。

适合后续执行：layout、typeset、distill

### P2 · 图展示了关系，但没有充分展示内容和结果

P2P 切换目前主要改变字符串；Agent 结束只有勾与 Ready；手机保留机器名却隐藏 Code review 与 Project notes。用户需要靠正文补出完整含义。

| 图 | 核心画面 | 有意义的变化 |
|---|---|---|
| P2P | 两个设备身份锚点与一个可见文件或网页片，明确内容在哪、从哪访问 | Files/Web apps 改变内容对象；连接保持，避免暗示文件搬家 |
| Khor Agent | Khor 接收短请求，交给 Codex/Claude 执行具体工作，汇集两项可读成果 | 请求、分工、结果依次反馈；结果有内容，不只一个勾 |
| Terminal | 稳定的运行进程片与同一个会话输出 | 切换观看设备，宿主与会话内容保持，表达继续工作 |

Agent 是此段重点，任务和成果应比第三方 logo 更显眼。依然使用正式标记、概念插画与虚拟示例，不增加整张 GUI 截图、不编造实测指标或未经核实的功能承诺。

手机独立编排：优先保留做什么和得到什么，机器名退为次级；必要说明采用可读字号，不用删除解释换取容纳。图可改纵向、支路可以上下排列。继续正常滚动、有限动画、可读静态终态，不增加新的固定滚动段。动画进入时只演示一次明确变化，完成后停稳。

适合后续执行：shape、clarify、adapt、最后 polish

## 已有优点

- 三种拓扑分别是连接、分发汇合、固定宿主与切换观看端，逻辑基础值得保留
- 使用真实身份标记并明确标注 Example，没有把示例冒充真实连接
- 选择可逆、动效有界，低动态偏好和离屏收束方向正确

## 阅读与体验

认知负担不来自选项数量：每图只有一两个操作。问题来自画面主次与抽象内容，八项检查中两项不足。初访者难以从 Agent 图直接说出交给 Khor 什么、拿回什么；核实能力的人只看到结果勾，证据感不足；手机用户遇到小字和被隐藏的任务内容。

希望形成的顺序：记住 Khor → 看懂资源如何相连 → 看懂任务如何分工 → 看懂工作如何继续。

## 检测与判断的边界

ProductTour.astro 单次 CLI 扫描为零项。浏览器注入层报告两项 shape-assembled illustration，目标为 1024×1024 的内联 SVG；没有捕获准确选择器，不能认定属于三图，可能涉及正式品牌 SVG。它们不进入修复清单，也不据此重画品牌资产。叠层中的 low contrast text 没有对应具体 finding，未计数。

两位评审均独立在 Chrome 中观察；没有真实 iPhone Safari 新验证。技术检测没有替代画面判断。
