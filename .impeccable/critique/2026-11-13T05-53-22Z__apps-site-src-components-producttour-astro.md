# Assessment A — Khor 三幕设计反思

独立设计评估，未阅读历史评审或 Assessment B 检测结果

目标：`apps/site/src/components/ProductTour.astro`，以及 NetworkDiagram、SessionDiagram、ResourceDiagram 和对应动画

现场：`http://127.0.0.1:23820/#connect`，桌面 1440×1000、手机 390×844，独立可见 Chrome 会话

## 核心判断

现在的三幕把产品分类摆出来了，却没有把 Khor 的使用价值演出来。第一幕是网络路由图，第二幕是聊天内容切换器，第三幕是一个订单网页和文件视图。访客要自己把它们翻译成“我在不同设备上，继续同一份工作，并使用远端资源”。这一步解释恰好应由画面完成。

“抽象”并不来自没有全尺寸 GUI，而是画面缺少可见的因果。“丑”主要来自构图和图形语言没有形成一个有主角、有重心、有节奏的整体：同一种左标题右内容结构重复三遍，网状线条、聊天面板、白色订单表格各讲各的。克制的黑底与留白不能自动产生精致感。

设计专属性：偏低。系统、agent 标志和文本是具体的；主体构图换掉这些标志后，仍可用于 VPN、模型聚合器或代码编辑器。Khor 特有的“设备网络 → 持续存在的 terminal/agent session → session 中可用的资源”没有成为图形本身的结构。

## 5 个优先问题

### P1 · 1. 第一幕过早讲传输路径，没有先给人一个连接设备的理由

实际看到的是 MacBook、Linux、iPhone 三个圆，绿色线段在 Direct / Via relay 间切换。动画主要在 MacBook 与 Linux 之间运行，iPhone 是一个静止的下方节点。访客能认出“电脑连起来”，却看不出“我现在能做什么”，也不知道为什么必须理解 relay。

“A private peer-to-peer network, built around your devices”仍是分类说明，几乎只是把标题展开。私有网络和直接/中继之间的关系需要已有知识补足。即使目标是开发者，这一幕仍应先回答使用目的，再补机制。

重做场景：用可辨认的设备轮廓或具有空间层次的精简装置，建立“随身设备 / 家中电脑 / 远端主机”的三点关系；设备加入一个连续的私人空间后，点亮可用的工作入口。线路只在这条关系里承担连接含义。Direct / relay 作为一次短暂的路径变化出现，工作入口保持稳定，让“路径变化，仍能连接”成为观看结果，而非让访客先研究网络拓扑。不要画出未经验证的安全或可用性承诺。

### P1 · 2. 第二幕最重要的跨设备继续工作，动画几乎没有可见证据

现场的两个连续状态从 `view=mac` 切换到 `view=phone` 时，聊天内容和其余构图完全不变，只有底部 MacBook Pro / iPhone 按钮的选中底色移动。这说明控制状态变了，但没有让人看到“人在另一台设备上继续同一个会话”。随后整个内容又跳到 Claude，访客要同时推断 session、host、view 三种身份。

最显眼的是“Check the CSV export dates”和本地日期解释；“On build-01”和“Continue from”是外围小字。主次颠倒了：示例任务的业务细节变成主内容，Khor 的跨设备能力成为脚注。Terminal、Codex、Claude 像三个产品标签页，未清晰形成一个统一的 session 集合。

重做场景：保留一个具有固定名称、颜色细节和最近一行输出的工作对象，显示它实际运行的设备。Terminal 与 agent 以同一尺寸、同一关系的 session 小卡片并列出现；它们共享容器和访问方式，但内容类型仍可辨认。观看窗口从电脑转到手机，工作对象、历史和运行设备保持不变。用一条新输出继续出现作为“继续”的可见证据。动画每段只改变一个变量，先讲 session 集合，再讲访问设备变化。不要暗示 session 运行主机发生迁移。

### P1 · 3. 第三幕把示例业务做成主视觉，掩盖资源从哪里来、如何进入 session

白色大卡片是三幕中最强烈的视觉焦点，标题却是 Atlas Web；下方是订单号、日期和金额。访客更容易记住“一个订单导出应用”，而不是“当前 session 可以访问远端 web app、编辑文件、查看 Git 变化”。随后切换为 diff 和文件列表，仍是同一个矩形内容换页，没有展示资源与设备、session 的关系。

当前来源只靠上下两处小字表达：session 可写着 `Codex · build-01`，资源底部写着 `From MacBook Pro`。`localhost:5173` 没有视觉锚点说明是哪台机器的 localhost。技术人员会想追问来源，新访客可能直接忽略它。三种资源都是“显示出来了”，但“在每个 session 都可用”没有被证明。

重做场景：让第二幕的同一 session 留在画面中心；一侧保留资源所在设备，另一侧用三个简化而可辨认的对象表现 web、文件、workspace。只展开一个资源的最小证据：远端 web 预览进入 session，文件的一行修改产生 Git 变化，workspace 显示对应文件位置。资源来源和使用位置要一眼能连起来。订单金额、日期问题、README 解释都不承担 Khor 的核心说明，应移出主视觉。若使用同一任务故事，只保留任务名和一个结果，不用整段业务说明。

### P1 · 4. 动画是轮换内容，没有组成三幕连续的解释

第一幕用流动线段；第二幕每 3.6 秒交替切设备选中态或 session；第三幕每 4.8 秒换一个面板。它们都有“在动”，但没有同一视觉主角被保留、进入下一层的过程。第一幕网络中没有 session；第二幕的 host 只剩小字；第三幕的网络与访问设备又消失。三幕在代码里共享状态，不等于访客在观看时能识别叙事连续。

第二幕的循环尤其削弱阅读：读一段 agent 回答时，画面下一拍可能只换底部设备，再下一拍才换回答。这个节奏要求观察者自己分析哪一类状态发生了变化。

重做规则：三幕各完成一个句子，分别是“这些设备连在一起”“同一批工作可以从这些设备继续”“工作的资源就在 session 中”。让设备、session、资源具有稳定的外形、位置关系和命名；每幕开始有明确建立，中心动作只发生一次，结果停留足够久，然后自然回到开头。循环的评价标准应是静音看完能复述发生了什么，不能只是控件轮流亮起来。

### P2 · 5. 三段同构布局没有视觉节奏，手机还把关键关系拆出了同屏范围

桌面三次重复相近的左侧两行标题、灰色副句、右侧内容容器。第一幕的空心圆与细线缺少主次；第二幕是大段暗色面板；第三幕突然变成强亮白板。三者不是同一套图形语言的递进。标题第二行正好放着关键价值，却一律降成灰色，削弱了需要记住的部分。

手机现场第二幕首屏可以看到标题、三个 session 标签和几乎完整的聊天卡，但跨设备的 `Continue from` 在屏幕下方；看到它时标题已经离开当前观看中心。主卡片保留大量固定空白，却没有为核心关系换来可读空间。第三幕的大白卡进一步拉长段落。

重做构图：先为三幕分别画出一个单帧就成立的主画面，再安排文字与动效。保持相同的材质、线宽、光源和强调色语法，同时让主角从设备群、工作对象、资源关系依次放大。每幕可以改变画面重心与远近，避免连续三个展示柜。手机用重新构图的紧凑场景，让设备身份、session 和动作结果同屏，而非只把桌面内容上下堆叠。

## 值得保留的部分

1. 三个标题的 devices → tasks → resources 次序是可用的信息骨架；保留这个次序，重写其视觉表达
2. 黑底、有限强调色、短标题，以及没有到处加句号的语气，方向符合成熟工具的克制感；需要更准确的构图来承接
3. 设备、运行主机、session、资源的示例数据已经相互关联，Terminal 与 agent 也都在场；这是后续连续场景的素材基础。暂停和 reduced-motion 处理也应保留

## 认知负荷

四项失败：单一焦点、视觉层级、工作记忆、渐进披露。访客要在业务示例中寻找产品信息，记住上一幕的设备身份，并自行补齐 session 和资源之间的关系。Direct / relay、订单日期、agent 对话内容都先于关键使用价值被展开。

通过：每组主要选项不超过 3 个，局部信息分组清楚，可以一次切换一种内容。没有单一选择组超过 4 项。第二幕同时出现 3 个 session、2 个访问设备和暂停控件，这增加了状态解释负担，但问题不应简单归结为“按钮太多”。

综合为高认知负荷（8 项中 4 项失败），来源是关系不明，而非元素数量大。

## 情绪旅程

第一幕：安静、技术感，但像一张等待讲解的网络图，没有产生“原来这就能解决我的问题”的瞬间

第二幕：最需要建立价值时，注意力转向 CSV 日期，理解进入低谷

第三幕：白色表格制造视觉高潮，但高潮属于示例应用；最终没有留下 Khor 的关键画面或一句可复述的收益

合适的高潮应是同一份工作在另一设备上继续，随后让所需资源自然出现。结束时让人记住“设备变了，工作还在这里”及其资源关系，避免暗示未经确认的同步或迁移机制。

## 小观察

- Mac/Finder、Linux 企鹅、Apple 标志能说明平台，却不如精炼的设备形体直接表达“电脑 / 主机 / 手机”；品牌标志可以成为设备上的次级标记
- “Example network”“Example sessions”有助于说明演示属性，但目前它们占据固定脚注位置，令画面更像组件样例集
- 不应从本评估推导出“加更多装饰”或“改回完整 GUI 截图”；需要先修场景的动作和关系，再做造型与材质

## 给下一轮的设计问题

这些问题供父级综合评估使用，本子任务不向用户另行提问

1. 哪一个瞬间应成为整段的记忆点：跨设备继续同一 session，还是远端资源在 session 中直接可用？两者可以连续出现，但需确定前后主次
2. 三幕能否共用一个稳定的工作对象，而不需要访客读懂任何 CSV 业务细节？
3. 手机每幕能否在一屏内同时看到来源、动作和结果？若不能，先删去哪个示例细节？
