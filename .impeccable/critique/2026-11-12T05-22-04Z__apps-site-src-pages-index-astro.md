# Khor 网页整体审视 · 2026-11-12

目标：`apps/site/src/pages/index.astro`，连同下载、安装文档及其浏览路径。基线 `0125a9a0`，本轮为只读审视，没有改产品源文件或运行构建。

结论：Khor 已有清楚的视觉身份，接下来应围绕「看懂用途 → 看见真实产品 → 理解设备协作 → 知道怎样开始」统一精修。保留 kapestack、指定 Fog、50% 毛玻璃、完整 Desktop GUI、原始 SVG 和五幕故事，不恢复用户已删除的介绍片段。

## 应保留的部分

- Fog、玻璃窗口、原始图标形成了自己的视觉世界；桌面首屏左右分工与主次 CTA 清楚。
- 真实 Khor GUI、同一个项目 / 会话 / 文档的自洽数据，比另造产品界面更可信。既定不可操作项不作为缺陷，也不建议灰化。
- 原生、可逆的滚动时间轴、浏览器主题下的 GUI、自适应下载和静态站架构是可继续使用的基础。减少动态效果已停用 Fog；离屏 Fog 的实际 WebGL 绘制为零。

## 五个重点

### P1：文字与图形被排成两个步骤

每段前 12% 换字，14% 才允许图形启动。没有增加总页高，却增加了主观等待。桌面采样中 “With many harnesses” 已有 85.5% 可见度，四颗节点仍全是系统脸；停在交叉淡入中间，两句大标题会叠字。

建议：保留首幕一次 .5 / .7 屏的阅读停留，后续段从起点就同时交接文字并启动第一笔动作；文字在前约 8–10% 稳定，图形中段演化，末端短暂落稳。所有阶段仍占同一条滚动区间，不再每幕重复文字前奏。文字采用短交接或裁切，不把两个完整大标题长时间压在同一位置。具体比例应通过一轮连续预览确认，不把新数字当成规则。

当前手机演化 6.2 屏加首幕 .7 屏，共约 6.9 屏的有效滚动行程；包含 sticky 舞台的 section 高度为约 7.9 屏。是否再缩短总长度，应在重排重叠节奏后判断。

### P1：GUI 下载后的起步路径断开

下载页推荐 macOS App，安装文档却从 curl、PATH、常驻进程与 LaunchAgent/systemd 开始。读者不知道下载 App 后是否还需要装 CLI，也没有 GUI 打开、连接设备、打开第一条会话的清楚路线。

建议：按真实 App 的现状补齐 GUI 首次使用路径，再把 CLI 安装作为明确的另一条路线。下载选择先区分 App 与 CLI，再区分架构。

### P2：完整 GUI 缩成了难以检查的缩略图

1360 × 850 的 GUI 在手机上约为 351 × 219px；原生 13px 文字约为 3.4px，44 × 38 控件缩成约 11 × 10px。保持完整外观有展示价值，但不能同时假定它是手机上可直接阅读和操作的体验。

建议：保留完整 Desktop 的首图，提供同一画面的可读放大查看方式；让一个简短的任务结果在小尺寸下也能被理解。不要重做 Mobile 客户端展示，不增加用户已撤回的「打开体验」按钮，不改变不可操作项正常颜色。

### P2：Khor 的独特用途仍由访客推断

“Work across your devices” 和图标演化解释了一个概念，但 P2P 自有设备访问、文件 / 网页与 Git 跟踪在首页没有得到明确而简洁的交代。真实 GUI 已足够丰富，读者仍需要一个具体结果来理解它。

建议：在现有首屏或 GUI 内用一句经过验证的事实和同一个任务的结果补足，不增加长介绍区块、未实现能力、绝对安全承诺或虚构背书。英文标题可以保留，harnesses 之类术语要能由上下文直接理解。

### P2：品牌主题与跨页方向需要统一

当前官网也读取 App 的 canvas token：亮色浏览器中，故事舞台变成米白，Meet 再转入暗色。用户明确的黑场光照叙事与 GUI 跟随系统主题应分别决定。建议 Fog 保持原参数，品牌动画沿既定黑场呈现，GUI 继续自动明暗。

首页 kapestack / Khor 的视觉身份与下载、文档的旧小号 khor 外壳缺少连续性。下载页“功能”还指向已不存在的 `/#features`。顶部“下载”滚到页底，首屏主下载直接进入推荐版本 / 选择页，同名动作也需要统一。

## 其他需要纳入精修的部分

- 初始载入立即启动完整 GUI、图标字体、终端代码及 Fog。开发服务器测得主页面和 iframe 共约 8MB 响应正文，其中含 Vite；不能把它当线上包体。建议先稳定显示已有首图，再在合适的可见 / 空闲时机启动交互与可选模块。
- Fog 离屏仍有调度回调，但实际 GPU 绘制已为零；不把它描述成始终在后台绘制。精修重点应放在首屏并发加载与 GUI 资源上。
- 减少动态效果虽然停掉了动画，却保留约 7.9 屏的手机故事高度；应提供更紧凑的静态阅读路径。
- 页面主体无横向溢出，主 CTA 易点、跳过链接和焦点轮廓存在。手机导航链接、复制按钮及缩放后的 GUI 命中区域偏小；改善点击空间时不必把视觉按钮都画大。
- 顶部黑字在 Fog 向暗场过渡的瞬间会短暂降低可读性。应按背景阶段提前完成导航墨色交接。
- 区分「页面展示可连接 / 访问的设备」与「目前可下载的客户端」。当前公开列表只有 macOS App、Linux/macOS CLI，平台脸不应让访客误以为五个平台安装包都已提供。

## 整体质量与使用者

认知负担中等：首屏分组清楚，长故事、缩略 GUI、六行平铺下载选择和 GUI→CLI 的文档跳转增加了理解成本。入场安静、有识别度；中段重复等候形成低谷；完整图标是视觉高点，下载后的文档交接又降低了开始使用的信心。

- 初次访问者需要明确 Khor 的具体用途与 GUI 起步流程。
- 手机访客能得到正确的桌面下载提示，但不能从极小 GUI 中读取细节。
- 验证产品的人会被真实界面与版本信息说服，也会遇到失效导航和页面风格断点。
