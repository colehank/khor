# 药丸拨杆 Lab

从 `apps/gui` 启动：

```sh
./node_modules/.bin/vite --config lab/deck-joystick.vite.ts
```

打开 `http://localhost:23637/lab/deck-joystick.html`。同一网络的手机可以使用启动日志中的 Network 地址。

这个入口用 Vite alias 给正式 `DeckBand` 注入试验参数；手势模型、浅 U、`SessionScreen`、玻璃控件、头像、状态环、标签总览行和样式直接使用生产代码，不维护第二份交互实现。终端使用真实 xterm 加示例输出，不连接节点。正式 App 使用固定默认值，不读取 Lab 的本地参数。

- 长按展开；向左／右轻拨立即预选前／后一项，继续按住持续翻选，偏移切换慢／中／快三个固定档位，边界留出抖动容差。
- 回到触碰起点暂停；保持候选，直到松手确认。预选期间不打开中间内容。
- 药丸右侧保留刷新位置。开始上拉即显示「全部标签」和上折角，达到门槛后突出，松手打开总览；无需先等长按。长按探索中上推也保留这个入口。
- 「全部标签」和上折角垂直排列，始终位于这次按下位置的中点正上方；和左右速率箭头共用同一手势起点。横向切换、回中、上推时不追随手指漂移；重新按下才重设位置。直接上拉也用同一对齐方式。
- 长按后，左右的 `›`／`››`／`›››` 分别显示真实慢／中／快速，每翻选一项柔和地依次提亮一轮；箭头不完全熄灭，不位移、不弹跳。慢档单枚呼吸，中／快档按方向依次提亮，节拍与真实换项一致。按下的位置保留中点；回中时箭头恢复静止，不显示「暂停」文字，继续停留不会翻选。
- 候选沿当前 app 的浅 U 排列，中央低、两侧抬高，头像下带标题。当前名称最多两行，邻项标题单行省略，文字不随头像缩放。速度使用分级箭头表达，无速度文字、刻度、底板或待选圈；头像自身的状态环保留。上推时仅强调轻文字「全部标签」。弧线跟随预选连续移动，松手确认不等待动画。
- 探索时突出当前候选和左右两项，外侧仅留渐淡的头像，不再排列难读的省略标题；邻项文字加宽、主标题扩大可用宽度并均衡断行。背景从上到下逐渐收暗，保留上方内容的轮廓，候选区落在安静的底上。整个探索层统一淡入，减少动态效果时直接出现；减少透明度时使用实色底。
- 轻点保持内容入口，短横滑保持相邻切换。内容与总览直接使用已有 `MobileContentSheet`／`useContentSheet`，默认半高、抓手可展开与收起、可拖动，保留终端几何。独立标签页圆钮已从正式组件移除。
- Escape、失焦、多指、取消、尺寸或标签列表变化撤销预选。

试验参数在旁边调整，下一次触碰生效。当前默认：长按 280 ms、停区半径 10 px、推远 56 px 到最快，慢／中／快档分别 1400／1000／700 ms 每项。第一项仍立即响应；接下来每一项都按档位留足一个间隔。180 ms 的呈现过渡后，标题分别约有 1220／820／520 ms 的静止时间。旧版 650／240 ms 的本地试验参数不沿用；新参数保存在 `khor.joystick-lab.v2`。

这三个数值是针对本 Lab 的试用起点，并非文献验证过的最佳档位。依据与边界：

- [Aceituno 等，2017，自动滚动研究](https://www.sciencedirect.com/science/article/abs/pii/S1071581916300878)：速度映射会影响越过目标、任务表现与负担；研究任务是文本选择，不能直接换算成本 Lab 的项／秒。
- [Google Switch Access](https://support.google.com/accessibility/android/answer/6301490?hl=en)：逐项自动扫描分别提供扫描间隔和首项延迟设置。这里也将首次响应与后续阅读节拍分开，而不让首次操作等待完整间隔。
- [Apple Motion](https://developer.apple.com/design/human-interface-guidelines/motion)：动效要简短、准确地反馈实际动作，能够随时取消。箭头每轮与真实换项同步，回中立即停止；减少动态效果时保留静态档位数量。

后续用真实标题查找任务比较误选、反向修正和完成时间，再调档位；长标题仍可回中停留阅读。

验证：

```sh
node lab/deck-joystick/check.mjs
node scripts/check-deck-scrub.mjs
./node_modules/.bin/tsc --noEmit -p lab/deck-joystick.tsconfig.json
```

浏览器验证覆盖真实鼠标和 Chrome 触摸输入、回中停留、只提交最终目标、上推总览、搜索／关闭／新建、取消与明暗主题。iPhone 的原生触控、触感与系统键盘仍需实际设备体验。

本轮正式前端构建、默认检查、`content-toolbar`、`content-ui` 与 `browser-yield` 已通过。新增 UIKit 上滑方法和 recognizer 安装代码提取后，使用相同 `objc2` 版本通过 `aarch64-apple-ios-sim` 编译；完整 GUI 的 iOS 检查在外置盘依赖编译阶段中止，尚未验证完整 iOS 构建或设备运行。
